Multiple XIP Support

Execute in place (XIP) regions are areas where an application can execute code directly from ROM rather than having to load it from RAM.

Windows CE allows you to construct multiple XIP regions in a single system. There are several reasons for using multiple XIP regions instead of a single region:

  • You can break applications into functional subsets and install them separately from the core of the operating system (OS).
  • You do not need to replace the whole image to add new features.
  • You do not need to replace the whole image to fix a bug.
  • The user can do updates.
  • Updates are permanent and not vulnerable to cold resets.

The growing popularity of flash memory as a replacement for masked ROM is one of the enabling technologies for using multiple XIP regions. In the Help topics that discuss multiple XIP regions, ROM refers to the flash memory where the system image resides.

A multiple XIP system will divide the ROM image into discrete, upgradeable units. Two of the primary factors going into the decision on how to divide the image are the owner of the modules and files in the region and the functionality of the modules and files in that region.
