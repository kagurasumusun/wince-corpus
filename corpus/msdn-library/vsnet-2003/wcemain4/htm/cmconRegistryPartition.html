Registry Partition for Flash Memory

The registry backup is not stored in the file area; it has its own separate, dedicated partition. Because it is a critical data set, there must always be a complete copy in flash, even when a new version is being written. As a result, the back-up function maintains two copies: the newest copy and the previous one. When WriteRegistryToOEM is called, that function erases the older backup and writes the current registry data into that area of the flash. These two copies must not share any part of a block, so when the previous version is erased, it will not affect the other copy.

If the registry for your platform were not expected to be larger than 100 KB, and if a single flash component were used that had a block size of 128 KB, then two blocks would need to be set aside to back up the registry. However, if the registry were expected to be 150 KB, four 128-KB blocks would be needed to back it up, because two blocks would be required to store one copy, and neither copy could share a block with the other. If the array has two devices per bank, space for the registry is allocated in block-pairs.
