Surrogate Pairs

Windows CE processes surrogate pairs as pairs of 16-bit code values. At display time, the surrogate pair displays as one glyph. Most surrogate support is automatic; that is, if an application supports Unicode and uses standard application programming interfaces (APIs) such as ExtTextOut and DrawText, it also supports surrogates. If your code uses standard system controls, surrogate pairs should not require any changes.

You can also write your own code to handle surrogate text processing. A separated Unicode value from either the lower reserved range or the upper reserved range must be one half of a surrogate pair. Thus, you can detect a surrogate pair by doing simple range checking. If you encounter a Unicode value in the lower or upper range, you can track backward or forward one 16-bit width to get the rest of the character. Keep in mind that CharNext and CharPrev move by 16-bit code points, not by surrogates.

Because surrogate support is limited to handling and display, set to Read Only any edit control used in your application that displays such content.

For sorting, all surrogate pairs are treated as two Unicode code points. Surrogates are sorted after other Unicode code points, but before the private user area. Sorting for a stand-alone surrogate character — that is, either the high or low character is missing — is not supported.
