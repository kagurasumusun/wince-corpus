PSM_OEMInfo

This structure is used to pass OEM-specific information about the hardware platform to the Intel Persistent Storage Manager (PSM) software stack during initialization.

typedef struct PSM_OEMInfo {
VOID_PTR PhysicalReadStartAddress;
VOID_PTR PhysicalWriteStartAddress;
VOID_PTR PhysicalBurstReadStartAddress;
VOID_PTR VirtualReadStartAddress;
VOID_PTR VirtualWriteStartAddress;
VOID_PTR VirtualBurstReadStartAddress;
UINT32 MaximumArrayLength;
UINT32 MaximumRegistrySize;
UINT32 ManagedAreaStart;
UINT32 ManagedAreaLength;
UINT8 ReadBusWidth;
UINT8 WriteBusWidth;
UINT8 BurstReadBusWidth;
} PSM_OEMInfo, *PSM_OEMInfoPtr;

Members

PhysicalReadStartAddress
PhysicalReadStartAddress and VirtualReadStartAddress are the addresses for the beginning of the array. PhysicalReadStartAddress indicates where flash code execution occurs after the operating system (OS) is up. VirtualReadStartAddress is the address used to show where code execution is handled during situations before the OS is built, such as registry initialization. For the example system, the physical address is 0x0000000, and the virtual address is 0xA5000000. These addresses must match those entered in the memory management unit (MMU) initialization table in the previous section.

These must be the address for the beginning of the array that contains the file partition. If the array consists of more than one device or bank, this should be the beginning address of the whole array, not just the area that stores the files.

PhysicalWriteStartAddress
PhysicalWriteStartAddress and VirtualWriteStartAddress are for those systems that need to map reads and writes to the flash into two regions. Recall that some microprocessors cannot write to a memory region that is read using page mode, so it is necessary to use a second chip select to write to the flash. These are the addresses that the PSM should use to write to the flash. They must match those used in the MMU initialization table.

If the system reads and writes the flash using the same address, these entries will be identical to the PhysicalReadStartAddress and VirtualReadAddress entries, respectively, as shown in the example.

This must be the address for the beginning of the array that contains the file partition. If the array consists of more than one device or bank, this should be the beginning address of the whole array, not just the area that stores the files.

PhysicalBurstReadStartAddress
PhysicalBurstReadStartAddress and VirtualBurstReadStartAddress describe where burst reads begin. They are typically both the same as PhysicalReadStartAddress and VirtualReadAddress entries, respectively, as shown in the example.

MaximumArrayLength
This is the total size of the array, in bytes, that includes the file partition. For the example system, the total array consists of two 8-megabyte (MB) components, so the total array size is 16 MB, or 0x1000000. If the array consists of multiple banks, this entry should be size of all those banks.
MaximumRegistrySize
This is used by the registry utility. It is the maximum size that the registry back-up utility should reserve for single copy of registry. The PSM utilities will round this value up to the nearest block-size, and reserve a partition that is big enough to store two copies.

For the example system, the maximum size of the registry was estimated to be 150 kilobytes (KB), small enough to fit in a single block-pair. PSM will create a partition that is big enough to store two back-ups. For the example system, this entry will be 153600 (150 * 1024), and PSM will reserve two block-pairs for the registry back up.

ManagedAreaStart
This tells PSM where to begin the file storage. It is the offset from the beginning of the array in bytes that contains the file partition. The beginning of the array was specified earlier in the StartAddress entries. For the example system this entry will be 0xC40000.
ManagedAreaLength
This is the size of the file partition and registry storage in bytes. For the example system, this entry will be 0x34000.
ReadBusWidth
This is the width in bits of the flash array. If only a single x16 component were used, this entry would be 16. The example system uses two 16-bit components in parallel, so the entry should be 32.
WriteBusWidth
This entry will be the same as the ReadBusWidth.
BurstReadBusWidth
This entry will be the same as the ReadBusWidth.
