I/O Port

Although I/O ports are not required, the Remote Desktop Protocol version 5.1 supports serial and parallel port redirection. This gives a server application the ability to interact with the client's serial port to connect devices such as a bar code scanner. I/O ports, therefore, are a recommended feature of Windows Thin Client devices. The following list defines the requirements for the serial port if it is implemented in a Windows Thin Client device:

  • RS-232-C hardware, if it is present, must meet minimum requirements.

    In general, the serial port hardware must support the standard features that are found in the universal asynchronous receiver/transmitter port of a computer.

  • The serial port must meet minimum speed requirements.

    Serial ports must support speeds of up to, and including, 115.2 kilobytes per second (KBps).

  • The serial port must meet framing requirements.

    The serial port must support all of the combinations of parity and stop bits; also, it must support word lengths of at least seven and eight data bits.

  • The serial port must meet flow-control requirements.

    Hardware flow control that uses Request To Send (RTS) and Clear To Send (CTS) must be supported. Data Terminal Ready (DTR) and Data Set Ready (DSR) hardware flow control is optional. Software flow control must be supported, including the capability to support a clean stop in transmission of the current buffer. Supporting such a clean stop is more challenging for implementations that support large direct memory access (DMA) buffers than it is for implementations that use small serial ports that are based on the first in, first out (FIFO) method.

    The serial port must support a maximum skid of 16 bytes; this is the maximum number of bytes that continue to be sent after the receiver requests a flow control off command.

  • The serial port must support a break in hardware.

    When the serial port hardware receives a break command, it must stop transmission cleanly at a framed byte boundary. Notice that the break command is differentiated from the sending of a continuous stream of logic 0 bytes, because the 0 bytes is framed.

  • The serial port connector must use a standard DB-9 connection.

    For ease of use and convenience, serial ports must use the standard DB-9 connector.

  • The serial port must support minimum signal-line requirements.

    Serial port signal-line support requirements are listed in the following table.

    Name of required signal Description
    Ground (GND) Electrical ground.
    Transmit Data (TXD) Data output; must provide RS-232-C signals at +/– 12V.
    Receive Data (RXD) Data input; must handle RS-232-C signals at +/– 12V.
    Ready To Send (RTS) Software-controlled output used for hardware flow control; must provide RS-232-C signals at +/– 12V.
    Clear To Send (CTS) Input that must generate an interrupt on every +/– 12V edge. This interrupt must be enabled only when the serial port is powered.
    Data Carrier Detected (DCD) Input that must generate an interrupt on every +/– 12V edge. The interrupt must wake up the device from suspend mode and be enabled at all times, which includes the times that the serial port is in suspend mode.
    Data Terminal Ready (DTR) Software-controlled output; must provide RS-232-C signals at +/ – 12V.

You also can choose to implement the optional signal lines that are defined in the following table.

Name of optional signal Description
Data Set Ready (DSR) Input that generates an interrupt on either edge of +/– 12V. This interrupt must be active only during stand-by and full-power modes.
Ring Indicator (RI) Input that generates an interrupt on a transition from +12V to –12V. This interrupt must be active only during stand-by and full-power modes.
