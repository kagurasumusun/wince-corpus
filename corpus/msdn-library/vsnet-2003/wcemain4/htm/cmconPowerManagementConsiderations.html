Power Management Considerations

When the kernel calls the OEMIdle function, the target device is requested to go into a sleep, or idle, state. This consists of saving the current state, placing the memory into a refresh state if necessary, stopping the clock, and suspending execution. When an interrupt, including a scheduled interrupt generated by the timer occurs, the device ends its idle state, the previous state is restored, and the scheduler is invoked. If no new threads are ready to run, the kernel will again call OEMIdle.

Because a certain amount time of time is required for the target device to go in and out of an idle state, real-time performance can be adversely affected. Therefore, it is recommended that an OEM's implementation of OEMIdle be set to return immediately when it is called.
