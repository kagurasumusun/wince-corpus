OAL Migration

An OEM adaptation layer (OAL) is the layer between the Windows CE kernel and the hardware of your target device.

The following table describes migration issues for the OAL.

Issue Description
Unsupported variables The following variables are no longer required in the OAL by the kernel:
  • dwSleepMin
  • dwPartialDiffMSec
  • ticksleft
  • DiffMSec
New scheduling variables dwReschedTime has been added to the OAL to determine if the kernel should schedule a thread to run. This affects both OEMIdle and the handling of the system tick.

The following table describes OAL migration issues related to the kernel and device drivers.

Issue Description
Kernel name change A version of the kernel executable that is built as part of the build process has changed names to allow better tools integration.

The kernel executable known as Nk.exe is now called Nkkd.exe.
ActivateDeviceEx replaces ActivateDevice and RegisterDevice ActivateDeviceEx reads the registry key specified in its lpszDevKey parameter to get the DLL name, device prefix, index, and other values. Next, it adds the device to the active device list and stores the relevant values there. If no device index was specified in the key named in lpszDevKey, it assigns a free index. Then, it loads the device driver DLL in the process space of the Device Manager.
GetThreadPriority and CeGetThreadPriority The current priority is no longer returned.

In Windows CE 3.0 and earlier, a call to GetThreadPriority or CeGetThreadPriority would return the current thread priority. This might incorrectly return the priority of a thread that had its priority boosted because of priority inversion.
x86 page tables The x86 page tables are now setup in the same way as ARM, requiring the x86 platform to provide a valid OEMAddressTable structure back to the kernel, defining the virtual to physical mapping.

The following table describes OAL migration issues related to the SDK.

Issue Description
HeapCreate The dwMaximumSize parameter of HeapCreate is now honored and allocates only as much memory as requested. If you had previously passed in 0, you will still get an unlimited heap as specified by Microsoft Win32®.
System Halt Should the system halt, the OEM will now get called in through the OAL function lpNKHaltSystem, giving the OEM the opportunity to reset the device.
