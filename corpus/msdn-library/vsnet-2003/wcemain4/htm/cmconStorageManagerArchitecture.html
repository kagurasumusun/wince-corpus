Storage Manager Architecture

The following illustration shows the storage architecture for the Microsoft® Windows® CE .NET operating system (OS).

The Storage Manager modules are loaded through the registry.

The "Dll" subkey of the HKEY_LOCAL_MACHINE\System\StorageManager registry key enables the Storage Manager. The PNPUnloadDelay subkey of the HKEY_LOCAL_MACHINE\System\StorageManager registry key specifies the time delay in milliseconds after the Storage Manager receives a Plug and Play (PnP) identifier unload notification of a block driver before it is actually unmounted. This notification forces unmounts of the partition driver and any file systems. During this period, the mount points move into a suspended state and requested I/O access to the mount points fail with ERROR_DEVICE_NOT_AVAILABLE. The primary use for this is during suspend/resume cycles where a block driver might unload and reload on resume. When the Storage Manager receives a load notification, it examines the block device to see if it is identical to the previously unmounted device. If it is identical, the block device remounts under the previous mount points.

The following registry key examples tell the file system to load the FSD Manager:

[HKEY_LOCAL_MACHINE\System\StorageManager]
    "Dll"="fsdmgr.dll"
    "PNPUnloadDelay"=dword:1000
[HKEY_LOCAL_MACHINE\Loader]
    "SystemPath"=multi_sz:"\\Release\\"
[HKEY_LOCAL_MACHINE\System\StorageManager\AutoLoad\Relfsd]
    "Dll"="relfsd.dll"
    "Paging"=dword:1

The block driver reports that it is a particular profile. Then, the file system looks at the profile to determine what to do. Storage drivers report a profile back in the STORAGEDEVICEINFO structure. The szProfile string retrieves this profile. The structure is also available in the STOREINFO returned from the GetStoreInfo API. The Storage Manager uses the registry to retrieve appropriate information about the store. The information is stored in the HKEY_LOCAL_MACHINE\System\StorageManager\Profiles\szProfile registry key.

The HKEY_LOCAL_MACHINE\System\StorageManager\Profiles\szProfile\PartitionTable registry key defines the partition table to use. The partition table is a list of values. The name is the partition identifier, and the value is the file system driver. The following registry key examples show the 07 registry entry, which defines NTFS as the partition type, and the instruction is not to load any file system:

[HKEY_LOCAL_MACHINE\System\StorageManager\Profiles\PCMCIA]
    "Name"="PCMCIA/Compact Flash Device"
    "Folder"="Storage Card"
    "AutoMount"=dword:1
    "AutoPart"=dword:0
    "AutoFormat"=dword:0
    "MountFlags"=dword:0
    "FileSystem"="fatfsd.dll"
    "PartitionDriver"="mspart.dll"
[HKEY_LOCAL_MACHINE\System\StorageManager\Profiles\HDProfile]
    "Name"="IDE Hard Disk Drive"
    "Folder"="Hard Disk"
    "AutoMount"=dword:1
    "AutoPart"=dword:0
    "AutoFormat"=dword:0
    "MountFlags"=dword:0
    "FileSystem"="fatfsd.dll"
    "PartitionDriver"="mspart.dll"
[HKEY_LOCAL_MACHINE\System\StorageManager\Profiles\HDProfile\PartitionTable]
    "07"=""
[HKEY_LOCAL_MACHINE\System\StorageManager\Profiles\CDProfile]
    "Name"="IDE CDROM/DVD Drive"
    "Folder"="CDROM Drive"
    "AutoMount"=dword:1
    "AutoPart"=dword:0
    "AutoFormat"=dword:0
    "MountFlags"=dword:0
    "FileSystem"="udfs.dll"
    "PartitionDriver"=""

The following registry key example is the default for the FAT file system; profiles can override these values:

[HKEY_LOCAL_MACHINE\System\StorageManager\FATFS]
    "FriendlyName"="FAT FileSystem"
    "Dll"="fatfsd.dll"
    "Flags"=dword:00000024
    "Paging"=dword:1
    "CacheSize"=dword:0

The following registry key example is the default for the Universal Disk File System (UDFS); profiles can override these values:

[HKEY_LOCAL_MACHINE\System\StorageManager\UDFS]
    "FriendlyName"="CDFS/UDFS FileSystem"
    "Dll"="udfs.dll"
    "Paging"=dword:1

The following registry key examples are the default for all profiles; a named profile overrides these values:

[HKEY_LOCAL_MACHINE\System\StorageManager\Profiles]
    "AutoMount"=dword:1
    "AutoPart"=dword:0
    "AutoFormat"=dword:0
    "MountFlags"=dword:0
    "DefaultFileSystem"="FATFS"
    "PartitionDriver"="mspart.dll"
    "Folder"="Mounted Volume"
[HKEY_LOCAL_MACHINE\System\StorageManager\Profiles\PCMCIA]
    "Name"="PCMCIA/Compact Flash Device"
    "Folder"="Storage Card"
[HKEY_LOCAL_MACHINE\System\StorageManager\Profiles\HDProfile]
    "Name"="IDE Hard Disk Drive"
    "Folder"="Hard Disk"
[HKEY_LOCAL_MACHINE\System\StorageManager\Profiles\HDProfile\FATFS]
    "EnableCacheWarm"=dword:0
[HKEY_LOCAL_MACHINE\System\StorageManager\Profiles\TRUEFFS_DOC]
    "Name"="DiskOnChip M-Systems"
    "Folder"="DiskOnChip"
[HKEY_LOCAL_MACHINE\System\StorageManager\Profiles\TRUEFFS_PCMCIA]
    "Name"="PCMCIA TrueFFS device"
    "Folder"="PCMCIA"
[HKEY_LOCAL_MACHINE\System\StorageManager\Profiles\SDMMC] 
    "Name"="SD MMC device"
    "Folder"="SD Card"

The following table shows the various flags that you can place in the HKEY_LOCAL_MACHINE\System\StorageManager\Profiles registry key.

Flag Description
"Folder" This is the base name to use when a volume is mounted on this store. If a name is in use then a number is concatenated to the base name and increased each time.
"FileSystem" The default file system to load.
"PartitionDriver" The default partition driver to load. If this string is empty, load the built-in NULL partition driver. There is no partitioning.
"AutoFormat" Formats the store automatically.
"AutoPart" Automatically partitions the store with largest creatable partition.
"AutoMount" Automatically mounts each detected partition if the FSD Manager is available.
"Name" This is the friendly name of the store and is available in the szStoreName member of the STOREINFO structure.
"MountFlags" Flags on how the partition is mounted.

You can assign one value to the MountFlags registry subkey of HKEY_LOCAL_MACHINE\System\StorageManager\Profiles. The following table shows the available values for the MountFlags registry subkey.

Value Description
1 Specifies a hidden file system.
2 Specifies that the file system may contain the system registry. The first mounted partition on the store gets the hive.

For more information, see Hive-Based Registry.
4 Specifies to mount as the root of file system.

For more information, see Mounting an Installable File System as the Root.
8 Specifies to hide the ROM when mounting the file system root. Use with FLAG_ROOTFS.

For more information, see Mounting an Installable File System as the Root.

The file system registry subkey in either the HKEY_LOCAL_MACHINE\System\StorageManager\StorageManager\FATFS registry key or under the profile HKEY_LOCAL_MACHINE\System\StorageManager\Profile\<profile name>\FATFS registry key contains values specific to the FAT file system.

Some predefined registry subkeys apply to all file systems. The following table describes these registry subkeys.

Flag Description
"FriendlyName" This is a descriptive name for the file system.
"Dll" Module to load for the file system.
"Paging" Set to 0 to disable paging. Set to 1 to enable paging. One is the default.

For information on the FAT file system and the FAT file system registry setting, see FAT File System and FAT File System Registry Settings.

Use the AutoLoad registry subkey of the HKEY_LOCAL_MACHINE\System\StorageManager registry key to load an installable file system. AutoLoad eliminates the need for the LoadFSD command. By specifying the name of the installable file system in this registry key, the Storage Manager loads the file system. The following registry key is an example of using the AutoLoad registry subkey:

[HKEY_LOCAL_MACHINE\System\StorageManager\AutoLoad\Relfsd]
    "Dll"="relfsd.dll"
    "Paging"=dword:0
