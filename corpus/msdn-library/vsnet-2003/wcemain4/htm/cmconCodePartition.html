Flash Memory Code Partition

The code partition must be big enough to store all of the firmware. For most systems, this is the boot and initialization code, and the operating system (OS) image. The boot code receives control after a RESET; it initializes the hardware, then transfers control to the OS image.

One of the main reasons to use flash instead of other nonvolatile technologies is its ability to be reprogrammed in-system. To save memory, the previous code image is erased and the new image programmed into the flash. When the previous image is erased, the boot code must not be lost, because the update could be interrupted before the new image is programmed. There is no way to recover from an interrupted update if the boot code is lost. As a result, if the OS image will be updated, the boot code must reside in its own block or blocks, so that when the rest of the code is erased, the boot code will not be affected.

If the system does not support reprogramming the OS image, the boot code and OS image can share a block.

Creating the Flash Memory Code Partition

Processor-specific tools typically generate the boot code. This code begins executing at a RESET, initializes the hardware, and then jumps to the OS image. If the OS image will execute entirely from RAM, the boot code will include a utility to copy the OS image from flash to RAM.

The ROM Image Builder Utility creates the OS image. It locates the image using commands in the MEMORY section of the Config.bib file. Usually, the code section is named NK, and the designer will specify the name, beginning address, size and type of the code partition. Example entries for this section are shown in the following code example.

;
; name     address     size        type
  NK       80000000    01000000    RAMIMAGE
  RAM      8C120000    00ED0000    RAM
