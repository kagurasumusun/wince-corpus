Microsoft Windows CE .NET  

New OS Features

This topic contains information about the new operating system (OS) features included in Microsoft® Windows® CE .NET 4.0 and Microsoft Windows CE .NET 4.1. Not all the new features listed here can be found in the Platform Builder Catalog. Some new OS features apply to more than one Catalog feature. For more information about Platform Builder Catalog features, see Catalog Features. For information about the new Platform Builder features, see What's New.

The following tables in this topic show the new OS features for Windows CE .NET 4.0, Windows CE .NET 4.1, and the feature names that have changed:

SIP allows a device to call or receive calls from any SIP client. A SIP client can be a Windows CE device, a machine running Microsoft Windows XP, or a third-party SIP user agent. CPU Architecture Enhancements The CPU architecture was enhanced with the following functionality:
  • An improved WMA audio decoder and optimized memcpy for ARM processors.
  • An optimized memcpy function has been added to enable improved performance on memory intensive operations for ARM-based processors.
  • The ARM compiler has been updated to correctly threshold the memcpy sizes and subsequently call the optimized memcpy routines in most cases, and the inline version of memcpy only for very small blocks. In Windows CE .NET 4.0, the ARM compiler aggressively inserted an inline version of memcpy and hence, would not benefit from the optimized memcpy for ARM processors.
  • A workaround has been implemented in the ARM v4 and ARM v4I kernels to address an address line problem during critical shutdown. This change allows you to hook the Data Abort Handler in the kernel and do your own processing such as drive the address lines to the proper state prior to shutdown.
  • Support has been added in the ARM kernels to save and restore Coprocessor 0 (CP0) state during a context switch. Certain multimedia applications can use CP0 for enhanced performance. Without this change, applications would not be able to use the CP0, because the contention among applications wanting to use CP0 must be managed by saving and restoring the state during a context switch.
  • A new VirtualSetAttributes API has been added to the ARM kernel to enable graphics software to take advantage of the new feature in the Intel XScale microarchitecture to disable the cache for a memory region but leaving the buffering on to gain advantage of memory access coalescing. This improves graphics performance on the Intel PXA250 processor under certain types of graphics operations. Subsequently, the Intel DBPXA250 BSP display driver was enhanced to make use of the VirtualSetAttributes API and thus, make better use of the memory bus by coalescing reads and writes in the software.
  • The Intel XScale microarchitecture has a longer pipeline than other ARM platforms. The compiler for Windows CE .NET has been updated to take advantage of this hardware difference. No shipped code for Windows CE .NET has been compiled with this optional flag but you are encouraged to build your applications with this optimization enabled.

  • An improved audio driver for Hitachi-based systems using the HD64465 companion chip.
  • Support for anti-aliased fonts in the TVIA5000 display driver.
  • An improved high-speed serial port driver.
Device Management This feature allows you to install application and software updates without involving the user. It supports polling, download, failure recovery, and status reporting. Device management consists of the device management service, the client, and the Microsoft Systems Management Server (SMS) device proxy.

For more information, see Device Management Overview.
File System Enhancements File system drivers now include the following enhancements in Windows CE .NET 4.1:
  • Support for preserving compression file attributes in the RAM file system, which results in improved Internet Explorer performance when caching or downloading files.
  • Performance improvements to the FAT file system (FATFS) related to large file copy and delete operations.
  • Support for memory-mapped file caching, which enables database code to turn on or turn off cache flushes.

For more information, see File Systems.
File Viewers This feature includes the following functionality:

  • The Microsoft Image Viewer allows the user to control how images are viewed to create a slide show. Images can be sorted, rotated, or zoomed. The timing between slides can be set and there are a variety of transition effects to choose from.
  • The Microsoft PowerPoint Viewer displays presentations created in Microsoft PowerPoint® 97, PowerPoint 2000, and PowerPoint XP.
  • The Microsoft Excel Viewer displays documents created in Microsoft Excel 97, Excel 2000, and Excel XP.

IEEE 1394 This feature's modules include the following new driver: IEEE 1394 Serial Bus Protocol 2 (SBP-2) Driver.

The SBP-2 driver provides applications the ability to access block-based mass storage devices, such as hard drives and CD-ROM drives on the IEEE 1394 bus by using the standard file system APIs.

For more information, see IEEE 1394 SBP-2 Drivers.

NTLM v2 Authentication Protocol This feature is implemented as a security package that is accessible through the Security Support Provider Interface (SSPI). NTLM v2 has several enhancements over the older LAN WAN protocol that address security issues and session security requirements for confidentiality, integrity, and 128-bit encryption.

Power Manager This feature now includes the following enhancements:

Speech API (SAPI) This feature is a subset of the Microsoft Speech Application Programming Interface (SAPI) version 5.0. SAPI 5.0 is a programming standard for speech recognition and text-to-speech. Speech recognition applications allow a computer to respond to spoken commands. Text-to-speech applications allow a computer to synthesize a voice that speaks words that are in a string or text file.

For more information, see Speech API Overview.
TCP/IPv6 Support This feature is a suite of standard protocols that is the next generation of network layer protocols for the Internet. Using 128-bit addresses, IPv6 provides more IP addresses than its predecessor, IPv4, which uses 32-bit addresses.

Windows Messenger for Windows CE .NET This feature is a client application that combines real-time voice and text communications with file transfer capability. Windows Messenger is presence-enabled. This means that users can see who is available online before they try to contact other people, and they can control their online status, which other people see. They can also initiate remote assistance, multiplayer games, and other applications using Windows Messenger.

The Windows Messenger client leverages the Communications Service service provider, the Session Initiation Protocol (SIP) stack, the Real-Time Protocol (RTP) stack, and the MSN Messenger protocol stack.

For more information, see Windows Messenger Overview.
Winsock 2.2 This feature provides a general-purpose networking API based on the socket interface from the University of California at Berkeley. Winsock is designed to run efficiently on Windows OSs while maintaining compatibility with the Berkeley Software Distribution (BSD) standard, known as Berkeley Sockets. Most Windows CE network communication passes through the Winsock interface. Windows CE .NET 4.1 implements Winsock 2.2 and is fully backwards compatible with Winsock 1.1.

For more information, see Winsock 2.2.
