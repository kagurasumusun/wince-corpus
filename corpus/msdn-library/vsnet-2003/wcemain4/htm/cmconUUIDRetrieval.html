UUID Retrieval

Each Windows Thin Client must have a UUID assignment as part of the licensing agreement. A UUID is a 16-byte integer that virtually is guaranteed to be unique; it usually is represented as a string.

The following string shows a UUID that is generated on the computer of the author.

4208fb66-e22a-11d1-a7d7-00a0c982c00d

Microsoft has defined the following structure as a container for the 16 bytes that are required by a UUID.

typedef struct  _GUID
    {
    DWORD Data1;
    WORD Data2;
    WORD Data3;
    BYTE Data4[8];
    }    GUID;

The format specification and algorithms to generate these UUIDs, including C code implementation, are detailed in Network PC Design Guide, Version 1.0b or later. For more information, see this Microsoft Web site.

You are required to store the UUID in a region of nonvolatile memory on the Windows Thin Client. You must ensure that the UUID cannot be erased or overwritten after the device has been shipped. This is especially true of Windows Thin Clients that can have their software upgraded in the field.

You also are required to implement a KernelIoControl function that reads the UUID from the nonvolatile memory. %_WINCEROOT%\Public\Rdp\Oak\Uit\Wbttscmn\Ioctl.cpp contains the GetUUID(GUID* myUUID) function, which in turn calls the KernelIoControl function for the IOCTL_HAL_GET_UUID. The control code that is specified for reading a UUID is IOCTL_HAL_GET_UUID.

An example of the recommended implementation for any Windows Thin Client device that uses the Remote Desktop (RDP) client can be found at %_WINCEROOT%\Platform\Cepc\Kernel\Hal\Oemoictl.c.
