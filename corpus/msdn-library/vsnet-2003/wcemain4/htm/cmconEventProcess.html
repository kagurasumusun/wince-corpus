Event Process

Filesys Startup

When the file system starts with the final registry, not the boot hive, it will read the event names from the registry and create the events as manual reset events. When the module that added the event data is run, it will call OpenEvent to open the event and set the event. Any waiting thread will be released. The event will remain active for the life of the OS.

Waiting Threads

When modules start, they will first try to call OpenEvent for the API sets that they are related to. If OpenEvent fails, the API set was never, and will never be, registered. If OpenEvent succeeds, the module can call the WaitForSingleObject function to wait for the API set to be registered. This eliminates polling and lets a module know for sure if an API set is ever going to be registered.
