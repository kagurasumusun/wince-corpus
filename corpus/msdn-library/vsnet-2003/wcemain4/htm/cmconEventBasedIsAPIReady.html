Determining if an API is Ready

Currently, if a component or module depends on an API set being registered, the component or module uses the IsAPIReady function. This API returns TRUE or FALSE depending on whether the API set was registered. The main problem with the API is that dependent API sets may never get registered if the module that registered them is not part of the configuration. Another problem is that some components may end up polling and waiting for the transition so that, for example, they can display a user interface.

The kernel and file system applications are the only two applications guaranteed to run when the OS boots. Currently, the file system has a named event that drivers can wait on to indicate a transition from the boot registry to the final registry. Any driver that waits on the event has the opportunity to reread registry settings once the event is triggered. The event is a manual reset event that never gets cleared. This way ensures that any driver that loads and runs after this event is set will automatically not wait in their Wait* API call.

The methodology used by the registry can be used in other parts of the OS to trigger waiting applications.

For more information, see Event Registration and Event Process.
