Client Information Key

The following subkey is the root subkey for storing client information in the registry.

[HKEY_LOCAL_MACHINE\Software\Microsoft\WBT\Clients\Registration]

From this root, each client must have its own subkey to inform the shell about the client and each connection that has been defined for it.

The following are examples of client information keys.

[HKEY_LOCAL_MACHINE\Software\Microsoft\WBT\Clients\Registration\RDP]
[HKEY_LOCAL_MACHINE\Software\Microsoft\WBT\Clients\Registration\VT100]
[HKEY_LOCAL_MACHINE\Software\Microsoft\WBT\Clients\Registration\3270]

A client information key can have any name, as long as it is unique. The shell enumerates the keys in the Registration key to determine the registered clients.

The following table shows the named values for HKEY_LOCAL_MACHINE\Software\Microsoft\WBT\Clients\Registration.

Value Description
DefaultClient: REG_SZ No default setting. The DefaultClient value specifies the registered client key to designate as the default client when an end user creates a new connection. This key name must not be confused with the Type entry of a registered client.

The following code example shows how to set the default client to RDP.

[HKEY_LOCAL_MACHINE\Software\Microsoft\WBT\Clients\Registration]
    "DefaultClient"="RDP"

Client information entries must be contained in named values placed at the root of each client information key.

HKEY_LOCAL_MACHINE\Software\Microsoft\WBT\Clients\Registration\Your client name

If the entry of a client is incomplete or not valid, then the shell ignores the client, and a user is not able to create connections that are based on the client. It is important to enter appropriate values, because an error message is not posted to a user if the shell encounters a client that is not properly configured.

The following table shows the named values for a client.

Value Description
Description: REG_SZ No default setting. This value specifies the display name for the client. For example, the display name for the Microsoft Remote Desktop Protocol (RDP) might be "Microsoft Remote Desktop Client." When creating connections, a user is presented with the list of emulators and their descriptions.

This value is required.

Type: REG_SZ No default setting. The Type value specifies the short eight-character description for the client. A user sees the specified string in the Type column of the Windows Thin Client Shell user interface (UI). The value that is specified for Type does not need to be the same as the name of the client key. In other words, it is acceptable for two clients that have two different client information keys to have the same Type value. For example, two VT100 clients might have different client key names — "VT100a" and "VT100b" — but the Type value can remain "VT100" for both clients.

This value is required.

NewExe: REG_SZ No default setting. The NewExe value specifies the helper application to call when creating a new connection. Each client must have a helper application for creating new connections. The helper application for creating new connections must be a wizard.

This value is required
NewCmdLineArgs: REG_SZ No default setting. The NewCmdLineArgs value specifies the command-line arguments to pass to the helper application that is specified by the NewExe value. This is useful if you want to provide one combined helper application to create, edit, and delete connections. The command-line arguments can be used to specify the required function.

This value is optional.

The following code example shows the client information key that is required for RDP, as specified in the registry.

[HKEY_LOCAL_MACHINE\Software\Microsoft\WBT\Clients\Registration\RDP]
    "Description"="Microsoft Remote Desktop Client"
    "Type"="RDP"
    "NewExe"="Tsconwiz.exe"
    "NewCmdLineArgs"=""
