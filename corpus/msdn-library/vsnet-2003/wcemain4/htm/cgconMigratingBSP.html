Migrating a BSP

In addition to creating a BSP, you should consider migrating or updating a BSP to be fully compatible with the features in Windows CE .NET. This topic provides a complete list of steps required to migrate the BSP to Windows CE and contains the implementation details for each step.

These steps are categorized as required, recommended, or optional. You should attempt to implement each of these features in your BSP. At a minimum, implement the required and recommended features on your BSP.

The following procedure shows a summary of the list of steps needed to migrate a BSP:

  1. Add the BSP to the Catalog.

    The following table shows a summary of how to add your BSP to the Catalog.

    Step Description
    Use the BSP Wizard to create a BSP definition for MyBSP in the Catalog. Required
  2. Update your OAL.

    The following table shows a summary of how to update your OAL.

    Step Description
    Implement a variable system timer tick in the OAL. Required. At a minimum, use the new variables.
    Update IRQ-to-SYSINTR mappings with OEMTranslateIrq. Required
    Update IRQ-to-SYSINTR mappings with OEMTranslateSysIntr. Required
    Update IRQ-to-SYSINTR mappings with OEMRequestSysIntr, for new SYSINTR mappings. Required
    Add new IOCTLs. Required
    Remove old IOCTLs. Required
    Remove CreateStaticMapping space in the OAL. Optional
    Enable KITL in the BSP by adding or updating HALKITL.C. See the shipping platform code. Required
    Enable KITL in the BSP by using the PCI Reg tool and populate registry with KITL info. This is required so the PCI bus driver does not try to load a product driver for the debug NIC. Required
    Enumerate KITL, other debug devices, and any intermediate PCI bridges. Required
    Enable installable ISRs in the BSP by implementing shared interrupts in main ISR. Recommended for systems using shared interrupts
    Enable installable ISRs in the BSP with the NKChain interrupt handler. Recommended for systems using shared interrupts
    Setup and Initialize fixed and built-in devices. Required
    Add a hive-based registry. Optional
  3. Update your Boot Loader.

    The following table shows a summary of how to update your boot loader.

    Step Description
    Use BLCOMMON infrastructure. Recommended
    Update the .bib files and verify that the address range is compatible with the OS image. Required
    Remove PCI code from the boot loader and only enumerate debug devices and any intermediate PCI-PCI bridges. Required
    Remove code to clear memory for a clean boot. The KITL library based on user selections from Platform Builder now does this. Optional
    Enable VMINI in the boot loader. See Readme.txt in %_WINCEROOT%\Public\Common\Oak\Drivers\Ethdbg\Vmini. Optional
  4. Update your Kernel, Debugger, and Profiler.

    The following table shows a summary of how to update your kernel, debugger, and profiler.

    Step Description
    Update kernel image names, kern, kernkitl, kernkitlprof, and directories. Required
  5. Update your Build Environment

    The following table shows a summary of how to update your build environment.

    Step Description
    Adjust for new CPU names; for example SA1100 is now ARMV4 and R4300 is now MIPSII_FP. Required
    Adjust for new Kernel names. Required
    Use BSP and BSP_NO environment variables, set as appropriate in platform batch file and reference in platform .reg and .bib files. Recommended
    Set BSP_DISPLAY flag. Required
    Use new SYSGEN flags; filter platform dirs files based on CE_MODULES to build only require components. Required
  6. Update your Device Drivers.

    The following table shows a summary of how to update your device drivers.

    Step Description
    Use the CSP and common drivers. Recommended
    Use the new driver loading model to load drivers. Recommended
    Use the new NDIS driver loading model to load NDIS miniports. Recommended
    Use ActivateDeviceEx to load drivers. Recommended
    Use I/O Resource Manager (IORM) and update registry for drivers. Recommended
    Use PCI bus driver and update registry for drivers. Optional
    Use Installable ISRs in device drivers. Optional
    Use power management in device drivers. Recommended
    Update device drivers to provide device notifications. For more information, see Device Interface Notifications. Optional
