Flash Memory Partitions

An important feature of Intel Persistent Storage Manager (PSM) is the ability to store code, files, and the registry in a single flash component or array. The first step in including PSM in a system is to decide how much space to reserve for each function. The flash array will then be divided into appropriately sized partitions. Most implementations allow the code and registry partitions to be as big as needed, and use whatever flash is remaining to store files.

A partition is a part of a flash device or array that is dedicated to a single function. They begin and end on flash block boundaries because each partition must be completely independent of the others. For example, the file system routinely erases the blocks it manages. If one of those blocks contained code, the code would be lost when the file system erases that block.

If the flash is accessed in pairs, which provide 32-bit access, memory will be allocated in pairs of blocks, or block-pairs. If the design uses pairs of 28F128J3 devices with a block size of 128 KB, connected to 32 MB chips, the processor will read from both devices every time it does a 32-bit access. The lower 16-bits will be in one device and the higher ones in the other. Because the array will generally be read in pairs, it must be modified in pairs. Because two blocks, or a block-pair, is the minimum amount of memory that can be erased, the minimum granularity for a partition in this array would be 256 KB. A group of devices connected in parallel is called a bank.

If the flash array contains more than one flash device, a partition can span multiple components. Similarly, a partition can span multiple banks. In these multi-component or multi-bank arrays, the flash devices may be different sizes, but all must be from the same component family. All devices in a bank must be the same size.

A designer can dedicate an entire device or bank to a partition.
