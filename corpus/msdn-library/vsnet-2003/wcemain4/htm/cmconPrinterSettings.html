Printer Settings

Both the Add Printer Wizard (APW) and Setup user interfaces (UIs) are backed by logic, which reads and writes printer information. Additional printer manufacturers and models can be added to ntprint_parsed.txt, which will be built into the run-time image (NK.BIN). The printer name must be identical to the printer name of the server, so that the correct driver can be loaded onto the server during a redirected print operation.

The registry settings for the installed printers are stored in the following registry key.

HKEY_LOCAL_MACHINE\WBT\Printers\DevConfig

However, new printers should not be added by adding additional registry settings. New printers should be added by going through the Add Printer wizard, because the wizard adds some binary data to the registry depending on the printer added. This binary data is critical for the correct functioning of redirected printing.

Addition of a new printer through the wizard has additional associated logic in RDP 5.1. Binary data associated with the printer is stored in HKEY_LOCAL_MACHINE\Software\Microsoft\Terminal Server Client\Default\AddIns\RDPDR under the named value PrinterCacheData0.

For details regarding the format of this data refer to %_WINCEROOT%\Public\Rdp\Oak\Uit\Wbttscmn\Printerhelper.cpp

The format of the registry information is as follows.

[HKEY_LOCAL_MACHINE\WBT\Printers\DevConfig\LPT1:]
    "Name"="My WBT Printer"
    "Driver"="HP LaserJet 6L"
    "Default"=1
[HKEY_LOCAL_MACHINE\WBT\Printers\Default]
    @="LPT1: "

The key name (LPT1:) in the preceding example can be replaced by any physical port that is available on the Windows Thin Client.

"Name" is the user-defined "friendly name" of the printer; this name is optional.

"Driver" is the Microsoft Windows model name of the printer; this name is required.

The default local printer is the one that has the port name that is the default value ("@") of the Windows Thin Client\Printers\Default key. If this value or key does not exist, then no local printer is the default printer.
