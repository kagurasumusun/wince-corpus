Terminal Server Client Registry Settings

The registry subkey that controls the configuration of the Terminal Server Client is HKEY_LOCAL_MACHINE\Software\Microsoft\Terminal Server Client. The following table shows the named values for this subkey.

Value Description
CEConfig Default setting is "WBT". This value identifies whether the Terminal Service Client is being used within a Windows Thin Client shell. The following list shows the available settings.
  • "WBT" -- Used when the Terminal Server Client is running in a Windows Thin Client Shell. This is when SYSGEN_WBTSHELL = 1
  • "Maxall" -- Used in all other configurations.
CEUseScanCodes: DWORD Default setting is 0.
Keyboard Type: DWORD Default setting is 4.
Keyboard SubType: DWORD Default setting is 0.
Keyboard FunctionKeys: DWORD Default setting is C.
Keyboard Layout No default setting. This value specifies the LOCALE of the keyboard in hexadecimal as a string.

Configuration Settings

You should set CEConfig to "WBT" for any platform configuration that uses the Windows Thin Client Shell. The following list identifies the behavioral changes to your platform caused by this setting:

  • File change notifications through protected server library (PSL) calls will be disabled.
  • The Windows Thin Client Shell will not bring up the Microsoft Terminal Server Client (MSTSC) user interface.
  • Keyboard hooks will be disabled for the Windows Thin Client Shell
  • Additional registry migration will occur for Windows Thin Client platforms because the connections are started through registry settings and not through .RDP files.

The following list describes issues that a CE device running the Windows Thin Client might encounter if it has CEConfig set to "Maxall":

  • Crashes in Filesys.exe when drive redirection is enabled and a file copying through the clipboard is attempted.
  • Choosing Cancel from a dialog box asking if you want to enable drive redirection will cause the MSTSC user interface to appear in the Windows Thin Client.
  • Hoy key messages, such as CTRL+ALT+LEFT, might be sent to remote sessions.

The following code example shows the registry settings in Rdp.reg associate .rdp files with MSTSC.

[HKEY_CLASSES_ROOT\.rdp]
    @="rdpfile"
[HKEY_CLASSES_ROOT\rdpfile]
    @=LOC_RDPCONNECTION
[HKEY_CLASSES_ROOT\rdpfile\DefaultIcon]
    @="\\Windows\\mstsc.exe,-101"
[HKEY_CLASSES_ROOT\rdpfile\Shell\Open\Command]
    @="\\Windows\\mstsc.exe %1"

Keyboard Settings

You can use the keyboard subkeys to allow non-English keyboards to connect to the Windows Thin Client. The following code example shows the registry settings for a Japanese keyboard.

IF LOCALE=0411
IF BSP_KEYD_JPN1!    //BSP_KEYBD_JPN1=1 is for 101 keyboard layout for Japanese
[HKEY_LOCAL_MACHINE\Software\Microsoft\Terminal Server Client]
    "Keyboard type"=dword:7
    "Keyboard SubType"=dword:2
    "Keyboard FunctionKeys"=dword:c
    "Keyboard Layout"="0x00000411"
ENDIF
ENDIF

These settings also apply to any non-RDP application that transmits scan codes to a server.
