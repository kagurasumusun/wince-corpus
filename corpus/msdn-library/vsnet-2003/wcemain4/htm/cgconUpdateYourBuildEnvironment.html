Update your Build Environment

The following steps show how to update your BSP to handle the new build and environment system:

  1. Adjust for new CPU names.

    The CPU names have been changed significantly. You should make the following changes in your BSP to adjust for the new CPU names:

    • All the sources files for your BSP must be updated to use the new CPU names.
    • Change Kernel\Hal\SHx to Kernel\Hal\SH
    • Update the command line build window parameters to use the new CPU names.
    • Filter \platform and \public files based on CEModule variables.
  2. Adjust for new kernel names.

    Along with the CPU names, the kernel names have also been changed significantly. You should make the following changes in your BSP to adjust for the new kernel names:

    • Update the command line build window parameters to use the new kernel names.
  3. Use new BSP and BSP_NO environment variables.

    Several new BSP and BSP_NO variables have been introduced to help create and configure BSPs with more flexibility. You should make the following changes in your BSP to adjust for these new variables:

    • Set BSP_NO variables in your platform batch file for any options your platform hardware does not support. In addition, when using common drivers such as display, audio, network, and so on, you should set positive BSP variables to choose defaults for each type of device. For example, set BSP_DISPLAY_PERM3 = 1 or BSP_WAVEDEV_TVIA5000 = 1. Positive BSP variables should also be set in the BSP's .cec files using the DefaultDriver keyword. Failure to do so means you will be prompted to choose the default each time you build a project based on the platform. In the case where a device is detected, such as a PCI bus, a number of drivers may be included in the image. For example, by setting all of the BSP_DISPLAY variables, the image will detect and load a driver for all of the support display devices.
  4. Set the BSP_DISPLAY flag.

    All the display drivers have been moved to the public drivers tree under %_WINCEROOT%\Public\Common\Oak\Drivers\Display. Display drivers are now listed in Common.reg and Common.bib files.

  5. Support platform Sysgens to optimize the build.

    Platform dirs, reg, and bib files can now be filtered based on CE_MODULES variables. This means that unless an OS feature is chosen which requires a platform device driver, for example, USB, that driver should not be built and should not be included in a .bib or .reg file. Adding conditionals to the dirs, reg, and bib files does this. See the shipping platform files for more information.
