Software Recommendations

In Microsoft® Windows® desktop operating systems (OSs), shells allow users to switch between applications by using either the taskbar or the Task Manager, or by pressing the ALT+TAB key combination. These shells enumerate top-level visible windows to determine the applications to which users can switch.

In contrast, the Windows Thin Client Shell keeps track of connections by process identifier. When a connection is started, the shell changes the status of the connection from inactive to active. The shell starts the connection by calling the CreateProcess function on the application that is associated with the StartExe entry of the connection, and then passing the StartCmdLineArgs function as the command-line arguments. When the connection starts, the client software comes to the foreground.

The user can switch to the shell by pressing the CTRL+ALT+END key combination. Then, the user can start other connections or switch to an active session. If the user chooses to switch to an active session, then the shell calls the SetForegroundWindow function on the top-level window that is associated with the process identifier of the connection. If multiple top-level windows are associated with the connection, then the shell calls the SetForegroundWindow function on the first valid window that is enumerated upon calling the EnumerateWindows function.

This design analysis provides the rationale for many of the requirements that are specified in all topics related to this subject. These requirements must be met for client software to be compatible with the Windows Thin Client Shell. Recommendations for your software design also are provided.
