Startup Behavior

You can configure the shell to start applications automatically prior to launching the user interface (UI). This functionality was put in place to provide a desktop window for applications that require a UI, such as the Windows Thin Client Setup Wizard, and that must run before the shell UI is started. Applications that do not require a UI must start as part of the Windows CE initialization process.

The following registry key specifies applications to start automatically.

[HKEY_LOCAL_MACHINE \Software\Microsoft\WBT\Shell\Startup]

This registry key is the Startup key. Each autostart entry must have a specific key to which it is assigned in the root of the Startup key. The key name is converted to an integer by the shell, so that it must be a name that is converted easily; for example, 1, 10, or 20. The key name can represent an integer of 1 or greater; indexes are not required to be sequential. Each Startup key represents an index that specifies the order in which an application must be started. The shell first starts the application that has the lowest index value, and works its way up to the application that has the highest index value.

The following is an example of some application Startup keys.

[HKEY_LOCAL_MACHINE \Software\Microsoft\WBT\Shell\Startup\10]
[HKEY_LOCAL_MACHINE \Software\Microsoft\WBT\Shell\Startup\20]
[HKEY_LOCAL_MACHINE \Software\Microsoft\WBT\Shell\Startup\21]

Each Startup key must have the following entries assigned to it:

Value Description
Application: REG_SZ No default is set in the registry. The Application value specifies the executable file to be started automatically.

This value is required.

CmdLine: REG_SZ No default is set in the registry. The CmdLine value specifies the command-line arguments to pass to the application that is specified by Application.

This value is not required.

WaitOnProcess: REG_DWORD No default is set in the registry. The WaitOnProcess value specifies whether the shell must wait for the process to end before the shell continues. If WaitOnProcess is 1 or greater, then the shell waits for the application to end before continuing. If WaitOnProcess is 0, then the shell starts the process and continues. Applications that are started with a WaitOnProcess value that is equal to 0 must not be applications that have a UI.

This value is required

There are no default settings for these values. If the required values are not set, or if any set value is not valid, then the shell ignores the value and no error is posted to the user.
