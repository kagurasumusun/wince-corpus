Persistent Registry

When using the RAM-based registry, Windows Thin Client must restore the registry when it is turned off or reset. If you implement the required functionality in the OAL, then the registry can be saved to an OEM-specified persistent storage area by using a call to the RegFlushKey function.

LONG RegFlushKey(
HKEY hKey //handle of key to write
);
Note   When you call the RegFlushKey function in Windows CE, the hKey parameter is ignored, and the entire registry is flushed. Do not call RegFlushKey more than necessary, because this can be time-consuming, depending on the implementation of the OEM — for example, writing to flash — and the size of the registry.

Calling the RegFlushKey function calls the WriteRegistryToOEM function. If WriteRegistryToOEM is not implemented in the OAL, then RegFlushKey will fail. Therefore, you must implement WriteRegistryToOEM, as demonstrated in the following code example.

BOOL WriteRegistryToOEM(
  DWORD dwFlags,
  LPBYTES lpData,
  DWORD cbData
);

If the WriteRegistryToOEM function succeeds, then the RegFlushKey function will succeed. If WriteRegistryToOEM fails, then RegFlushKey will fail. For information about implementing this function, see WriteRegistryToOEM.

You also must implement the ReadRegistryFromOEM function. If this function is implemented correctly, then the OS calls the function during initialization while the Filesys.exe file is being initialized. Therefore, after Filesys.exe loads, the registry is updated by means of a call to ReadRegistryFromOEM by the OS. For information about implementing this function, see ReadRegistryFromOEM.
