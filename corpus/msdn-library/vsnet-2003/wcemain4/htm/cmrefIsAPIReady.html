IsAPIReady

This function tells whether the specified application programming interface (API) set has been registered.

BOOL IsAPIReady( 
DWORD hAPI 
);

Parameters

hAPI
Handle to the specified API set.

Return Values

TRUE indicates that the API set has been registered and the APIs are ready for use. FALSE indicates that the API set has not been registered and the APIs are not ready for use.

Remarks

In Windows CE, a system-level API may not be available to be called at the time that an application or driver needs to use it. In this situation, it is important to test for the API's readiness prior to making the API call. If an API is called before it is ready to be used, an exception can occur, which can potentially terminate your thread and process. Applications and drivers that potentially may run before Gwes.exe and the Shell (Windows Explorer or an OEM-customized shell) system components are loaded must call IsAPIReady prior to using the APIs supported by these system components. The following table shows which handles to use with IsAPIReady.

Handle Description
SH_SHELL Detect shell services APIs
SH_GDI Detect GDI APIs
SH_WMGR Detect Windows Manager APIs

In Windows CE, the APIs that make up a version of the operating system can differ from device to device. If you are writing an application or driver that targets a particular device, the API set should be known. If you are targeting more then one device, it is important to dynamically reference APIs. This will enable your application or driver to run on a variety of devices. To dynamically reference an API, use LoadLibrary to load the dynamic-link library (DLL) that exposes the API and then use GetProcAddress to return a pointer to the API.

In Windows CE .NET, there is a way to test for the occurrence of some API sets. The method uses an event that applications can wait on for a particular API set to be ready. If the API set is going to be available, WaitForSingleObject will block until the API set has been registered. If WaitForSingleObject fails, the API set is not registered on the system. Applications should switch to this API set detection method because it is more flexible than calling ISAPIReady. For more information, see Event Object Notification.
