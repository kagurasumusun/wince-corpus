Keyboard Hardware

You must provide Windows Thin Client devices with a keyboard for user input. The following list shows the requirements are for the keyboard device:

  • The keyboard and keyboard subsystem must support all of the functionality that is required in a Windows environment.

    The hardware that performs keyboard scans can be simple and can require CPU control from the low-level hardware-dependent portion of the driver. The keyboard subsystem must provide support for the following functionality:

    • Delivery of scan codes

      The Terminal Server client on Windows CE .NET 4.1 does not support sending virtual key codes directly to the server. Instead the client reads the virtual key codes from the message queue and converts these virtual key codes to scan codes using the MapVirtualKey function. Therefore the keyboard driver has to support the MapVirtualKey function correctly. The only valid setting for the HKEY_LOCAL_MACHINE\Software\Microsoft\Terminal Server Client "CEUseScanCodes" registry key is 0. This indicates that the RDP client receives virtual key codes, translates them into XT scan codes, and sends the translated codes to the server.

    • Roll-over
    • Separate LEFT SHIFT, RIGHT SHIFT, ALT, CTRL, and Windows keys
    • Function keys from F1 to F12
  • Keyboard hardware must meet the minimum Windows CE and Windows Thin Client requirements.

    The minimum hardware requirements for all Windows CE and Windows Thin Client devices are the following:

    • Interrupt on key press
    • Interrupt on key release
    • Keyboard roll-over support
    • Keystroke debounce support
    • Keyboard buffer
