Microsoft Windows CE .NET  

Applications and Services Development

The following services are available to assist application developers:

  • ActiveSync
  • Active Template Library (ATL)
  • C Libraries and Run-times
  • Component Services (COM and DCOM)
  • LDAP (Lightweight Database Access Protocol) Client
  • Message Queuing (MSMQ)
  • Microsoft Foundation Classes (MFC)
  • Object Exchange
  • Pocket Outlook Object Model (POOM) Application Programming Interface
  • Simple Object Access Protocol (SOAP) Toolkit
  • Standard SDK for Windows CE
  • Microsoft® .NET Compact Framework Beta Release
  • XML

ActiveSync

ActiveSync is a service manager that maintains a device partnership with a computer host that enables remote procedure calls and data synchronization. The following table describes the features that you can add to your operating system.

Feature Description
ActiveSync Provides the base services.
File Sync Enables file synchronization.
Inbox Sync Provides a synchronization solution for e-mail messages in conjunction with the Pocket Outlook Object Model (POOM).
Pocket Outlook Database Sync Provides a synchronization solution for the personal information manager (PIM) components.

Active Template Library

Active Template Library (ATL) for Windows CE is a C++ template library designed to help create small, fast Microsoft® ActiveX® servers. An ActiveX server is a dynamic-link library (DLL) or executable (.exe) that contains one or more Component Object Model (COM) components. These components can be anything from a simple dialog box to a full ActiveX control.

This feature is only available in display-based configurations.

C Libraries

The following table describes the features that you can add to your operating system. Note that the Full C Run Time feature and the Standard String Functions feature are not available in display-based configurations.

Feature Description
C++ Exception Handling Supports compiler C++ exception handling equivalent to the desktop C++ compilers.
Full C Run Time Supports full ANSI C run time and is only available in headless configurations.
Run-Time Type Information Supports compiler Run-Time Type Information (RTTI) equivalent to the desktop C++ compilers.
Standard IO Supports the standard input/output library.
Standard IO ASCII Supports the standard input/output ASCII library.
Standard String Functions - ASCII Supports the standard ASCII string functions and is only available in headless configurations.

Component Services

The Component Object Model (COM) is a platform-independent, object-oriented system for creating binary software components that can interact with other COM-based components in the same process space, in other processes, or on remote devices. To allow developers to manage the memory footprint of a device, three levels of run-time support for COM-based applications are available. The following table describes each feature.

Feature Description
Minimal COM Minimal COM implementation providing a baseline application programming interface (API) set for COM object creation. This feature requires about 10–20K of memory and does not include Automation support.

This feature is only available in headless configurations.
COM Midrange implementation of COM and Automation that supports only in-process free-threaded objects. This feature requires about 100–200K of memory.
Full COM Full-featured COM implementation equivalent to Microsoft Windows NT® 4.0 SP5 and Automation that supports in-process and out-of-process objects and all threading models. This functionality is equivalent to DCOM with the remoting functionality disabled. This feature requires approximately 700K of memory.
DCOM Remote Access Full-featured COM implementation equivalent to Microsoft Windows NT® 4.0 SP5 that includes remote COM and Automation. This feature requires approximately 700K of memory.
COM Storage Add-on feature to COM, DCOM, or Minimal COM that provides structure storage functionality.

LDAP Client

Lightweight Directory Access Protocol (LDAP) version 3.0 is used to access a directory that stores names, addresses, phone numbers, and other types of information. The LDAP API simplifies writing directory applications.

Message Queuing

Message Queuing (MSMQ) enables applications running at different times to communicate across heterogeneous networks and systems that may be unreliable or temporarily offline. In addition to the TCP-based protocol, MSMQ includes the following enhancements:

  • Allows you to specify HTTP as the transport protocol for messages.
  • Provides an XML-based SOAP extension that defines a reliable end-to-end messaging protocol.

Microsoft Foundation Classes

Microsoft Foundation Classes (MFC) for Windows CE is a comprehensive class library and complete object-oriented application framework designed to help build applications, components, and controls. You can create anything from a simple dialog box–based application to a sophisticated application that uses the full MFC document or view architecture.

This feature is only available in display-based configurations.

Object Exchange

OBEX is compact binary protocol that works with Bluetooth and IrDA that enables a wide range of devices to exchange data in a simple and efficient manner, such as getting business card information, pulling status information from a factory machine, or pushing a file to another portable computer.

This feature is only available in display-based configurations.

Pocket Outlook Object Model

The POOM API allows user applications to access the PIM) data stores and manipulate data. The data stores hold calendar, contact, and task data.

This feature is only available in display-based configurations.

Simple Object Access Protocol Toolkit

SOAP is an XML-based protocol for object exchange and remote procedure calling. Microsoft® Windows® CE .NET provides functionality similar to the SOAP Toolkit version 2 on the desktop. It provides a layer that allows COM objects to use SOAP as the transport protocol for remote procedure calls and to interact with Web services.

Microsoft® .NET Compact Framework Beta Release

This is a hardware-independent program execution environment for secure downloadable applications optimized for resource-constrained computing devices. It offers a choice of languages, initially Microsoft Visual Basic® and Microsoft Visual C#™, and eliminates the common problems faced with language interoperability.

This feature is only available in display-based configurations.

Windows CE Standard SDK

The Standard Software Development Kit (SDK) feature includes a common baseline of Windows CE technologies to make it easy to port applications.

This feature is only available in display-based configurations.

XML

Windows CE .NET supports Microsoft XML version 2.0. The following table describes the features that you can add to your operating system.

Feature Description
Core Services and Document Object Model Provides the Document Object Model (DOM) for base XML functionality.
XML HTTP Implements the XML HTTP object.
XML Query Language Provides support for XML Query Language (XQL) and XPATH.
XML Stylesheet Language Transformations Provides Extensible Style Sheet Language Transformations (XSLT) that enables you to transform one class of XML document to another.
XML SAX Provides SAX2 support for event-based parsing of XML documents and includes MSXML Writer.
XML Minimal Parser Supports parsing based on Simple API for XML (SAX) for resource constrained devices.
