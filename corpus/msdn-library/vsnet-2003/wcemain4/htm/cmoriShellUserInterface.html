Microsoft Windows CE .NET  

Shell and User Interface

Microsoft® Windows® CE .NET combines the Microsoft Win32® application programming interface (API), user interface (UI), and graphics device interface (GDI) libraries into the Graphics, Windowing, and Events Subsystem (GWES) module (Gwes.exe). GWES is the interface between the user, the applications, and the operating system (OS).

GWES supports all the windows, controls, and resources that make up the Windows CE UI, which enables users to control applications. GWES also includes support for user input and for GDI, which includes support for fonts, text drawing, line and shape drawing, palettes, and printing.

Resources are objects that are used within an application but are defined outside an application. GWES includes support for the following resources:

  • Bitmaps
  • Carets
  • Cursors
  • Dialogs boxes and message boxes
  • Icons
  • Images
  • Keyboard accelerators
  • Menus
  • Strings
  • Timers

A control is a child window that an application uses in conjunction with another window to perform I/O tasks. Common controls are a set of windows that are supported by the common control library, which is a dynamic-link library (DLL) that is included with Windows CE. GWES includes support for the following common controls:

  • Command bands controls
  • Command bars
  • Date and time picker controls
  • Header controls
  • Image lists
  • List view controls
  • Month calendar controls
  • Progress bars
  • Property sheets
  • Rebar controls
  • Status bars
  • Tab controls
  • Toolbars
  • ToolTips
  • Trackbars
  • Tree view controls
  • Up-down controls

A window control is a predefined child window that allows a user to make selections, carry out commands, and perform I/O tasks. GWES includes support for the following window controls:

  • Buttons, including check boxes, push buttons, radio buttons, and group boxes
  • Combo boxes
  • Edit controls
  • List boxes
  • Scroll bars
  • Static controls

Display-based platforms include most of the available GWES functionality by default. For more information about GWES support available on all display-based platforms, see Introduction to User Interface Services on Windows CE.

The following table shows additional GWES features that platform developers can add to display-based platforms, beyond the capabilities that are available by default.

Feature Description
Accessibility Provides options that allow persons with disabilities to use computers more easily.
Fonts Provides a choice of 60 different fonts for displaying and printing text.
Mouse Allows users to provide input through a mouse.
Multiple Screens Enables a device to connect to multiple screens, which can serve as one large screen when combined.
Printing Supports the ability to send printing commands to device drivers.
Software-based Input Panel Allows users to provide input through a software-based input panel displayed on a touch screen.
Stylus Allows users to provide input through a stylus and touch screen.

Platform developers can also customize the UI by creating a skin. The default UI is similar in appearance to the UI in Windows 95. A platform developer can choose the Windows XP-like Sample Skin feature to provide a UI that is similar in appearance to the UI in Windows XP. A platform developer can also create a custom skin. For more information about skins and the creation of skins, see Creating a Skin.

Platform developers can also change the behavior of menus. By default, menus contain only one level; that is, menu items do not open submenus. Platform developers can choose the Overlapping Menus feature to provide support for cascading, overlapping menus to enable submenus. Platform developers can also set the SYSGEN_MENU_TAP_UI environment variable to require that the user tap a menu item before the item is activated.

The shell architecture in Windows CE allows platform developers to implement a wide variety of shells, including a fully customized shell that is adapted to the platform. The following table shows the shell features that platform developers can add to display-based platforms.

Feature Description
Command Processor Includes an application for a command-line-driven shell that provides console input and output and a limited number of commands. This feature is also available on headless platforms.
Standard Shell Provides a shell that is similar to the shell on the Windows-based desktop platforms.
Taskman Sample Shell Provides a sample shell implementation that includes an ALT+TAB handler that sends this key combination to the taskbar window and a Run dialog box. This feature can be used as is or as a basis for a custom shell.
Windows Thin Client Shell Provides a Windows Thin Client user interface.

Headless platforms do not require GWES support because such platforms do not require an interactive display or an input device, such as a keyboard or mouse. Platform developers can, however, add Minimal Configuration features to a headless platform to build platforms that have levels of GWES support that are intermediate between the headless platforms and display-based platforms that Windows CE provides.

The following table shows the Minimal Configuration features.

Feature Description
Minimal GWES Configuration Provides basic windowing and message queue support.
Minimal Notifications Configuration Provides support for notifications.
Minimal Input Configuration Provides support for keyboard input.
Minimal GDI Configuration Provides GDI support, including TrueType fonts, text drawing, and palette support.
Minimal Window Manager Configuration Provides support for window management.

For more information about Minimal Configurations, see Minimal Configurations Overview.
