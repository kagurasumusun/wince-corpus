SIP and TEL URIs

If the application requests a call to a telephone or computer, the Communications Service creates a SIP INVITE with the URI specified in the IRTCSession::AddParticipant method. The SIP or TEL URI can include an e-mail address, IP address, DNS name, or canonical telephone number. If a TEL URI is requested, the Communications Service creates a SIP INVITE with the to header set to 'to: telephone-number'.

RFC 2806 defines the formats for valid TEL URIs; however, the Communications Service supports only a subset of those formats. The application is responsible for creating a valid TEL URI and the number should follow the canonical phone number format. The Communications Service strips off the qualifiers and sends only the canonical number to the gateway. The gateway determines if the number is acceptable.

The following table shows examples of valid TEL URIs.

TEL URL Explanation
TEL: +1-425-123-4567 TEL URI with global phone number format.
TEL: +358-666-1234567 TEL URI with global phone number format.

The format for SIP URIs is given in RFC 2543 (SIP). The following table shows examples of valid SIP URIs.

SIP URL Explanation
SIP:someone@10.1.2.3 SIP URI with IP address.
SIP: someone@example.com;transport=TCP SIP URI with transport specified as TCP. The default transport is UDP if none is specified.
SIP: someone@example.com Basic SIP URI.
SIP: +1 206 345-1234@1.2.3.4;user=phone SIP URI with global phone number format and specified gateway.
