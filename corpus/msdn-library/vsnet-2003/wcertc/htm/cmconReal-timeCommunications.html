Communications Service

The Communications Service support with the Real Time Communication (RTC) client API enables you to build applications that perform text messaging using voice over IP (VoIP), IP telephony bridging from an IP device to a PSTN phone through a Gateway, accessing presence information of your contacts to see if they are on line, and controlling if your own presence information can be accessed or is blocked by other clients on the network. Microsoft® Windows® CE provides Communications Service application programming interfaces (APIs) built on the Session Initiation Protocol (SIP), an IETF standard (RFC 2543). The SIP allows a device to call, or receive calls from, any SIP client. A SIP client can be a Windows CE device, a Windows XP machine, or a third-party SIP user agent. The Windows Messenger application supports the Communications Service as a backend.

The Real Time Communication client API supports the following:

  • Sets up VoIP connections between Windows CE devices, Windows XP systems, third-party SIP user agents, or Public Switched Telephone Network (PSTN) phones.
  • Initiates text-messaging sessions, which can occur simultaneously with voice connections.
  • Receives presence information to see if your contacts are online, enables you to change your own presence state and send notifications, and monitors who is watching your online presence.

The following table shows the scenarios that are supported through the Communications Service.

Scenario Requirements
Windows CE-SIP client Requires a Windows CE device and a SIP client. These devices must be logged on to the network. Direct voice connections can occur peer-to-peer or through a SIP server.
Windows CE-phone Requires a Windows CE device, a gateway, and a PSTN phone.
Phone-phone Requires a Windows CE device, a gateway, and two or more PSTN phones.
