DiskOnChip Registry Entry Descriptions

The HKEY_LOCAL_MACHINE\Drivers\BuiltIn\TrueFFS registry entry key name indicates the device and the partition number the key refers to. See the examples in the following table.

Registry entry key name Description
HKEY_LOCAL_MACHINE\Drivers\BuiltIn\TrueFFS Registry entry for Device 0 partition 0.
HKEY_LOCAL_MACHINE\Drivers\BuiltIn\TrueFFS1 Registry entry for Device 0 partition 1.
HKEY_LOCAL_MACHINE\Drivers\BuiltIn\TrueFFS10 Registry entry for Device 1 partition 0.
HKEY_LOCAL_MACHINE\Drivers\BuiltIn\TrueFFS12 Registry entry for Device 1 partition 2.

WindowBase

The WindowBase parameter determines the physical address of the DiskOnChip in the system memory. The value should be within the 32-bit address range and is determined during hardware design or system integration. The value shown serves as an example only and is typical for x86 designs.

ADDRESS_SHIFT

This entry can have only two values: 8 or 0. This field determines how the physical address will be shifted before it is passed to the Virtual Copy function. By default, most systems require that this field be set to a value of 8. In some systems, it needs to be set to a value of 0. Currently, there are no tools available to determine which value to use. The appropriate value should be determined empirically until a test tool is available.

Further, the shift value depends on the MMU initialization value configured in the OAL. The physical address is the base address of the DiskOnChip. The physical address parameter must be passed in such a way that the MMU translation maps it into the correct physical location. Because the OAL can be customized by each implementation, this entry must be set up to either shift the address right 8 places or not to shift the address.

DOC_ACCESS_TYPE

This entry determines the data bus width when accessing DiskOnChip. All the Registry Entries are hexadecimal values. The DiskOnChip Millennium Plus is a True 16-bit data access device, so the DOC_ACCESS_TYPE entry is not applicable in case of this device usage. Furthermore, the DiskOnChip Millennium Plus cannot address shifted as the other DiskOnChip family devices. The value of this entry can be any of values in the following table.

Value Description
"DOC_ACCESS_TYPE"=dword:8 8-bit access, the DiskOnChip is accessed on a byte boundary.

Note   In this case the address lines of the DiskOnChip are connected directly to the address lines of the host without shifting. A0 of the DiskOnChip is connected to A0 of the host.
"DOC_ACCESS_TYPE"=dword:10 16-bit access, the DiskOnChip is accessed on a word boundary.

Note   In this case the address lines of the DiskOnChip are not connected directly to the address lines of the host. Instead they are shifted one position: A0 of the DiskOnChip is connected to A1 of the host.
"DOC_ACCESS_TYPE"=dword:20 32-bit access, the DiskOnChip is accessed on a long boundary.

Note   In this case the address lines of the DiskOnChip are not connected directly to the address lines of the host. Instead they are shifted two positions: A0 of the DiskOnChip is connected to A2 of the host.

The DiskOnChip Millennium Plus is a True 16-bit data access device, so the DOC_ACCESS_TYPE entry is not applicable in case of this device usage. Further more the DiskOnChip Millennium Plus cannot address shifted as the other DiskOnChip family devices.

Folder

This parameter determines the folder name associated with the DiskOnChip. If this string is absent, the default name is, "Storage Card".

DOCBaseXX

The TrueFFS/CE now enables you to support more than one DiskOnChip device utilizing the one instance of the driver. For example, you can have a DiskOnChip on physical address 0xD0000 and another one on address 0xD8000, and so on. This allows you better flexibility in choosing the capacity and the form factor of the storage devices in your system.

The DocBaseXX fields in every registry entry indicate the WindowBases of the rest of DiskOnChips in the system. In the following example the registry entry HKEY_LOCAL_MACHINE\Drivers\BuiltIn\TrueFFS refers to the device 0 partition 0. DocBase10 in the first registry entry indicates the WindowBase of device 1 is D8000h. DocBase20 in the second registry entry HKEY_LOCAL_MACHINE\Drivers\BuiltIn\TrueFFS10 for device 1 indicates the WindowBase of device 2 is c8000h, for example DOCBase10 specifies the base address of the second DiskOnChip device in the system, DOCBase20 specifies the base address of the third DiskOnChip device in the system and so on. In the entry of the second device there is no need to indicate the base address of the first device. This is shown in the following registry entries.

[HKEY_LOCAL_MACHINE\Drivers\BuiltIn\TrueFFS] 
    "Dll" = "TrueFFS.dll" 
    "Prefix" = "DSK" 
    "Order" = dword:1 
    "WindowBase" = dword:D0000 
    "DocBase10" = dword:D8000 
    "DeviceArrayIndex"=dword:0
    "IClass" = "{A4E7EDDA-E575-4252-9D6B-4195D48BB865}"
[HKEY_LOCAL_MACHINE\Drivers\BuiltIn\TrueFFS10] 
    "Dll" = "TrueFFS.dll" 
    "Prefix" = "DSK" 
    "Order" = dword:1 
    "WindowBase" = dword:D8000 
    "DocBase20" = dword:c8000 
    "DeviceArrayIndex"=dword:2
    "IClass" = "{A4E7EDDA-E575-4252-9D6B-4195D48BB865}"
[HKEY_LOCAL_MACHINE\Drivers\BuiltIn\TrueFFS20] 
    "Dll" = "TrueFFS.dll" 
    "Prefix" = "DSK" 
    "Order" = dword:1 
    "WindowBase" = dword:c8000 
    "DeviceArrayIndex"=dword:3
    "IClass" = "{A4E7EDDA-E575-4252-9D6B-4195D48BB865}"

DeviceArrayIndex

The DiskOnChip Millennium Plus enables you to define up to 4 storage devices to be located on a single physical DiskOnChip device, two out of these partitions can be set to be a read-only or a write only drives. The DeviceArrayIndex parameter defines the order in which the different drives are loaded by the TrueFFS/CE driver.

IClass

The IClass is a GUID that defines the interfaces that the driver exposes. A device driver should only claim to export an interface if it implements that interface in its entirety. Any code that attempts to interact with a driver will expect that the driver actually supports whatever interfaces it advertised.
