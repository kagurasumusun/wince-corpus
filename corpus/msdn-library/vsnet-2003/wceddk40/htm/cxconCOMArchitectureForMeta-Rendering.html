COM Architecture for Meta-Rendering

The DVD playback middleware on Windows CE uses a meta-renderer COM object to instantiate the actual renderer of a DVD stream. As such, the meta-rendering framework is not restricted for the sole use of DVD. The meta-rendering framework can also be used to support multiple media data types, middleware and application software by the same or multiple renderers. However, its use in Windows CE is limited to the DVD-Video API.

The meta-renderer is a well-known object in the system. This means that any component can instantiate in-proc and query for the interface it needs to render a particular type of multimedia content. Such an interface is called a primary playback control or primary rendering interface. It is primary in the sense that two multimedia data types are considered identical if they can be rendered using exactly the same (with the same GUID) primary rendering interface. This means that the primary rendering interface and its GUIDE uniquely represents the multimedia data type in the meta-rendering environment.

For example, the DVD-Video navigator middleware on Windows CE required the IDVDRenderer interface provided to it to be able to function as a complete navigation and playback subsystem. This means that IDVDRenderer is a primary rendering interfaced used by the DVD-Video navigator on Windows CE. To acquire access to the DVD rendering functionality, the navigator simply creates an instance of the meta-renderer and queries it for the IDVDRenderer interface.

The function of the meta-renderer is to locate COM objects that are implementing the requested interface in the system. The meta-renderer will then instantiate and properly initialize it, provide all necessary support to it, and return a fully functional interface to the requesting component. This means that aside from the primary rendering interface, the renderer often has to support other interfaces that serve the purposes of initialization and other secondary functions including data transfer.

The current version of the meta-renderer object required that every renderer implement the IBitstreamProcessor interface, which is used to initialize the renderer object. IBitstreamProcessor in turn makes use of the IDMAChannel interface to represent low level data transfer facilities of the renderer.

On successful return from QI to the meta-renderer, a fully functional and initialized primary playback control interface is returned together with a set of data ports to be used for data streaming into the renderer.

Note   In this schema, any renderer can choose to implement and expose an arbitrary number of primary rendering interfaces representing multiple media types, rendering capabilities, and the needs of various middleware or application software.
