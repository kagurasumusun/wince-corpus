Supported and Unsupported USB Features

Windows CE supports bus enumeration, power management, transfer types, class drivers, integrated and external hubs, and limited support for unknown USB peripherals.

The bus enumeration process is a multistep query sequence: the HCD module acquires information from a connected device, assigns it a unique USB address, and sets a configuration value. Once enumeration is complete, the device is configured and ready to conduct, transmit, and receive transactions. At this point, the USB driver module attempts to load one or more USB device drivers to control the device, based on the information contained in the device and interface descriptors. If no suitable driver has been registered for the device, a user is prompted to enter the name of a driver to control the device.

Windows CE provides support for bus-powered and self-powered devices. For both types of device, the USB driver module reads the power requirements of the device from the descriptor information and rejects the device if it exceeds the maximum power threshold. You can set the current-draw limit, so you should not rely on any particular amount of available current, except as detailed in the Universal Serial Bus Specification, Revision 1.1. USB hubs enforce current-draw limits, not the host computer. The hub will shut down devices that draw too much current. Hubs that cannot control the power level on individual ports may simply shut down all their ports, or may be forcibly shut down by an upstream hub, when a current over-draw situation occurs. This can cause multiple USB devices to disconnect from the bus if a single device draws too much current. Complex power saving modes or partial-power modes are not supported for USB devices when the host platform is suspended. Instead, the entire bus is shut down. Consequently, there is no support for resuming from suspension in response to the needs of a USB device.

All four types of data transfer defined in the Universal Serial Bus Specification, Revision 1.1 are supported. USB device drivers can use any of the transfer types that are appropriate for the endpoints of their peripherals.

The USB architecture implemented supports loading class drivers. Examples of USB device classes include the human input device (HID) class and the mass storage class. You can write their own class drivers and load them appropriately, using the registry mechanism.

Support for integrated and external hubs up to five levels deep, which is the maximum allowed by the Universal Serial Bus Specification, Revision 1.1.

Unknown USB peripherals generally cause no problems in Windows CE.
