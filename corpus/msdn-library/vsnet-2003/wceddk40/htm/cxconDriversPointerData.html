Drivers and Pointer Data

The OS manages pointers passed directly as parameters. Drivers must map all pointers contained in structures. DeviceIoControl buffers are often structures that contain data; some of these structures may be pointers. To map a pointer contained in a structure, call MapPtrToProcess. Set the first parameter to the pointer, and the second parameter to GetOwnerProcess.

Windows CE–based device drivers run in one of the system process address spaces. This architecture affects your device driver development projects whenever you wish to share chained data structures between an application and a device driver.

The device driver gains access to the data in the address space of an application by calling MapPtrToProcess. The following list shows in detail how a driver gains access to memory in the address space of an application; this process is not required when you pass a simple pointer to a device driver. It is required only when you pass a pointer to a pointer, as might occur with a linked list.

  1. Application mapped into slot 0.
  2. Application calls DeviceIoControl.
  3. Device Manager mapped into Slot 0.
  4. Device Manager sets permissions to application space.
  5. Device Manager calls XXX_IOControl.
  6. Driver calls MapPtrToProcess.
  7. Driver returns from XXX_IOControl.
  8. Device Manager resets permissions to application space.
  9. Application mapped into slot 0.
