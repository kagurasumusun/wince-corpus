Driver Development Tools

Platform developers, independent hardware vendors (IHVs), and application developers may be interested in developing device drivers for Windows CE-based platforms. Platform developers should use Platform Builder, IHVs and application developers can use either Platform Builder or Microsoft Visual Studio.

The following table compares the uses of Platform Builder and Visual Studio for driver development.

Platform Builder Visual Studio
You can use the kernel debugger for true driver debugging. You can only use the application debugger, which limits you to simple debugging methods such as debug messages.
You can develop any type of driver. You can only develop network and PC Card drivers.
You cannot debug and test on Pocket PC–based devices. You can target Pocket PC–based devices.
You can package and export drivers as .cab files for end-users to use on their target device. You can package and export drivers as .cab files for end-users to use on their target device.
Note   Moving a driver project from one product to another may be difficult.

Additionally, Platform Builder allows you to develop and test drivers on many different standard development boards (SDBs). Platform Builder includes board support packages (BSPs) for many SDBs. For more information about these provided BSPs, see Board Support Packages. Platform Builder includes the Windows CE Test Kit (CETK) that allows you to test all types of drivers. For more information about testing drivers, see Driver Testing. After you have fully tested your driver, you can validate it and submit it to Microsoft. For more information about driver validation and BSP Certification, see Third Party Device Drivers. If Microsoft validates your drivers, you can use Platform Builder to package and export the drivers as .msi files for other platform developers to add to their Catalog.

Keep in mind that obtaining supported SDBs may be difficult or expensive.
