Device Manager

The Device Manager is a user-level process that runs continuously and launches through the kernel. The Device Manager provides tracks all loaded device drivers and their interfaces and issues notifications for appearance and disappearance of device interfaces. It also provides power notification callbacks to device drivers.

The Device Manager owns the Active key in registry. Unlike what was recommended in previous versions of Windows CE, the Active key should never be accessed, for read or write, except directly by the Device Manager and indirectly through the parameter to a device driver's Init function.

The following list shows the tasks that the Device Manager provides APIs to perform:

  • Registers special file names with the kernel that map the stream interface functions.
  • Loads drivers by reading and writing registry values. For example, the PC Card driver locates the device driver and then loads the device driver through ActivateDeviceEx.
  • Unload drivers when the devices no longer need them.
  • Manage device interfaces and interface notifications.
  • Manage resources relevant to device drivers such as IO space, IRQs, and so on.
  • Provides power management services. For more information, see Power Management.

The Device Manager provides the following load and unload APIs:

  • ActivateDeviceEx
  • DeactivateDevice

The Device Manager looks for the root key value at HKEY_LOCAL_MACHINE\Drivers\RootKey to determine the root key to start the driver loading process. The default value of RootKey is Drivers, but is usually set to be Drivers\BuiltIn. The Device Manager loads the driver specified by the Dll value found in the key specified by the RootKey value, which is typically the Registry Enumerator (RegEnum.dll).

When the Device Manager loads, it loads the I/O Resource Manager to read a list of available resources from the registry. For more information on the I/O Resource Manager, see I/O Resource Manager.
