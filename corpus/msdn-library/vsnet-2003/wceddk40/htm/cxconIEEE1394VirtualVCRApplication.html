IEEE 1394 Virtual VCR Application

Any application utilizing the virtual VCR driver will want to manage several issues. The following list shows the issues during initialization:

  • Utilize IOCTL_VVCR_QUERY_STATE to determine which predefined plugs exist and what their handles are.
  • Using the media type definition from IOCTL_VVCR_QUERY_STATE, determine what the appropriate streaming frame size is for the type by utilizing IOCTL_STREAM_GET_MEDIA_SIZE.
  • For each plug returned by IOCTL_VVCR_QUERY_STATE, using the direction and handle values, initiate streaming sessions against the plugs. The plugs from IOCTL_VVCR_QUERY_STATE are considered remote plugs in the context of IOCTL_STREAM_START_RECV_SESSION or IOCTL_STREAM_START_XMIT_SESSION.
  • Initiate an appropriate streaming buffering system for the application. Buffer streaming should be handled through the streaming filter driver using IOCTL_STREAM_ATTACH_BUFFER, IOCTL_STREAM_DETACH_BUFFER, and IOCTL_STREAM_QUERY_BUFFER_STATE.

The following list shows the issues during regular processing:

  • Keep at least one IOCTL_VVCR_EVENT command always issued asynchronously to handle incoming events from the virtual VCR driver.
  • If IOCTL_VVCR_EVENT notifies the application of a play, wind, or record request, internally change state and begin streaming to your output plug, if one was located in the results from IOCTL_VVCR_QUERY_STATE, streaming from your input plug, if one was located in the results form IOCTL_VVCR_QUERY_STATE, cease all streaming, or move the applications emulated tape by rewinding it, fast forwarding it, and so on.
  • If IOCTL_VVCR_EVENT returns a plug state change event that introduces an unknown plug, as opposed to one previously known about from IOCTL_VVCR_QUERY_STATE, issue an IOCTL_VVCR_QUERY_STATE to determine any remaining details about that plug, and process it in whatever way desired.
  • If IOCTL_VVCR_EVENT notifies the application of a request to scan to a different tape location, VVCR_EVENT_AbsoluteTrackNumber, VVCR_EVENT_TimeCode, VVCR_EVENT_RelativeTimeCounter, move the applications emulated tape appropriately.
  • Regularly use IOCTL_VVCR_SET_MECHANISM_POSITION to update the driver on the current position of the emulated tape.
  • Use IOCTL_VVCR_SET_MECHANISM_STATE whenever the application's emulated mechanism moves from state to state. From stopped to playing, or playing to rewinding, and so on.
  • Ensure that while streaming, that whatever medium the application uses as permanent storage can handle the necessary throughput for the appropriate stream. During internal testing of this type of code, it was determined than many types of storage, particular types of hard drives with varying DMA characteristics, and file systems are incapable of managing the correct amount of sustained throughput, resulting in either overflow while recording, where incoming data was dropped as the hard drive could not write it fast enough, or underflow while playing, where the hard drive could not keep up and provide data fast enough to be transmitted on time.
