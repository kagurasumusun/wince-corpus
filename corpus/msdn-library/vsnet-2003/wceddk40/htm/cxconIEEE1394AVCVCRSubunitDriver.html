IEEE 1394 AV/C VCR Subunit Drivers

This document discusses interfaces and technologies associated with IEEE-1394. Each of the technologies in use has a specific standards document associated with it. It is impractical to attempt to present a tutorial on each of the technologies within this documentation. It is suggested that you obtain the specific standards, so as to understand some of the finer details of the technologies involved. The specific standard relating most to this document is the AV/C Digital Interface Command Set VCR Subunit Specification Version 2.0.1, made publicly available by the 1394 Trade Association. This document is an excellent resource in examining details for the involved developer.

However, there are cases where the information in the specification mentioned earlier is precluded by the VCR Subunit Driver documentation. For example, BCD values are automatically converted for the user to and from decimal by the VCR Subunit Driver; the earlier-mentioned specification refers to many fields as BCD encoded. Each of these instances is generally well documented, but you should nonetheless be attentive.

The VCR Subunit driver is intended to provide applications with the ability to control devices on the IEEE 1394 bus that export an AV/C Tape Subunit API. It does not, however, provide the capability of exporting VCR-style functionality. That task requires a Virtual Subunit driver.

The VCR Subunit driver is designed to include the Streaming Filter Driver (AVC_STREAM) hierarchically below it in the device stack. The Subunit driver handles control of the VCR device, and the Streaming Filter Driver provides streaming functionality. Commands not recognized by the VCR Subunit driver are merely passed down to the Streaming driver, so the actual set of applicable commands include those for both drivers.

IEEE 1394 AV/C VCR Subunit Driver Control Functionality

The specification mentioned earlier combines commands suitable for both consumer and professional VCR products into a single document. The professional commands, by and large, are significantly more complex than the consumer commands, and are heavily associated with detailed editing functionality. TVPAK is designed for use in consumer products, and therefore has little need for the type of functionality provided by the professional commands. Therefore, the command set supported is a subset of that documented in the specification; a subset including those commands that are most likely to be implemented on a consumer VCR.

IEEE 1394 AV/C VCR Subunit Driver APIs

The API descriptions are broken into two categories: the IOCTLs themselves and a detailed list of commands that can be performed with IOCTL_VCR_AVCCMD. The IOCTLs are direct calls to DeviceIoControl that the author can make. IOCTL_VCR_AVCCMD has so many variations that the commands are best documented separately. These commands are shown in the following table.

Command Description
AVC_VCR_CMD_ANALOG_AUDIO_OUTPUT_MODE Can query the VCR subunit's current mode put out on its source plugs, or configure the VCR subunit's output to a specific audio source on its source plugs. This is primarily useful in selecting secondary audio channels or controlling the monaural/stereo configuration.
AVC_VCR_CMD_INPUT_SIGNAL_MODE Queries the VCR subunit's current interpretation of the type of signal format it is prepared to accept, or attempts to set the VCR subunit to accept a specific type of input signal.
AVC_VCR_CMD_LOAD_MEDIUM Requests that the VCR subunit eject any currently loaded media, or open/close its tray mechanism if present.
AVC_VCR_CMD_MEDIUM_INFO Requests information about the type of medium currently inserted into the VCR.
AVC_VCR_CMD_OUTPUT_SIGNAL_MODE Queries the VCR subunit's current interpretation of the type of signal format it is prepared to output, or attempts to set the VCR subunit to put out a specific type of A/V signal.
AVC_VCR_CMD_PLAY Instructs the VCR subunit to begin playback of inserted media.
AVC_VCR_CMD_RECORD Instructs the VCR subunit to begin recording.
AVC_VCR_CMD_RECORDING_DATE Allows querying of the recording date value stored internally in the VCR subunit, the recording date value stored on an inserted medium, or setting the current internally stored recording date.
AVC_VCR_CMD_RECORDING_SPEED Sets the particular recording speed at which the VCR stores data on its media. In some types of VCRs, the speed is directly related to the quality of the recording.
AVC_VCR_CMD_RECORDING_TIME Queries the current recording time from an inserted cassette.
AVC_VCR_CMD_RELATIVE_TIME_COUNTER Can either query or set the VCR subunit's internal Relative Time Counter. The RTC is a time counter of the current position on the inserted media to an arbitrary position on the tape, such as where the tape was wound when it was inserted.
AVC_VCR_CMD_TIME_CODE Queries the VCR subunit for the current Time Code value, based on the current position of inserted media, or requests that the VCR subunit attempt to search for a particular time code.
AVC_VCR_CMD_TRANSPORT_STATE Attempts to determine the current state of the medium inside the device — for example, whether it is currently stopped, playing, paused, or recording.
AVC_VCR_CMD_WIND Controls the state of the tape mechanism, setting it to states such as Stop, Rewind, or Fast Forward.
