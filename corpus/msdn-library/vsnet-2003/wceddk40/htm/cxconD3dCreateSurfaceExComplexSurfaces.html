D3dCreateSurfaceEx and Complex Surfaces

Creation of a complex surface causes an array of surfaces to be passed to CreateSurface. However, even in complex cases, only a pointer to the root surface is passed to D3dCreateSurfaceEx. It is necessary for the driver to go through the attachment lists of the root surface and create driver-side copies for all attached surfaces. This can be a tricky operation if the driver is attempting to handle creations for cube maps, MIP maps, and so on.

There are two types of DirectDraw surface attachments, implicit and explicit. An implicit attachment is formed during a complex surface creation. For example, when creating a primary flipping chain, the primary and back buffer are created by a single CreateSurface API call and they are attached to one another implicitly by the CreateSurface call. Another example is a MIP map chain where a series of MIP maps is created by a single CreateSurface API call. An explicit attachment is formed when surfaces created from different CreateSurface calls are attached explicitly by AddAttachedSurface.

The style of attachment has an implication for D3dCreateSurfaceEx processing. When two surfaces are explicitly attached, then both of those surfaces were created by separate calls to CreateSurface and each surface will have resulted in a call to D3dCreateSurfaceEx before the surface attachment was made. However, in the case of an implicitly attached surface, only a single CreateSurface and D3dCreateSurfaceEx call is made for the entire chain of surfaces. Therefore, when processing a D3dCreateSurfaceEx call a driver must run the attached list of surfaces to identify handles, and create driver side data structures for each attached surface. However, the attached surface list may contain a mixture of implicitly and explicitly attached surfaces. The driver will already have been notified of explicitly attached surfaces by D3dCreateSurfaceEx and probably will not want to process such surfaces again.

The driver can distinguish between implicit and explicit attachments by means of the DDAL_IMPLICIT flag stored in the dwFlags field of the ATTACHLIST data structure. If DDAL_IMPLICIT is set in the dwFlags field the attachment is implicit and no separate D3dCreateSurfaceEx call will be seen for the attached surface. If this flag is not set the attachment is explicit and the attached surface will result in its own D3dCreateSurfaceEx call. By examining this flag, the driver can determine whether it needs to process an attached surface as part of the parent surface's D3dCreateSurfaceEx call or whether a separate D3dCreateSurfaceEx call will have been made for the attached surface.
