IEEE 1394 Unit Filter Driver Architecture

The unit filter driver is not in a device stack underneath the virtual subunit driver. The virtual subunit driver cannot send commands to the unit filter driver by sending them down the device stack as it does for AVC_STREAM. As a result, a virtual subunit driver must communicate both with the drivers below it and communicate through a special reference to the unit filter driver. Locating and referencing the unit filter driver is not necessarily simple, as the UNIT_OpenUnitDevice documentation explains. To facilitate the process, the unit filter driver exports functions that the virtual subunit driver can call to open the appropriate device object on the unit filter driver, and to close the same device object when it is no longer required. These functions are UNIT_OpenUnitDevice and UNIT_CloseUnitDevice.

When opened, the virtual subunit driver will obtain a device object pointer. This device object is used as the destination of virtual subunit IRPs. The virtual subunit can request functionality of the unit filter driver by generating IOCTL requests and sending them in IRPs to the given device object.
