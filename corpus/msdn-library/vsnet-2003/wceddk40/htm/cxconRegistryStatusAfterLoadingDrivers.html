Registry Status After Driver Loading

After the enumeration and configuration of the PCI bus and its bridges, the PCI bus driver loads the Dll indicated by Drivers\PCI\Instance\Dll in order to load the device drivers. This Dll is typically RegEnum.dll, the registry enumerator. RegEnum goes through the Instance subkeys of the Drivers\PCI key to determine which drivers to load, according to their Order. If no Order is specified, the associated driver is loaded last. In this example, no Order is specified for any of the drivers, so the load order is arbitrary. If the serial driver is loaded first, the PCI bus driver finds the Drivers\PCI\Instance\Serial1 key and loads the corresponding DLL, if it is not loaded already. Then it calls its default entry point, COM_Init, with the key Drivers\PCI\Instance\Serial1. Then the driver reads its configuration information from the registry. The same driver is used for 16550 serial controllers on the built-in, ISA and PCI buses. Because the registry key passed to the COM_Init function has all of the information the driver needs to run, it does not care how the registry has been populated, whether by the OEM, user, or by a bus enumerator such as the PCI bus driver. This type of driver is a bus-agnostic driver.

For the first NE2000 driver instance, the PCI bus driver first loads NDIS.dll, if necessary, and calls the default entry point NDIS_Init with Drivers\PCI\Instance\NE20001 passed in as a parameter. NDIS examines the registry and recognizes that the MiniPort value is present, so it loads NE2000.dll, if necessary, and calls its default entry point, as defined by the NDIS driver. The same procedure is used for the second NE2000 driver instance.
