Creating Driver-Side Surface Structures

The DirectDraw run time will call the driver's D3dCreateSurfaceEx entry point after it has called the CreateSurface entry point and allocated memory for the surface. The run time calls D3dCreateSurfaceEx only for those surfaces tagged with DDSCAPS_TEXTURE, DDSCAPS_EXECUTEBUFFER, DDSCAPS_3DDEVICE, or DDSCAPS_ZBUFFER flags.

Before calling D3dCreateSurfaceEx, the run time will assign an integer value as a handle to the surface. This value will be stored in the dwSurfaceHandle member of the DDRAWI_DDSURFACE_MORE structure (as pointed to by the lpSurfMore member of the DDRAWI_DDSURFACE_LCL structure). See DDRAWI_DDRAWSURFACE_MORE and DDRAWI_DDRAWSURFACE_LCL structures.

These integer values start at one and are kept as small as possible. (Zero is a guaranteed invalid value for a surface handle.) The intention is that a driver can keep an array of pointers into its own structures. As soon as it receives a handle (when D3dCreateSurfaceEx is called) that is beyond the end of the array, it can reallocate the array and continue. The Direct3D run time will pass no handle value to the driver before that handle is shown to the driver through D3dCreateSurfaceEx. However, the driver should be robust enough to handle values that are out-of-range, or that refer to a slot in the handle table that has been freed (that is a handle for which DestroySurface has been called). Note that because zero is a guaranteed invalid value, the zero entry in the handle table can be reused for other purposes.
