Optimized Texture API

Three new capabilities indicate the level of optimization that can be applied to a DirectDrawSurface object. In DirectX 6.0 and beyond, only textures can be marked with these caps bits. The optimized surface paradigm may be extended in the future to cover other types of surfaces, although the semantics may not be the same as for textures.

To address these issues as cleanly as possible, three new flags are provided in the DirectDraw4::CreateSurface method. When none of these three flags is specified, the decision whether to patch or swizzle is left entirely up to the driver. These flags are as follows:

DDSCAPS2_HINTDYNAMIC
Indicates to the driver that this surface will be locked very frequently, (for example, once per frame) for use such as streaming video or procedural textures. This cap should work for all driver-enumerated texture surface formats. The driver should avoid any transformation for these textures, especially if it requires some overhead.
DDSCAPS2_HINTSTATIC
This indicates to the driver that the surface can be reordered/retiled/swizzled in the IdirectDrawSurface5::Blt methods (described in the Direct3D SDK and DirectDraw SDK documentation, respectively). This operation will not change the size of the texture. It is relatively fast, and symmetrical, because the application may still lock these bits (although it will take a performance hit when doing so). Drivers are not allowed to fail locks on these surfaces and therefore cannot use lossy compression techniques. MIP map surfaces can be interleaved in this case.

This cap is not intended to force swizzling under any circumstances, especially those in which no performance benefit will arise. In particular, some texel formats may silently fail to swizzle.

DDSCAPS2_OPAQUE
This indicates to the driver that this surface will not be accessed by the application again. This flag behaves like the DDSCAPS2_HINTSTATIC flag, but with the addition of allowing actual compression using a hardware-specific compression scheme. This operation is relatively slow, but should allow simple, symmetric compression schemes (such as YUV 4:2:0, or color cell compression) to be used, providing compression ratios from 2 to 6x. Asymmetric schemes such as VQ should not be used here because they will result in unacceptable benchmarks.

The driver can interleave MIP map textures arbitrarily. This technique should probably only be requested outside of internal rendering loops such as when textures are loaded from disk. Heap size reports after such a texture is loaded will reflect the reduced memory consumption if compression was applied. It should be remembered that there is additional header overhead on textures and therefore compressing many small textures will not save as much memory as might be expected.

In general, there is no guarantee about texture compression ratio, or compression quality implied by this flag.

Surfaces created with this flag will fail in the following cases:

  • Calls to the IdirectDrawSurface5::Lock method will fail.
  • Calls to the IdirectDrawSurface5::GetDC method will fail. Both methods are described in the DirectDraw SDK documentation.
  • Subrectangle blits to such surfaces will fail.
  • All blits from such surfaces will fail.

The only way to put data into such surfaces is with a full surface blit call.
