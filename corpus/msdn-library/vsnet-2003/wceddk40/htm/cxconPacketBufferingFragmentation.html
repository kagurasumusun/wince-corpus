Packet Buffering and Fragmentation

Data packets are sent to the HCI layer using the following interface functions.

typedef int (*HCI_DataPacketDown_In) (
HANDLE         hDeviceContext,
void          *pCallContext,
unsigned short connection_handle,
BD_BUFFER     *pBuffer
);
typedef int (*HCI_DataPacketDown_Out) (
void    *pCallContext,
int      iError
);

Both data and command packets are placed in the HCI queue. Data packet fragmentation is happening automatically – upper layers have no control over it.

However, it is impossible to properly reassemble data on the way up without knowing the size of the total packet. If the protocol is following the L2CAP packet format, that is, the data is length-prefixed, reassembly is handled by the HCI, and the packet is delivered through the following function.

typedef int (*HCI_DataPacketUp) (
void             *pUserContext,
unsigned short    connection_handle,
BD_BUFFER        *pBuffer
);

However, if the upper interface exposes the HCI_DataPacketUpAclUnbuffered function, it is expected to handle the buffering of incoming ACL packets, which will be reported to it immediately. In this case, there are no restrictions on the packet format. The following example code shows the HCI_DataPacketUpAclUnbuffered function prototype.

typedef int (*HCI_DataPacketUpAclUnbuffered) (
void             *pUserContext,
unsigned short    connection_handle,
unsigned char     boundary,
unsigned char     broadcast,
BD_BUFFER        *pBuffer
);

See Bt_ddi.h for complete specifications of the HCI interface.
