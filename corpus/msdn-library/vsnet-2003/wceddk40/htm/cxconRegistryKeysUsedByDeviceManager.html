Registry Keys Used by the Device Manager

The Device Manager uses the Active and BuiltIn subkeys of HKEY_LOCAL_MACHINE\Drivers.

Active

Device drivers should never modify any of the values in this part of the registry that the Device Manager places here.

The HKEY_LOCAL_MACHINE\Drivers\Active key contains subkeys that track currently active drivers that the Device Manager loaded. Device driver setup routines should not modify the Active key's contents, nor should they rely on the presence of any specific values within the Active key other than those listed below. When a device driver is loaded, the Device Manager passes the device driver the path to its Active key as the dwContext parameter in the device driver's Init function. The Init function can read the values in that key and can create new values in that key but is not permitted to access the key in any way after the Init function returns. The device driver can rely on the presence of the following values in the Active key.

Subkey Description
Name The device driver's device file name. For example "COM1:" or "SCR7:". Some devices are unnamed and may not have this value. Only present for drivers that specify a prefix. For more information on device file names, see Device File Names.
Key Registry path to the device.
PnpId The Plug and Play identifier string. Only present for PC Card drivers.
Sckt Current socket and function pair of the PC Card. Only present for PC Card drivers.

BuiltIn

During boot, the Device Manager invokes ActivateDeviceEx on the registry key referenced by HKEY_LOCAL_MACHINE\Drivers\RootKey. The referenced key is by default HKEY_LOCAL_MACHINE\Drivers\Builtin and the default driver loaded from there is the Registry Enumerator. This single action results in all other device drivers ultimately loading correctly.
