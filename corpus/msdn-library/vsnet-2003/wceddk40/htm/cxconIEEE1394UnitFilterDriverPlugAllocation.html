IEEE 1394 Unit Filter Driver Plug Allocation

A virtual subunit may need to permanently allocate serial bus plugs and have those plugs associated with a particular subunit plug. Many clients do not dynamically query for plugs; they query once when they identify the subunit, or they use hard-coded plug numbers or depend on broadcast. To accommodate these older clients, newer clients should be using an AV/C plug management API dynamically; a virtual subunit needs to have default plugs allocated and externally visible no later than when it receives an IRP_MN_START_DEVICE request.

As allocating default plugs is likely to be a common occurrence among virtual subunits, the unit filter driver offers some code for facilitating the process. The IOCTL_UNIT_PROCESS_REGISTRY_PLUGS command accepts a registry handle as an argument and processes the values and keys underneath in a known format. It uses that information to allocate the local plugs by issuing callbacks into the subunit's registration callbacks. It uses UNIT_AllocateLocalPlugCB to do this.

The registry key passed is an HKEY to a known location. This location is preferably the virtual subunit driver's registry key as obtainable from IoOpenDeviceRegistryKey with PLUGPLAY_REGKEY_DRIVER.

The registry format is defined as the following.

Plugs\incremental plug definition index\values

Incremental plug definition index refers to an incrementing, unique number for each plug to be defined. For example, 0 for the first plug, 1 for the next, and so on.

Values refers to the types in the following table.

Name Type Purpose
MediaType DWORD This must be one of the values defined by the Avc_stream.h STREAM_MediaType enumeration. The numerical equivalents of the textual types are listed below. This is the media type that this plug expects to stream.
Direction DWORD 1 to represent an input plug, which receives streams, or 2 to represent an output plug, which transmits streams.
SubunitPlugID DWORD This identifies which subunit plug is represented by the serial bus plug that these registry entries define. The subunit plug identifier is entirely relative to the subunit, and is defined at the discretion of the developer.
MaximumThroughput DWORD This is a requirement only for output plugs, and represents the maximum number of bits per second that this plug will ever stream.

The MediaType registry entry must be chosen from the numerical values for particular types. The types are defined in Avc_stream.h and are shown in the following table.

Name Numerical value
STREAM_MediaType_MPEG 0
STREAM_MediaType_MPEG_TimeShifted 1
STREAM_MediaType_DSS 2
STREAM_MediaType_DSS_TimeShifted 3
STREAM_MediaType_Audio_AM824 4
STREAM_MediaType_Audio_24x4Pack 5
STREAM_MediaType_Audio_32fp 6
STREAM_MediaType_DV_SD_625_50Hz 7
STREAM_MediaType_DV_SD_525_60Hz 8
STREAM_MediaType_DV_SDL_625_50Hz 9
STREAM_MediaType_DV_SDL_525_60Hz 10
STREAM_MediaType_DV_HD_1250_50Hz 11
STREAM_MediaType_DV_HD_1125_60Hz 12

The definitions for type DWORD in the registry are in hexadecimal. The numerical values in the table above are in decimal. An example of the following registry definition can be found in Common.reg.

; Define the default plugs that the Virtual VCR subunit should create on startup:
[HKEY_LOCAL_MACHINE\WDMDrivers\{A7F514FB-8FF1-442f-9547-5CCDA55EAE0}\0000\Plugs\0]
; MPEG, Output Plug, 26Mpbs peak
    "MediaType"=dword:0
    "Direction"=dword:2
    "SubunitPlugID"=dword:0
    "MaximumThroughput"=dword:18cba80
[HKEY_LOCAL_MACHINE\WDMDrivers\{A7F514FB-8FF1-442f-9547-5CCDA55EAE0}\0000\Plugs\1]
; MPEG, Input Plug
    "MediaType"=dword:0
    "SubunitPlugID"=dword:0
    "Direction"=dword:1

Having plugs automatically allocated only indirectly makes the plugs known to the virtual subunit driver. Indirectly, as the creation is done through the UNIT_AllocateLocalPlugCB routine mentioned above. At any time, the virtual subunit driver can issue an IOCTL_UNIT_QUERY_LOCAL_PLUGS command to the unit driver. This command permits the virtual subunit to get updates on whether the state of any plug has changed. For example, if an external node connects to a local plug associated with the subunit, an IOCTL_UNIT_QUERY_LOCAL_PLUGS command that is pending at the time will receive a response describing the new connection state. A virtual subunit may need to know when at least one connection to a plug is made, or know that all connections to a plug are broken. This information may need to be used as an indicator on whether the virtual subunit should start or stop streaming data at that time. Usually, streaming is started or stopped due to other indicators, such as the pressing of a PLAY or STOP button on a VCR.
