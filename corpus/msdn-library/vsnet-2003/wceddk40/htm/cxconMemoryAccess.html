Memory Access

Different processes map into different virtual addresses. This might suggest that any one process could look into the memory of any other process. While this is true, there is a barrier to this being universally true all of the time. That barrier is the security system that is in place.

A driver can access memory in any process, but to do so it must know how to unlock the permissions for those address spaces.

While the details of the virtual-to-physical mapping are device-dependent, the basic layout tends to be the same from one device to another.

When a device driver creates a thread, this can cause complications with respect to accessing the address space of an application. The reason for this complication is that access to process address spaces is set on a per-thread basis. Each thread has a 32-bit flag, one bit per Windows CE process that describes which process a thread can access.

A thread can call SetProcPermissions function, to modify the permission mask to allow the thread to access any process address space. The same thread can call GetCurrentPermissions to get the mask field for current permissions, so that they can be reset when the thread has accessed the process data.
