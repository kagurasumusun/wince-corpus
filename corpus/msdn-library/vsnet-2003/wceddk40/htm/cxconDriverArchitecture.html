Driver Architecture

You can take advantage of direct memory access (DMA), interrupts, the PCI bus driver, and installable interrupt service routines (ISRs) when you develop your driver. The device driver model characterizes drivers by the device interfaces they expose to the upper layers; these device interfaces are typically, but not necessarily, applications.

The driver publishes its interface class in the registry as IClass. Each IClass contains a globally unique identifier (GUID) and a name. The GUID describes the specific device interface. The name identifies an instance of the interface, such as COM1 or DSK1. Drivers can explicitly advertise their fully implemented interfaces with AdvertiseInterface, but it is easier and more straightforward to let the Device Manager do it by setting IClass correctly in the registry. Applications can query the interfaces with RequestDeviceNotifications.
