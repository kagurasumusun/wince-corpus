Driver Debugging

You can debug your device driver using debug zones, the kernel debugger, various hardware-debugging methods, and the Visual Studio debugger.

Debug zones and the Windows CE Console Debug Shell tool (Cesh.exe) provide the following support:

  • A way to selectively turn the debugging message output from your driver on and off by using macros. This allows you to trace execution of your device driver code without halting the OS. Tracing is a simple and non-intrusive way of catching problems in your driver code without causing the OS to stop responding.
  • Process, thread, and debugging status information.
  • Access to debug zones through the IDE, and the ability to turn them on or off dynamically.

For more information about Cesh.exe, see Windows CE Console Debug Shell tool.

The kernel debugger stops all hardware interrupts, halts the entire OS, and provides the following debugging support:

  • You can single step through the OS or kernel code.
  • You can retrieve stack trace information.

For more information about the kernel debugger, see Platform Debugging.

PC Card extenders, logic analyzers, JTAG ports, and debug LEDs are various hardware debugging methods available. The following table compares the hardware debugging methods.

Hardware debug method Description
PC Card extenders Power draw is a common problem in tracing or debugging PC Card problems on mobile or handheld devices. You can use PC Card extenders to debug power draw related problems. Because some PC Card extenders provide their own power, you can rule out current fluctuations as the cause of your problem.
Logic analyzers Logic analyzers can help you monitor the microprocessor or PCI bus traffic and analyze any timing related problems in your device driver. For ISA, PCI, and compact PCI busses, many vendors offer software or hardware solutions that allow you to connect a logic analyzer to the bus and decode the bus activity. You can use this for hard-to-trace issues such as timing related problems or DMA transfers with your device driver.
JTAG ports JTAG-supported background debug monitors (BDMs) support hardware-assisted debugging.
Debug LEDs Debug LEDs are a low intrusive way to debug a device driver. You can treat an LED as an array of LEDs and decode a large range of addressed assigned to that one LED. This allows any write to an LED index to show up on the physical debug LED, and then you can use a logic analyzer to distinguish between the different indexes. By correlating indexes with parts of your code, you can analyze different parts of your code.

The Visual Studio debugger is another way to debug your device driver. For more information, see the Visual Studio documentation.
