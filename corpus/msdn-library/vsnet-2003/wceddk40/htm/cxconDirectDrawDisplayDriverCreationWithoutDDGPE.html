DirectDraw Display Driver Creation Without DDGPE

This topic describes the steps necessary to create DirectDraw display drivers on Windows CE without using GPE.

The native interface to DirectDraw is described. Using DDGPE (as described in DirectDraw Display Drivers), while easier to implement, will not get you all the functionality described in this topic.

For your driver, you most likely need to modify the functions and callbacks to reflect your specific hardware needs. To get your driver up and running as soon as possible, you should implement the driver initialization code first, and then add functionality (start with flipping, for example).

In addition to the functions, callbacks, macros, and structures listed in the reference section, driver writers must include both Ddrawi.h and Ddraw.h in their driver. Both of these include files are provided with DXPAK.

Note   All callback function names listed in this reference section are pseudonyms to be decided on by the display driver writer.

Display driver developers should reuse the code base provided by the DDGPE classes. The DDGPE classes will simply add the small amount of code required to make your display driver function correctly. However, it is feasible to write display drivers from scratch that conform to the Windows CE–based DDI interface definition and that also support the DirectDraw HAL interface.

The following topics describe what driver developers must do to create a display driver that supports DirectDraw without using any GPE-based classes.

  • Display Driver Preparation describes the steps necessary to create a display driver from scratch that is ready to support the addition of a DirectDraw HAL implementation.
  • DDHAL Functionality Implementation Without GPE briefly outlines possible steps you could take to implement a simple DirectDraw HAL in your display driver, using the sample source code (DDHAL Resources) provided with this document.
