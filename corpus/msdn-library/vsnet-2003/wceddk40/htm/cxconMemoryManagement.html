Memory Management

Unlike running in user mode, when you execute code in kernel mode, you need access to the entire physical memory. Because the IST is running as a user-mode thread and may need access to a block of physical memory to communicate with the device, you must map this block of memory to the address space in which the IST is running.

The following list shows how to map this block of memory to the address space of the IST:

  1. Reserve a block of virtual memory by calling VirtualAlloc. You must pass the MEM_RESERVE value as an argument to this function.
  2. Windows CE allocates the memory and gives you a pointer to the block. You then need to map this block of memory to the corresponding block of physical memory by calling VirtualCopy. Do not forget to specify the PAGE_NOCACHE argument so that the values inside that block are not cached. This flag will force the system to not optimize out a read.

VirtualCopy also supports the PAGE_PHYSICAL flag. You must set this flag when you are mapping physical memory that resides beyond 512 MB, that is, physical memory with an address above 0x1FFFFFFF.

You can free virtual memory by using the VirtualFree function.

The following table shows the memory management functions.

Function Description
MapPtrToProcess Maps a pointer from one address space to another. Mainly, you should use this API to exchange pointers between address spaces.
GetCurrentProcess Retrieves a process identifier to use with the MapPtrToProcess function.
SetProcPermissions Gives the current process access to address spaces of other processes.

To speed up the code, the volatile qualifier in the C language prevents the compiler from using any optimization for a variable that stores its value in a register.
