Direct3D Surface Handles

The Direct3D DDI is designed to promote a model whereby the Direct3D run-time components parse as little of the command stream as possible before handing the commands to the driver. Additionally, the command stream should be formatted so that it can be directly consumed by future hardware.

One important change directed towards these goals is the movement of all surface-related data out of intermediate structures owned by the Direct3D/DirectDraw run time into structures owned, updated, and formatted by the driver.

Surfaces are referred to by handles embedded in the command stream. In these high-frequency operations, the driver can look up its own representation of a surface from the handle.

The mechanism for assigning these handles is a new driver entry point called D3dCreateSurfaceEx. This entry point is called directly after calls to the existing CanCreateSurface and CreateSurface entry points, and after a video memory address and handle have been assigned to a surface. At D3dCreateSurfaceEx time, the driver can copy all pertinent information out of the DirectDraw run time's copy of the surface structure and into its own surface structure. Surface data such as size, format, and fpVidMem (a member of the DDRAWI_DDRAWSURFACE_GBL structure) are obvious candidates for which driver-side copies would be required.

Handles are guaranteed by the run time to be unique per device and per process. Handles are not guaranteed to be unique per context, and this has some implications for drivers that will be discussed in greater detail in Creating Driver-Side Surface Structures.

D3dCreateSurfaceEx is then called again during surface destroy time with fpVidMem set to NULL to indicate a surface/handle association destruction.
