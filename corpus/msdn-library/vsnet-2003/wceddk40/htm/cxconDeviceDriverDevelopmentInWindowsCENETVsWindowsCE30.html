Device Driver Improvements in Windows CE .NET

The following list shows some of the device driver improvements in Windows CE .NET:

  • Drag-and-drop integration of your driver into the Catalog. In Windows CE 3.0, you had to manually add drivers to the Catalog. For more information, see Catalog Customization.
  • Conducted tests across all sample platforms and microprocessor architectures. This allows support for a wide variety of peripherals and hardware. In Windows CE 3.0, Microsoft tested drivers primarily on the Hitachi D9000 hardware development platform (ODO) and CEPC hardware platforms. For more information, see Board Support Packages.
  • Consistent and clean architecture. For more information, see Driver Architecture.
  • Device drivers are categorized by their exposed device interfaces. In Windows CE 3.0, drivers were categorized as stream, native, and other types of drivers. For more information, see Device Driver Loading Model.
  • Device interface notifications alert interested modules when device interfaces appear and disappear. For more information, see Device Interface Notifications.
  • Extensive Power Management. For more information, see Power Management.
  • There are additional CSP drivers for CPU-native peripherals, additional drivers for many new chipsets, and many platform-independent drivers. For more information on where these drivers are, see Device Driver Development and Creating a BSP.
  • There are additional drivers for new device classes. For information on all of the device classes, see Drivers.
  • Migrating, or porting drivers to new platforms is simpler and less difficult than in Windows CE 3.0. For more information, see Driver Migration.
