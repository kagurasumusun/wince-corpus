Bump Mapping

Bump mapping is an elegant technique that enables a surface to appear wrinkled or dimpled without the need to model these depressions geometrically.

Bump mapping in the usual sense involves perturbing the angles of the surface normals according to information given in a two-dimensional bump map. This tricks the local reflection model, where intensity is mainly a function of the surface normal, into producing local variations on a smooth surface. This deception is evident only when silhouetted, because in that case the perturbations will no longer be visible at the edges. That is, the silhouette follows the line of the model and is therefore not perturbed. This is an important technique because it appears to add texture to a surface, rather than modulating the color of a flat surface.

Because bump mapping for Direct3D is done by texturing a surface in the rendering phase without perturbing the geometry, it bypasses serious modeling problems that would otherwise occur. If the object is polygonal, the mesh has to be fine enough to receive the perturbations from the texture map. This is a serious drawback, if the texture is to be an option.

Bump mapping is perturbed environment mapping that allows an arbitrary number, shape, and color of lights to be specified. DirectDraw specifies new pixel formats for bumps: DDPF_DU and DDPF_UV. These are integrated with multitexture blending through the D3DTEXTURESTAGESTATETYPE enumerated type, described in the DirectX SDK documentation. Environment mapping can be done by the application.

Bump mapping in this case is more accurately described as per-pixel texture coordinate perturbation by rasterizers for diffuse and specular environment maps. This capability is integrated with Direct3D multitexture support. Bump mapping is performed in the local surface coordinate system (texture coordinates (u, v)).

This technique allows the lighting environment of the scene to be represented in an image environment map (either for diffuse or specular effects). It permits the lights to be of any number, shape, color, or intensity distribution that can be represented in such a map. These maps can be created in advance for static cases, or easily updated on the fly for changing light sources, using blits.

Conventional bump mapping schemes derived from Phong shading are limited to spherical light sources of constant color and fixed fall-off curve. These do not require the additional texture addressing capabilities of per-pixel environment mapping and can work well for diffuse lighting effects, but cannot produce the visually structured specular highlights required for photo realism. In the future, use of such techniques will be facilitated by the integration of environment mapping calculations directly into the Direct3D geometry pipeline.

Bump mapping is commonly provided in photo realistic renderers. It can be used to drastically increase surface detail effects, without tessellating the surface into large numbers of small triangles. When used with specular effects, bump maps can simulate reflective yet rough surfaces, such as wet stone or pavement. When supported by 3D accelerators, such effects can be performed in real time, allowing dynamic light source changes. Direct3D's support of bump mapping eliminates one of the few remaining barriers to representing surfaces and environments with photo realistic quality.

When a DirectDrawSurface object is created with a bump-map format, that texture is considered to be a bump map. This object can be bound into the Direct3D device using any of the textures bound to the texture stages. A programmed texture blending stage can be set to perform the bump map operation by setting D3DTOP_BUMPENVMAP. The texture defined for this stage is a DirectDrawSurface object with a bump-map format. It will use the texture coordinates of the flexible vertex format specified by this stage's texture coordinate identifier to position itself on the rendered objects. It will also respect the specified texture stage's controlling filtering, wrapping, and so on.

The bump values in this texture will perturb the texture coordinates used by the immediately following texture, which should be considered a specular or diffuse environment map.

Emulation

This methodology can be emulated on any hardware that supports an 8-bit paletted texture mode. The restriction is that the environment map used (the texture immediately following the bump texture map) must have a resolution of exactly 16X16 texels, and no filtering. This is indicated by the D3DTEXOPCAPS_MAXBUMPENVMAP16X16 flag. Other parts will have no limits on the size of the environment map that the bump map can perturb.

More general methods for bump-mapped environment mapping will be supported in future versions of DirectX, when additional information, such as normal vector data, is provided in the DDI.

Bump mapping is enabled with the multitexture blending operations D3DTOP_BUMPENVMAP and D3DTOP_BUMPENVMAPPREMODULATE. The latter operation is a combination of bump mapping and gloss mapping that allows the specular reflection intensity to be encoded in the same surface as the bump map data.

There are now four additional texture states provided at each stage:

  • D3DTS_BUMPENVMAT00
  • D3DTS_BUMPENVMAT01
  • D3DTS_BUMPENVMAT10
  • D3DTS_BUMPENVMAT11
