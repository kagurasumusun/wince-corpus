Troubleshooting: Building a Driver

The following table shows problems you may encounter in the process of building your driver and lists their possible solutions.

Problem Possible solution
The build cannot find files you expected it to include. Ensure that the paths to the files are specified with the INCLUDES macro in the sources file.
The C_DEFINES and RCOPTIONS macros in your sources file are not working. Ensure that you are using the CDEFINES and RDEFINES macros instead. The C_DEFINES and RCOPTIONS macros are only appropriate on a Windows-based desktop platform.
You cannot compile Miniport.rc because the build cannot find Windows.h. Add the Windows.h file location to the RDEFINES macro in the sources file.
Your object files are not building. Check the arguments you are passing to the build utilities. Ensure that you did not accidentally pass an empty argument when using a switch.
The build cannot find a static library, or you receive an error compiling your .def file because it cannot find Deffile.inc. Do not copy files to the place that the build utility is searching. Instead, run the Master Build tool (Cebuild.bat) from %_WINCEROOT% with the proper build environment settings. These generate the proper library and include directories for your build environment. Ensure that you run Cebuild.bat from %_WINCEROOT% for every build configuration that you may use to build your driver. For more information on Cebuild.bat, see Master Build Tool.
You do not have a proper build environment for your driver. Create a project. Then, from the Build menu, choose Open Build Release Directory. This opens a command-line interface with the correct environment variables. You can then navigate to the directory where your driver is, and then run the Build tool (Build.exe). For more information on Build.exe, see Build Tool.
You do not want to use a project. Use the Windows CE Build Environment tool (Wince.bat). For more information on Wince.bat, see Windows CE Build Environment Tool.
You want to put your driver into the %_FLATRELEASEDIR% of your project. Type set WINCEREL=1 from the command line and the build utility will move your driver to the %_FLATRELEASEDIR%. If it is a debug build, the .dll, .pdb, and .map files move to the %_FLATRELEASEDIR% as well.
You want to change your %_FLATRELEASEDIR% environment variable. Type set _FLATRELEASEDIR=MyFlatReleaseDir. MyFlatReleaseDir is a placeholder for your desired flat release directory. For more information on changing environment variables, see SET.
The compiler behaves as if some structures and macros in header files do not exist, even though they do. Ensure that WINCEOEM=1 is in your sources file. This is often set in a Sources.cmn file so you may run into this issue if you copy a driver from the Public directory and try to build it someplace else.
Sources files with NMAKE conditionals in them do not build properly. NMAKE understands conditionals, but BUILD.EXE does not. Do not use conditionals in your sources files.
