Point, Line, and Triangle Filling Requirements

The following are requirements for filling points, lines, and triangles.

Points

The point fill and rasterization rules are identical to the triangle fill rules. All flags and capabilities that apply to triangles also apply to points, and vice versa. The reference implementation expands a point into a rectangle and applies the triangle fill rules to the result.

Given a point with coordinates P0(x,y), generate four new points P1, P2, P3, and P4 as follows.

P1(x,y) = (x – 0.5, y – 0.5)
P2(x,y) = (x – 0.5, y + 0.5)
P3(x,y) = (x + 0.5, y + 0.5)
P4(x,y) = (x + 0.5, y – 0.5)

The rectangle is then generated as two triangles, such as (P1, P2, P3) and (P1, P3, P4). You may also examine the reference rasterizer implementation in the source files Setup.cpp and Scancnv.cpp.

Lines

Line fill rules for the desktop are found in the reference rasterizer source files, Setup.cpp and Scancnv.cpp.

Triangles

Triangle fill rules are documented in the DirectX Windows NT® DDK in the reference rasterizer source files Setup.cpp and Scancnv.cpp.

Hardware should supply the culling caps and properly implement the three culling modes. The following code fragment determines whether to cull the current triangle.

if (CurrentCullMode != D3DCULL_NONE) {
    int ccw = (((v[0]->sx - v[2]->sx) *
                (v[1]->sy - v[2]->sy)) <
               ((v[1]->sx - v[2]->sx) *
                (v[0]->sy - v[2]->sy)));
if ((CurrentCullMode == D3DCULL_CW && (ccw == 0)) ||
        (CurrentCullMode == D3DCULL_CCW && (ccw != 0))) {
        // Current triangle is culled, move onto
        // next triangle.
    }
}
// Current triangle is not culled, render it

The preceding code sample tests to determine which way the triangle is facing. The triangle is defined 0,1,2 and tested for being counter-clockwise in screen space. If it is not, and there is clockwise culling, then that triangle will not be drawn because the vertices go in clockwise order.
