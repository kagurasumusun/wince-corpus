Interrupt Service Threads

The interrupt service thread (IST) is a user-mode thread that does most of the interrupt processing. The IST is idle most of the time and relies on the OS to wake it when it needs to process interrupts. Achieve this by associating an event object with an interrupt identifier.

The IST first creates an event object and associates it with the logical interrupt. Use the CreateEvent function to create an event object. As soon as possible, the IST should wait for this event to signal. When the hardware interrupt occurs, the kernel signals the event on behalf of the ISR, then the IST performs necessary I/O operations in the device to collect the data and process it. When the interrupt processing completes, the IST should inform the kernel to re-enable the hardware interrupt.

Usually, IST threads run at above-normal priority. They can boost themselves to a higher priority before registering their event with the kernel by calling CeSetThreadPriority.

The following table shows the functions that the IST uses commonly.

Function Description
InterruptInitialize Links the event with the interrupt identifier of the ISR.
WaitForSingleObject Used to wait for an event to signal. This call is usually inside a loop so that as soon as an interrupt is processed, the IST gets back to this call waiting for the next interrupt to handle.
InterruptDone Instruct the kernel to enable the hardware interrupt related to this thread.

The following lists shows examples of what an IST might do at startup:

  • Create a structure and store interrupt values in it.
  • Use CreateEvent as the IST trigger.
  • Read the IRQ and SysIntr values from the registry and allow the OAL to create the mapping before the driver loads.
  • Store the handle for the thread you are creating.

The following code example shows a typical IST start.

struct ISTData      // Declare the structure to pass to the IST
{
    HANDLE hThread; // IST Handle
    DWORD sysIntr;  // Logical ID
    HANDLE hEvent;  // handle to the event to wait for interrupt
};

ISTData g_KeypadISTData;
// Create event to link to IST
g_KeypadISTData.hEvent = CreateEvent(NULL, FALSE, FALSE, NULL);
// Translate IRQ to logical ID (x86 CEPC)
g_KeypadISTData.sysIntr = Mapirq2Sysintr(5);
//start the thread
g_KeypadISTData.hThread = CreateThread(NULL, 0, &KeypadIST, &g_KeypadISTData, 0, NULL);

The following code example shows how to set the IST thread priority, disconnect any previous events from the associated ISR, and connect to the associated ISR.

// change the thread's priority
CeSetThreadPriority(g_KeypadISTData.hThread, 0);

// disconnect any previous events from logical ID
InterruptDisable(g_KeypadISTData.sysIntr);

// connect logical ID with event
InterruptInitialize(g_KeypadISTData.sysIntr, g_KeypadISTData.hEvent, NULL, 0);

The critical part of the IST happens in a loop that runs until manually aborted. Once in the loop, immediately block until the triggering event returns from the kernel, this signifies that the IRQ has pulsed. This loop also does actual processing of the interrupt. Signal InterruptDone in the kernel with the interrupt identifier. This calls down to OEMInterruptDone in your OAL to unmask the IRQ. The following code example shows this loop.

DWORD KeypadIST(void *dat)
{
    ISTData* pData = (ISTData*)dat;
    // loop until told to stop
    while(!pData->abort)
    {  // wait for the interrupt event…
        WaitForSingleObject(pData->Event, INFINITE);
        if(pData->abort)
            break;
                // handle the interrupt
        // let OS know the interrupt processing is done
        InterruptDone(pData->sysIntr);
    }
    return 0;
}

If your device is installable, you may want to disconnect and turn off the IST permanently. Set a flag that cancels the IST loop, call InterruptDisable to disconnect the triggering event from the logical identifier, and close the thread. The following code example shows how to disconnect and turn off the IST.

// set abort flag to true to let thread know that it should exit
g_KeypadISTData.abort = TRUE;

// disconnect event from logical ID
// this internally sets g_KeypadISTData.sysIntr which in turn sets g_KeypadISTData.hEvent through the kernel
InterruptDisable(g_KeypadISTData.sysIntr);

// wait for thread to exit
WaitForSingleObject(g_KeypadISTData.hEvent, INFINITE);

CloseHandle(g_KeypadISTData.hEvent);
CloseHandle(g_KeypadISTData.hThread);
