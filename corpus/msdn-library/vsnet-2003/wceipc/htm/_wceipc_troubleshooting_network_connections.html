Microsoft Windows CE 3.0  

Troubleshooting Network Connections

Connecting legacy devices to a network is not always a straightforward process. If you are unable to establish a network connection, consider the following:

  • Is the target device a Handheld PC 2.00 or a Palm-size PC 2.01? If so, it's likely that there are no installed Ethernet drivers. Ethernet drivers are available in the "Optional components" subdirectory on the Windows CE Services CD.
  • Is the NetBIOS registered on the target CE device? Use nbt.exe on the desktop or nbtce.exe on Windows CE to check NetBIOS registration status.
  • Are you using Remote Access Service (RAS) over a modem to connect your device to the network? In the RAS environment, IP address and WINS of a dial-up adapter are not exposed through a registry key. To enable name server registration, a fake adapter must be created in the registry to store the WINS address. 
    [HKEY_LOCAL_MACHINE\Comm\RASMSMQ\Params\tcpip]
    "WINS"="x.x.x.x"
  • Does your device have unique name? Is it different from the default? If not, the name registration service will not load.
  • Is there a DNS server on the net? Windows NT can operate without DNS server by using NetBIOS broadcasts. Windows CE requires DNS, WINS, or a subkey in [HKEY_LOCAL_MACHINE\Comm\Tcpip\hosts] for name resolution.
  • Does the DNS server know about the target machine? Use the NSLOOKUP utility to find out.
  • Which WINS servers are used? If DNS does not know about the device, or has an incorrect IP address, this usually means that the CE device did not sync up with the WINS server. Run IPCONFIG /ALL on Windows NT/2000 or look in [HKEY_LOCAL_MACHINE\Comm\your netcard driver name\Parms\Tcpip] subkey value "WINS" or "DhcpWINS."
  • What does WINS know about the name in question? You may need to query WINS to discover this information. RFC1001/1002 explains how to write your own small tool to do WINS queries.
  • Is the device configured properly? Here are some common configuration errors:
    • The redirector is present on the device, yet NETREG is configured to emulate NetBIOS. On a device with a redirector, you can run cmd.exe and net view. This forces the redirector to load and attempt to register the name on the net.
    • The redirector is not present, but NetBIOS has been configured to use redirector for network administration.
    • Network tracking was enabled on a device running a version of Windows CE earlier than 2.12 (this disables the redirector).
    • Network tracking is disabled and the periodic update has a long cycle (remember, cycle value is in seconds).
  • Does WINS have the correct address for the device name? If WINS does not have the correct address, NETREG has probably failed to register the device. Make sure WINS is running. If WINS does have the correct address, check the [HKEY_LOCAL_MACHINE\Comm\Tcpip\hosts] key for possible outdated cache entries for the target computer.

If all else fails, check the log file on the target machine. The source computer may not have NetBIOS service running and it may not be responding correctly to node status queries. In this case, MSMQ will not be able to retrieve a machine name for an incoming connection and will reject the connection. To check whether the connecting device answers a node status query, determine the IP address and run "ping –a <device_ip_address>".

Use the NETMON utility to track general connection problems.
