CAsyncSocket::ShutDown

This method disables reception, transmission, or both on a socket.

BOOL ShutDown( 
int nHow = sends );

Parameters

nHow
A flag that describes what types of operation will no longer be allowed, using the following enumerated values:
  • receives = 0
  • sends = 1
  • both = 2

Return Value

Nonzero if the function is successful; otherwise, it is zero, and a specific error code can be retrieved by calling GetLastError. The following errors apply to this method:

WSANOTINITIALISED
A successful AfxSocketInit must occur before using this API.
WSAENETDOWN
The Windows CE Sockets implementation detected that the network subsystem failed.
WSAEINVAL
nHow is not valid.
WSAEINPROGRESS
A blocking Windows CE Sockets operation is in progress.
WSAENOTCONN
The socket is not connected (SOCK_STREAM only).
WSAENOTSOCK
The descriptor is not a socket.

Remarks

If nHow is zero, subsequent receiving on the socket is disallowed. This has no effect on the lower protocol layers.

For Transmission Control Protocol (TCP), the TCP window is not changed and incoming data is accepted, but not acknowledged, until the window is exhausted. For User Datagram Protocol (UDP), incoming datagrams are accepted and queued. In no case is an ICMP error packet generated. If nHow is one, subsequent sending is disallowed. For TCP sockets, a FIN is sent. Setting nHow to two disables sending and receiving as described earlier in this topic under Parameters.

ShutDown does not close the socket, and resources attached to the socket are not freed until Close is called. An application should not rely on being able to reuse a socket after it has been shut down. In particular, a Windows CE Sockets implementation is not required to support the use of Connect on such a socket.

See the example for CAsyncSocket::OnReceive.

Requirements
