Architecture

The MFC library is sometimes identified with the Document/View architecture. However, you do not need to develop MFC applications using the Document/View architecture. Using MFC, you can create single-document applications without this architecture and even dialog-based applications.

However, because of the popularity and several advantages of the Document/View architecture, the following topics focus on its use.

The parts of the MFC framework most visible to the user are the document and view. Most of your work in developing an application with the framework goes into writing your document and view classes.

The CDocument class provides the basic functionality for programmer-defined document classes. A document represents the unit of data that the user typically opens with the Open command on the File menu and saves with the Save command on the File menu.

The CView class provides the basic functionality for programmer-defined view classes. A view is attached to a document and acts as an intermediary between the document and the user. The view renders an image of the document on the screen and interprets user input as operations upon the document. The view also renders the image for both printing and print preview.
