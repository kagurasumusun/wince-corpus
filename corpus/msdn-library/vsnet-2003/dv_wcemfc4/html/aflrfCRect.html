CRect

This class is similar to a Windows CE RECT structure. CRect also includes methods to manipulate CRect objects and Windows CE RECT structures.

A CRect object can be passed as a method parameter wherever a RECT structure, LPCRECT, or LPRECT can be passed.

Note   This class is derived from the tagRECT structure. The name tagRECT is a less-commonly-used name for the RECT structure. This means that the data members in the order, left, top, right, and bottom, of the RECT structure are accessible data members of CRect.

A CRect contains member variables that define the top-left and bottom-right points of a rectangle.

When specifying a CRect, you must be careful to construct it so that it is normalized—in other words, the value of the left coordinate is less than the right and the top is less than the bottom. For example, a top-left with coordinates (10,10) and bottom-right with coordinates (20,20), defines a normalized rectangle; but a top-left with coordinates (20,20) and bottom-right with coordinates (10,10), defines a non-normalized rectangle. If the rectangle is not normalized, many CRect methods may return incorrect results. See CRect::NormalizeRect for a list of these methods. Before you call a method that requires normalized rectangles, you can normalize non-normalized rectangles by calling the NormalizeRect function.

Use caution when manipulating a CRect with the CDC::DPtoLP and CDC::LPtoDP methods. If the mapping mode of a display context is such that the y-extent is negative, as in MM_LOENGLISH, then CDC::DPtoLP will transform the CRect so that its top is greater than the bottom. Methods such as Height and Size will then return negative values for the height of the transformed CRect, and the rectangle will be non-normalized.

When using overloaded CRect operators, the first operand must be a CRect; the second can be either a RECT structure or a CRect object.

Shared Utility Classes

Beginning with Visual C++ 6.1, the simple utility classes (CRect, CSize, and CPoint) have been modified to be MFC-independent. This allows these utility classes to be used by ATL projects and projects that do not use the MFC library.

The include file for the MFC utility classes is Afxwin.h. There are no changes in using these classes from previous versions of MFC. The include file for the utility classes in an ATL or MFC-independent project is Atltypes.h. This version allows you to use the utility classes without needing to link to the MFC DLL.
