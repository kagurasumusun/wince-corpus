CDialog

This class is the base class used for displaying dialog boxes on the screen. Dialog boxes are of two types: modal and modeless. A modal dialog box must be closed by the user before the application continues. A modeless dialog box allows the user to display the dialog box and return to another task without canceling or removing the dialog box.

A CDialog object is a combination of a dialog template and a CDialog-derived class. Use the dialog editor to create the dialog template and store it in a resource; then use ClassWizard to create a class derived from CDialog.

A dialog box, like any other window, receives messages from Windows CE. In a dialog box, the main interest should be in handling notification messages from the dialog box controls, because this is how the user interacts with a dialog box. ClassWizard browses through the potential messages generated by each control in the dialog box, and you can select which messages you wish to handle. ClassWizard then adds the appropriate message-map entries and message-handler methods to the new class. You need only to write application-specific code in the handler methods.

You can write message-map entries and methods yourself instead of using ClassWizard.

In almost all dialog boxes you add member variables to the derived dialog class to store data entered in the dialog box controls by the user or to display data for the user. ClassWizard browses through the controls in the dialog box that can be mapped to data; ClassWizard then prompts you to create a member variable for each control. At the same time, you choose a variable type and permissible range of values for each variable. ClassWizard adds the member variables to the derived dialog class.

ClassWizard then writes a data map to automatically handle the exchange of data between the member variables and the dialog box controls. The data map provides functions that initialize the controls in the dialog box with the proper values, retrieve the data, and validate the data.

To create a modal dialog box, construct an object on the stack using the constructor for the derived dialog class and call DoModal to create the dialog window and its controls. To create a modeless dialog, call Create in the constructor of the dialog class.

You can create a template in memory by using a DLGTEMPLATE data structure as described in the API Reference. After you construct a CDialog object, call CreateIndirect to create a modeless dialog box, or call InitModalIndirect and DoModal to create a modal dialog box.

ClassWizard writes the exchange and validation data map as an overridden version of CWnd::DoDataExchange that ClassWizard adds to your new dialog class. For more information on exchange and validation functionality, see the DoDataExchange method in CWnd.

Both the programmer and the framework call DoDataExchange indirectly through a call to CWnd::UpdateData.

The framework calls UpdateData when the user chooses the OK button to close a modal dialog box. The data is not retrieved if the user chooses the Cancel button. The default implementation of OnInitDialog also calls UpdateData to set the initial values of the controls. You override OnInitDialog to further initialize controls. OnInitDialog is called after all the dialog controls are created and just before the dialog box is displayed.

You can call CWnd::UpdateData at any time during the execution of a modal or modeless dialog box.

If you develop a dialog box yourself, you add the necessary member variables to the derived dialog-box class, and add methods to set or get these values.

A modal dialog box closes automatically when the user chooses the OK or Cancel buttons, or when your code calls the EndDialog method.

When you implement a modeless dialog box, always override the OnCancel method and call DestroyWindow from within it. Do not call the base class CDialog::OnCancel, because it calls EndDialog, which makes the dialog box invisible but does not destroy it. You should also override PostNcDestroy for modeless dialog boxes in order to delete this, because modeless dialog boxes are usually allocated with new. Modal dialog boxes are usually constructed on the frame and do not need PostNcDestroy cleanup.

Remarks

In Windows CE, all dialog boxes are control parents and are recursive. When a user tabs through a parent dialog box that also has a child dialog box, the dialog manager will always tab into the child dialog box too.

If a dialog box is outside the visible area of the screen, Windows CE does not automatically reposition it. Windows CE does not support the DM_REPOSITION message.

If a dialog box is created with version 1.0 or 1.1 of MFC for Windows CE, the MFC framework does not automatically center it. To center it, call the CenterWindow function inside the dialog box OnInitDialog handler.

If a user presses ALT+H while the dialog box has the input focus, the system posts a WM_HELP message to the dialog procedure. An application should respond to this message by displaying context-sensitive Help for the dialog box.
