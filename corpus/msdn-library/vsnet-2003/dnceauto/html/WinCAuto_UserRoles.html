Overview

There are many roles involved in the creation of an automotive platform. For example, your group may include developers who write applications that run on the automotive platform, develop user interface (UI) prototypes, and design themes that determine what the end user will see and hear. Additionally, some developers may serve the role of platform developer and build the platform, add device drivers, and incorporate the applications into the final build of the platform. You also need developers to design and build the actual hardware, and, of course, testers to make sure that all of these elements work together without any glitches.

Typically, there is a unique role for each developer throughout the development process; each role is associated with a specific task, and each developer needs a specific skill set in order to complete their task.

Roles and Skill Sets

To get the most out of Windows CE for Automotive (WCEfA) as it relates to your duties, you should be familiar with the specific skills required for each role.

In general, developers programming for the automotive platform may need the following:

  • Knowledge of the hardware used for the automotive platform.
  • Knowledge of the Microsoft® Windows® CE operating system.
  • Knowledge of WCEfA.
  • Familiarity with automotive programming topics.

In this article, we describe common WCEfA user roles and the skills each user needs to use WCEfA version 3.5. For a list of resources to assist you in learning these skills, see Learning Materials.

User Role Descriptions

This section lists brief descriptions for each user role. To review skills that you should acquire before using WCEfA, see User Skills.

To find resources for acquiring a particular skill, see Learning Materials.

Application Developer

The application developer may create any or all of the distinct application types that run on the automotive platform:

  • OEM Developer

    OEM developers write resident, native applications for their companies' particular automotive device.

  • Third-Party Developer

    Third-party developers write "aftermarket," installable applications that can be added to the automotive platform.

  • Custom Style Class Developer

    Custom style class developers create custom style classes that allow controls to be rendered differently. An example of this would be a round, pie-chart meter, which fits with the meter concept but needs to be drawn differently. This person can also create new controls.

Hardware Developer

The hardware developer leverages Microsoft reference platforms, such as the CEPC, to design electronics hardware for automotive use.

Platform Component/Custom API Developer

The platform component/custom API developer creates new middleware that all automotive applications can use.

Platform Developer

The platform developer builds the final binary image (nk.bin) for an OEM device. This means integrating device drivers, Microsoft and OEM APIs, and applications into the final build.

Project Manager

The project manager ensures that the right product gets shipped on time. This means creating the project schedule, coordinating the efforts of different teams, and tracking the progress of each phase of the project.

Tester

The tester plans and executes tests of various aspects of device/application functionality to ensure that everything works perfectly before being released to the end user.

Theme Designer

The theme designer takes screen layouts from the UI prototype developer and uses them to create a theme. This means figuring out such things as what the screens have in common (for example, can you use a button from screen 1 in screen 2?), and creating a graphical representation and mapping it to a set of controls. The theme designer also decides things like what a button should be, and then makes the button chips (chips are the bitmaps that represent part of a graphical control). The person in this role also often designs the form for the application.

UI Prototype Developer

The UI prototype designer builds both speech UI and graphical UI desktop prototypes using Automotive Common Controls (ACC).

Definitions

The following terms appear in User Skills. To find resources for learning the technology associated with each term, see Learning Materials.

ACC
ACC is a packaged set of services and COM objects that make it easy for both the automotive supplier and the application developer to design and implement a graphical and speech interface for an automotive computing device.
ACC XML Schema
Arranges theme information — such as properties of a theme and the style properties associated with each control under a theme — into a document structure that is used by the theme compositor tool to generate a theme.
ATL
Active Template Library is an architecture for building COM components in C++ that slices code into smaller, manageable pieces that are stored in various files of a COM project.

The automotive application wizard is based on the familiar ATL Wizards provided with Microsoft Visual Studio® version 6.0. It facilitates development of the user interface of an automotive application using the ATL architecture.

COM
Software applications written for WCEfA are based on COM.

COM is designed for C++ developers who must reference and use information residing in various locations in a consistent manner. COM allows software developers to use the same programming model to implement a range of technologies in automotive applications. This provides automotive software developers with a consistent framework on which to integrate various levels of functionality into automotive applications.

COM is a platform–independent, distributed, object–oriented system for creating binary software components that can interact. COM objects can be created with a variety of programming languages. Object–oriented languages, such as C++, provide programming mechanisms that simplify the implementation of a COM object. These objects can be within a single process, in other processes, or even on remote machines.

eMbedded Visual Tools
eMbedded Visual Tools is Microsoft's complete desktop development environment for creating applications and system components for Windows-powered devices. eMbedded Visual Tools 3.0 includes eMbedded Visual Basic and eMbedded Visual C++.
Perl
Perl is a scripting language that was initially designed as a filter language for system processing functions, but has grown and mutated considerably since, with a well-supported and full-featured Win32 variant (also known as ActivePerl).
Windows CE Platform Builder
Windows CE Platform Builder version 3.0 is a tool for building custom Windows CE-based platforms and components, including those for WCEfA. Windows CE Platform Builder includes the latest version of the Windows CE OS, a set of embedded development tools, an integrated development environment (IDE), support for the Microsoft run-time libraries, and sample code.
Visual Studio
Visual Studio is Microsoft's package of visual development tools, composed of Visual Basic, Visual C++, Microsoft Visual J++™ , Microsoft Visual InterDev® , and Microsoft Visual FoxPro® .
Win32 API
The Win32 programming model is a popular programming approach for writing applications designed to run on 32–bit versions of Windows. You can use the Win32 API to write automotive applications based on the Win32 programming model while taking advantages of the features and capabilities unique to the automotive platform.

Differences in the implementation of the programming elements depend on the capabilities of the underlying features of the platform. For example, WCEfA supports only a subset of the Win32 API functions available to developers.

Windows CE
Windows CE is an open, scalable, 32-bit operating system that is designed to meet the needs of mobile devices, such as hand-held computers and automotive devices.
XML
Extensible Markup Language (XML) is basically structured ASCII with embedded tags that allow data to be self-describing and extensible.

About Windows CE for Automotive

Windows CE for Automotive (WCEfA) is an operating system built on Windows CE technology to make possible new categories of in-car computers that are capable of safely providing drivers and passengers with hands-free communication, access to personalized information on the Internet, the ability to summon emergency services and roadside assistance, and an array of convenience and entertainment applications. WCEfA is an open platform that allows developers to quickly create powerful in-car computing solutions. It offers flexibility and choice of computing platforms, hardware peripherals, and software components, as well as a large community of developers familiar with Windows CE development practices.
