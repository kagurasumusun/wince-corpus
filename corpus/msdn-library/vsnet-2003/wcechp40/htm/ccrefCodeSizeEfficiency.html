Code Size Efficiency

Using the iwcall or iw16 declspec requires one additional word of text space instruction, per interworking call. In addition, the function address must be placed into and loaded from the literal pool. This requires two additional words not required by the linker-generated thunking routine. Some function calls do not incur this cost, Further, because different load instructions can share a given literal pool entry, some function calls do not add words for a declspec. In addition, the literal pool entry may be loaded into a register that different BX instructions use without reloading the register.

Allowing the linker to generate an interworking thunking routine incurs an expense of additional three words per called function but no additional words at the call sites.

Note    Regardless of how many different callers call a function, no function will ever have more than one interworking thunking routine associated with it.

If a program contains only a few interworking functions called from many places, then allowing the linker to generate the thunking routine will likely result in smaller overall code size.

If a program contains many different functions with each interworking function called from only a few places, then using the iwcall or iw16 declspec will result in code size similar to that required by a linker-generated thunking routine.

A linker-generated thunking routine for CLTHUMB requires four words instead of three.
