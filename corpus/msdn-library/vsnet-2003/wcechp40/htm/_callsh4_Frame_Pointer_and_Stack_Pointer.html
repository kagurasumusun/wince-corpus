SH-4 Frame and Stack Pointers

The following list gives more information about stack and frame pointers:

  • The stack pointer and frame pointer addresses are aligned on 4-byte boundaries.
  • If a routine has alloca() locals, or dynamically allocates stack frame space for any other reason, this specification requires a separate frame pointer register is required to access incoming arguments and locals. A leaf routine may use any free integer register as the frame pointer. A non-leaf routine must use a permanent register. The routine must not modify the frame pointer register between the prolog and epilog.
  • A routine that uses alloca() references everything in the frame at a lower address than the alloca() area relative to R15. R15 never contains a defined value at the time of an alloca() call. Thus, the alloca() operation never has to copy this part of the stack frame, and no data relocation problems arise. The routine references everything in the frame at an address higher than the alloca() area relative to the frame pointer.
  • By convention, a routine that establishes a separate frame pointer should use R14. A routine may establish another frame pointer to more efficiently access data in large stack frames.
  • If a routine establishes no frame pointer, R15 must remain unchanged between the end of prolog and the beginning of the epilog.
