Device Management Operation

A typical device management operation involves the following steps:

  1. Poll the server.

    The Device Management engine sends an HTTP POST to the server containing its current hardware and software configuration, and a list of packages that it currently has. The package list is then retrieved from the device management client database. For more information about the client database, see Device Management Client Database.

    For more information about polling the server, see Poll Request to the Server.

  2. The server responds to the device Poll.

    The server determines if there were any changes since the last poll through the X-Last-Poll: header. If there are changes, the server builds a list, the ServerList, of what the client should have and what needs to be removed. This is then sent to the client as the Poll response.

    For more information, see Server Response to the Device Poll.

  3. Send a package request to the server.

    The client receives and parses the server response. If both the add and remove elements on the packages Element are empty, the operation is complete, because there are no changes from the server or because no packages apply. If the add and remove elements are non-empty, the client immediately removes all the package entries from the database that are in the remove list. If there are items in the add list, the client adds them to the client database. If there are items in the add list with Required="YES", the client adds these to a Server Request List. These are mandatory packages and are downloaded without any user interaction. Items not marked YES are optional and may be selected for a later download if provision for a UI is made. If the Server Request List is not empty, the client POSTs a package request to the server with the package identifiers of the packages it is requesting.

    For more information, see Package Request to the Server.

  4. Download instructions from the server.

    The server responds with an XML document containing one or more download instructions for the packages that the client has sent.

    For more information, see Download Instructions from the Server.

  5. Schedule download tasks.

    The client parses the download XML and schedules a separate download task for each item. The status of the item is set to downloading in the client database.

  6. Receive packages from the server.

    The client then receives the packages from the server specified in the download instruction.

  7. Send reports to the server.

    When the download task completes, the device updates the client database with the status. This can be one of two states:

    • The download failed (after the appropriate retries).
    • The download succeeded.

    If the download failed, depending on the failure scenario, the download task is scheduled again after the retry interval. If the failure is due to a network condition, then the task is restarted after the required network condition is met.

    Once the download is complete, the client sends a status report to the management server.

    For more information, see Reports to the Server.
