Reports to the Server

Reporting is an important part of the feedback loop when the device is receiving updates from servers such as SMS. There are several types of reports:

  • File system reports or software inventory
  • Installed application reports or software inventory
  • Custom OEM reports

The following steps outline how all reports are generated and posted to the server in a similar way.

  1. The server creates a set of download instructions that include the script to download.
  2. The device polls the server, downloads the script, and executes the PostInstall action.
  3. The PostInstall action executes the script engine and the script engine generates the reports and POSTs the results to the URL specified in the script.

If the server requires the report to reoccur, it must perform the following steps:

  1. Send download instructions to the device with a task specifying the script to download without a PostInstall action.
  2. Send the device download instructions with a recurring task, but without the CopyFile element and only a single PostInstall command.

The status is always returned to the server and is specified in the ServerURL registry entry. The X-Device-Action header allows the server to determine that this is a status response.

There are two different types of status responses:

  • Responses that are generated on the setup of download events.
  • Responses that are generated after the success or failure of an install.
    Note   No responses are generated on the success or failure of a download event. Responses are only generated on the setup, that is, the inclusion of such events in the Scheduler queue and on success/failure of an install of downloaded CAB files.

If the device is unable to post an immediate response to the server when the event occurs, the event should be queued on the device and sent the next time a connection is available up to a maximum of RetryLimit times. The default value is 5.

For more information about the device management registry settings, see Device Management Registry Settings.

Report XML Elements

The following table shows the report XML elements.

Element Description
status Element Topmost and only element in case of a status report.
MS-DevMgmt-Reports Element Topmost element in the report XML data. All other report elements are nested within it.
AppsReport Element Used to report the installed applications to the server.
App Element Used to report the install state of an application.
FileReport Element Used to report the contents of the device's file system to the server.
Directory Element Used to describe file system directories currently on the client system.
File Element Used to describe the files that exist on the client system.

Report Schema

The following schema is the recommended schema for a Report task scheduled to the server. This is required for the Microsoft Systems Management Server (SMS) and can be modified subject to the server requirements. For more information, see the documentation for the server requirements.

<MS-DevMgmt-Reports
   ID="Task ID for this report" >
   <AppsReport>
      <App
         Manufacturer="Producer of the application"
         Name="Name of the application"
         Ver="Version of the application"
         Lang="Language of the application"
         />
   />
   <FileReport>
      <Directory
         Name="Directory name"
         Created="Creation date"
         LastAccessed="Last access date"
         Attributes="File system attributes" >
         <File
            Name="File name"
            Version="File version"
            Company="Company name"
            Description="File description"
            Size="File size in bytes"
            Created="Creation date"
            LastModified="Last modified date"
            LastAccessed="Last access date"
            Attributes="File system attributes"
            />
         />
      <File
         Name="File name"
         Version="File version"
         Company="Company name"
         Description="File description"
         Size="File size in bytes"
         Created="Creation date"
         LastModified="Last modified date"
         LastAccessed="Last access date"
         Attributes="File system attributes"
         />
      />
   />
/>

Report Samples

The following code example is an example of what a Report message might look like.

POST /devmgmt.dll/ HTTP/1.1
X-Device-UUID: 934F9095-1DC6-49b9-918D-C36E5B2FBDB2
X-Device-Auth: 72066466-B755-4913-87E5-9844BCF3FDA3
X-Device-client-version: 1.0
X-Device-Action: Report

<MS-DevMgmt-Reports ID="ReportID" >
   . . .report xml. . .
</MS-DevMgmt-Reports>

The following code example shows a status report.

POST /devmgmt.dll?status/ HTTP/1.1
X-Device-UUID: 934F9095-1DC6-49b9-918D-C36E5B2FBDB2
X-Device-Auth: 72066466-B755-4913-87E5-9844BCF3FDA3
X-Device-client-version: 1.0
X-Device-Action: Status
<status code="100" ID="6A8D3907-705C-425e-9FEC-A443AD4FA8B6" Type="Install" Text="Install of package succeeded"/>
