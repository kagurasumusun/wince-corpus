Writing the Desktop StockPor Application

StockPor stores multiple data for each stock: the symbol, company name, last quote price, purchase date, purchase price, gain/loss, and the last time the stock information was updated. The user interface is straightforward — the Open command opens a data file, Add Stock adds a new stock, Change Stock changes information about one stock, Delete Stock deletes the selected stock.

The portfolio data is stored in a shared memory-mapped file, created by the following code in stocks.cpp.

m_hFile   = CreateFile (m_szFile, GENERIC_READ | GENERIC_WRITE,
                       FILE_SHARE_READ | FILE_SHARE_WRITE, NULL,
                       CREATE_ALWAYS, FILE_ATTRIBUTE_NORMAL, NULL);
m_hMapObj = CreateFileMapping (m_hFile, NULL, PAGE_READWRITE, 0,
                              sizeof (PORTFILE), SZ_MAP_OBJ);
m_pStocks = (PPORTFILE)MapViewOfFile (m_hMapObj, FILE_MAP_WRITE, 0, 0, 0);

The data file has a fixed size. Up to 500 stocks can be stored in a structured name STOCK.

typedef struct tagStock
{
   UINT      uidStock;        // the stock ID
   UINT      uFlags;          // see SF_* definitions
   FILETIME  ftViewTime;      // time stamp of item shown in list view
   FILETIME  ftUpdated;       // updated time of the stock
   FILETIME  ftLastModified;  // last modification time of stock
   char      szSym [10];
   char      szCompany [80];
   char      szLastPrice [20];
   char      szPurDate [20];
   char      szPurPrice [20];
   char      szGain [20];
} STOCK, *PSTOCK;

The file is structured as follows.

typedef struct tagPortFile
{
   UINT  uVer1;         // must match FILE_VERSION
   UINT  uidCurrStock;  // current stock ID

   UINT  cChg, cDel;    // change/delete logs
   UINT  rgidChg [MAX_STOCKS], rgidDel [MAX_STOCKS];

   UINT  cStocks;       // # of stocks in portfolio
   STOCK rgStocks [MAX_STOCKS];

   UINT  uVer2;         // must be equal to FILE_VERSION
} PORTFILE, *PPORTFILE;

PORTFILE::uidCurrStock is incremented each time a new stock is created and becomes the object ID of the new stock. PORTFILE::rgidChg is an array of object IDs for changed stocks.

PORTFILE::rigidDel is an array of object IDs for deleted stocks, so the ActiveSync provider knows how many objects must be synchronized. The ActiveSync provider deletes these entries once synchronization is completed.

Each stock in the application list view can be marked with the SF_IN_VIEW flag. When ActiveSync informs the application about changes, the application checks this flag to identify new stocks to be added to the list view.

The desktop application is coordinated with its ActiveSync provider in the following ways:

  • They share the same data file. File access is protected by the named mutex "StockPortMutex."
  • For each data-file change, the application puts changed object IDs in PORTFILE::rgidChg and deleted object IDs in PORTFILE::rgidDel, then signals the named event "StockPorChange." The ActiveSync provider uses a thread to check for this named event; when notified it calls IReplNotify::OnItemNotify on the object IDs. The ActiveSync provider then removes the entries from the shared memory.
  • The ActiveSync provider sends the application a WM_DATA_CHANGED message after any synchronization that changed the database.
  • When the application receives this message, it compares the data in the list view with the data on the file. It uses SF_IN_VIEW flag and STOCK::ftViewTime to indicate what stocks need to be synchronized.
