Generating and Reusing Object IDs

Each object on a Windows CE device, including files, directories, databases, and records within databases, is identified by a unique 32-bit identifier. In many cases, a device-side ActiveSync provider can use each object's ID as the CEOID (CE object ID) it returns to ActiveSync.

Reusing OIDs is the simplest and most straightforward mechanism for assigning unique synchronization IDs to device-side objects. If it is not possible to use CEOIDs to identify your objects to ActiveSync, you can devise your own mechanism for generating unique IDs. There are several important restrictions that apply to custom numbering schemes:

  • You can use only the bottom 16 bits of the CEOID DWORD for your custom IDs. This limitation must be strictly adhered to.
  • Each object's ID must be unique within the object store.
  • Object IDs must be persistent. OIDs cannot change between synchronization sessions or restarts.
  • Objects must have ordered relationships that can be determined when the service provider compares them.
