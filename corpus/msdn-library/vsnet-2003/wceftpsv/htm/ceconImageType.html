Image Type

Data is sent, using TCP/IP, as contiguous bits that are packed for transfer into 8-bit transfer bytes, and the client-side receiver stores the data as contiguous bits. The structure of the storage system might necessitate padding the file, or each record for a record-structured file, to some convenient boundary — byte, word, or block. This padding must be all zeros and can occur only at the end of the file or at the end of each record. There must also be a way of identifying padding bits so that they may be removed if the file is retrieved.

In Unix, if you transfer a binary file in ASCII mode, it replaces carriage returns with a CRLF sequence. The FTP server treats both identically as an Image type.

Image type is intended for the efficient storage and retrieval of files and the transfer of binary data. This data type should be accepted by all of your FTP implementations.
