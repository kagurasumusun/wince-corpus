Platform Building

After you have configured your platform, you can build a platform using the Platform Builder integrated development environment (IDE).

The build options available from the Build menu are context-sensitive and depend on the objects selected in the Workspace window. For example, the options available for source code files will be different than those available for features, projects, or platforms.

Before you build a platform using the IDE, you need to select an active configuration. If you copy a platform from another computer that is based on microprocessors that are not installed on the current computer, the corresponding configurations will be unavailable in the Select Active Configuration list on the Build toolbar.

Note   When you change the settings for a platform, these changes apply only to the active configuration selected in the Platform Settings dialog box. If you select a different active configuration when you build the platform, these setting changes will not be incorporated into the build.

The Platform Builder build system creates an operating system (OS) image in four stages. These stages are the Sysgen phase, the Feature Build phase, the Release Copy phase, and the Make Image phase. The build system generates header files, links modules, copies the resulting modules to a release directory, and generates a binary image file. Most of the source code files supplied with Platform Builder is precompiled into static libraries. These static libraries, as well as code supplied by you or a third-party vendor, are combined into a binary file called Nk.bin, which can be downloaded to your target device. The Build Platform command on the Build menu executes all of the build phases in sequence.

Each feature you select from the Catalog has a corresponding Sysgen variable. If a feature is included in your platform, the IDE sets the corresponding Sysgen variable during the Sysgen phase of the build process. The build system uses these variables to link the corresponding static libraries into modules. The system also filters the system header files, creating headers that only contain prototypes for the functions exported by your platform. Import libraries for the system modules are also created during this phase. The filtered headers and import libraries make up the SDK. The board support package (BSP) is built at the end of the Sysgen phase.

After the Sysgen phase, the Feature Build phase is run. During this phase, all user features including Platform Builder project (.pbp) files, dirs files, sources files, and makefiles (.mak) files are compiled and built.

During the Release Copy phase, the build system copies all the files you need to make an OS image to the Release directory. The modules and files created during the Sysgen phase are copied to this directory first, followed by the files created by the Feature Build phase.

At the beginning of the Make Image phase, the project-specific files, which include Project.bib, Project.dat, Project.db, and Project.reg, are copied to the Release directory. The information contained on the BIBInfo tab of the Platform Settings dialog box is then added for each module or file.

During the Make Image phase, the files in the Release directory are combined in the binary image file Nk.bin. The Make Image phase corresponds to the Make Image command on the Build menu. If you modify the project-specific files or the BIBInfo information, or otherwise modify the files contained in the Release directory, you will need to run the Make Image command again before the changes will be reflected in your image.

The Generate Platform Headers and Regenerate Platform Headers commands on the Build menu execute the Sysgen phase of the build process. Regenerate Platform Headers performs a clean, deleting any files built during a previous Sysgen phase, before running a new Sysgen cycle. The Build Platform and Rebuild Platform commands act in the same way.

Build Selected Feature(s) allows you to build just those features and projects highlighted in the FeatureView window. You can use the Batch Build command to build multiple build configurations. The Compile, Build project, and Rebuild All commands are available in the FileView window and are used when working with projects.

The Stop Build command on the Build menu can be used at any time during a build and will stop the build as soon as the build system reaches the end of the current executing command or the next phase. You can run the Clean command to remove any intermediate and output files.

Using the Custom Build tab on the Platform Settings dialog box, you can assign custom actions and environment variables to projects and files. Actions are available during the Feature Build and Release Copy phases. Environment variables are available during the Feature Build and Make Image phases.

The following table shows the actions available to build system.

Action Description
#BUILD(DIR, …) Builds all the source code in the subdirectories specified in the dirs file. The dirs file is located in the directory specified after the comma.
#BUILD(SOURCES, …) Executes the macro defined in the sources file located in the directory specified after the comma.
#BUILD(MAK, …) Sends compiler and linker variables defined in the makefile project at the location specified to the build system.
#CUSTOM(…,…) Executes the custom command specified.
#SRCCODE(DIR,…) Allows you to browse, from the FeatureView window, to the files in the subdirectories listed in the dirs file. The dirs file is located in the directory specified after the comma.
#SRCCODE(SOURCES,…) Allows you to browse, from the FeatureView window, to the files used by the sources file. The files are defined in the sources file in the directory specified after the comma.
#SRCCODE(MAK,…) Allows you to browse, from the FeatureView window, the files used by the makefile.

Environment variables and actions are executed on a per project basis during the Feature Build phase. This means that environment variables set in one project will not affect variables defined by another project. In all other build phases, variables are defined globally. For more information about custom build options, see Custom Build Tab.

You can also use the Environment tab on the Platform Settings dialog box to set environment variables. For information about this dialog box, see Platform Settings Dialog Box.

All feature groups must be resolved before you build your platform. If Platform Builder encounters unresolved feature groups in a platform, the Feature Resolution dialog box is displayed, and you must choose the appropriate implementation before the build process can continue.

You must rename Myplatform\%_WINCEROOT% to build a platform copied from another workstation with a different %_WINCEROOT% than your workstation.

For example, on the original workstation, %_WINCEROOT% is set to Wince410 while %_WINCEROOT% is set to MyInstall on your workstation, and you copy MyPlatform\Wince410 from the original workstation to MyInstall\Public on your workstation. In this example, you would rename the platform directory from %_WINCEROOT%\Public\MyPlatform\Wince410 to %_WINCEROOT%\Public\MyPlatform\MyInstall.
