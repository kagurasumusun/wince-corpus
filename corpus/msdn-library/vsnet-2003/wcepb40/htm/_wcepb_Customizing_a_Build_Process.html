Build Process Customization

You can specify custom build rules to use with any project or with any individual files that do not already have a rule associated with them. These rules then process the files at the appropriate point in the build, if the output file is out-of-date relative to the input file.

By default, text files containing C (.c) and C++ (.cpp) source code have tools associated with them. To specify a custom build rule for these files, you must select the Always Use Custom Build Step check box on the General tab in the Project Settings dialog box.

The custom build rules for individual files run only in builds for configurations in which you selected the files. That is, if your file set includes an .l file, and you select the .l file in only one configuration, the rules that you specify run only in that configuration.

Custom build rules run at different times, depending on the tab on which you specify the custom rules. The following tabs are used to specify the custom rules for projects or individual files:

  • Use the Custom Build tab to enter rules that will run only when any input file is out-of-date relative to its output file, or if the output file does not exist.

    When creating a custom build rule by using a custom batch file, precede the batch file with call to ensure that all custom build rules following that rule will be executed.

    When custom build rules create or incorporate files that are foreign to the current project or require a dependency relationship, choose Dependencies on the Custom Build tab, if the option is available, to identify these dependencies.

    Specify input dependencies on a per-file basis to ensure that your build steps run in the order that you need them to. For example, you may have a custom build step that creates an output file, MyOutput.h. Another file in the project, MyInput.cpp, may have a build rule that depends on MyOutput.h. You can specify MyOutput.h as an input dependency to MyInput.cpp, and the build system will first ensure that MyOutput.h exists and is up-to-date before running the custom build steps for MyInput.cpp.

    You can specify input dependencies for a file even if the build process does not recognize the extension of either the input file or the dependent file.

  • Use the Pre-link Step tab to enter rules that will run between compile and link time. No file time stamps are checked. For example, you could create directories or set file attributes before the linker runs.
  • Use the Post-build Step tab to enter rules that will run after successful completion of the normal build process, including successful completion of rules that you entered on the Custom Build tab. No file time stamps are checked.

    These rules will run after any steps that are specified on other build rule tabs. You can also use the Post-build Step tab to perform steps that do not necessarily run on specific files, for example, to copy an output file to a drop point, to generate an e-mail message reporting that the build has finished, or to run a process that does not create an output file.

You can select the directories in which to put the intermediate and final output files for each project configuration. By putting these files in different directories you prevent the build results from overriding each other.
