Probe and Emulator Communication

The driver is responsible for providing API elements to establish and maintain the communication between the driver and the hardware debug equipment. By default, when the driver loses a connection with the hardware, it should attempt to reconnect, automatically and transparently, as soon as possible, and maintain the connection as long as possible. If the driver cannot do this, perhaps because it requires some form of user interaction, the driver could expose a connection COM interface, and a Platform Builder plug-in could provide the user with a dialog to set up the communication.

The main reason that API elements for target/probe configuration are not specified is that there are many possible variations, and specifying would not fit in all cases, would be limited, or would be biased towards a specific solution.
