File Checkin

When you check a file in, the source code control system changes the status of the file to read-only and it records that you have checked in the file. It also records the differences between the contents of the file when you checked it out and when you checked it in.

You generally want to view the changes to the file before you check it in to confirm the changes that you made. In some cases, you may want to discard all changes to your file before checking it in. In other cases, you may need to merge changes that other developers have made to the file after you checked it out. If you had the file checked out exclusively, after you check it in, others can check out the file.

If your source code control system does not support exclusive use, it could happen that while you had the file checked out, another developer also may have checked out the file, made changes, and then checked in the file. In this case, before you check in your local copy of the file, you need to find out if there were changes made by other developers. If so, you need to merge those changes into your local copy. Then, you can verify that all of the changes are compatible and that none cause problems when you use the file. After you have verified the changes, you can check in the file.

If you make changes to a local file, and then decide that you do not want to keep the changes, you can have the source code control system check in the file, but ignore any changes that you made to it.
