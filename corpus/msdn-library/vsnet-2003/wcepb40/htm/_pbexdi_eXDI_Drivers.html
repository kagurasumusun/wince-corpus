eXDI Drivers

An eXDI driver facilitates communications between the IDE and a probe or emulator. At a minimum, an eXDI driver exposes the IeXdiServer and IeXdiCPUContext interfaces, where CPU is the target microprocessor. For example, an eXDI driver that targets a platform based on an x86 microprocessor exposes the IeXdiServer and IeXdiX86Context interfaces. An eXDI driver may expose additional interfaces to implement additional functionality such as target configuration or execution tracing.

An eXDI driver must register its class identifier (CLSID) with the Component Object Model (COM). The IDE handles the registration for the marshaling proxy stub at setup time. The driver must also register with the IDE by adding registry keys. The driver can add necessary keys automatically during the installation process.

The IDE reads registry keys to enable hardware debugging. To add your driver to the registry, create a HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\eXdi\DriverList registry key, if the registry key does not exist. Under the HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\eXdi\DriverList registry key, add a registry entry that is equal to the CLSID of the driver in REG_SZ format. You can specify a friendly name for the driver as the value for the registry entry.

After adding the required information to the registry, your driver appears in the IDE in the Configure Remote Connection dialog box. The name for the driver that appears in the dialog box is the friendly name that you specified in the registry. For more information about the Configure Remote Connection dialog box, see Configuring eXDI Hardware-Assisted Debugging.
