OS Image Types

Before you debug a platform, you must build an OS image that can be debugged after it is downloaded to a target. When you create a project, the IDE automatically creates both a debug configuration and a release configuration, with default options set for each. Depending on which configuration you choose, you can build either a debug OS image or a release OS image. In addition, you can build a debugger OS image that uses the kernel debugger.

The following table shows the types of OS images.

OS image type Description
Debugger-enabled
  • Contains a debug version of the kernel that includes KdStub
  • Required for using the kernel debugger
  • Includes all characteristics of a debug image
Debug
  • Uses .lib files from the %_WINCEROOT%\Public\Common\Oak\Lib\<microprocessor>\Debug directory
  • Places object files in a Debug directory
  • Provides full symbolic debugging information, in Microsoft format
  • Provides Ethernet debug functions
  • Provides ability to turn debug zones on and off
  • No optimization. Optimization generally makes debugging more difficult.
Release
  • Uses .lib files from the %_WINCEROOT%\Public\Common\Oak\Lib\<microprocessor>\Retail directory
  • Places object files in a Release directory
  • Provides no symbolic debugging information
  • Optimized for maximum speed
  • Has a smaller image size than either a debug or a debugger image
Retail Same as release.

The following table shows environment variables that control the type of OS image to be built.

Variable Value Description
IMGNODEBUGGER Undefined This setting instructs the Make Binary Image tool (Makeimg.exe) to include the Kd.dll kernel debugger library in the Nk.bin binary OS image file.
  1 This setting instructs Makeimg.exe to exclude Kd.dll from the Nk.bin OS image file.
WINCEDEBUG Debug This setting instructs the IDE to disable any compiler optimization, to generate debugging information in object files, and to place object files in a Debug directory.
  Retail This setting instructs the IDE to allow compiler optimization, which is incompatible with the debugger, and to not generate debugging information in object files. The IDE places object files in a Release directory.
