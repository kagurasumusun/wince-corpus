Platform Modification

Use FeatureView and the Catalog together to view and modify your platform. FeatureView shows all of the features currently in your platform.

The Catalog displays features you can add to your Windows CE–based platform, including BSPs, core OS features, transport layers, and device drivers. You can import additional features into the Catalog using Catalog feature files (.cec).

Once a platform has been created, the features displayed in the Catalog are filtered based on the configuration and variant selected during the creation of the platform with the New Platform Wizard. This allows you to work with the set of features that is most likely to meet your platform requirements. The Variant list, which appears at the top of the Catalog, displays the variants associated with the selected configuration. You are also given the option of selecting ALL, which displays all of the features in the Catalog.

Both the Catalog and FeatureView also contain folders that are containers for related groups of features.

To move items from the Catalog to FeatureView, right-click the feature and choose Add to Platform, use the Platform/Insert menu and choose the Selected Catalog Feature item, or simply drag the item from the Catalog and drop it onto FeatureView.

For information about icons used in the Catalog and FeatureView windows, see Object Icon Types.

A feature group describes the interface and functionality that is exposed by sets of features. It does not contain the functionality necessary to implement the feature. An implementation contains the functionality required to implement a feature.

There can be more than one implementation for a specified feature group. For example, Display is a display driver feature group. If you add Display to your project, you are adding a placeholder for a display driver without specifying which display driver. There are several standard display driver implementations, including ddi_ati, ddi_flat, ddi_rflat, and Mq200. Each of the standard drivers contains the functionality to implement a unique kind of display driver.

When you initially add a feature group from the Catalog to your platform, it appears as a feature group in your FeatureView window. Before you can build your platform you must convert all feature groups into features. The process of converting a feature group into a feature is called resolving. To resolve the feature, you must select an implementation to replace the feature group. This is done by selecting Resolve Feature(s), which can be accessed by right-clicking the feature group or from the Platform menu. Once resolution is complete, the item is shown as a feature. If you attempt to build a platform with unresolved features, the Feature Resolution dialog box appears. For more information about the Feature Resolution dialog box, see Resolving a Feature.

If you add an implementation directly to your platform, it automatically resolves to a feature.

Anchored features are features that are included in a platform through the platform creation process or that you have manually inserted. The CESysgen.bat file contains dependency rules. The IDE tools compare the features in your platform against these dependency rules and automatically include any additional features that are required to support the anchored features. These features, which are brought in automatically by the tools, are considered unanchored features.

Each time you add or remove a feature from your platform, or perform any other action that would require a Sysgen of the platform, the tools compare the features in your platform against the CESysgen.bat file and redisplay the list of features in the FeatureView window. The Build tab of the Output window also displays a list of all the unanchored features that were added. The system starts with no unanchored features each time this process is run and adds in all the required features. For more information about the build process, see Platform Building.

The last stage of this dependency analysis compares the list of core OS modules in your platform with the list of BSP variables set by the batch file for the BSP you are using to determine which drivers are supported by your current OS configuration and by your BSP. The tool then automatically inserts the drivers necessary to meet the requirements of your system. These drivers are imported as anchored features into your platform.

Each driver feature group contains a default driver, which is set by variables in the BSP batch file and by the DefaultDriver element in the Catalog feature file for each BSP. To override the defaults, simply add the specific driver you want to your platform.

You can only delete anchored features from your platform. Unanchored features can only be removed if the feature that pulled them in is removed from your platform. If you want to anchor an unanchored feature, ensuring that it is not removed from the platform if its parent feature is removed, you can choose Anchor Feature(s) from the shortcut menu. You can also reverse this process, by choosing Remove Anchor from Feature when an anchored feature is selected.

The dependency functionality will not be included in the features you create unless you add it to the batch file manually.

You can examine the list of special feature notifications for your platform by selecting Review Special Notifications from the Platform menu. A window appears that lists the special notification summaries associated with the features included in your platform. You can select each Notification Acknowledged check box in the list to acknowledge the associated notification.
