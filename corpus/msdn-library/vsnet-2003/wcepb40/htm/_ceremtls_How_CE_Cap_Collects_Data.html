How Remote Call Profiler Collects Data

Remote Call Profiler profiling levels allow you to control data collection for specific scenarios, threads, and processes.

The Remote Call Profiler logger starts when you start a process containing a statically linked instrumented module, or when you load a dynamically linked instrumented module in a noninstrumented application. You can also start the logger manually. Logging continues until all instrumented modules stop running.

The Remote Call Profiler logger collects data for threads in a profiling run. It determines if a thread is to be profiled by checking the state of the Global Profiling Level, Process Profiling Level, and Thread Profiling Level associated with the thread.

When a thread enters a function, the logger checks the global, process, and thread profiling levels for that thread. The state of all three levels must be ON to profile the thread. Otherwise, Remote Call Profiler does not profile the thread.
