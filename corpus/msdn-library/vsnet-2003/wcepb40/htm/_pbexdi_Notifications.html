eXDI Notifications

eXDI should provide notifications so that all willing clients can stay in sync with the target state and with actions requested by other clients. There are two kinds of notifications a client can do: memory changes and run state changes. There is no need to notify clients of memory changes due to target code execution. Memory change notification should only occur if the target is halted and the memory is changed by one of the eXDI clients.

Run state changes imply automatic memory change of the entire memory and all microprocessor registers.

Your driver should notify an eXDI client, such as Platform Builder, of its own memory and run changes. The driver cannot ignore run change or memory change notifications, as it does not know the origin of a request.
