Module Information Access

The IDE automatically obtains module information for the first module from the .bin file that is downloaded to the target device. The first module is typically the Nk.exe module. From the IDE you can also load information for other modules by using the Refresh Module window. When you load information for other modules, Microsoft Platform Builder version 4.0 and later sends a request to list modules to OsAxS.dll through the eXDI driver. For more information about OsAxS.dll, see OsAxS.

In the registry, you can override this behavior by entering subkeys and values under the HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Platform Builder\3.00\Hardware Debug\BinImage registry key. You must use the 3.00 subkey, and not a subkey corresponding to the current version of Platform Builder.

For each additional module to be loaded, you must specify a subkey that corresponds to the module. For example, for the Coredll.dll module you must specify a Coredll.dll subkey that contains the following two values:

  • LoadOffset (REG_DWORD): the address at which the module is loaded in virtual memory space
  • UseRegKey (REG_DWORD): the individual module-enable flag
    Note   You can specify the ForceUseAllSubRegKey flag to bypass individual flags.

As an alternative, you can automatically populate these registry keys by gathering module information from the OsAxSReadControl function from OsAxS.dll. The OsAxSReadControl function supports the same API as the API for KDStub for HANDLE_RELOAD_MODULES_REQUEST and HANDLE_RELOAD_MODULES_INFO.
