Breakpoint Viewing and Enabling

When you set a breakpoint on a line of code, a breakpoint symbol, or glyph, appears in the margin to the left of the code. The glyph varies according to the type of breakpoint that has been enabled. There are four different types of breakpoints: disabled or enabled breakpoints, and resolved or deferred breakpoints.

Once a breakpoint is set, the user can disable it at any time; the breakpoint remains, but the program will not break there while the breakpoint is disabled. Enabling the breakpoint makes it an active breakpoint again.

Beginning with Windows CE .NET, the kernel debugger recognizes a further level of distinction for breakpoints. When the user sets a breakpoint in design mode, or in a source file that is not recognized by the debugger as having been loaded on the device, this breakpoint will be identified as deferred. This means that the breakpoint does not actually exist on the device, and no stop will occur at the requested breakpoint location. In addition, if a user tries to set a breakpoint in code that is in the ROM space of the device, the deferred breakpoint glyph will also be shown in the editor window. A resolved breakpoint is in code that the debugger recognizes to be loaded on the device.

Once the device is booted, or the debugger is connected, the debugger will start loading the appropriate modules (for example, DLLs and EXEs). When a module that was built using the source file with the breakpoint is loaded the debugger will attempt to bind the breakpoint on the device. If this binding is successful, the breakpoint will appear as bound in the editor window and the device will halt execution when it reaches the source location. The breakpoint has become resolved.

The breakpoint glyph will be different, depending on its status:

  • An enabled breakpoint is a solid circle colored red.
  • The disabled breakpoint is a hollow circle. The circle edge is the same color as the circle edge of the deferred breakpoint. The circle fill color will be the color selected by the user in the Text background selection of the dialog box located in Tools->Options-> Format Tab -> Source Windows ->Breakpoint background color selection.
  • The deferred breakpoint (described previously) is a hollow circle. The circle edge will be the color selected by the user in the dialog box mentioned previously. The circle fill color will be the breakpoint foreground color as selected in the same dialog.
  • The resolved breakpoint is a solid circle the color of the circle edge.

If you set more than one breakpoint on a line, and some breakpoints are disabled while others are enabled, a gray dot appears in the left margin in the source window, Disassembly window, or Call Stack window. The gray dot does not appear in the Breakpoints dialog box. The first time you choose Disable Breakpoint on the shortcut menu, all breakpoints on the line are disabled, and the gray dot changes to a hollow circle. If you choose Enable Breakpoint on the shortcut menu, all breakpoints on the line are enabled, and the hollow circle changes to a red dot.

An asterisk (*) in the check box next to the breakpoint indicates that the breakpoint is not supported on the current platform.

Note   The maximum number of breakpoints that can be set in the IDE is 256. The debugger will notify the user through a message box if the limit of 256 breakpoints has been exceeded.
