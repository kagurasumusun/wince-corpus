File Checkin and Checkout

When you begin work on a project, typically you open the project in the workspace and get the current versions of the project files to make sure that you are looking at the most up-to-date sources. Before you begin to modify the source files, you check them out; after you have completed the modifications, you check in the files.

When you have a file checked in, your local copy of the file is read-only, and you cannot save any changes to it. When you check out a file, you can make changes to your local copy of the file, and then save those changes to the file. When you check in the file, you copy those changes to the master copy of the file in the source code control system. This makes those changes available to other members of your group. Whether multiple developers can check out a file simultaneously depends on the characteristics of your source code control system.

In addition to selecting files directly from the FileView tab, you can also check them in and out by selecting from the other tabs. For example, if you select a class to check out on the ClassView tab, Platform Builder prompts you to check out the files that are associated with that class.
