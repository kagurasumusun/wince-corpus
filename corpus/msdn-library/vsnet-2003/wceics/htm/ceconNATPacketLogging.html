Firewall Packet Logging

The Windows CE .NET internet connection firewall (also known as the packet filter) can signal dropped packets, as well as the creation and deletion of connections.

OEMs and ISVs can implement code that can receive these notifications and generate reports or notifications to the user. The following table shows the appropriate APIs to use.

Function Description
LogDroppedPacket Used by client DLLs that monitor dropped packets.
LogConnectionCreation Used by client DLLs that monitor connection creation.
LogConnectionDeletion Used by client DLLs that monitor connection deletion.
LogInit Called once to initialize client logging.

To receive the notification, a DLL must be created that implements these APIs, and be registered as a FirewallLoggerDLL.

NAT packet logging works by reading the registry value HKLM\Comm\IPNat\FirewallLoggerDLL (string containing the DLL to load).

Note   This DLL is optional, as are each of the logging functions. This means that if you do not want to log packet drop or connection creation and deletion events, do not provide this registry value and do not implement the related functions.

It is also important to understand that this logging DLL is on the critical path for Netword Address Translation (NAT). Any code implemented in these functions will directly affect the performance of the Window CE network address translator. As a result, Microsoft recommends that you minimize this code.
