Implementing the System Tick

The system tick is the only interrupt required by the kernel and you must hook the interrupt with HookInterrupt and then provide a system tick ISR to handle the tick.

When threads are active in the system the thread timer goes off every millisecond. The thread timer ISR updates CurMSec every millisecond so blocking operations and GetTickCount calls are as accurate as possible. The timer ISR only returns SYSINTR_RESCHED to the kernel's interrupt dispatcher if a thread scheduling event is ready to occur, if dwReschedTime is less than or equal to CurMSec. If no scheduling event is ready, the ISR returns SYSINTR_NOP. SYSINTR_NOP indicates that running threads will be interrupted by the timer ISR but will not have to wait for the kernel to run its scheduling algorithm before they resume execution.

The thread timer ISR does not schedule an IST. It tells the kernel when it is time to run a thread scheduling algorithm and when to update CurMSec.

You must implement the thread scheduling timer as part of the OAL.

Note   ARM processors only have one interrupt so they do not call HookInterrupt.

Testing Tick Support

To test that the system tick has been initialized and functional, you can write to an LED when a system tick occurs.
