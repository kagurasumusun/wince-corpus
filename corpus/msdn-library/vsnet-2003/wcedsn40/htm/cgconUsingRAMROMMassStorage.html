Using RAM, ROM, and Mass Storage

The following table shows how the various memory types are used.

Memory type Description How used
RAM RAM is divided into two areas as shown in the following list:
  • The object store, which resembles a permanent, virtual RAM disk. Data is retained when the system is suspended, and devices typically have a backup power supply for the RAM to preserve data if the main power supply is interrupted. When operation is resumed, the system looks for a previously created object store in RAM.
  • Program memory, which works like the RAM in personal computers. Program memory stores the heaps and stacks for the applications that are running.
 The program is paged to RAM and then executed.
ROM ROM stores the entire operating system and applications that come with it. If uncompressed, the program is executed in-place.

If compressed, the program is decompressed, paged to RAM, and then executed.

Flash Flash is typically used for data storage and can be used for program storage. The data is paged to RAM and then executed.

Programs stored in Flash are handled in the same manner as programs stored in ROM.

Executing programs directly from ROM saves program RAM and reduces the time required to start an application. This is because the program does not have to be copied into RAM before it is launched.

It is important to consider the speed of the flash and RAM when optimizing your system. The following table shows how a program that is stored in flash memory can be executed.

Program execution in flash Description
A program stored in flash memory is copied to RAM and then executed. You do this by selecting the Compressed attribute or moving a dynamic-link library (DLL) or executable file to the MODULES section.

Although this introduces a small load-time overhead, with the faster access times of RAM, it still results in notably faster execution speeds.
A program is executed in-place (XIP) from flash memory. Flash XIP reduces the amount of system RAM used, but it sacrifices performance in doing so.

For example, you might have a SoftModem driver in your system where speed is of utmost importance. If that DLL is stored in the MODULES section, as is standard, the code segment will be executed in-place from flash memory. However, if you mark this DLL as compressed, it will be copied to RAM at load time and executed from there. The tradeoff is higher RAM consumption, but a slightly better flash footprint because the DLL was stored compressed. Also, because this is a driver, it is pinned in RAM rather than being paged in and out.

You can use a similar approach for executables. For example, on a network appliance where the primary user activity is browsing, you can mark the browser and its associated components as compressed, resulting in measurably faster execution.

Because the majority of components in a CE device are in Microsoft-supplied binary image builder (.bib) files, it is not recommended that you modify these attributes directly in the source .bib file. Instead, use the Preromimage.bat capability, which is called by Makeimg.exe, to launch a script immediately before RomImage.exe is invoked. This script can modify the file attributes within the generated Ce.bib file. In this manner, you can easily create different scripts that optimize the .bib file differently for different usage scenarios.

Boot Loaders

When using flash memory, you should add a separate boot ROM to your retail device. By doing this, if the flash memory is corrupted, the device can still boot to perform a simple recovery or remote update.

For x86 processors, replace the BIOS with Romboot or some other boot loader program that sets up the peripherals and then loads the OS image. DOS is not required to run Windows CE.

Mass Storage

Enable the FAT-based cache to allocate an appropriate amount of cache RAM for the size of your storage device: the larger the mass storage device, the larger the cache should be. Use the following table to determine the appropriate size of cache to allocate.

Registry entry Number of sectors Cache (KB)
2 2 1
4 4 2
8 8 4
10 16 8
20 16 32
40 64 32
80  128 64
100 256 128
200 512 256
400 1024 512
800 2048 1024
1000 4096 2048

The settings are stored in the following registry key.

[HKEY_LOCAL_MACHINE\System\CurrentControlSet\Control\FATFS]
    "CacheSize" = dword:400

CacheSize is a hexadecimal number of sectors to be cached. This needs to be a power of 2.
