Residential Gateway Implementation

By default your gateway image includes the correct components, but some are disabled in the registry settings for security reasons. To finish configuring your Internet gateway device, you should change the settings in Project.reg as described in the following procedure.

To implement a residential gateway configuration

  1. Change the following Project.reg settings for the registry key HKEY_LOCAL_MACHINE\Comm\ConnectionSharing: 
    [HKEY_LOCAL_MACHINE\Comm\ConnectionSharing]
    "EnablePacketFiltering"=dword:1 ; enable the Firewall/Packet filter on the public network
    "EnableAddressTranslation"=dword:1 ; enable NAT 
    "EnableDhcpAllocator"=dword:1 ; enable DHCP allocator on private network
    "EnableDnsProxy"=dword:1 ; handle DNS requests from private network
    "PrivateInterface"="NE20001" ; name of interface to use as the private network
    "PublicInterface"="VMINI1" ; name of interface to use as the public network

    Determine the names of the interfaces on your device. Type s ipconfig /d /all in the Target Control Window. One of the network adapters can be VMINI, which allows that adapter to be shared between the device and the debugger. During development this is useful because it not only allows you to use two-only adapters for your gateway and debugging; it also makes it easier to determine which to use as the private and public interfaces, since the debug interface would normally be on the "public" side of the device.

  2. Optional. If you are using ISA cards, you may need to configure the network cards in Platform.reg to make sure you have the correct IRQ/IO information. (PCI and PCMCIA are automatically configured via Plug and Play (PnP.)
  3. Determine the address of the device using one of the following methods.
    1. Review the debug log, which will display the address used. This will likely be an AutoIP assigned address in the 169.254.x.y range, unless you manually assign a default in your image See the Setting the Default Page procedure in the topic for more information about changing the default Web page.

      - or -

    2. Connect a device or PC to the network on the private side of the device and renew the IP address of the device via DHCP. On most Microsoft operating systems, this can be done from the command line using ipconfig. You can then look at the default gateway setting received by the device, which this will be listed in the ipconfig output. This address will be the address of the IGD.
  4. Verify the card configuration at http://[device IP address]/networkadmin/network.

Setting a Static IP Address for the Device

Most devices deployed into an unmanaged network are preconfigured with an internal network address to a known, private address such as 192.168.1.1. The following code example shows how to add a private address to the Project.reg file with Platform Builder.

[HKEY_LOCAL_MACHINE\Comm\NE20001\Parms\Tcpip]
    "IPAddress"="192.168.1.1"
    "SubnetMask"="255.255.0.0"
    "EnableDHCP"=dword:0

Setting the Default Page

Microsoft includes a sample administration utility (NATADMIN.DLL) that can be accessed on the devices Web server from the private network.

Once the Web server is enabled and you have your image loaded, you can browse to http://[device IP address]/networkadmin to review and/or change the settings. Additionally, this location can be changed to be the default page for the device in the Project.reg file.

You can make the networkadmin page be the default page for the gateway device by adding the following in Project.reg or changing it in Servers.reg.

[HKEY_LOCAL_MACHINE\COMM\HTTPD\VROOTS\/]
    @=\\windows\atadmin.dll
    "a"=dword:0

If you change the default page, you will get to it by browsing directly to http://[gatewaydeviceIP], which you can access from the debug window in Microsoft Platform Builder, or you can set in your image to be a default. Microsoft recommends a default in the reserved address range such as 192.168.1.1 if you change it. By default the gateway comes up in AutoIP mode and assigns itself an address in the 169.254.x.y range.

You may also want to set a default initial password on the devices administration site. The user can change this later by way of the Web site. See the documentation on the Windows CE Web Server for more information about how to configure this.

Other Considerations

If you have a proxy server on the public side of the gateway, this is set on the client device. Note also that this may prevent your client from locating the gateway to browse to for settings. To locate the gateway, either turn off the proxy settings while browsing to the gateway or change your client configuration to "bypass the proxy" for addresses in the appropriate range. This will not likely be a problem on a typical customer site; this may be a problem in your organization while you are developing and testing a device.

Recommendations

Microsoft recommends the following.

  1. Customize the settings page to be appropriate for your device and target customer. This will not only give you the ability to brand the user interface for the device, but also will allow you to add or remove settings as appropriate.
  2. Change the default name of the device by modifying the following lines in Project.reg. 
    [HKEY_LOCAL_MACHINE\Ident]
    "Name"="WinCE"
    "Desc"="WinCE Device"

    For example, change them to: 

    "Name"="MyGateway"
"Desc"=" Internet Gateway Device"
  3. The Internet Gateway Device (IGD) can include Universal Plug and Play (UPnP), along with the IGD schema, depending on the options you chose in the initial wizard. This schema is a sample implementation included only to show how to implement the schema. As a result it may require further customization to expose the full capability of your device. UPnP allows certain clients, including Windows XP, DirectX, Messenger, and others to automatically locate and properly negotiate through the gateway device. This not only simplifies the user experience, but also makes having a gateway more seamless to the user, because the OS and its applications can directly locate and use the gateway.

    To configure your device to use the UPnP schema if you did not choose that option:

    1. Drag the Sample UPnP (Internet Gateway Device) schema implementation into your project from the catalog. This feature is located in the catalog under Communications and Networking Services, Networking Features, Internet Connection Sharing (ICS), Sample UPnP IGD Schema Implementation.
    2. Disable UPnP on the public interface for security reasons. 
      [HKEY_LOCAL_MACHINE\COMM\UPnP\Exclude]
"PublicInterface"=dword:1

    Where PublicInterface is the name of the public interface of the gateway. This should be the same as the value of HKEY_LOCAL_MACHINE\Comm\ConnectionSharing:PublicInterface for IPNAT settings. More information is available on these settings in the UPnP documentation on the USB Implementers Forum, Inc. Web site.

  4. Review very carefully the various components and settings chosen for your device. You may want to include other components to aid in development, such as telnet. You may also decide to remove unneeded support to reduce the size of the footprint. One example would be to remove dialup support if you do not plan on using a modem with your device.
  5. Make sure your device is as secure as possible. This can only be done by fully understanding the components and settings used in your device.
