Filesys.exe Boot Process

After the kernel starts the Filesys.exe process, Filesys.exe must initialize its state before triggering the kernel to finish its initialization. The reason the kernel must now wait is because of its dependency on the registry that is initialized by Filesys.exe.

The following process shows the actions that occur during the Filesys.exe boot process:

  1. Detect if this is a cold or warm boot.

    On a cold boot, all the object store memory is initialized and then mapped for Filesys.exe. Call pNotifyForceCleanboot to let the OEM know that this is a cold boot.

    On a warm boot, memory is not initialized before being mapped for Filesys.exe.

  2. On a cold boot call OEMIoControl with IOCTL_HAL_INIT_RTC.
  3. Initialize the database subsystem and APIs.
  4. Initialize the file system APIs.
  5. Initialize the point-to-point message queue application programming interfaces (APIs).
  6. Read in the Initobj.date file to create a RAM file system if the RAM files system is part of the OS image.
  7. Initialize the registry.
  8. If Device.exe is not started, load the storage manager if HKEY_LOCAL_MACHINE\System\StorageManager points to a loadable DLL.
  9. If storage manager is loaded, create a thread to initialize it. The thread will exit when done.
  10. Initialize the national language support (NLS) data.
  11. Set the locale to use with the database engine by calling CeChangeDatabaseLCID.
  12. Populate the object store databases by loading data from Initdb.ini.
  13. Open event SYSTEM/FSReady and set the event.

    This indicates to the kernel and other applications that Filesys.exe is ready.

  14. Filesys.exe now waits for the kernel to signal that it can boot the rest of the system.
  15. Create named events for all event names in the registry at location HKEY_LOCAL_MACHINE\System\Events. These events will be set by the process that owns them.
  16. Filesys.exe reads from HKEY_LOCAL_MACHINE\Init and launches the applications listed.
  17. If Device.exe is in the list and it has already started, open event SYSTEM/BOOTPHASE2 and signal it. This allows Device.exe to reread the registry and perform the final driver initialization. Any driver can also wait on the same event to be notified when the real registry comes online. This allows the driver to reread registry data if needed.
  18. Initialize the time zone and set daylight savings time (DST) if necessary.
