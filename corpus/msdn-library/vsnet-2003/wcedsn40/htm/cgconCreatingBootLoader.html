Creating a Boot Loader

The boot loader is an integral part of the Microsoft® Windows® CE operating system (OS) development process and, in some cases, part of the final product solution. Its tasks are wide and varied, but in general, the purpose of the boot loader is to place the OS image into memory and to jump to the OS startup routine. The boot loader can obtain the OS image in a number of different ways, including loading it over a cabled connection, such as Ethernet, universal serial bus (USB), or serial. The boot loader also loads the OS from a local storage device, such as Compact Flash, hard disk, or DiskOnChip. It may store the image in RAM or in nonvolatile storage, such as flash, electrically erasable programmable read only memory (EEPROM), or storage device, for later use.

The boot loader is typically used during the development process to save time. Rather than transferring the development image to the target device through a manual process, such as a flash programmer or the IEEE 1149.1 standard for the test access port and boundary scan (JTAG), the boot loader allows the developer to quickly download a new development image to the target device. In many final product solutions, the boot loader is removed from the product and the OS image is stored on the device and bootstrapped by the system reset process. However, platforms that do not efficiently support this ability, such as x86 platforms, or platforms that need to perform pre-boot tasks, such as OS image updates, may choose to include the boot loader in the final product.

Each boot loader differs in the tasks it carries out and the way it performs them, but this documentation will attempt to describe some of the common behaviors among boot loaders. Information about the libraries and functions provided by Microsoft that are used for developing a boot loader is also available. The most common form of boot loader is one that downloads the OS image over Ethernet into a target device RAM and much of the documentation will focus on this solution; however, the basic infrastructure remains the same for all boot loaders.
