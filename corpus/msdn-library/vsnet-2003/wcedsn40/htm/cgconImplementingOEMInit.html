Implementing OEMInit

The kernel calls OEMInit to set up the hardware. Your OEMInit should perform any necessary initialization operations on hardware, such as initializing the system controller or PCI interface. You should also initialize Ethernet, parallel, or another debug transport.

The kernel calls your implementation of OEMInit to set up the hardware for the target device. OEMInit can register ISRs by calling HookInterrupt to associate an ISR with an interrupt request line (IRQ) value. OEMInit must register the interrupt for the system tick. This is the base functionality that is required by the kernel to schedule threads.

The OEM can initialize both optional function pointers and optional variables to enhance the following system capabilities:

  • Logging functions
  • KITL debugging
  • Registry functions
  • Secure loader functions
  • Save and restore coprocessor registers
  • High performance counters
  • System halt
  • Event tracking
  • Detection of idle time
  • Stack scavenging
  • User notification alarm
  • Multiple execute in place (XIP) regions
  • Default thread quantum
  • Enable debug IO control
  • Erasing the object store
  • Supporting CPU utilization functionality
  • Object store cold boot
  • ARM FPU support
  • Zeroing memory
