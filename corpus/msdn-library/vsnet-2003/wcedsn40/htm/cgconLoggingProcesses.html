Implementing Process Logging

Process logging is a technique that monitors the threads and processes running on a target device. You can use process logging while debugging your OS to determine which parts of the OS run the most often.

To implement process logging for your OS

  1. Implement the logging functions in the OAL. The following table shows the logging functions that can be implemented in the OAL to support the logging feature. These functions are called by the kernel in response to the events that they are expected to catch. Note that the actual function name can be of your own choosing but must contain the same parameters. In step 2, you assign a callback pointer to the function implementation.
    Function Description
    LogProcessCreate Logs information when a process is created.
    LogProcessDelete Logs information when a process is terminated.
    LogThreadCreate Logs information when a thread is created.
    LogThreadDelete Logs information when a thread is terminated.
    LogThreadSwitch Logs information when a thread is scheduled to run.

    To assist in the implementation process, Windows CE includes scheduling log functions that provide the names and addresses of processes and threads in your OS. You can use these functions to implement the logging functions. The following table shows the scheduling log functions.

    Function Description
    SchedLogGetProcessName Retrieves the name of a process.
    SchedLogGetThreadProgramCounter Returns the application counter, module, and function names of a thread.
  2. Implement the OEMInit function so that each global variable shown in the following table points to its associated function
    Variable Description
    pLogThreadCreate Points to LogThreadCreate.
    pLogThreadDelete Points to LogThreadDelete.
    pLogProcessCreate Points to LogProcessCreate.
    pLogProcessDelete Points to LogProcessDelete.
    pLogThreadSwitch Points to LogThreadSwitch.
  3. Set the SCHEDLOG environment variable and then build the platform.

    This will include the SchedLog.lib library in your OS image.

OEMInit must be set up to point to the global variables to your logging functions. After starting, SchedLog.lib uses the pointers to the logging functions to perform the logging tasks.
