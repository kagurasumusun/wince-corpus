LoadIntChainHandler

This function is called by a driver to install an ISR to handle a particular interrupt.

HANDLE  LoadIntChainHandler(
LPCWSTR lpFilename,
LPCWSTR lpszFunctionName,
BYTE bIRQ
);

Parameters

lpFilename
Pointer to a null-terminated string that names the DLL executable module. If the string specifies a path but the file does not exist in the specified directory, the function fails. When specifying a path, be sure to use backslashes (\), not forward slashes (/). If the string does not specify a path, the function uses a standard search strategy to find the file. For more information, see LoadLibrary.
lpszFunctionName
Name of the interrupt handler entry point. The entry point is defined as follows. 
DWORD ISRHandler(DWORD InstanceIndex);
bIRQ
IRQ value that is used to identify what interrupt the installed ISR will service.

Return Values

If the function succeeds, then a valid HMODULE handle to the installed handler is returned; otherwise, INVALID_HANDLEVALUE is returned.

Code Example

This code sample shows linker settings for a debug version.

/nologo /entry:"MyEntry" /base:"0x10000000" /dll /pdb:"WMIPSDbg/eh2.pdb"
/debug /machine:MIPS /nodefaultlib:"$(CENoDefaultLib)" /nodefaultlib
/out:"WMIPSDbg/eh2.dll" /implib:"WMIPSDbg/eh2.lib"
/subsystem:$(CESubsystem) /STACK:65536,4096

Remarks

The ISR handler is contained in a DLL where the DLL is treated in a special way and is loaded into the kernel process space. The DLL can contain more then one ISR handler and so the DLL can be used in several calls to LoadIntChainHandler. All ISR handlers will have a full stack, based on the CPU and be able to use C code to perform the work. The DLL cannot link implicitly to any other DLL and all code must be contained in the DLL. The DLL must be compiled in a way to eliminate C run time from being included by default.

Note   When building a kernel driver for R4111 or Thumb, the environment variable NOMIPS16CODE must be set to one.
