OEMRequestSysIntr

This function is used in the OEMIoControl routine to implement IOCTL_HAL_TRANSLATE_IRQ and IOCTL_HAL_REQUEST_SYSINTR.

DWORD OEMRequestSysIntr(
DWORD Irq
);

Parameters

Irq
[in] An IRQ within the allowed IRQ range.

Return Values

The return value depends on the condition associated with the IRQ passed to this function. The return values are shown in the following table.

IRQ condition Return Value
IRQ not already mapped Next available new SYSINTR mapping is created, and that SYSINTR is returned.
IRQ already mapped and not shareable Returns the SYSINTR that is mapped.
IRQ is already mapped and is shareable New SYSINTR mapping is created; the next available SYSINTR is used.

Remarks

The OEMInit routine is expected to make an initial pass of mapping the IRQ and SYSINTR tables for built-in devices static mapping whose drivers simply read their SYSINTR values out of the registry. The OAL must also be responsible for determining which interrupts are shareable, which is typically each of the four PCI interrupts, and which are interrupts are not shareable.

A device driver should never request a new SYSINTR more than once. In particular, a PCI device should read its SYSINTR from the registry because the PCI bus driver has already requested it. In general, a device driver should never request a SYSINTR.

Most legacy drivers will request a new SYSINTR that will be different than the one the PCI bus has requested. This will still work, provided installable ISRs are used, but a SYSINTR will have been wasted.

Be sure that the Ethernet debugging adapter Init routine calls OEMRequestSysIntr. See OEMEthInit in %_WINCEROOT%\Platform\ArmIntegrator\Kernel\HAL\Halether.c
