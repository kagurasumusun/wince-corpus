Enabling Power Management

Power management functions respond to system calls for turning the system off or for idling it. These system calls may be triggered by either hardware or software events, such as throwing a power switch or an idle timer count. The following table shows the functions you must implement to enable power management on your target device.

Function Description
OEMPowerOff Places the target device in a power-off state.
OEMIdle Places the target device in an idle state. This is the lowest energy usage state possible balanced with the need to return from idle quickly.

The kernel calls OEMPowerOff when the user presses the OFF button or when GWES enters a time-out period predefined by the user or OEM. In contrast, the kernel calls OEMIdle when there are no threads ready to run.

You can find code samples of OEMPowerOff and OEMIdle in the %_WINCEROOT%\Platform\Hardware Development Platform\Kernel\Hal directory.

When the OEMIdle function is called by the kernel, the OEM device is requested to go into a sleep, or idle, state. This consists of saving the current state, placing the memory into a refresh state if necessary, stopping the clock, and suspending execution.

When an interrupt, including a scheduled interrupt generated by the timer occurs, the device ends its idle state, the previous state is restored, and the scheduler is invoked. If no new threads are ready to run, the kernel will again call OEMIdle.

In order to conserve power while continually awakening the target device, the kernel provides variables that contain information about when the next scheduled kernel event will occur. You can use this information to customize the behavior of the OEMIdle function and the OEM timer interrupt service routine (ISR).

The following table shows the kernel variables available in the OEM timer ISR and OEMIdle functions.

Kernel variable Description
dwPreempt The number of milliseconds until this thread should be pre-empted.
dwSleepMin The number of milliseconds until the first time out (if any) expires, requiring a reschedule.
dwPartialDiffMSec Used in conjunction with DiffMSec to indicate the amount of time that has passed since the last time the scheduler examined the sleep queue.

To lower the power usage of your Windows CE-based device, use the OEMIdle function to enable the processor to sleep for periods of longer than one millisecond. You can program the system tick timer to wake up on the first timeout available by using the dwSleepMin and DiffMSec variables (dwSleepMin - DiffMSec). Because the hardware timer is likely to have a shorter maximum timeout than the system timer, you can program the hardware timer for its maximum sleep time. When the system returns from idle, OEMIdle must update the CurMSec and DiffMSec variables with the real number of milliseconds that have elapsed. The sample platforms also keeps partial millisecond counts for both CurMSec and DiffMSec (dwPartialDiffMSec for DiffMSec and dwPartialCurMSec for CurMSec) in case another interrupt occurs, which will cause the system to stop idling before the system timer fires.

The following code example shows how to implement OEMIdle with these variables.

void
OEMIdle(
    DWORD dwIdleParam
    )
{
    DWORD dwIdleMSec;
    DWORD dwDiffMSecPrev = *pDiffMSec;
    static DWORD dwPartialCurMSec = 0;      // Keep CPU-specific sub-
// millisecond leftover.

    // Use for 64-bit math
    ULARGE_INTEGER currIdle = {
        curridlelow,
        curridlehigh
    };

if ((int)(dwIdleMSec = dwReschedTime - dwPrevSec) <= 0) {
    //already time to wakeup
    return;
    
    //
    // Calculate the idle period
    //
    dwIdleMSec = dwSleepMin - dwDiffMSecPrev;

    //
    // The system timer may not be capable of arbitrary timeouts. Get the
    // CPU-specific highest possible timeout available.
    //
    dwIdleMSec = CPUGetSysTimerCountMax(dwIdleMSec);

    //
    // Because OEMIdle( ) is being called in the middle of a normal 
    // reschedule period, CurMSec, dwPartialCurMSec, dwPartialDiffMSec 
    // and CurTicks need to be updated accordingly.
    //
    CPUGetSysTimerCountElapsed(RESCHED_PERIOD, pCurMSec, pDiffMSec, 
        &dwPartialCurMSec, &dwPartialDiffMSec, pCurTicks);
    dwDiffMSecPrev = *pDiffMSec;
    
    //
    // Set the timer to wake up much later than usual, if needed.
    //
    CPUSetSysTimerCount(dwIdleMSec);
    CPUClearSysTimerIRQ( );

    //
    // Enable wakeup on any interrupt, then go to sleep.
    //
    CPUEnterIdle(dwIdleParam);
    INTERRUPTS_OFF( );

    //
    // It is awake. The wake-up ISR (or any other ISR) has already run.
    //
    if (dwDiffMSecPrev != *pDiffMSec) {
        //
        // The full sleep period is completed. Update
        // the counters.
        //
        // Subtract reschedule period, because ISR also incremented.
        *pCurMSec  += (dwIdleMSec - RESCHED_PERIOD);
        *pDiffMSec += (dwIdleMSec - RESCHED_PERIOD);
        CurTicks.QuadPart += (dwIdleMSec - RESCHED_PERIOD) * 
            dwReschedIncrement;

        currIdle.QuadPart += dwIdleMSec;
    } else {
        //
        // Some other interrupt woke system up before the full idle period 
        // was complete.  Determine how much time has elapsed.
        //
        currIdle.QuadPart += CPUGetSysTimerCountElapsed(dwIdleMSec, 
            pCurMSec, pDiffMSec, &dwPartialCurMSec, &dwPartialDiffMSec,
            pCurTicks);
    }

    // Reset counters
    CPUSetSysTimerCount(RESCHED_PERIOD);
    CPUClearSysTimerIRQ( );

    // Update global idle time
    curridlelow = currIdle.LowPart;
    curridlehigh = currIdle.HighPart;

    return;

Use the above code example and the OAL to implement the extended idle period. The following code example, in the OEM timer ISR, is used to determine whether the kernel should schedule a thread (SYSINTR_RESCHED returned) or do nothing (SYSINTR_NOP returned). 

ULONG ulRet = SYSINTR_NOP;
if ((int)(CurMSec - dwReschedTime) >= 0)
       ulRet = SYSINTR_RESCHED;

By returning SYSTINTR_NOP when appropriate, a system tick ISR can prevent the kernel from rescheduling unnecessarily and therefore save power.
