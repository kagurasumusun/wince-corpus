OEMCertifyModule

This function enables the OS loader to pass the module code — for example, DLL, EXE, and OCX — to the OEM for the purpose of verifying that a module is safe to run on the system.

BOOL OEMCertifyModule(
LPBYTE lpData, 
DWORD cbData 
);

Parameters

lpData
Pointer to a buffer allocated by the OS that contains the module code for the module being loaded.
cbData
Size of the buffer pointed to by lpData, in bytes, passed in by the OS. If cbData is zero, then the end of the module has been reached.

Return Values

The following table shows the values that this function can return.

Value Description
OEM_CERTIFY_TRUST (2) The module is trusted by the OEM to perform any operation.
OEM_CERTIFY_RUN (1) The module is trusted by the OEM to run, but it is restricted from making certain function calls.
OEM_CERTIFY_FALSE (0) The module is not trusted by the OEM and therefore is not allowed to run.

Remarks

To implement this function, assign the address of this function to pOEMLoadModule in OEMInit of the OEM adaptation layer (OAL). The pOEMLoadModule global pointer is exposed by the OS in the OAL. The OS loader calls pOEMLoadModule multiple times until the end of the module is reached. Because the end of the module may never be reached if the loader fails to fully load a module, an OEM must be prepared to handle the situation where pOEMLoadInit is called before the end of the previous module is reached.

Both DLLs and EXEs are assigned trust levels by the OEM. All of the modules from the MODULES section of a .bin file are assumed to be trusted (OEM_CERTIFY_TRUST) and are not tested by the OEM. The OEM should test the modules from the FILES section of the .bin file and other file systems.

An EXE is always assigned a trust level before any of its dependent DLLs are loaded. When a dependent DLL is loaded, the OEM assigns it a trust level. The kernel then compares this DLL trust level to the trust level of the EXE. Based on this comparison, a DLL certification level is obtained for the OS. The kernel will reduce the trust level of the DLL if necessary in order for the DLL to run. If the trust level of the EXE is higher then the DLL, the DLL will not be loaded by the kernel. A DLL can use the CeGetCurrentTrust function to determine the trust level of the EXE if a DLL needs more control over which EXEs are able to load it. The following table shows the resulting DLL certification level based on the combination of OEM-assigned trust levels.

OEM certification for EXE OEM certification for DLL DLL certification level
OEM_CERTIFY_TRUST OEM_CERTIFY_TRUST OEM_CERTIFY_TRUST
OEM_CERTIFY_RUN OEM_CERTIFY_TRUST OEM_CERTIFY_RUN
OEM_CERTIFY_TRUST OEM_CERTIFY_RUN OEM_CERTIFY_FALSE
OEM_CERTIFY_RUN OEM_CERTIFY_RUN OEM_CERTIFY_RUN

All ROM DLLs and EXEs are not certified by the OEM and are assumed to operate at a OEM_CERTIFY_TRUST level.

For information on API restrictions imposed on untrusted applications, see Trusted APIs.

In addition, the CreateProcess debug flags DEBUG_ONLY_THIS_PROCESS and DEBUG_PROCESS are restricted. If these flags are used by a nontrusted application, the identified process will still launch, but no debugging will occur.
