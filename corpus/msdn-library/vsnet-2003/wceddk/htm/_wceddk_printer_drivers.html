Microsoft Windows CE 3.0  

Printer Drivers

Windows CE versions 2.0 and later include support for printing. The printing model in the Windows CE operating system is a subset of the printing model defined for desktop Windows-based platforms. Only a small number of the graphics driver functions defined for printer drivers are required in printer drivers for Windows CE. The printer driver interface has not changed since Windows CE version 2.0.

The following sections describe the interaction between Windows CE–based printer drivers and Windows CE–based display mechanisms. These sections also describe the functions that printer drivers must implement and the port monitor functions that printer drivers call to send data to printers.

The Windows CE graphics display interface (GDI) and display driver perform most of the work involved in printing. At the beginning of the printing process, the GDI creates a device context with attributes that are retrieved from the printer driver during a call to the DrvEnablePDEV function. The display driver is used to render subsequent drawing commands that are issued from the application into the DC; the printer driver does not render the document. Therefore, some drawing functions that are allowed to be present in a printer driver, such as Drvstrokepath, are never actually called because the printer driver is not rendering the document.

After the document has been rendered, GDI sends the resulting 24-bit BGR bitmap to the printer driver so that the printer driver can format it and send it to the printer. To conserve memory, GDI actually renders the document in several bands, which are horizontal sections of the page, and GDI makes several calls to the printer driver to send the rendered bands to the printer. The document is, therefore, actually rendered several times. GDI optimizes the rendering as much as it can to skip items that are outside of the current band. The band range in size from ¼ of the page down to 1/100 of the total page, depending on the available memory. GDI always renders the largest bands possible. The band bitmaps passed to the printer driver are in the pixel format requested by the printer driver. Note that this architecture is different than in Microsoft Windows 95, Windows 98, Windows NT and Windows 2000. In those operating systems, the printer driver itself renders the bitmap; in Windows CE, GDI renders the bitmap, which is then passed to the printer driver for conversion into the printer's native data format. This results in lower printing performance than on the desktop operating systems, since high level information that the printer driver might make use of — such as compact representations of straight lines, solid color fills, and even text — is not available after Windows CE has rendered the page into a simple bitmap. Future versions of Windows CE may address some of these issues.

Windows CE–based printer drivers are required to implement only those graphics driver functions that are necessary for gathering printer metrics, setting up the printer, starting and ending print jobs, and preparing rendered strips for printing. Internally, the printer driver converts the bitmap data from a GDI bitmap format into the format that is required by the printer. This can include operations such as color reduction to the color space of the printer, data compression, and data conversion into the format that is used by the printer, a format sometimes known as a printer description language. Finally, the printer driver calls the port monitor to send the rendered strips to the printer.

Windows CE–based printer drivers are compiled as dynamic-link libraries (DLLs). As a result, they must export the DrvEnableDriver function.

For more information about Windows CE–based printer drivers, see Functions Implemented by Printer Drivers and Registry Keys for Printer Drivers.
