Microsoft Windows CE 3.0  

Initialization

This section describes changes to the initialization mechanism that have appeared in the DDGPE implementation of the DDHAL.

The process of initialization of the DDHAL has changed slightly from the Desktop specification. Unlike the DriverInit entry point in the Desktop implementation, the main initialization point for the Windows CE DDHAL is HALInit.

HalInit

HALInit is exported by the display driver. It is implemented in the DDGPE interface, so you can simply export it from your driver.

buildDDHALInfo

HALInit calls buildDDHALInfo with the appropriate parameters.

You should be able to convert your 32-bit buildDDHALInfo (or buildDDHALInfo32) function fairly easily. When transferring this function from your Desktop DDHAL implementation, keep in mind that the parameter list has changed slightly:

EXTERN_C BOOL buildDDHALInfo (
LPDDHALINFO lpddhi,
DWORD modeidx
);

Since there is no longer a DDHAL driver data structure associated with the device driver, your buildDDHALInfo function should be modified to use the DDHALINFO structure passed into it by HALInit. Also, your driver is now responsible for allocation of the callback structures. DDGPE expects all callback and capabilities data structures to be implemented as global variables (see the sample code or DDHAL Callbacks and Capabilities).

You will need to extend your buildDDHALInfo function to set up several global variables required by the DDGPE model. You should consult the sample code and Required Variables for examples and descriptions of these global variables.
