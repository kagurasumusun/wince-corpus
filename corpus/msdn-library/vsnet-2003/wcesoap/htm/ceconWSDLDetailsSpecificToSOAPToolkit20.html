WSDL Details Specific to SOAP Toolkit

The Windows CE .NET Simple Object Access Protocol (SOAP) Toolkit Web Services Description Language (WSDL) supports the following features:

  • The following combinations of style attribute of the <soap:binding> or <soap:operation> element and use attribute of the <soap:body> element values are supported:
    • document/literal
    • rpc/encoded (with encodingStyle set to "http://schemas.xmlsoap.org/soap/encoding/")
    • rpc/literal
  • When the <operation> child element of the <portType> element has a parameterOrder attribute, the value of this attribute is used to construct the operation's method signature. For example, the following WSDL syntax example specifies the parameterOrder attribute. 
      <types>
    <schema targetNamespace='http://tempuri.org/type'
...
    </schema>
  </types>
 
 <message name='Calc.Multiply'>
    <part name='A' type='xsd:double'/>
    <part name='B' type='xsd:double'/>
  </message>
  <message name='Calc.MultiplyResponse'>
    <part name='Result' type='xsd:double'/>
  </message>
  <portType name='CalcSoapPort'>
    <operation name='Multiply' parameterOrder='A B'>
      <input message='wsdlns:Calc.Multiply' />
      <output message='wsdlns:Calc.MultiplyResponse' />
    </operation>
  </portType>
...

    When the parameterOrder attribute is not present, the parts of the input and output messages appear as parameters in the method's signature in the following order:

  1. The input parameters are the first parameters in the signature. These input parameters consist of all the parts that only appear in the input message.
  2. The parameters that are used for both input and output are the second set of parameters in the signature. These input/output parameters consist of all the parts that appear in both the input and output messages.
  3. The output parameters are the last parameters in the signature. These output parameters consist of all the parts that only appear the output message. However, if the first part in the output message does not appear in the input message, that part is used as the return value.
  4. A WSDL file may have an optional <stk:binding> element. This element has a preferredEncoding attribute that determines the character encoding used by the SOAP Toolkit SoapClient and SoapServer objects when these objects generate SOAP messages. If this element is not present in the WSDL file, the SoapServer and SoapClient objects use UTF-8 encoding. If this element is present, the preferredEncoding attribute may have a value of either UTF-8 or UTF-16.

    The <stk:binding> element uses the following namespace: 

    xmlns:stk='http://schemas.microsoft.com/soap-toolkit/wsdl-extension'
