ISOAPError

This interface provides the properties necessary to create a <Fault> element in a Simple Object Access Protocol (SOAP) message.

The SoapServer and SoapClient objects each handle errors in a specific way. The following text describes how each of these objects handles errors.

How the Server Handles Errors

  1. If the COM object on the server returns an error, the SoapServer object queries the COM object for the ISOAPError interface. If the COM object implements the ISOAPError interface, the SoapServer object creates a <Fault> element whose:
    • <faultcode> child element has been set to the string returned by the faultcode property of the ISOAPError interface with a namespace prefix that identifies the namespace URI returned by the faultcodeNS property of the ISOAPError interface.
    • <faultstring> child element has been set to the value returned by the faultstring property of the ISOAPError interface.
    • <faultactor> child element has been set to the value returned by the faultactor property of the ISOAPError interface. If the faultactor property returns an empty string or a null value, the <faultactor> child element will be set to the service address specified in the Web Services Description Language (WSDL) document used to initialize the server
    • <detail> child element has been set to the XML text returned by detail property of the ISOAPError interface. (Note that the detail property must contain valid XML content with any text strings both placed inside of elements and properly escaped according to XML rules).
  2. If the COM object does not implement the ISOAPError interface, but does support the COM IErrorInfo interface, the SoapServer object creates a <Fault> element whose:
    • <faultcode> child element has been set to "SOAP-ENV:Client".
    • <faultstring> child element has been set to the value returned by the GetDescription method of the IErrorInfo interface.
    • <faultactor> child element has been set to the service address specified in the WSDL document used to initialize the server.
    • <detail> child element has been set to the content described in Understanding the SOAP Fault <detail> Contents.
  3. If the COM object supports neither the ISOAPError interface, nor the IErrorInfo interface, the SoapServer object creates a <Fault> element whose:
    • <faultcode> child element has been set to "SOAP-ENV:Client".
    • <faultstring> child element has been set to a message containing the name of the method that failed.
    • <faultactor> child element has been set to the service address specified in the WSDL document used to initialize the server.
    • <detail> child element has been set to the content described in the Understanding the SOAP Fault <detail> Contents.

How the Client Handles Errors

If the server returns a SOAP message containing a <Fault> element to the client, the <faultcode>, <faultstring>, <faultactor> and <detail> element values in the SOAP message are copied to the corresponding properties in the SoapClient object and the client generates an ErrorInfo object that can be used through the Err object.

If the error occurs on the client (for example during initialization), the SoapClient object generates values for its error properties: faultcode, faultstring, faultactor, and detail. As with an error occurring on the server, the SoapClient also sets an ErrorInfo object.

The following table shows the properties supported by the ISOAPError interface.

Property Description
faultcode (read-only) Provides the value of the <faultcode> element of the Simple Object Access Protocol (SOAP) <Fault> element.
faultstring (read-only) Provides the value of the <faultstring> element of the SOAP <Fault> element.
faultactor (read-only) Provides the value of the <faultactor> element of the SOAP <Fault> element.
detail (read-only) Provides the value of the <detail> element of the SOAP <Fault> element.
faultcodeNS (read-only) Provides the namespace URI used in the <faultcode> element of the SOAP <Fault> element.
