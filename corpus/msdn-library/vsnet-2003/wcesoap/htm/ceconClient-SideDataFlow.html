Client-Side Data Flow

The user application sends a message to the SoapClient object requesting an operation, in this case, the adding of two numbers. The SoapClient object processes this request and formulates a Simple Object Access Protocol (SOAP) request to the server. The server receives the request, performs the requested operation, and sends the result of the operation back to the client in the form of a SOAP response. The SoapClient object processes this SOAP response and sends a message that contains the result of the operation back to the user application. Setting Up the SoapClient Object

Before being able to send operation requests to the SoapClient object, the user application must first instantiate this object. This object is implemented in MSSOAP1.dll.

Upon instantiating the SoapClient object, the user application initializes the object by calling the SoapClient.mssoapinit method and passing in the following parameters:

  • The name of the Web Services Description Language (WSDL) file.
  • The service name.
  • The port information. A port specifies a binding to a particular communications link used to send the SOAP message. The <portType> element ties the port to a collection of operations.

Internally, all the methods described in the WSDL file are bound dynamically to the SoapClient object during initialization. This dynamic binding allows you to call any of the methods described in the WSDL file.

Processing Inside the SoapClient Object

The SoapClient and SoapServer are considered part of high-level API. In your application you use the SoapClient to send SOAP requests and the SoapClient does several things internally to send the request to the server. The following diagram illustrates how the SoapClient object processes the operation request from the user application, formulates a SOAP request message, and processes a SOAP response message.

The WSDLReader object loads the WSDL and Web Services Meta Language (WSML) files into a DOM and then analyzes these files. Based on this analysis, the WSDLReader object creates a WSDLOperation object for the requested operation (for example, AddNum(3, 4)). The WSDLOperation object then calls the GetOperationParts method, which returns from the DOM tree a collection of the parts defined for both the operation's input and output messages. The SoapClient object creates SoapMapper objects for each of these parts and loads the values specified in the operation request into these objects. The SoapSerializer object then builds the SOAP request message from the appropriate SoapMapper objects and sends it to the server.

The server processes the SOAP request and returns a SOAP response to the client. From this response, the SoapClient object loads the result of the operation into the appropriate SoapMapper object and returns the result to the user application.

The WSDLReader, WSDLOperation and SoapReader and so on are considered part of low-level API. Instead of using the SoapClient high-level API, you can use the low-level API in your application. The Calc sample applications in SOAP Sample Applications topic provide the working samples.
