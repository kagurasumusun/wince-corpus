Server-Side Data Flow

On the server-side, you have two choices for a SOAP listener (the handler of incoming SOAP requests on the server):

  • An Internet Server API (ISAPI) server
  • An Active Server Pages (ASP) server

In the Web Services Description Language (WSDL) file, the URL identified as the server-side handler of the SOAP request determines how the SOAP request is handled on the server. For instance, the following WSDL file syntax example identifies the URL (shown in bold) that invokes the ISAPI listener:

<definitions>
...
<service name='Calc' >
    <port name='CalcSoapPort' binding='wsdlns:CalcSoapBinding' >
      <soap:address location='http://MSSoapSampleServer/MSSoapSamples/Calc/Service/Rpc/IsapiCpp/Calc.wsdl' />
    </port>
  </service>
...
</definitions>

Reviewing the Server-Side Data Flow

Regardless of whether the SOAP request invokes an ISAPI or ASP listener, how the server handles the incoming and outgoing data is the same. The SoapServer object receives the SOAP request from the client, processes that request, and forwards a call to the COM method that matches the requested operation (in the following diagram, this is the call to the AddNum method). The method that was called then sends the result of the requested operation back to the SoapServer object, which then formulates this information into a SOAP response that the object sends back to the client. Processing Inside the SoapServer Object

The SoapServer and SoapClient are considered part of high-level API. In your application you use the SoapServer to process the SOAP requests and the SoapServer does several things internally. The following diagram illustrates how the SoapServer object processes SOAP request message and formulates SOAP response messages.

Upon receiving a SOAP request from the client, the SoapReader object loads this request message into one DOM structure, while the WSDLReader loads the WSDL and Web Services Meta Language (WSML) files into another DOM structure. The WSDLReader parses the request and creates a WSDLOperation object for the requested operation. The WSDLOperation object then calls the GetOperationParts method, which returns from the WSDL/WSML DOM tree a collection of the parts defined for both the operation's input and output messages. The SoapServer object creates SoapMapper objects for each of these parts and loads the values from the SOAP request into these SoapMapper objects. The SoapServer object then calls the COM method corresponding to the requested operation.

The COM method processes the parameters included in the call and returns the result to the SoapServer object, which maps the return value to the appropriate SoapMapper object. The SoapServer object then uses the SoapSerializer object to build a SOAP response message for the result value. The SoapServer object then sends this SOAP response message to the client.

The WSDLReader, WSDLOperation and SoapReader and so on are considered part of low-level API. Instead of using the SoapClient high-level API, you can use the low-level API in your application. The Calc sample applications in SOAP Sample Applications topic provide the working samples.
