Running the Test

The following command line shows the syntax for using Tux.exe to run the test, where test_case is the specific test case or range of test cases to run.

tux –o –d kbdtest –x test_case

The following command line shows the syntax for using Tux.exe to run the entire test.

tux –o –d kbdtest

After each test case finishes, a status report is displayed indicating whether it passed, failed, skipped, or aborted. After all of the specified test cases have finished, a summary of results is displayed.

While a test case is running, the test case name and instructions are displayed. If no keys are pressed for 20 seconds, the test case times out.

These test cases were designed to test the keyboard and keyboard driver for an American Handheld PC (H/PC) keyboard, but may be used to test any keyboard that includes the keys found on the H/PC. All of the keys may not be tested; see the test case description for details.

The following table shows the test cases.

51 Key sequence check test.
52 Key chording test.
53 Text editing test.
54 Repeat rate and key delay test.

Test Case 50 - Manual Key Press Test

To run this test case, press any key sequence and observe the keyboard messages that are generated. This test case is useful for examining the actions of any keys or sequences where problems are suspected and for testing event timing. You should verify that a keyboard message appears promptly when a key is pressed, released, or held down.

Test Case 51 - Key Sequence Check Test

This test case asks you to press a sequence of keys and then verifies that the keyboard driver has produced the proper messages. This test case must begin with the CAPS LOCK key toggled off; there is a reminder at the beginning of the test case. Halfway through the test case, you are then prompted to toggle the CAPS LOCK key on. This allows the test case to verify proper functionality of the keyboard when the CAPS LOCK is toggled on or off.

When an invalid message sequence occurs, you are warned and given the option to try again or skip the key sequence. If the key sequence is skipped, a failure is logged that describes the key sequence and the unexpected key event in the sequence.

Test Case 52 - Key Chording Test

This test case asks you to press a sequence of keys. If the keyboard is unable to generate certain key sequence, the test case will either time out or issue a warning to the log that an invalid key event has occurred. You are then given the option to skip this key sequence, which will cause a failure to be logged.

The following key sequences are used for this test case:

  1. CTRL+SHIFT+RIGHT ARROW
  2. CTRL+ALT+SHIFT+T
  3. CTRL+ALT+SHIFT+M
  4. CTRL+ALT+SHIFT+DELETE
  5. CTRL+ALT+P
  6. CTRL+ALT+X
  7. CTRL+ALT+SPACE
  8. CTRL+SHIFT+A
  9. CTRL+SHIFT+LEFT ARROW
  10. CTRL+SHIFT+DOWN ARROW
  11. ALT+SHIFT+9
  12. ALT+SHIFT+3

Test Case 54 - Repeat Rate and Key Delay Test

This test case asks you to press hold down various keys while noting the repeat rate and key delay. The progress of this test case is logged with a description of the rates and delays used during each phase of the test case. A failure is logged if the correct repeat rate or delay is not observed.

Test Case 55 - Asynchronous Test

This test case asks you to press a sequence of keys. A failure is logged if a key has the wrong asynchronous state.
