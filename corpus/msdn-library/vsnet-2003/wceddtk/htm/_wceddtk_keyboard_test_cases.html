Microsoft Windows CE 3.0  

Keyboard Test Cases

This test suite verifies proper keyboard message generation with correct virtual codes, the repeat and delay features of the keyboard, and the keyboard's ability to recognize certain key combinations.

Test Case 50 - Manual Key Press Test

In this test case, you press any key sequence and observe the keyboard messages generated. This test case is useful for examining the actions of keys or sequences where problems are suspected. It can also be used to test the timing of events. You should verify that keyboard messages appear promptly when a key is pressed, released, or held down.

This test case is a tool that lets you observe all Win32 keyboard messages delivered to a window in response to keyboard actions. This test displays the following messages in the order that they are received:

  • WM_KEYUP
  • WM_KEYDOWN
  • WM_SYSKEYDOWN
  • WM_SYS-KEYDOWN
  • WM_CHAR
  • WM_SYSCHAR
  • WM_DEADCHAR
  • WM_SYS-DEADCHAR

The information received with each keyboard message is also displayed when applicable, including the transition state, previous-key state, ALT-key state, repeat count, virtual-key code, character, and key-scan code.

Test Case 51 - Key Sequence Test

This test case covers all keys typically found on a Handheld PC (H/PC) keyboard. However, the function keys (F1-F12) are not tested. Two-key combinations are tested and keyboard functionality is tested with CAPS LOCK on and off.

This test case requires you to press a sequence of keys. The test case then automatically verifies that the keyboard driver has produced the proper message. The test must start with CAPS LOCK toggled off — there is a reminder at the beginning of the test. Halfway through the test, you are asked to press CAPS LOCK and leave it toggled on for the remainder of the test key sequence. This allows the test case to verify proper functioning of the keyboard when the CAPS LOCK is toggled on or off.

When an invalid message sequence occurs, you are warned and given the option to try again or skip the key sequence. If the key sequence is skipped, a failure is logged describing the key sequence and the unexpected key event in the sequence.

Test Case 52 - Key Chording Test

This test case verifies the keyboard's ability to recognize a key when pressed together with one or more other keys. Two-key, three-key, and four-key combinations involving the ALT, CTRL, and SHIFT keys are extensively tested.

If the keyboard is unable to generate a certain key sequence, the test either times out or issues a warning in the log that an invalid key event occurred. You are then given the option to skip this sequence, and a failure is logged.

Test Case 53 - Text Editing Test

This is a tool to test the keyboard's ability to edit text in a window's text box.

Test Case 54 - Repeat Rate and Key Delay Test

This test case verifies the keyboard driver's ability to set the repeat rate and delay of pressed keys.

The progress of this test is logged with descriptions of the rates and delays used during each phase of the test. A failure is logged if the tester does not notice the correct repeat rate or delay.

Test Case 55 - Asynchronous State Test

This test verifies the keyboard driver's ability to determine the asynchronous state of keys.
