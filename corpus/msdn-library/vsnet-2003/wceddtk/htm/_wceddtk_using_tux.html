Using Tux

Tux consists of two components, Tux Client (Tux.exe) and Tux Server (Tuxsrv.exe). Tux Client is the actual Tux engine, and Tux Server acts as a remote UI and administration tool. Tux Client is a console application that performs the loading and execution of Tux test modules. Tux Server remotely controls one or more Tux Clients and allows the user to load and unload Tux test modules, select test cases to run from each loaded module, execute selected tests, and tally results.

This client/server architecture has several advantages:

  • One Tux Server can control multiple Tux Clients.
  • Separate address spaces for the test engine and the UI minimize the possibility of conflicting code and errors.
  • Separate address spaces allow Tux Server to keep running and provide results, even when the Client has caused a crash.
  • The test engine has a small memory footprint and working set size.
  • Tests do not need to compete with the harness for the UI, because the entire UI for the harness lives in Tux Server, which can be run remotely.
  • The status of full-screen tests can be monitored from a remote machine.
  • Tux Client can be ported to any platform that supports a minimal set of Win32 and Winsock APIs, while still taking full advantage of Tux Server's UI.
  • Tux Client can be run without Tux Server in a stand-alone mode, which is useful for batch testing.
