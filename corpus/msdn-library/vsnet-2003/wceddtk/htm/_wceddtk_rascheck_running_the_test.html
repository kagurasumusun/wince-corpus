Microsoft Windows CE 3.0  

Running the Test

The following command line shows the syntax for running the test.

rascheck [test_case] [parameters]

The following table shows the test cases.

Test Case Description
1 Starts callback thread.
2 Enumerates RAS-capable devices.
3 Checks for and cleans up open connections.
4 Creates a RAS phonebook entry.
5 Reads RAS dialing parameters.
6 Makes a RAS connection.
7 Hangs up a RAS connection.
8 Renames a test RAS phonebook entry.
9 Reads RAS dialing parameters for a renamed RAS phonebook entry.
10 Makes a renamed RAS connection.
11 Hangs up a renamed RAS connection.
12 Deletes a device configuration.
13 Tests oversize password.
14 Deletes a test RAS phonebook entry.

The following table shows the general test case parameters.

Parameter Description
-v verbosity Sets the verbosity level of the debug output, from 0 (extremely terse) to 15 (extremely verbose). Default verbosity is 10.
-z Routes log output to a console window. Default output is to the debugger.
-fl Routes log output to a file on the target device.
-fr Routes log output to a remote file opened via CESH.
-e entry_name Copies the specified RAS phonebook entry name for use in running the tests. If an entry name is not specified, a new entry will be created using default parameters (direct serial connection at 19200 baud). RAS phonebook entries may be created using the remote networking dialing application, Remnet.exe. The Rasentry.exe application, which is provided as sample code with Windows CE, may also be used.
-x Skips dialing tests. This option allows all RAS APIs except RasDial and RasHangUp to be tested, even in the absence of a RAS connection.
-h Prints a short help description.

Test Case 1

This test case opens a new thread for use by a RAS callback function. The callback function is used by the remaining test cases to handle messages from asynchronous RAS functions, such as RasDial and RasHangUp.

Test Case 2

This test case calls RasEnumDevices, first with invalid parameters to test the operation of the RAS API, and then with valid parameters to list all the RAS-capable devices on the system.

Test Case 3

This test case calls RasEnumConnections to enumerate the active RAS connections. If any connections are active, RasHangUp is called to close them.

Test Case 4

This test case creates a new entry in the RAS phonebook named "Temporary Ras #1". If an existing phonebook entry was specified on the command line using the -e parameter, it will be copied to create the new entry; otherwise, the new entry will be created using default parameters (direct serial connection at 19200 baud).

The following APIs are tested:

  • RasGetEntryProperties
  • RasGetEntryDialParams
  • RasEnumEntries
  • RasValidateEntryName
  • RasSetEntryProperties
  • RasSetEntryDialParams

The following deprecated APIs are also tested:

  • RasGetEntryDevConfig
  • RasSetEntryDevConfig

Test Case 5

This test case calls RasGetEntryDialParams to get dialing parameters for the upcoming call from the newly created RAS phonebook entry.

Test Case 6

This test case calls RasDial to make a call using the dialing parameters just read. If RasDial completes successfully, the call connection status will be monitored using the callback function. After the connection status reaches its final state (connected or disconnected), RasGetConnectStatus is called to confirm the status; a short delay follows.

Test Case 7

This test case calls RasHangUp to disconnect the call; it is only called if a connection handle was allocated during the previous case. It monitors callback messages until the final disconnected state is reached.

Test Case 8

This test case calls RasRenameEntry to rename the test RAS phonebook entry to "Temporary Ras #2" and then verifies that the entry was renamed successfully.

Test Case 9

Repeats test case 5 using the renamed RAS phonebook entry.

Test Case 10

Repeats test case 6 using the renamed RAS phonebook entry.

Test Case 11

Repeats test case 7 using the renamed RAS phonebook entry.

Test Case 12

This test case deletes the device configuration for the test RAS phonebook entry.

Test Case 13

This test case tests whether RAS can handle very long passwords, which are over 128 characters.

Test Case 14

This test case calls RasDeleteEntry to delete the test RAS phonebook entry and then verifies that the entry was deleted successfully.
