Microsoft Windows CE 3.0  

Running the Test

The following command line shows the syntax for using Tux.exe to run the test, where test_case is the specific test case or range of test cases to run.

tux –o –d rw_all –x test_case

The following command line shows the syntax for using Tux.exe to run the entire test.

tux –o –d rw_all

After each test case finishes, a status report is displayed indicating whether it passed, failed, skipped, or aborted. After all of the specified test cases have finished, a summary of results is displayed.

Before running this test, be aware that any information stored on the card is destroyed. The program will write to and read from every sector on the disk, without preserving the prior contents. This test tests each PC card that is inserted in the system, assigning one thread to each card.

This test communicates directly with the device drivers, which sit below the file system and FAT layers. If there are file system problems, you may be able to isolate the problem to a specific layer.

The Rw_all.dll test cases differ only in the number of sectors that are read or written per I/O burst. Because of the overhead in running the test, the more sectors you read or write at once, the faster the test will run. For example, processing one sector at a time is not as efficient as processing 128 sectors at a time.

Because none of these test cases stress the device driver, it is safe to choose any one of them. You may attribute any failures to defective hardware.

This test starts by outputting basic information about the PC card. This information contains the name of the device opened, the handle of the device, the number of sectors, and the number of bytes per sector. Cylinder, head, sector, and flag information is not given, because it is not applicable to this test. In the following screen shot, the number inside the square brackets indicates which thread is sending the status message.

[2] Attempting to open DSK2:
[1] Attempting to open DSK1:
[2] rw_all successfully opened DSK2:, hDsk=0x21E7BB1E.
[1] rw_all successfully opened DSK1:, hDsk=0x01E7BAFE.
[2] rw_all: Total sectors: 3936, Bytes per sector: 512.
[1] rw_all: Total sectors: 20480, Bytes per sector: 512.

If the device driver does not return an error, the test indicates, in milliseconds, how many sectors were written to and how long it took. Next, a message indicating that the program is attempting to read back those sectors is displayed. If the device driver does not return an error, the program attempts to verify the data. The following screen shot shows the output. 

[2] Attempting to write sectors 0 through 127.
[1] Attempting to write sectors 0 through 127.
[2] Successfully wrote 128 sectors in 516 ms.
[1] Successfully wrote 128 sectors in 514 ms.
[2] Attempting to read sectors 0 through 127.
[1] Attempting to read sectors 0 through 127.
[1] Successfully read 128 sectors in 280 ms.
[1] Attempting to write sectors 128 through 255.
[2] Successfully read 128 sectors in 318 ms.

If this pattern of successfully writing and reading of sectors continues to the end of the disk, the test outputs a short report on the access times, and then returns a passing value to Tux.exe. If the test passes, you can assume that the driver and the card are working properly. You should also take into consideration any timing issues that may arise; for example, a linear flash card will take much longer to finish a write operation. A successful test is shown in the following screen shot.

[1] Min Write Time: 393 ms, Max Write Time: 561 ms, Ave Write Time: 402 ms.
[1] Min Read Time: 171 ms, Max Read Time: 371 ms, Ave Read Time: 180 ms.

The following table shows the test cases.

Test Case Description

1004 Write and read all sectors 32 sectors at a time.
1005 Write and read all sectors 64 sectors at a time.
