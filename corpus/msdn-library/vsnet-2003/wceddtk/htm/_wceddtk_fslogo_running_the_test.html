Microsoft Windows CE 3.0  

Running the Test

The following command line shows the syntax for using Tux.exe to run the test, where test_case is the specific test case or range of test cases to run.

tux –o –d fslogo –x test_case

The following command line shows the syntax for using Tux.exe to run the entire test.

tux –o –d fslogo

After each test case finishes, a status report is displayed indicating whether it passed, failed, skipped, or aborted. After all of the specified test cases have finished, a summary of results is displayed.

All output from these test cases is sent to the debugger. Before running a test case, each storage card is formatted and all properties of the storage card are displayed.

To reduce the time it takes to test large cards, which are typically 40 MB or greater, the –l parameter should be used, test cases 3001–3007 should be run instead of test cases 5023–5029, and test cases 5012 and 5013 should be skipped. The -l parameter is used to control certain test parameters and thus reduce the amount of testing time for large size cards. This parameter must be preceded by the -c parameter to notify Tux.exe that it is a test DLL parameter as opposed to a Tux.exe parameter. The following command line shows the syntax. 

tux –o –d fslogo –c -l –x1001-5011,5014-5022,6001-7002 -c -u

The following table shows the test cases.

Test Case Description
1001–1008, 1101–1104 Tests object file system.
3001–3007 Tests moderate to large storage cards.
5001–5029 Tests multiple storage cards in parallel.
6001–6003 Tests FAT formatting of storage cards.
7001–7002 Stress tests.
9001–9010, 9031, 9032, 9061 Various file system utilities.

The following table shows the general test case parameters.

Parameter Description
-l Light version. Useful when using large multi-partitioned disks because the regular tests would take too long.
-r root_directory Specifies the root directory instead of "Storage Card".
-n Suppresses a pre-test format of the volume.
-p number Specifies the number of partitions to be tested. Useful for multi-partitioned cards only.

Test Cases 3001–3007

These test cases are designed to run on moderate to large size storage cards, which are roughly 40 MB or greater. They test the same functionality as test cases 5023–5029. These test cases fill up the storage card, leaving two, one, or zero clusters free and then try to perform operations to determine how the card will react to a disk full situation. These test cases are interdependent and must be run in order as a group; attempting to run them out of order could result in one or more of the tests being skipped.

The following table shows the test cases.

Test case Description
3001 Create a 100-byte file with 2 clusters free.
3002 Create a directory with 1 cluster free
3003 Create a 100-byte file with 1 cluster free.
3004 Create directories with 1 cluster free until disk is full.
3005 Create a directory with 0 clusters free.
3006 Create a 0-byte file with 0 clusters free.
3007 Create a 100-byte file with 0 clusters free.

Test Cases 6001–6003

These test cases test storage card formatting. They format each of the storage cards, using all of the FAT formats supported: FAT12, FAT16 and FAT32. These test cases will spawn one thread for each FAT storage card that is present.

Test case Description

Test Cases 7001–7002

Each of these test cases performs a multi-threaded file system stress test. Each test case runs for 30 minutes and stresses file reading, file writing, memory mapped file reading, stack operations, and exceptions. These test cases stress test the local object store file system and any SRAM or ATA FAT storage card that may be present. Do not run these test cases on multi-partitioned drives; they are not supported.

The following list shows the files and threads that are created:

  • Two exception threads (test case 7002 only)
  • Two stack threads

The following files and threads are created for the local object store file system:

  • A normal file is created with the following threads:
    • Sequential read
    • Random read
    • Write
  • A mapped file is created with the following threads:
    • Sequential read
    • Random read

The following files and threads are created for the every ATA card detected:

  • A normal file is created with the following threads:
    • Sequential read
    • Random read
    • Write
  • A mapped file is created with the following threads:
    • Sequential read
    • Random read

The following files and threads are created for every SRAM card detected:

  • A normal file is created with the following threads:
    • Sequential read
    • Random read
    • Write

The following table shows the test cases.

Test case Description
7001 Read/write/stack threads.
7002 Read/write/stack/except threads.
