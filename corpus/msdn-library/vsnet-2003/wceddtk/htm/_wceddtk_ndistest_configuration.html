Microsoft Windows CE 3.0  

NDISTest Configuration

Running NDISTest on a Windows CE-based device requires a Windows CE device with a PCMCIA slot and a network adapter. NDISTest may be run in one of the following configurations:

  • Standalone testing

    NDISTest is run on a single machine. You can run all of the tests in standalone mode. However, you will only be able to perform a partial stress test; only the sending of packets will be tested.

  • Two-machine testing

    Two-machine testing has the advantage of being able to perform a full stress test of your driver because both sending and receiving of packets is tested. To perform two-machine testing, you must have a Windows NT-based computer connected to a Windows CE-based device that has its own network adapter. You must also edit Hapi.ini and set the G_TestOptions global variable to the SKIP_1CARD_TESTS flag.

    The version of NDISTest running on the Windows NT machine must be compatible with the version of NDISTest running on the Windows CE machine. To prevent failures from occurring, use the Windows NT version of the NDISTest that is supplied with the Windows CE DDTK.

Before testing an NDIS miniport, you must edit the Hapi.ini configuration file to indicate which tests will be run, and how each test will be performed. To test a miniport driver successfully, you must define two sections in Hapi.ini: DLLs and Variables.

The DLLs section specifies which DLLs to load. For NDISTest, this section is always two lines long and should look like the following:

[DLLs]
ndistst.dll

The Variables section consists of variable initializations; it can contain multiple lines. The first line must look like the following:

[Variables]

Subsequent lines in the Variables section must have the following format:

variable_name=variable_value

All variables must begin with the dollar sign character ($). Variable names are limited to alphanumeric characters and the underscore character (_). Variables can have either strings or integers assigned as values. Strings must be enclosed in double quotation marks. You can specify integers as either decimal or hexadecimal numerals. To specify an integer as a hexadecimal numeral, use a 0x prefix.

A variable must be created and assigned to a value before it can be used in an expression or as an argument to a function. Therefore, a previously undefined variable can be used only to the left of the equal sign (=). Every time a variable is assigned, its definition is destroyed and recreated. Variables do not have fixed types, and type declarations are generally not necessary. The following examples show valid variable declarations:

# Variable $Temp is created as an integer variable with value 5.
$Temp = 5

# Previous variable $Temp is destroyed and new variable $Temp is created # as a floating point variable with the value 1.75
$Temp = 1.75

# Previous variable $Temp is destroyed, new variable $Temp is created as # a string with the value "string."
$Temp = "string"

For NDISTest, the Hapi.ini configuration file sets values for a number of global variables that control what tests are run and how they are run.

The following are the global variables that are used in the Hapi.ini configuration file:

  • G_DebugLevel

    Creates a global variable that is used to maintain debug settings — its value is unimportant. The scripts will set this variable as they execute.

  • G_WorkCard

    Specifies the name of the card to be tested.

  • G_TrustedCard

    Specifies the name of a trusted card in the system that will be used to assist in testing the card specified in G_WorkCard. This variable may be set to the NULL string, which will cause all of the tests requiring two cards in the same system to be skipped.

  • G_MessageCard

    Specifies the name of the card that is used to send commands to the remote Windows NT system running the NDIS test server used for two-machine testing. This variable may be set to the NULL string, which will cause all of the two-machine tests to be skipped.

  • G_Media

    Specifies the media to be tested. It must always be set to a value of 1 (Ethernet setting).

  • G_Ndis30Flag

    This variable must always be set to 0.

  • G_ScriptName

    This global variable only has an effect if the DO_RUNTEST bit is set in the G_TestOptions variable. If the DO_RUNTEST bit is set, this variable specifies the name of a specific script to be run, instead of running the functional, stress, or hardware compatibility testing suites.

  • G_TestOptions

    This variable is a combination of the following flags:

    • DO_FUNCTIONAL_TESTS (0x00001)

      If set, functional testing is performed.

    • DO_STRESS_TESTS (0x00002)

      If set, stress test is performed.

    • DO_PERFORMANCE_TESTS (0x00004)

      If set, performance testing will be performed.

    • DO_HCT_TESTS (0x00008)

      If set, hardware compatibility testing is performed.

    • DO_RUNTEST (0x00010)

      If set, only a single script runs. Functional, stress, and hardware compatibility testing will be skipped. When this flag is set, the G_ScriptName global variable must be set to the name of the script file to be executed. This is shown in the following example. 

      G_ScriptName="Cescripts\Lan\1c_srecv.tst"
    • ENABLE_VERBOSE_FLAG (0x10000)

      If set, output files that are generated include more detail.

    • SKIP_1CARD_TESTS (0x20000)

      If set, tests that use only a single card (1c_xxx.tst script files) are skipped.

Once Hapi.ini has been set up correctly, you are ready to run the NDIS test. A sample Hapi.ini file is shown in the following code example. 

[DLLs]
ndistst.dll

[Variables]

G_TestOptions=0x00001
G_WorkCard="ne20001"
G_TrustedCard="xircomce21"
G_MessageCard="ne20001"
G_Ndis30Flag=0
G_ScriptName="" 

To run functional tests and log verbose output:
G_TestOptions=0x10001

To test the first NE2000 compatible card in the system:
G_WorkCard="ne20001"

To use a Xircom CE2 card as the trusted card to assist testing an NE2000 
card:
G_TrustedCard="xircomce21"

To test an NE2000 compatible card and also use it for commands:
G_WorkCard="ne20001"
G_MessageCard="ne20001"
