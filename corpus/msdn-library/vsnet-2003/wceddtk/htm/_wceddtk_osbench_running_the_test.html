Microsoft Windows CE 3.0  

Running the Test

The following command line shows the syntax for running the test.

osbench [-all] [-t test_case] [-list] [-v] [-n number] 
[-m address] [-o file_name] [-h]

The following table shows the test cases.

Test Case Description
0 Critical sections test.
1 Event set-wakeup test.
2 Semaphore release/acquire test.
3 Mutex test.
4 Voluntary yield test.
5 PSL API call test.
6 Interlocked APIs (decrement, increment, testexchange, exchange) test.

The following table shows the test case parameters.

Parameter Description
-all Run all tests. Default: run only those specified by -t parameter.
-t test_case ID of test case to run (separate –t parameter required for each test case).
-list List test IDs with descriptions.
-v Output all samples. Default: output summary only.
-n number Number of samples per test. Default: 100.
-m address Virtual address to write marker values. Default: none.
-o file_name Output to comma-separated file. Default: output to debugger message window.
-h Print help screen.

Test Case 0

This test case tests the following:

  • EnterCriticalSection traditional (blocking) with priority inversion

    Time from a lower priority thread calling LeaveCS to a higher priority thread unblocking from the EnterCS call.

  • EnterCriticalSection traditional (blocking) without priority inversion

    Time from a higher priority thread calling EnterCS (blocked) to a lower priority running thread.

  • EnterCriticalSection fastpath (uncontested)
  • LeaveCriticalSection fastpath (uncontested)
  • EnterCriticalSection traditional (blocking) with priority inversion

    Time from a lower priority thread calling LeaveCS to a higher priority thread unblocking from the EnterCS call.

  • EnterCriticalSection traditional (blocking) without priority inversion

    Time from a higher priority thread calling EnterCS (blocked) to a lower priority unblocked thread running.

Test Case 1

This test case tests the following:

  • Event intra-process

    Time from SetEvent in one thread to a blocked WaitForSingleObject waking in another thread in the same process.

  • Event inter-process

    Time from SetEvent in one thread to a blocked WaitForSingleObject waking in another thread in a different process.

Test Case 2

This test case tests the following:

  • Semaphore signaling intra-process

    Time from a lower priority thread calling ReleaseSemaphore to a higher priority thread in the same process unblocking from a WaitForSingleObject call.

  • Semaphore signaling inter-process

    Time from a lower priority thread calling ReleaseSemaphore to a higher priority thread in a different process unblocking from a WaitForSingleObject call.

Test Case 3

This test case tests the following:

  • Mutex inter-process

    Time from a lower priority thread calling ReleaseMutex to a higher priority thread in a different process unblocking from a WaitForSingleObject call.

  • Mutex intra-process

    Time from a lower priority thread calling ReleaseMutex to a higher priority thread in the same process unblocking from a WaitForSingleObject call.

Test Case 4

This test case tests the following:

  • Yield to thread timing intra-process

    Time from a thread calling Sleep(0) to a thread in the same process of the same priority which previously called Sleep(0).

  • Yield to thread timing inter-process

    Time from a thread calling Sleep(0) to a thread in a different process of the same priority that previously called Sleep(0).

Test Case 5

This test case tests the following:

  • PSL API call (roundtrip) intra-process

    Calls an API function with no parameters and returns immediately.

  • PSL API call (roundtrip) intra-process

    Calls an API function with 7 DWORD parameters and returns immediately.

  • PSL API call (roundtrip) intra-process

    Calls an API function with 7 PVOID parameters and returns immediately.

  • PSL API call (roundtrip) inter-process

    Calls an API function with no parameters and returns immediately.

  • PSL API call (roundtrip) inter-process

    Calls an API function with 7 DWORD parameters and returns immediately.

  • PSL API call (roundtrip) inter-process

    Calls an API function with 7 PVOID parameters and returns immediately.

  • PSL API call (roundtrip) to NK.EXE

    Calls the GetOwnerProcess API function in NK.EXE, which returns immediately.

Test Case 6

This test case tests the following interlocked APIs:

  • InterlockedIncrement
  • InterlockedDecrement
  • InterlockedExchange
  • InterlockedTestExchange
