Implementing a Hosted Device

To implement a hosted device, you must provide the following elements:

  • A description of the device and its services.
  • An implementation of the device's behavior.

The service description is an XML document that lists the actions and state variables that apply to a specific service offered by the device. Device and service descriptions both use UTL as a schema. In Microsoft® Windows® CE .NET, the SCPD files and any other resources that need to be published on the network must be located under the Windows\Upnp root directory, which is the default resource directory.

The behavior of a device is defined by the services it offers. Each service requires a service description that lists the service's actions and state variables. The service and its corresponding service description describe the service interface that defines the ways in which control points can interact with a specific service.

To implement a service, a hosted device must provide a COM object that exposes the service's interface. To be used as a COM object, the service interface, which is composed in UTL, needs to be translated into a COM interface.

The objects that implement the service disp interfaces are called service objects. To manage a device's service objects, the hosted device must implement a device control object, which serves as the central control point for all service objects. While the device is being registered with the UPnP network, the application passes the device control object to the device host API. When a control request arrives for one of the device's services, the API calls into the device control object to request the relevant service object. The device control object can create an instance of the service object or return an interface on an already existing instance.

To serve as a control point for a device's service objects, each device control object must implement the IUPnPDeviceControl interface. To initialize a device, the device host API must call the IUPnPDeviceControl::Initialize method and pass in the full text of the UPnP device description as well as an initialization string that was specified at registration time.

When a control request arrives for one of the device's services, the device host API calls the IUPnPDeviceControl::GetServiceObject method on the device control object to obtain a pointer to a service object that implements the requested service. The device host API passes in the UDN and the service identifier of the requested service, as well as the address of a pointer to an IDispatch interface, at which the method is expected to return the service object.

To implement a device-hosting service on a Windows CE–based platform, you must complete the following steps:

  1. Create an XML device description template.

    The format of the XML device description follows the UPnP Device Archtitecture specifications with a few differences:

    • The UDN field does not hold the actual globally unique ID, but a descriptive placeholder.
    • Any file URLs, such as icons, presentation pages and SCPD-elements, should contain the local file path as shown in the following example. 
      <SCPDURL>SampleSCPD.xml</SCPDURL>
    • The eventSubURL and controlURL elements should be empty XML elements.
  2. Create a Service Control Protocol Definition (SCPD) XML file for each service offered by the device.
  3. Implement a COM object exposing the IUPnPDeviceControl interface.
  4. Implement an IDispatch interface for each device service.
