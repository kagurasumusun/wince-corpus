Running the PCMCIA Controller Driver Test

The PCMCIA Controller Driver Test executes the tux -o -d ddlx -c"Pcmcetsts" command line on default execution.

If you plug a PC Card into socket 0, you should run the test with the tux -o -d ddlx -c"-d Pcmcetsts 0" command line. If you plug a PC Card into socket 1, you should run the test with the tux -o -d ddlx -c"-d Pcmcetsts 1" command line. If you modify the command line for the test to specify socket 0 or socket 1, the test does not run until you plug a card into the slot that you specified.

If you plug in a PC Card prior to launching the test, when you launch the test a dialog box prompts you to remove the card. After you remove the card, the test updates the registry, and then prompts you with a second dialog box to plug in the PC Card. After you plug in the card, the test runs.

If you do not plug in a PC Card prior to launching the test, when you launch the test the test updates the registry and then prompts you with a dialog box to plug in a PC Card. After you plug in the card, the test runs.

Note   For a headless device, a debug message appears in the Microsoft Platform Builder IDE rather than a dialog box on the display of the target device.

The following table shows the test cases for the PCMCIA Controller Driver Test.

Test case Description
1001-1007 Configures the PC Card using the CardRequestConfiguration, CardReleaseConfiguration, and CardAccessConfigurationRegister functions. Test cases 1001-1005 configure the card as a modem card with varying settings for I/O address space and interrupt request (IRQ). Test case 1006 configures the card as a memory card. Test case 1007 exercises the CardAccessConfigurationRegister function.
1021, 1022 Verifies that the card supports exclusive access using the CardRequestExclusive and CardReleaseExclusive functions. Test case 1021 configures the card as an I/O card and test case 1022 configures the card as a memory card.
1041, 1042 Tests the CardRequestIRQ and CardReleaseIRQ functions. These functions configure the card as a modem card and continuously dial out.
1061-1064 Tests the CardGetStatus, CardGetEventMask, CardSetEventMask, CardRequestSocketMask, CardReleaseSocketMask, and CardResetFunction functions.
1081-1083 Tests the CardGetFirstTuple, CardGetNextTuple, CardGetParsedTuple, and CardGetTupleData functions.
1101-1113 Tests window-related functionality. Test cases 1101-1103 test the CardMapWindow function. Test cases 1104-1106 test the CardModifyWindow function. Test cases 1107-1113 test these functions with invalid input values.

Remarks

All test cases exercise the CardRegisterClient and CardDeregisterClient functions.

If any test case fails, you can refer to the debug output messages to find out which function calls failed.
