Tux

Tux consists of two components, the Tux client (Tux.exe) and the Tux server (Tuxsrv.exe). The Tux client is the Tux engine, while the Tux server acts as a remote UI and administration tool. The Tux client is a console application that loads and executes Tux test modules. The Tux server remotely controls one or more Tux clients and allows you to load and unload Tux test modules, select test cases to run from each loaded module, execute selected tests, and tally results.

The following list describes the various advantages of the Tux client/server architecture.

  • One Tux server can control multiple Tux clients.
  • Separate address spaces for the test engine and the UI minimize the possibility of conflicting code and errors.
  • Separate address spaces allow the Tux server to keep running and provide results, even when the client causes a crash.
  • The test engine has a small memory footprint and working set size.
  • Tests do not compete with the test harness for the UI, because the entire UI for the harness is on the Tux server.
  • You can remotely monitor the status of full-screen tests.
  • You can port the Tux client to any platform that supports a minimal set of Microsoft® Win32® and Winsock APIs while taking advantage of the UI on the Tux server.
  • You can run the Tux client without the Tux server in stand-alone mode, which is useful for batch testing.
