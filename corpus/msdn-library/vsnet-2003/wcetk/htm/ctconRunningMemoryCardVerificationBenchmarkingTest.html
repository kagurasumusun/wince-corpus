Running the Storage Device Block Driver Benchmark Test

The Storage Device Block Driver Benchmark Test executes the tux –o –d rw_all command line on default execution. Prior to running this test, be aware that any information on the storage device is destroyed. The test writes to and reads from every sector on the storage device without preserving the contents of the storage device. The test tests each PC Card that is inserted in the system, assigning one thread to each card. Microsoft recommends that you back up data on all cards and disks that are attached to the tested device before running the test.

Note   This test may take a long time to complete when you test a storage device with large data capacity because the test reads from and writes to each sector multiple times. Microsoft recommends that you run this test on a storage device with a data capacity of 64 MB or less.

This Storage Device Block Driver Benchmark Test communicates directly with the device drivers. The device drivers are in a layer that is below the file system layer and the file allocation table (FAT) layer. If you have problems with the file system, you may be able to isolate the problem to a specific layer.

The test cases for the Storage Device Block Driver Benchmark Test differ only by the number of sectors that are read or written during each I/O burst. The more sectors you read from or write to at one time, the faster the test runs, because of overhead in running the test. None of these test cases stress the device driver, so it is safe to choose any test case. You may attribute the failure of a test case to defective hardware.

The test starts by displaying basic information about the storage device. This information contains the name of the device, the handle of the device, the number of sectors on the device, and the number of bytes per sector. Information about cylinders, heads, sectors, and flags is not given, because this information is not relevant to the Storage Device Block Driver Benchmark Test.

If the device driver does not return an error, the test shows how many sectors it writes to and how long, in milliseconds, the operation takes to complete. A message then displays indicating that the test is attempting to read from those sectors. If the device driver does not return an error, the test attempts to verify that the data read is correct.

If this pattern of successfully writing to and reading from sectors continues to the end of the storage device, the test outputs a report that shows access times, and then returns a passing value to Tux.exe. If the test passes, you can assume that the driver and the storage device are working properly.

Note   In running the test, anticipate that in certain situations, timing issues may arise. For example, a linear flash card requires more time to complete a write operation than other storage devices.

The following table shows the test cases for the Storage Device Block Driver Benchmark Test.

Test case Description
1001: 1 Sector at a time Writes to and reads from all sectors one sector at a time.
1002: 4 Sectors at a time Writes to and reads from all sectors four sectors at a time.
1003: 16 Sectors at a time Writes to and reads from all sectors 16 sectors at a time.
1004: 32 Sectors at a time Writes to and reads from all sectors 32 sectors at a time.
1005: 64 Sectors at a time Writes to and reads from all sectors 64 sectors at a time.
1006: 128 Sectors at a time Writes to and reads from all sectors 128 sectors at a time.
1007: 5 Sectors at a time Writes to and reads from all sectors five sectors at a time.
1008: 13 Sectors at a time Writes to and reads from all sectors 13 sectors at a time.
1009: 129 Sectors at a time Writes to and reads from all sectors 129 sectors at a time.

Remarks

This test library can have one or more optional command-line entries to change the behavior of the test. To specify one or more optional command-line entries to the test library, you must use the –c command-line option. This option forces Tux to pass the specified string into the test library.
