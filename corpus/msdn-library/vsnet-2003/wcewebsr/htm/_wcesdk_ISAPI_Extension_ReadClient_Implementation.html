ISAPI Extension ReadClient Implementation

The extension control block member lpbData and the size of the client read buffer is specified by the cbAvailable value. The total number of bytes the client is going to send is specified by the cbTotalBytes value.

If the cbTotalBytes value is equal to the cbAvailable value, then all the data from the client has been read and there is no need to call ReadClient. If the cbTotalBytes value is greater than the cbAvailable value, then you will need to call ReadClient to make the Web server read more data from the client browser. The Web server will read in, at most, the number of bytes specified in the registry value PostReadSize before calling the ISAPI extension. If less than this number of bytes is sent across, cbTotalBytes will be equal to cbAvailable. If more than this number of bytes is sent across, the ISAPI extension is responsible for reading more data by way of ReadClient.

The advantage to using multiple calls to ReadClient is related to Windows CE memory constraints. You may want to use the Web Server to upload a 10-MB file to a flash card. You may have only 2 MB of RAM available, but sufficient storage space is available on the card. If the entire buffer from the client were read at once, the device would run out of physical memory. However, if you use a 4-KB buffer while calling ReadClient and call WriteFile immediately after each call, you can minimize the amount of RAM required.

If you use ISAPI ReadClient, you need to use caution when writing ISAPI filters that receive notifications for read raw data events.
