Debugging ISAPI Extensions and Filters

Because the Web server is loaded on startup, typically you would have to use a kernel-mode debugger to debug ISAPI extensions and filters. To make it easier to debug ISAPI applications, an executable version of the Web server, HTTPDEXE, is provided with Microsoft Platform Builder. HTTPDEXE is identical to the Web server, except that it runs as an executable application.

Keep in mind that because HTTPDEXE is not running as a DLL, the Web server administration tools have no effect. To turn the HTTPDEXE server off, you must restart your device.

Running the Web server as an executable application offers increased isolation from faulty extensions and filters. When the Web server is run as a Device.exe file, it is possible for a faulty ISAPI extension or ISAPI filter to destabilize the system. If the Web server is run as an executable application, ISAPI extensions and filters are in a different address space from system threads, which reduces the possibility of system corruption. If you want additional stability and do not plan to administer the Web server remotely, you should run the Web server as an executable application.

Another way to run the Web server on Windows CE is through Services.exe. Services.exe is like device.exe in that it hosts multiple services. Services.exe is designed to isolate nonsystem services such as the Web server from the device drivers running in Device.exe. This also decreases the likelihood that a crash in an ISAPI extension or filter will crash the system. However, it may crash services.exe and all running services under it.

Services.exe can be configured to act as a super server that listens on multiple sockets for multiple services on one thread and dispatches incoming connections to services. The Web server has been modified so it can be run as a super service or through Device.exe.

Note   When the Web server is run as a super server, the values for Port in the Web server base registry key and SSL base registry key are ignored. Instead, port information is configured through the super services that services.exe runs.

For more information, see the documentation on Services.exe.
