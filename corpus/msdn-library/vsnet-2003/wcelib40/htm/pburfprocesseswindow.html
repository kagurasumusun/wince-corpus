Processes Window

The Processes window displays information on all processes running on the target device. The window provides different information if the debugger is running or if it is at a debug stop or breakpoint.

Note   If a process has been started using Cesh.exe, the Processes window will not respond until that process has completed.
When the debugger is running
Process Name
Displays the name of the Process.
Process address
Displays the base address for the process in the global virtual address space of the target device. For example, if the relative address of a local variable in Graphics, Windowing, and Events Subsystem (GWES) is 0x000568f0, add its address to the base address of GWES, 0x06000000, and use address 0x060568f0 to access the variable in the debugger.
Access Key
Displays the access key bits that are needed for a thread to be able to see the address space of the process. This corresponds directly to the index entry of the process.
Process Handle
Displays the handle to the process.
CurZoneMask
Displays the current debug zone setting effective for this process. Debug zones allow you to debug by enabling macros that control the output of debug messages.
When the debugger is at debug stop
Name
Displays the name of the process.
VMBase
Displays the base of the process's memory section, or 0 (zero) if not in use.
AccessKey
Displays the access key bits that are needed for a thread to be able to see the address space of the process. This corresponds directly to the index entry of the process.
TrustLevel
Trust level of the process.
hprocess
Handle to the process.
BasePtr
Base pointer of the process load.
TlsUseL32b
Displays the TLS in-use bitmask for the first 32 slots. Thread local storage (TLS) is a Win32 mechanism that allows multiple threads of a process to store data that is unique for each thread.
TlsUseH32b
Displays the TLS in-use bitmask for the second 32 slots.
CurZoneMask
Displays the current debug zone setting effective for this process. Debug zones allow you to debug by enabling macros that control the output of debug messages.
pProcess
Displays the pointer to the process.
CmdLine
Pointer to the command line with which the process was started.
Shortcut Menu
Right-click the window to bring up the shortcut menu, which contains the following options.
Item Description
Refresh Deletes all entries in the window, allowing only current entries to appear.
Auto Refresh on Step Automatically refreshes the window as you step through a process. Click to turn on or off, if it is on.
Terminate Process Terminates the selected process.
Log Formats and moves all the current data in this window to the Log tab of the Output window.
Auto Log on Step Automatically moves the data in this window to the Output window after each debugging step. Click to turn on or off, if it is on.

Selecting Auto Log on Step also turns on Auto Refresh on Step. You can turn Auto Refresh on Step off manually at any time.
Debug Zones Select to bring up the Debug Zones dialog box.
Open in Threads Window Opens the Threads Window for the selected process.
Docking View Switches the active window from docking to nondocking mode. A check mark appears if the window is in the docking mode. When a window is in docking mode, it can be either docked to the border of the main Platform Builder window or, by pressing the CTRL key and clicking on the frame of the window, it can be changed to a floating window. This floating window can be moved outside of the main Platform Builder window and can be redocked at any time. If the window is in nondocking mode, it appears inside of the main Platform Builder window and can no longer be docked.
Hide Hides the Processes window.
