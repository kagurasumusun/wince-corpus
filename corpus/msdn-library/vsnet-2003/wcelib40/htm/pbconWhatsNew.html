Microsoft Windows CE .NET  

What's New

Microsoft® Windows® CE .NET 4.1 contains the following broad range of new and enhanced features:

  • Wireless technologies such as Bluetooth.
  • Next generation of network layer protocols, such as TCP/IPv6 support. TCP/IPv6 supports a significantly larger address space.
  • Device Management, which allows you to install applications and update software without involving the user.
  • File Viewers, which allow you to display documents created in Microsoft Word or Microsoft Excel, display Microsoft PowerPoint® presentations, and control how images are viewed.
  • Web notifications, which inform you when important quick fix engineering (QFE) releases, updates, and information related to creating Windows CE-based platforms are available from Microsoft.
  • Device emulation, which enables you emulate a device without any additional hardware.
  • Rich multimedia and browsing capabilities, such as Microsoft Internet Explorer 5.5 and Microsoft Windows Media™ codecs and controls.
  • New Help documentation about security best practices for most features. Security best practices content was created to help you design a more secure OS and use applications to mitigate security risks.

For more information about the new OS features, see New OS Features.

Windows CE .NET Test Kit The Windows CE .NET Test Kit (CETK) is a testing tool that incorporates command line tests into a graphical user interface (GUI). The tests are designed to assist you in testing your device drivers for the Windows CE OS.

The CETK is not included in the Platform Builder IDE. You can open the CETK from the Start menu by choosing All Programs, choosing Microsoft Windows CE .NET 4.1, and then choosing Windows CE .NET 4.1 Test Kit.
Enhanced Command Line Editor Allows you to permanently modify the command line for a test. You can also use the Command Line Editor for the CETK to apply the modified command line to all instances of the test within the CETK. If you modify the command line in this fashion, each time you select the test on a target device in the Windows CE .NET Test Kit window the test has the modified command line rather than the default command line. If you do not want to modify the command line for all instances of the test, you can apply the modification only to the target device for which you made the change. You can also reset the command line to the default setting.
Test Suite Editor Allows you to create and manage test suites for the CETK. A test suite is a selection of tests that is stored by the CETK and can be applied to any device using the CETK. You can use the Test Suite Editor to create a test suite that contains tests that you want to run. Rather than selecting each individual test on your device, you can simply apply the test suite to the device to automatically select the tests that you selected in the Test Suite Editor.
New tests for the CETK The following tests are new tests for the CETK:
  • File System Driver Test

    Tests a file system driver (FSD) that uses the Microsoft Win32® application programming interface (API). This test can identify problems with a storage device block driver that runs under the file allocation table (FAT) FSD. You can also use this test on a new FSD.

  • CD/DVD-ROM File System Driver Test

    Tests the file system that runs over a CD or DVD-ROM driver.

  • PCMCIA Controller Driver Test

    Tests the API of a custom driver for the PCMCIA controller. It is not necessary to run this test on the PCMCIA driver distributed with Windows CE .NET 4.1.

  • Printer Driver Test

    Tests the functionality of a printer driver that communicates over serial, parallel, USB, infrared (IR), or network connection.

  • Telephony API Server Test

    Verifies that a peripheral supports the ability to complete inbound calls using the Telephony API (TAPI).

  • Winsock 2.2 Test (v4/v6)

    Tests Winsock 2.2 and the transport stacks for IPv4 and IPv6. The test also verifies if it is possible to transfer data using the Ethernet network driver.

  • Winsock Stress Test

    Performs a large number of socket operations to stress the Winsock component. The socket operations may in turn stress the remainder of the networking stack.
