CWaitCursor

CWaitCursor does not have a base class.

This class provides a one-line way to show a wait cursor, which is usually displayed as an hourglass, while you are doing a lengthy operation. Good Windows CE programming practices require that you display a wait cursor whenever you are performing an operation that takes a noticeable amount of time.

To display a wait cursor, define a CWaitCursor variable before the code that performs the lengthy operation. The constructor of the object automatically causes the wait cursor to be displayed.

When the object goes out of scope (at the end of the block in which the CWaitCursor object is declared), its destructor sets the cursor to the previous cursor. That is, the object performs the necessary clean-up automatically.

Because of the way their constructors and destructors work, CWaitCursor objects are always declared as local variables — they are never declared as global variables nor are they allocated with new.

If you perform an operation which might cause the cursor to be changed, such as displaying a message box or dialog box, call the Restore method to restore the wait cursor. You may call Restore even when a wait cursor is currently displayed.

Another way to display a wait cursor is to use the combination of CCmdTarget::BeginWaitCursor, CCmdTarget::EndWaitCursor, and perhaps CCmdTarget::RestoreWaitCursor. However, CWaitCursor is easier to use because you do not need to set the cursor to the previous cursor when you are finished with the lengthy operation.

MFC sets and restores the cursor using the CWinApp::DoWaitCursor virtual function. You can override this function to provide custom behavior.

Example

BOOL CMyWnd::SomeLengthyProcess()
{
  CWaitCursor wait;
  //Do the lengthProcessing.

  MessageBox("Some result");    //This changes the cursor.
  wait.Restore();      //Restore the Wait cursor.
  //Continue Processing.

  //The destructor changes the cursor back to Regular cursor.
  return TRUE;      

}
