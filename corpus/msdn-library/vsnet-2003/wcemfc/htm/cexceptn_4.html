CException::GetErrorMessage

This method provides text about an error that has occurred. For example, call GetErrorMessage to retrieve a string describing the error that caused MFC to throw a CFileException when writing to a CFile object.

GetErrorMessage will not copy more than nMaxError –1 characters to the buffer, and it always adds a trailing null to end the string. If the buffer is too small, the error message may be truncated.

virtual BOOL GetErrorMessage(
LPTSTR lpszError,
UINT nMaxError,
PUINT pnHelpContext = NULL );

Parameters

lpszError
Specifies a pointer to a buffer that will receive an error message.
nMaxError
Specifies the maximum number of characters the buffer can hold, including the NULL terminator.
pnHelpContext
Specifies the address of a UINT that will receive the help context identifier. If NULL, no identifier will be returned.

Return Value

Nonzero if the function is successful; otherwise, it is zero if no error message text is available.

Example

CFile fileInput;
CFileException ex;

// Try to open a file for reading.
// The file will absolutely not
// exist because there are too many explicit
// directories in the name.
// If the call to Open() fails, ex will be
// initialized with exception
// information. The call to ex.GetErrorMessage()
// will retrieve an appropriate message describing
// the error, and we will add our own text
// to make sure the user is completely sure what
// went wrong.

if (!fileInput.Open(_T("\\Too\\Many\\Bad\\Dirs.DAT"), CFile::modeRead, &ex))
{
  TCHAR  szCause[255];
  CString strFormatted;

  ex.GetErrorMessage(szCause, 255);

  // In real situations, it is
  // appropriate to read this from
  // a string resource so it would be easy to
  // localize.

  strFormatted = _T("The data file could not be opened because of this error: ");
  strFormatted += szCause;

  AfxMessageBox(strFormatted);
}
else
{
  // The file was opened, so complete whatever work
  // with the fileInput which
  // we were planning.
  // :

  fileInput.Close();
}
