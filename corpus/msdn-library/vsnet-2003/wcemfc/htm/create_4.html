Creating Pocket PC Executable Files Using MFC

Use the Pocket PC MFC AppWizard (exe) to create executable files for the Pocket PC platform. This wizard is similar to the generic MFC exe wizard, but provides the additional architecture option of DocList-type applications for the Pocket PC.

To access the wizard, open the New dialog box by choosing File | New. Select the Projects tab to display available wizards.

  • Step 1 of 4 of the wizard lets you choose between single document, single document with a DocList window, and dialog-based architecture, and lets you specify what language you want your Resources in.
  • Step 2 of 4 presents a set of options dependent on the architecture choices you make in Step 1. In any case you can enable TCP/IP communication and provide for ActiveX controls.
    • If in Step 1 you choose single document with or without doclist, you can specify a control-bar type and a Shared New menu style.
    • If in Step 1 you choose a dialog-based architecture, you can retitle your dialog.
  • Step 3 of 4 lets you specify whether the MFC library should be statically linked at build time or linked as a shared DLL at runtime. This step also lets you choose to have automatic comments generated in your source code.
  • Step 4 of 4 gives you the chance to make changes in the names the wizard has generated automatically.

The following table outlines the items you can specify in Step 1 of 4 of the wizard.

To... Do This...
Specify the architecture Select Single document to generate an SDI-based project. You can then select Document/View architecture support if you want to use CDocument and CView base classes. If you are porting a non-MFC application, clear the checkbox.

-Or-

Select Dialog based to generate a program that displays a dialog box for user input based on a dialog-template resource. You can change the title of your dialog in step 2 of the wizard.

-Or-

Select Single document with Doc List to generate an application based on the CCeDocList class.
Specify the language for your resources Use the drop-down list to select from among the languages available on your system. If you select a language other than English, the DLL for that language must be already installed. The filenaming convention is APPWZXXX.DLL, where XXX is a three-letter language identifier.

The following table outlines the items you can specify in Step 2 of 4 of the wizard.

To... Do This...
Let your program communicate over TCP/IP networks Select Windows Sockets
Let your program use ActiveX controls Select ActiveX Controls.
Generate a New menu style that lets the user open a list of other applications (not available for dialog-based architecture) Select Shared New.
Specify control bar type (not available for dialog-based applications) To implement the Basic MenuBar (displaying both menus and buttons), select Basic MenuBar.

To implement Internet Explorer-style rebars, select Internet Explorer ReBars.

The following table outlines the items you can specify in Step 3 of 4 of the wizard.

To... Do This...
Source file comments? Select Yes to automatically generate comments in the source code.
Libary as shared or statically linked? To link the MFC library as a shared DLL so that your program calls it at run time, select As a shared DLL.

To link the MFC library at build time, select As a statically linked library.

The following table outlines the items you can specify in Step 4 of 4 of the wizard.

To... Do This...
Change file names, base classes Use the edit boxes to make changes to the automatically generated names. You can also change the base class of some files. For example, here is where you could substitute CScrollView for CView as the base view class for a Document/View application.
