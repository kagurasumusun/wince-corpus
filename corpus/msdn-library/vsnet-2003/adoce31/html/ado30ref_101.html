Error Values Reference

ADOCE can generate both ADOCE errors and SQL errors. ADOCE errors occur when the methods and properties of the ADOCE control are used improperly, such as trying to update a read-only recordset. SQL errors are generated when there is an error in an SQL statement used in the Open method.

You can use the On Error Resume Next statement along with inline error trapping to catch errors. After you perform an operation, check for inline errors by looking at the Err object to see if Err.Number is nonzero. By using the error code returned in Err.Number, you can handle each error appropriately.

Filtering errors can occur when you move a database between a desktop computer and a Windows® CE-based device using ActiveSync 3.1 or the ADOCE API.

When used on the Pocket PC® platform, the ADOCE control may return unspecified errors. If the high-word of these returned errors is 8007 (the error code in hex is 8007xxxx), then the low-word is the Windows CE system error code as returned by GetLastError. Some of these errors are documented in the following topics. Additional errors can be found in the winerror.h file that ships with the Pocket PC® SDK.
