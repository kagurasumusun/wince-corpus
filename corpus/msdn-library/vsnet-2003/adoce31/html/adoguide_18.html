Working with the Error collection

When a data-related error occurs, the data source provider captures information about that error in the Error collection. By programmatically examining the contents of the Error collection, errors can be handled and information can be given back to the user about the error. The Error collection only contains error information returned from a data source provider. ADOCE errors are recorded in the eMbedded Visual Basic Err object. In order to read the Errors collection, you will have to trap the errors using one of the eMbedded Visual Basic techniques for error trapping, such as On Error Resume Next.

The Error collection is a property of the Connection object and is accessed through the Connection object. Like other collections, the Item and Count properties can be used to access information about the collection. The Clear method can also be used on the Errors collection to reset the contents of the collection. The data source provider determines the return value of the properties for an Error object in an Errors collection. Not all providers will supply information for all the Error object properties, and some providers may support additional properties. Check the documentation for the data source provider for more information. The following table lists the properties of each Error object and notes which properties are supported by the proprietary database.

Error Object Property CEDB Support?
Description Yes
HelpContext No
HelpFile No
NativeError Yes
Number Yes
Source Yes

The following code example demonstrates how to iterate through the Errors collection and display information about errors that have occurred.

For Each errobj In newcn.Errors
    lblErrors.Caption errobj.Number & errobj.Description
