Using Colors on Multiple Displays

For a multiple screen system, all screens must have the same color depth. If the primary screen uses a palette, the SelectPalette and RealizePalette functions work in the same manner as those functions work on a single screen system, but across all screens. In addition, the palettes of all screens are synchronized.

The OS automatically handles painting into a device context that spans more than one screen. Usually, allowing the OS to automatically handle the painting produces good results, but the results can sometimes be less than optimal. To get the best results for each of the screens in a device context that spans more than one screen, call EnumDisplayMonitors to enumerate the screens that intersect your device context and paint the intersecting area in each of the screens separately, according to the display attributes for each screen.

The following code example shows how to paint the entire virtual screen optimally for each screen.

hdc = GetDC(NULL);
EnumDisplayMonitors(hdc, NULL, MyPaintScreenEnumProc, 0);
ReleaseDC(NULL, hdc);

The following code example shows how to paint the top half of a window using the capabilities of each screen.

GetClientRect(hwnd, &rc);
rc.bottom = (rc.bottom - rc.top) / 2;
hdc = GetDC(hwnd);
EnumDisplayMonitors(hdc, &rc, MyPaintEnumProc, 0);
ReleaseDC(hwnd, hdc);

If you perform all of your drawing in your code for handling the WM_PAINT message, you should be able to place your WM_PAINT code in the MonitorEnumProc callback function with only a few modifications.

The following code example shows how to paint in response to a WM_PAINT message using the capabilities of each screen.

case WM_PAINT:
hdc = BeginPaint(hwnd, &ps);
EnumDisplayMonitors(hdc, NULL, MyPaintEnumProc, 0);
EndPaint(hwnd, &ps);
