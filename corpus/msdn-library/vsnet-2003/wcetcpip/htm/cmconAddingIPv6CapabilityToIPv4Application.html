Adding IPv6 Capability to an IPv4 Application

You can add IPv6 capability to your Microsoft Windows application while still retaining IPv4 functionality. You do this by porting the IPv4 application to one that works with IPv4 and IPv6.

The document titled IPv6 Guide for Windows Sockets Applications at this Microsoft Web site contains complete, working examples of a simple Windows Sockets application that has been modified to support both IPv6 and IPv4.

The following table shows the major things to consider when porting.

Element to consider Consideration
Data Structures Because the size of an IPv6 address is much larger than an IPv4 address, you must ensure that your application defines properly sized data structures. You must change structures that are hard-coded to handle the size of an IPv4 address.
Functions You must ensure all functions support IPv6 addresses. The checkv4 utility identifies functions that do not support IPv6 addresses.
Note   Most Windows Sockets (Winsock) 2.2 functions support IPv6 addresses.
Hard Coded IPv4 Addresses Avoid hardcoding addresses. You must modify code that uses hard coded addresses or literal strings with code that works with both IPv4 and IPv6.
User Interface In general, due to the length of IPv6 addresses, you should use address names in the UI instead of 128-bit addresses.

Consider the variability in the size of an IPv6 address when porting an application. For more information, see Internet Protocol version 6 Addressing and IPv6 Addresses.

You can use the Checkv4 utility in the build release directory command window in Platform Builder to identify code in your application that may be sensitive to porting. The Checkv4.exe utility documentation includes tips on the order in which to address IPv6-enabling issues (the order in which to approach the porting process in your applications). The utility recommends how to resolve the sensitivity. For information about using the Checkv4 utility to port an application, see Porting an IPv4 Application to IPv6.

Best Practices

  • To ensure that structures are properly sized, and that your functions handle both IPv4 and IPv6, you must change functions and structures as shown in the following table.
    Change from Change to
    GetAdaptersInfo GetAdaptersAddresses
    gethostbyaddr getaddrinfo
    gethostbyname getnameinfo
    gethostname getaddrinfo or getnameinfo
    inet_addr SOCKADDR_STORAGE
    inet_ntoa SOCKADDR_STORAGE
    IP_ADAPTER_INFO IP_ADAPTER_ADDRESSES
    SOCKADDR SOCKADDR_STORAGE
    SOCKADDR_IN SOCKADDR_STORAGE
  • When using the getaddrinfo function, the application must perform name resolution before it opens the socket. For example, for IPv4, you could open the socket, then perform name resolution, and finally connect to the interface. For IPv6, you must always perform the name resolution first.
  • Decide whether to use names or number-based IPv6 addresses. If you use names, consider using naming conventions for the user interface and for use in error checking.
  • Ensure fields in the user interface are sufficient length to display IPv6 addresses. For maximum IPv6 address string length, see INET_ADDRSTRLEN in ws2tcpip.h.
  • Consider whether the information provided for IPv4 is appropriate for IPv6.
  • The capability to specify an IP address should depend on whether IPv4 is in use or if IPv6 is available.
  • Thoroughly search and test the code for literal strings.

Code Examples

The following code example for an IPv6 server shows how to use the SOCKADDR_STORAGE structure, which handles both IPv4 and IPv6 addresses.

#include <winsock2.h>
#include <ws2tcpip.h>
#include <windows.h>
#include <tchar.h>

#define DEFAULT_FAMILY      PF_INET6
#define DEFAULT_SOCKTYPE   SOCK_STREAM
#define DEFAULT_PORT      "1234";

int _tmain (int argc, TCHAR* argv[])
{
   SOCKET sock, SockServ[FD_SETSIZE];
   int nFamily = DEFAULT_FAMILY;
   int nSockType = DEFAULT_SOCKTYPE;
   char *szPort = DEFAULT_PORT;
   TCHAR szOutput[256];
   SOCKADDR_STORAGE ssRemoteAddr;
   int i, nNumSocks, cbRemoteAddrSize;
   WSADATA wsaData;
   ADDRINFO Hints, *AddrInfo, *AI;
   fd_set fdSockSet;

   if(WSAStartup(MAKEWORD(2,2), &wsaData))
   {
      // WSAStartup failed
      return 1;
   }

   memset(&Hints, 0, sizeof(Hints));
   Hints.ai_family = nFamily;
   Hints.ai_socktype = nSockType;
   Hints.ai_flags = AI_NUMERICHOST | AI_PASSIVE;

   if(getaddrinfo(NULL, szPort, &Hints, &AddrInfo))
      return 1;

   i = 0;
   for(AI = AddrInfo; AI != NULL; AI = AI->ai_next) 
   {
      if (i == FD_SETSIZE) 
      {
         // getaddrinfo returned more addresses than we could use
         break;
      }

      if((AI->ai_family == PF_INET) || (AI->ai_family == PF_INET6)) // only want PF_INET or PF_INET6
      {
         SockServ[i] = socket(AI->ai_family, AI->ai_socktype, AI->ai_protocol);
         if (SockServ[i] != INVALID_SOCKET)
         {
            if (bind(SockServ[i], AI->ai_addr, AI->ai_addrlen) == SOCKET_ERROR)
               closesocket(SockServ[i]);
            else 
            {
               if(nSockType == SOCK_STREAM)
               {
                  if (listen(SockServ[i], 5) == SOCKET_ERROR)
                     closesocket(SockServ[i]);
                  else
                     i++;   // TCP serv socket setup successfully
               }
               else
                  i++; // UDP serv socket setup successfully
            }
         }
      }
   }
   
   freeaddrinfo(AddrInfo);
   
   if (i == 0) 
   {
      // unable to serve on any address
      return 1;
   }

   nNumSocks = i;

   FD_ZERO(&fdSockSet);

   for (i = 0; i < nNumSocks; i++)   // want to check all available sockets
      FD_SET(SockServ[i], &fdSockSet);

   if (select(nNumSocks, &fdSockSet, 0, 0, NULL) == SOCKET_ERROR)
   {
      // select() failed
      return 1;
   }

   for (i = 0; i < nNumSocks; i++)   // check which socket is ready to process
   {
      if (FD_ISSET(SockServ[i], &fdSockSet))   // proceed for connected socket
      {
         FD_CLR(SockServ[i], &fdSockSet);
         if(nSockType == SOCK_STREAM)
         {
            cbRemoteAddrSize = sizeof(ssRemoteAddr);
            sock = accept(SockServ[i], (SOCKADDR*)&ssRemoteAddr, &cbRemoteAddrSize);
            if(sock == INVALID_SOCKET) 
            {
               // accept() failed
               return 1;
            }

            char szClientName[128];
            if (getnameinfo((SOCKADDR*)&ssRemoteAddr, cbRemoteAddrSize,
               szClientName, sizeof(szClientName), NULL, 0, NI_NUMERICHOST) != 0)
               strcpy(szClientName, "");
            _stprintf(szOutput, TEXT("Accepted TCP connection from client %hs\r\n"), szClientName);
            OutputDebugString(szOutput);
         }
         else
            sock = SockServ[i];

         break;      // Only need one socket
      }
   }

   for(i = 0; i < nNumSocks; i++)
      closesocket(SockServ[i]);

   shutdown(sock, SD_BOTH);
   closesocket(sock);

   WSACleanup();

   return 0;
}

The following code example shows using the getaddrinfo function, which handles both IPv4 and IPv6 addresses.

SOCKET
OpenAndConnect(char *ServerName, char *PortName, int SocketType)
{
    SOCKET ConnSocket;
    ADDRINFO *AI;

    if (getaddrinfo(ServerName, PortName, NULL, &AddrInfo) != 0) {
        return INVALID_SOCKET;
    }

    ConnSocket = socket(AI->ai_family, SocketType, 0);
    if (ConnSocket == INVALID_SOCKET) {
        return INVALID_SOCKET;
    }

    if (connect(ConnSocket, AI->ai_addr, AI->ai_addrlen) == SOCKET_ERROR) {
        closesocket(ConnSocket);
        return INVALID_SOCKET;
    }

    return ConnSocket;
}
