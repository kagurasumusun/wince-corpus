Porting an IPv4 Application to IPv6

You can modify an application to support both IPv4 and IPv6. For information about things to consider when porting to IPv6, see Adding IPv6 Capability to an IPv4 Application.

To Port an IPv4 application to IPv4/IPv6 application

  1. Determine the user interface elements that are dependent on a specific length for the IP address string.
  2. Determine whether it is appropriate to display the address when using IPv6. If it is appropriate, change the controls so they can display an IPv6 address. If it is possible that either IPv4 or IPv6 addresses can be used, ensure that the user interface can accommodate either.
  3. In Platform Builder, open the build release directory command window.
  4. At a command prompt, type Checkv4 <filename>, where filename is the name of the file you want to check.

    Checkv4 parses the file and provides feedback as to where IPv6 porting issues exist in that file.

    Note   Some recommendations made by the Checkv4 utility require structures available only in recent versions of the Ws2tcpip.h header file, such as SOCKADDR_IN6 structure. These header files are available in Platform Builder version 4.1.
  5. Using the Checkv4 output as a guide, fix the structures and declarations to enable IPv4/IPv6 compatibility.
  6. Review the source code for hard-coded loopback addresses or other literal strings.
  7. Review the user interface, including informational dialog boxes. Consider whether the information is appropriate for IPv6.
  8. Determine whether the application relies on underlying protocols or programming interfaces, such as DCOM. If the underlying protocol or interface does not handle IPv6 in a transparent manner, make the appropriate programmatic changes to handle IPv6 addresses.
  9. Test the user interface. The following list shows the expected behavior:
    • Changes accommodate both IPv6 and IPv4 addresses
    • Protocol address display locations, such as informational dialog boxes, handle IPv6 addresses properly.
