ActivateDeviceEx

This function loads a device driver and adds its registry values to the Active key in the registry. 

HANDLE ActivateDeviceEx(
LPCWSTR lpszDevKey, 
LPCVOID lpRegEnts, 
DWORD cRegEnts, 
LPVOID lpvParam
);

Parameters

lpszDevKey
[in] A pointer to a string containing the registry path of the device driver's registry key. This key contains the driver's DLL name, prefix, and other data.
lpRegEnts
[in] Points to an array of REGINI structures, each of which defines a registry value to add to the device's Active registry key before its driver is loaded. You should normally set this to NULL unless it is for a bus driver.
cRegEnts
[in] A count of the number of REGINI structures to which lpRegEnts points. This affects a generalization of ActivateDevice.
lpvParam
[in] An opaque pointer to a driver-specific data structure. You can it to pass parameters to the loaded driver without having to write them through the registry. lpvParam is passed to the XXX_Init function as a second parameter. This is intended for bus drivers to use to pass bus-specific information, entry points, or both to loaded drivers. Using this prevents clients of that bus from being able to be bus-agnostic. This is acceptable for some busses.

Return Values

On success, ActivateDeviceEx returns a handle that you can use later as the parameter to DeactivateDevice.

Remarks

ActivateDeviceEx offers more functionality than ActivateDevice. Both of these functions replace RegisterDevice.

ActivateDeviceEx can load non-stream drivers, protocols, and services that are bound to the Device Manager. It can also load multiple drivers with the Registry Enumerator (RegEnum.dll) and can add bus-specific values to the Active key. For more information on RegEnum.dll, see Registry Enumerator.

ActivateDeviceEx reads the registry key specified in lpszDevKey to get the DLL name, device prefix, index, and other values. Next, it adds the device to the active device list, and stores the relevant values there. If there is no device index specified in the key named in lpszDevKey, then it assigns a free index. Then it loads the device driver DLL in the process space of the Device Manager.

ActivateDeviceEx can return zero for success rather than failure. If either DEVFLAGS_NOLOAD or DEVFLAGS_UNLOAD is set in the Flags value of the device key then ActivateDeviceEx returns zero. There is no way to tell the difference between success and failure in that case.

The Index value indicates port numbering with stream interface drivers, such as COM0: or COM1:. If there is no Index value, the Device Manager generates one.

The Flags value is a set of bits to modify the behavior of ActivateDevice; this value is optional and is set to zero if there is no value present. Bits 3 through 23 are reserved and must be set to zero. The driver being loaded may use bits 24 through 31 of the Flags value. The following table shows the defined bits; %_WINCEROOT%\Public\Common\DDK\Inc\Devload.h defines these bits.

Flag Value Description
DEVFLAGS_NONE 0x00000000 No flags defined
DEVFLAGS_UNLOAD 0x00000001 Unload driver after call to entry point XXX_Init, or Init returns.
DEVFLAGS_LOADLIBRARY 0x00000002 Use LoadLibrary instead of LoadDriver
DEVFLAGS_NOLOAD 0x00000004 Do not load DLL
DEVFLAGS_NAKEDENTRIES 0x00000008 Entry points do not have Prefix prepended.
Note   The DEVFLAGS_FSD_NEEDTOWAIT flag also exists. For more information see Hive-Based Registry.

The dwClientInfo parameter of ActivateDevice is a registry entry for the DEVLOAD_CLIENTINFO_VALNAME value.
