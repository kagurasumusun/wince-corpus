IeXdi2OleAutoServer::AddDataBpOle

This method adds a data breakpoint.

HRESULT AddDataBpOle(
  VARIANT bpKind,
  VARIANT MemType,
  VARIANT dwAddressSpace,
  VARIANT dwAddress,
  VARIANT AddressMask,
  VARIANT strRegName,
  VARIANT Data,
  VARIANT DataMask,
  VARIANT RWAccessType,
  VARIANT dwAccessWidth,
  VARIANT dwTotalBypassCount,
  VARIANT* pvtPIeXdiDBP2
);

Parameters

bpKind
[in] Kind of breakpoint (hardware, software, or algorithmic).
MemType
[in] Type of memory (physical, virtual, or peripheral I/O).
dwAddressSpace
[in] Address space , if breakpoint concerns physical memory or peripheral I/O.
dwAddress
[in] Address of the data to be accessed to break on.
AddressMask
[in] Mask to apply to data at dwAddress for matching.
strRegName
[in] Name of register to be monitored.
Data
[in] Value of data to be accessed for breaking on.
DataMask
[in] Mask to apply on data comparison.
RWAccessType
[in] Data access type (read, write, or both).
dwAccessWidth
[in] Data width specification.
dwTotalBypassCount
[in] Total number of bypasses to allow before triggering a CPU halt on this breakpoint.
pvtPIeXdiDBP2
[out, retval] Pointer to IeXdi2DataBP object interface for this breakpoint.

Return Values

The following table shows return values for this method.

Value Description
S_OK Indicates the function was successful.
E_FAIL Indicates an unspecified failure.
E_NORESAVAILABLE Indicates a breakpoint resource was not available and the method cannot instantiate all breakpoints.
E_OUTOFMEMORY Failed to allocate necessary memory.
E_INVALIDARG Indicates one or more arguments are invalid.
EXDI_E_COMMUNICATION Indicates a communication error between host driver and debugging target.

Requirements

OS Versions: Windows CE 5.0 and later.
Header: exdi2.h.
Link Library: ole32.lib, oleaut32.lib.
