Tux.Net Test Suites

All test cases that Tux.Net can execute must reside within a test suite. A Tux.Net test suite is a class that derives from Tux.Net's TestSuite base class.

Within a TestSuite class, test methods can be defined that Tux.Net recognizes and executes as test cases. Test methods must be marked using test case attributes in order for Tux.Net to recognize them.

Any assembly that defines a class deriving from TestSuite and which hosts test methods can have these test methods executed by Tux.Net.

The following shows a very simple Test Suite, without any test cases:

    public class BeginEndExample : TestSuite
    {
        // This will be run before any of the
        // tests (methods) in this suite (class).
        public override void Begin()
        {
            base.Begin ();
            // Put any suite level setup code here.
        }

        // Test Methods here...

        // This will run after all the tests (methods)
        // in this suite (class) that will be run
        public override void End()
        {
            // Put any suite level cleanup code here.
            base.End ();
        }
    }

In the above example, the two methods Begin and End are automatically invoked by Tux.Net. Begin will be called before the first test case in the BeginEndExample class is executed, and End will be called after the last. These two methods are virtual methods defined in the TestSuite base class, and their implementation must include a call to the base class method. They are optional methods; you don't have to implement them, but they can be useful.
