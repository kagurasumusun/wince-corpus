Delivering Data as Parameters to Test Cases

Data-driven tests are a good way to maximize the effectiveness of automation. Tux.Net supports data-driven test cases by allowing test cases to accept parameters and providing a way to deliver different sets of parameters from a data file.

To deliver simple data types (strings, ints, etc) as parameters

  1. Add a parameter to the test method and a ParameterAttribute to supply a default value for this parameter
  2. Create a data file (.xml) to supply data to the test case
  3. Provide the .xml file on the Tux.Net command-line

If you need to pass in more than a simple type, we recommend that you create a class to encapsulate the data you want to pass to your test case. You will take an object of the type you have created as a parameter to your test case method. You will supply the data for this class in an xml files, just as with simple data types. Tux.Net will use the data in the xml files to create an instance of your class and pass it to your test method.

The following code shows a test method that takes a simple value and a test method that takes a customized test data class. The customized class is shown as well:

/// <summary>
/// Sample passing int to a test case
/// </summary>
/// <param name="intData"></param>
/// <returns></returns>
[TestCaseAttribute( "Sample passing int to a test case", Type = TestType.Functional )]
[ParameterAttribute( 42 )]
public Logging.LogResult TestInt(int intData)
{
    GlobalLogger.AddComment("inside TestInt");
    GlobalLogger.AddComment("intData = {0}", intData);
    return Logging.LogResult.Pass;
}

/// <summary>
/// Sample: passing object to a test case
/// </summary>
/// <param name="myData"></param>
/// <returns></returns>
[TestCaseAttribute( "Sample: passing object to a test case", Type = TestType.Functional )]
public Logging.LogResult TestMyData(MyData myData)
{
    GlobalLogger.AddComment("inside TestMyData");
    GlobalLogger.AddComment("myData = {0}", myData.ToString() );
    return Logging.LogResult.Pass;
}

/// <summary>
/// Sample class for demonstrating passing an object to a test case
/// </summary>
public class MyData
{
    /// <summary>
    /// Empty constructor needed for serialization
    /// </summary>
    public MyData()
    {
        this.StringData = "hello";
        this.IntData = 42;
        this.ListData.Add("item1");
    }

    /// <summary>
    /// String Data
    /// </summary>
    public string StringData;

    /// <summary>
    /// Int Data
    /// </summary>
    public int IntData;

    /// <summary>
    /// ArrayData
    /// </summary>
    public ArrayList ListData = new ArrayList();

    /// <summary>
    /// Returns data represented as a string for logging
    /// </summary>
    /// <returns></returns>
    public override string ToString()
    {
        return this.StringData + ", " + this.IntData.ToString();
    }
}

You can specify the data you want loaded into your customized test data class from the Tux.Net command line, a commandline.txt file, or a separate xml file. We recommend keeping the test data in a separate xml file for all but the simplest cases. A sample xml file and command line are provided in SampleData.cs and SampleData.xml.
