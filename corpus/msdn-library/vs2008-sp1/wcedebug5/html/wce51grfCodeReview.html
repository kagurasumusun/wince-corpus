Code Review

Code review is likely the most important safeguard we have to ensure quality automation, and thus efficient testing. Getting your code reviewed before checking in is required, but it is also recommended that you send out intermediate code reviews for any large project, or any time you are working on something that is new to you. If you are writing test cases for a feature area, sending out an initial code review after you have written just a couple test cases will catch mistakes early.

All files that you are changing, adding, or deleting must be reviewed. This includes cs, csdproj, and sln files in addition to commandLine.txt, sources, makefile, and dirs. For guidelines on how to review code please see http://devices/site/automation/Standards%20and%20Processes/CodeReviewChecklist.doc. A check-in checklist is also available at http://devices/site/automation/Standards%20and%20Processes/CheckinChecklist.doc. Besides code review, use of FxCop and building from the build window (by typing BuildManaged) are vital steps that you must take before checking in.
