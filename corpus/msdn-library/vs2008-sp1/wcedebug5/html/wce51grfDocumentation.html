Documentation

Documentation of automation code is performed nightly after building. MSDN-style documentation files are produced from XML comments in the code itself. All automation code (UIAL, Area Library, Test, Tools, or other) is expected to use XML comments on all public classes, methods, and variables. These comments will be published to documentation files online, so they should be as useful and descriptive as possible. Here is an example of a fully documented class using XML comments (the triple slashes ///):

/// <summary>
/// Explain what data this class represents and what
/// actions it performs.
/// </summary>
public class DocumentationExample
{
    /// <summary>
    /// One line summary of the purpose of the method.
    /// </summary>
    /// <param name="parameter">
    /// Description of what the parameter is for.
    /// </param>
    /// <returns>
    /// Description of what is returned by the method.
    /// </returns>
    /// <remarks>
    /// Describe preconditions, postconditions, side
    /// effects, or other items of interest.
    /// </remarks>
    /// <exception cref="ArgumentException">
    /// Describe the situation where this exception
    /// might be thrown. Include one of these for every
    /// type of exception that you throw in this method.
    /// </exception>
    public int DoSomethingInteresting(string parameter)
    {
        return 0;
    }

    /// <summary>
    /// Describe the Field variable.
    /// </summary>
    public int Field
    {
        get
        {
            return this.field;
        }
    }

    private int field;
}
