Verification

Whenever possible, verification of success of functionality should be in the Area Libraries instead of test cases. For example, if there is a function in the area library called DialNumber(int number) which dials a given phone number, the verification that the number was dialed (it showed dialing in the UI) should go in the area library instead of the test cases. This reduces duplicated verification code in all the test cases that utilize this function. XML comments should be added to each area library method explaining the verification that was performed in the function so that test cases dont repeat the verification.

Verification of functionality can take many forms. Sometimes you will be checking the properties of controls exposed from the UIAL – such as the text of an edit box or the checked state of a check box. Other times you will simply want to verify that the correct dialog is being displayed as a result of your UI actions. In that case you can use the VerifyAllControls method exposed by every dialog class in the UIAL.
