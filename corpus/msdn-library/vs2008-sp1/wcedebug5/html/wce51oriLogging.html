Logging

The Logging library contains classes associated with logging test data and test result management. The Logging library is generic enough that it can be used by any tool, even desktop tools, and not just by .Net test automation. The main interfaces into the Logging library for .Net Automation are GlobalLogger and GlobalLogResultManager.

MTK, UIAL, Area Libraries, and Test components use GlobalLogger for logging text and comments to log files during testing. GlobalLogger frees you from worrying about where and how to log data; your data is always saved to the file that GlobalLogger has been configured to deliver to. GlobalLogger also has the notion of logging levels, allowing you to assign varying importance to different comments. For instance, UIAL comments may be logged at debug level and only turned on during debugging, whereas comments at the test level would always be logged. GlobalLogResultManager is used for keeping track of the result of your test - Pass or Fail - as you perform multiple steps in each test case. It is used almost exclusively in the "Test Cases and Suites" and "Area Libraries" layers.

More information on Logging is available in the documentation at Tux.Net Test Harness.
