Using TestStep

One way to keep your test cases organized and their results analyzable is to use the TestStep construct to group logically associated actions and verifications. The TestStep construct has two primary uses: logging management and results management. The TestStep helps you with logging management by preceding each TestStep in your log with a description of the step, indenting all logged comments in the step at the same level, and displaying the result of the step upon completion. The TestStep also helps you with results management because it automatically tracks results applied to the GlobalLogResultManager and generates a result per step. This makes it easier to identify the area of code that caused a test failure, because you can see which test steps failed and which did not explicitly in the log file.

The following example illustrates how logging is affected by the use of the TestStep construct. Notice the indentation of each nested step relative to the last outer step, the step descriptions logged at the beginning of each TestStep, and the Verification result logged at the end of each TestStep.

using Manager = Microsoft.MobileDevices.Utils.GlobalLogResultManager;

/// <summary>
/// Example: Test logging with the TestStep class
/// Expected results look like this:
/// *** Test ID:        0
/// UnitTest: Test the TestStep logging feature
/// Logging outside of all test steps
///     [1] Begin Step: Outer test step
///     [1] Logging in outer test step
///         [2] Begin Step: Inner test step
///         [2] Logging in inner test step
///         [2] Outer step currently has result Pass
///         [2] End Step  : Inner test step
///     [1] Verification = Pass: Inner test step
///     [1] Another comment in the outer test step
///     [1] End Step  : Outer test step
/// Verification = Pass: Outer test step
/// Another comment outside of all test steps
/// *** Result:         Passed
/// </summary>
/// <returns>True</returns>
public LogResult TestTestStepLogging()
{
    // This comment is logged outside all test steps
    GlobalLogger.AddComment("Logging outside of all test steps");

    // Everything between the starting and ending braces
    // of this using statement is in the outer test step
    using(TestStep outer = new TestStep("Outer test step"))
    {
        // This comment is logged as part of the outer test step
        GlobalLogger.AddComment("Logging inside the outer test step");

        // Everything between the starting and ending braces
        // of this using statement is part of both the outer
        // and the inner test steps
        using(new TestStep("Inner test step"))
        {
            // This comment is logged as part of the inner test step
            GlobalLogger.AddComment("Logging inside the inner test step");

            // You can access the results of the outer step as long
            // as you have given it a name
            GlobalLogger.AddComment("Outer step currently has result {0}",
                outer.Summary);
        }

        // This comment is logged as part of the outer test step
        GlobalLogger.AddComment("Another comment in the outer test step");
    }

    // This comment is logged outside all test steps
    GlobalLogger.AddComment("Another comment outside of all test steps");

    return Manager.Results.Summary;
}

The next example illustrates results management using the TestStep construct. Three elements of the example are particularly noteworthy:

  • Adding results can be done inside any test step, or even outside all test steps.
  • All test step results are automatically summarized and added into the outer test step when a test step is complete, so at the end of your test you can simply use GlobalLogResultManager.Results.Summary to get the result of your test overall.
  • You can access the results of named test steps, both to query state and to reset results.
using Manager = Microsoft.MobileDevices.Utils.GlobalLogResultManager;

/// <summary>
/// Tests the results functionality of test step.
/// Expected text is shown below:
/// *** Test ID:        0
/// UnitTest: Test the TestStep results feature
/// Verification = Pass: pass outside
///     [1] Begin Step: Outer test step
///     [1] Verification = Fail: fail in outer step
///         [2] Begin Step: Inner test step
///         [2] Verification = Pass: inside inner step
///         [2] Outer step currently has result Fail
///         [2] Clearing test results: outer step is good
///         [2] End Step  : Inner test step
///     [1] Verification = Pass: Inner test step
///     [1] End Step  : Outer test step
/// Verification = Pass: Outer test step
/// *** Result:         Passed
/// </summary>
/// <returns>LogResult</returns>
public LogResult TestTestStepResults()
{
    // This result is not associated with a test step
    // it is simply associated with the test as a whole
    Manager.Results.Pass("Initially set as Pass");

    // Everything between the starting and ending braces
    // of this using statement is in the outer test step
    using(TestStep outer = new TestStep("Outer test step"))
    {
        // This result is associated with the outer test
        // step, which is failing once this is executed
        Manager.Results.Fail("fail in outer step");

        // Everything between the starting and ending braces
        // of this using statement is part of both the outer
        // and the inner test steps
        using(new TestStep("Inner test step"))
        {
            // This result is associated with the inner test
            // step, which will be passing once this is executed
            Manager.Results.Add("inside inner step", true);

            // GlobalLogResultManager.Result.Summary will always
            // give you the summary for the current step, so you
            // can see the results of the current step even if
            // you did not give it a name
            if (Manager.Results.Summary == LogResult.Pass)
            {
                // Reset the outer summary
                GlobalLogger.AddComment("Outer step currently has result {0}",
                    outer.Summary);

                // You can reset the results for any named step
                // at any time - you may want to do this if an
                // inner step makes it possible for an outer step
                // to try a verification again
                outer.Clear("outer step is good");
            }

            // When we reach the closing brace for this step
            // its results are summarized and added as a result
            // to the outer step automatically
        }

        // When we reach the closing brace for the outer step its
        // results are summarized and added as a result to the
        // test case automatically
    }

    // At the end of your test simply return the summary of all
    // results from the entire test case - it will have the results
    // of all test steps rolled into it automatically
    return Manager.Results.Summary;
}
