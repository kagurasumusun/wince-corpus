Passing and Failing

Every test case results in a type of result, represented by the LogResult data type. LogResult can be any of the following values:

Result Description
Pass The test passed
Fail The test failed
Skip The test was skipped
Abort The test aborted from execution
Block The test was blocked from running by a known application issue
Warn The test passed, but indicated warnings

It is the responsibility of a test case to perform its test and then return an appropriate value from those listed above.

Tux.Net also watches for unhandled exceptions and automatically reports such exceptions as a Fail result. It is valid to utilize this as a test organization strategy. This enables test cases to run until they detect an undesirable state, and then throw an exception to let Tux.Net know the test has failed. It is recommended that you create VerifyX methods to help with this strategy. For instance, if you need to verify that an integer is positive in the course of a test, failing the test if it is not, you could create a VerifyPositive(int x) method which throws an exception if x is not positive. The test will be aborted in the middle and Tux.Net will log a failing result.
