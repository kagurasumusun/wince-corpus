Multiple Skus

In general, the Area Library should manage the differences between SKUs and products. Most of the time test cases should be completely unaware of what product or SKU they are running on. This is possible because the Area Library design that we are using hides SKU from tests.

Area Libraries should be written to factor out features that are applicable to only one product or SKU into separate classes. Sometimes you may find that a feature area exists on multiple products, or multiple SKUs, except a few methods that are not applicable on all configurations. In these cases you should throw a NotSupportedException from the methods on the configurations that are not supported. Since these methods do not apply to all configurations, they should only be used from test cases that are using the TestCaseAttribute to limit the types of devices they are run on. Throwing an exception allows the test writer to quickly realize that the wrong method is being used if he attempts to use the method without the correct TestCaseAttribute specifications. It also allows you to easily implement the method in the future if the product is changed to support this configuration in the future – with the only change to the test case being to alter the TestCaseAttribute to allow the newly supported configuration.
