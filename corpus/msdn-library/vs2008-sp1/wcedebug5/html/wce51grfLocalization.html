Localization

Because products often ship in multiple languages, you often need to localize your test cases so that they can run on multiple languages. Most localized strings in the product are represented as resources in a string table and are specified by the module (dll, exe, mui) that holds the resource and the ID of the resource. The MobilityToolKit.IdnString object exists to encapsulate this data and decode it at runtime to get a properly localized string.

Because text is very UI dependent, localized resources (in the form of IdnStrings) should be exposed in the UIAL. Each UIAL has an IdnHolders file which contains one IdnHolder class for each dialog in that UIAL. The IdnHolder class for a dialog should contain an IdnString for each localized string seen on that dialog. The IdnHolders file for a UIAL looks like this (but continues with more IdnStrings and more classes):

namespace Microsoft.MobileDevices.AbstractionLayer.Inbox.PocketPC
{
    /// <summary>
    /// IdnHoder class holding all the Idn strings for the InboxMainWnd dialog.
    /// </summary>
    public class InboxMainWndIdnHolder
    {
        /// <summary>
        /// WWE="Delete"
        /// </summary>
        public readonly Mtk.IdnString DeleteSK2 =
            new Mtk.IdnString(Mtk.ModuleNames.outresDll, "MNU_22501_POPUP1_82");

        /// <summary>
        /// WWE="Reply"
        /// </summary>
        public readonly Mtk.IdnString ReplySK2 =
            new Mtk.IdnString(Mtk.ModuleNames.outresDll, "MNU_22501_POPUP1_251");
    }

    /// <summary>
    /// IdnHolder class holding all the Idn strings for the ReadDialog dialog.
    /// </summary>
    public class ReadDialogIdnHolder
    {
        /// <summary>
        /// WWE="Delete" on SK2 in read note
        /// </summary>
        public readonly Mtk.IdnString DeleteSK2 =
            new Mtk.IdnString(Mtk.ModuleNames.outresDll, "MNU_32720_POPUP0_129");

Because localized resources are product specific, they should be used primarily by the Area Library, not by tests. If a test accesses an IdnString from the UIAL directly, it is limiting itself to run only on the product that the UIAL is written for. This should only be done in the rare cases. Usually, UI actions or verifications that depend on localized text should be integrated into the methods in the area library that utilize them. These IdnString objects are accessed through the dialog class that contains them as in the following method:

/// <summary>
/// Example: use an IdnString from UIAL
/// </summary>
public void UsingLocalizedResources()
{
    // Reference localized string through the dialog in the application
    GlobalLogger.AddComment("The localized resource is: {0}",
InboxApp.ManageFoldersDialog.ManageFoldersDialogIdns.NewToolbar);
}
