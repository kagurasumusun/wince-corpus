IeXdi2OleAutoServer

This interface supports debugging a COM server for an OLE automation plug-in. It supports methods that:

  • Re-maps custom interfaces for debugging
  • Set and retrieve property values
  • Control execution

This interface contains methods that enable OLE automation.

Methods

This interface inherits the methods for the IUnknown and IDispatch interfaces.

The following table shows the IDispatch methods.

Method Description
IDispatch::GetIDsOfNames Maps a single member name and an optional set of parameter names to a corresponding set of integer dispatch identifiers (DISPIDs).

These identifiers can then be used on subsequent calls to IDispatch::Invoke.

IDispatch::GetTypeInfo Retrieves the type information for an object.
IDispatch::GetTypeInfoCount Retrieves the number of type information interfaces that an object provides, either 0 or 1.
IDispatch::Invoke Provides access to properties and methods exposed by an object.

The following table shows the methods that set and retrieve properties for the IeXdi2OleAutoServer interface.

Method Description
fSupportseXdi2Exec Retrieves a property that, if VARIANT_TRUE, indicates the IeXdi2Exec interface is supported.
fSupportseXdi2Mem Retrieves a property that, if VARIANT_TRUE, indicates the IeXdi2Mem interface is supported.
dwExecMode Sets or retrieves a property that indicates the current execution mode.

This property is typically 0 for 32-bit mode and 1 for 16-bit mode.
dwTargetCpuMajorFamily Retrieves a property that indicates the CPU family of the target device, such as X86=0, SHX=1, MIPS=2, ARM=3, IA64=4, or unknown=-1.
strTargetCpuMajorFamily Retrieves a property that indicates the name of the target device CPU family such as X86, SHX, MIPS, ARM, IA64, or unknown.
dwTargetCpuCapabilities Retrieves a property that indicates the CPU capabilities of the target device, such as:
  • Coprocessor
  • Instruction support for MMX, ARMv5, ConCan, SH4, or MIPS4
  • 32-bit array
strTargetName Retrieves a property that indicates the name of the debugging target.
strProbeName Retrieves a property that indicates the name of the hardware probe.
fSupportsAsyncBreak Retrieves a property that, if TRUE, indicates the debugging target can be halted asynchronously by a user break.
fSupportsFramePointerStdReg Retrieves a property that, if TRUE, indicates the current CPU supports a frame pointer register.
fSupportsReturnAddressStdReg Retrieves a property that, if TRUE, indicates the current CPU supports a return address register.
fSupportsClockCycleCount Retrieves a property that, if TRUE, indicates the debugging target can return the clock cycle count on Halt since last Run or Single Step.
cExceptions Retrieves a property that indicates the number of exceptions provided by the eXDI service.
RunState Sets or retrieves a property that indicates the run state of the debugging target.
dwLoCycleSinceLastRun Retrieves, if supported, a low significant DWORD property that indicates the number of clock cycles that executed after the debugging target resumed execution.
dwHiCycleSinceLastRun Retrieves, if supported, a high significant DWORD property that indicates the number of clock cycles that executed after the debugging target resumed execution.
fIgnoreCurrentExcept Sets or retrieves a property that, if TRUE, indicates that a potential exception on the current instruction must be ignored by debugger and passed to the OS.
Note   this setting can be used only once.
CurrentExecAddr Retrieves a property that indicates the current executable address when the debugging target is halted.
cHaltReasons Retrieves a property that indicates the number of halt reasons.
fCodeBpBypassCountSupported Retrieves a property that, if TRUE, indicates a bypass counter is supported for code breakpoints.
fDataBpBypassCountSupported Retrieves a property that, if TRUE, indicates a bypass counter is supported for data breakpoints.
fDataBpSupported Retrieves a property that, if TRUE, indicates data breakpoint resources are always available from the debugging target.
fDataBpMaskableAddress Retrieves or sets a property that, if TRUE, indicates a data breakpoint address mask can be defined.

If this property is TRUE, it implies that the fDataBpSupported field is also TRUE.
fDataBpMaskableData Retrieves a property that, if TRUE, indicates a data breakpoint data mask can be defined.

If this property is TRUE, it implies that the fDataBpSupported field is also TRUE.
fDataBpDataWidthSpecifiable Retrieves a property that, if TRUE, indicates that a data-breakpoint-specific data width can be defined.
If this property is TRUE, it implies that fDataBpSupported field is also TRUE.
fDataBpReadWriteSpecifiable Retrieves a property that, if TRUE, indicates that a data-breakpoint-specific data access type can be defined.

If this property is TRUE, it implies that fDataBpSupported field is also TRUE.
fDataBpDataMatchSupported Retrieves a property that, if TRUE, indicates that the matching on a data breakpoint data field is supported.

This means the data field is not always Don'tCare and triggers not only on address comparison.
cSwCodeBpAvail Retrieves a property that indicates the number of software code breakpoints still available on the debugging target.

This property is -1 if no limit is known.
cHwCodeBpAvail Retrieves a property that indicates the number of hardware code breakpoints still available on the target.

This property is -1 if no limit is known.
cSwDataBpAvail Retrieves a property that indicates the number of software data breakpoints still available on the debugging target. This property is -1 if no limit is known.
cHwDataBpAvail Retrieves a property that indicates the number of hardware data breakpoints still available on the target.

This property is -1 if no limit is known.
cMemMaps Retrieves a property that indicates the number of memory maps provided by the eXDI service.
