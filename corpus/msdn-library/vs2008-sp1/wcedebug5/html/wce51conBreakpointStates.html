Breakpoint States

When you set a breakpoint, a breakpoint glyph appears in the margin at the left of the code. The glyph appearance indicates the breakpoint state. For information about setting colors for breakpoint glyphs, see Selecting Breakpoint Colors.

The following table describes different breakpoint states and their associated glyphs:

State Glyph Description
Disabled Hollow circle Indicates that the program does not break at this point.

To make the breakpoint active again, enable the breakpoint.
Enabled,

instantiated

 Solid red circle Indicates the program breaks at this point.
Enabled,

not instantiated

 Solid pink circle Indicates an enabled breakpoint is set, but the program is not loaded.

At the next stopping event, the debugger will attempt to instantiate the breakpoint. If the breakpoint can be instantiated, the glyph color changes to red.
Resolved Solid circle

same color as the circle edge

 Indicates a .dll or .exe file that was built using the source file with the breakpoint is loaded on the target device.

If the debugger successfully bound the breakpoint, the target device stops executing when it reaches the source location.

Deferred Hollow circle Indicates a breakpoint set in a source file that is not loaded.

A deferred breakpoint does not exist on the device, and no stop occurs at the requested breakpoint location.

In addition, if a user tries to set a breakpoint in code that is in the ROM space of the device, the deferred breakpoint glyph is also shown in the editor window.

An asterisk (*) in the check box next to the breakpoint indicates that the breakpoint is not supported on the current OS design.

If you set more than one breakpoint on a line, and some breakpoints are disabled while others are enabled, a gray dot appears in the left margin in the source window, Disassembly window, or Call Stack window.
