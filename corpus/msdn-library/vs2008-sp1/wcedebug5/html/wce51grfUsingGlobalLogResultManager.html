Using GlobalLogResultManager

A test case often needs to perform several operations in succession, where each operation has its own success value. The test needs to track these multiple values in order to make a final pass/fail determination, resulting in multiple points of complexity where bugs can crop up in the test case itself. For example, misuse of Boolean or bit-wise operators can result in loss of a valid failure, which inadvertently ends up being a pass. Tracking all these results can also become so confusing that the wrong result is returned.

The GlobalLogResultManager is to results management what GlobalLogger is to logging: a one-stop utility that manages results for you. Keeping track of a LogResult over the course of your test case can be error-prone. Allowing the GlobalLogResultManager to keep track of results allows you to forgo logical processing of multiple result steps for verification or determination of a final result. You can simply trust the manager instead.

The example below demonstrates use of the Add, Pass, Fail, and Clear methods of the GlobalLogResultManager. It also shows how to return the LogResult that GlobalLogResultManager has been tracking for you.

using Manager = Microsoft.MobileDevices.Utils.GlobalLogResultManager;

/// <summary>
/// Example: Using GlobalLogResultManager to manager results
/// </summary>
public LogResult TestCase()
{
    // You can add results based on a boolean expression
    // This addition will add a pass result, since the boolean
    // expression is true.  Use this for calls to methods
    // that return a bool for pass/fail
    Manager.Results.Add("Add passed result", (1 < 2));

    // Before this call the overall result is pass, but after
    // this call it will be fail, since the test is false
    Manager.Results.Add("Add failed result", (1 > 2));

    // You can clear the results at any time and this will put
    // you back in a passing state - use this carefully
    Manager.Results.Clear();

    // If you know that a result is pass as a result of your
    // own check you can call Pass to log the passed result
    Manager.Results.Pass("Add a known passed result");

    // Similarly, you can call Fail to log failed results
    Manager.Results.Fail("Add a known failed result");

    // When you are done with your test return Summary - this
    // will aggregate all the results you have added such that
    // any failure will result in an overall fail result
    return Manager.Results.Summary;
}
