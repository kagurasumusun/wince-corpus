Using Attributes

Attributes can be used in various ways on test cases or test suites:

  • To describe an aspect of the test, in terms of what it tests or what it does. The TestCaseAttribute description and test type help with this
  • To specify any restrictions the test, for instance, language or platform restructions. Custom attributes that know how to detect qualifications for a test are generally used for this purpose.
  • To group tests for execution in a convenient manner. The test-type and group parameter to TestCaseAttribute are examples of this. These can be used from the command-line to identify specific tests to run. This is discussed in more detail below.

Grouping

In general, it is better to arrange test cases logically in TestSuite classes based on what feature or features they are testing rather than how or when the tester expects to run them. For instance, if you have two feature sets and three different sub-features in each, it might be better code arrangement to create one TestSuite class for each feature set, rather than a TestSuite class for each sub-feature. Code-reuse is easier when similar tests are near each other. However, this presents a problem if you want to run tests just from a specific sub-feature, and not all tests in a TestSuite. The Groups parameter to TestCaseAttribute can help with this.

The TestCaseAttribute takes a Groups parameter that lets you specify a list of strings representing Test Groups. When you run your tests with Tux.Net, you can specify a Test Group (or multiple groups) to run and Tux.Net will run all tests that contain an attribute for one of the specified groups.

The following code sample will run with either the command line parameter "-group Circles" or "-group Squares":

/// <summary>
/// Sample Test Case assigned to two groups, 'Circles' and 'Squares'
/// </summary>
/// <returns>Test Result</returns>
[TestCaseAttribute( "Test plotting of all known shapes",
     Type = TestType.BVT,
     Groups = new string [] {TestGroupNames.Circles,
                             TestGroupNames.Squares})]
public Logging.LogResult TestPlotAllShapes()
{
    GlobalLogger.AddComment("executing TestPlotAllShapes");
    return Logging.LogResult.Pass;
}

/// <summary>
/// List of predefined group names
/// </summary>
public class TestGroupNames
{
    /// <summary>Circle Group Name</summary>
    public const string Circles = "Circles";

    /// <summary>Square Group Name</summary>
    public const string Squares = "Squares";
}

This example shows a test case that belongs to two different logical groups. It also demonstrates using string objects, for example TestGroupNames.Circles, to ensure consistent use of group names and to avoid typos when assigning group names.

Multiple SKUs

Some test cases are only applicable to one product or one SKU of a product. In these cases, use a TestCaseAttribute to specify which configurations your test can be run on. The harness will only run your test on devices that meet the criteria specified in this attribute.

The following example uses the MobileDevicesDescriptor (defined in the Windows Mobile plug-in, MDUtils) and shows how to specify that your test suite only runs on PocketPC. In addition, the first test case will only run on GSM and CDMA, for English and German languages. The second test case will only run on English devices.

/// <summary>
/// Summary description for DeviceDescriptorExample.
/// All tests in this test suite will only be run
/// on PocketPC.
/// </summary>
[MobileDevicesDescriptor(Product = Products.PocketPC)]
public class DeviceDescriptorExample : TestSuite
{
     [TestCaseAttribute( "Sample for a Sku specific test")
     [MobileDevicesDescriptor(Sku = Skus.Gsm | Skus.Cdma,
                  Languages = new int[] {0x0409, 0x0407})]
      public Logging.LogResult SkuSpecificTest()
      {
            // This test will only be run on PocketPC
            // This test will only be run on GSM or CDMA
            // This test will only be run on WWE and GER
      }

      [TestCaseAttribute( "Sample for a Language specific test")
      [MobileDevicesDescriptor(Languages = new int[] {0x0409})]
      public Logging.LogResult LanguageSpecificTest()
      {
            // This test will only be run on PocketPC
            // This test will only be run on WWE
      }
}

It is straight-forward to implement a plug-in like MDUtils to provide other attributes for constraints. Look at the a MDUtils project for more details.
