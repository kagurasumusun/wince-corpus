CeLog Usage Scenarios

CeLog is a logging tool that can be used to log high-frequency events. Because of that, it can capture many kernel and operating system events that would otherwise be impossible to view. Instrumentation in Windows CE kernel makes calls to the CeLogData API that log scheduling, resource usage, and other operating system events. In addition, you can create custom data structures that allow you to log your own high-frequency events. By combining your own events with built-in events, you can view the relationship of OS events to your data.

For example, the Windows CE kernel calls CeLogData to log the CELID_THREAD_SWITCH event every time execution switches from one thread to another. When you view a log file produced by CeLog, you can see the order in which each thread ran and the length of time each thread ran, and you can view relationships between running threads.

The following list provides some examples of ways in which you may find CeLog event tracking useful:

  • Capturing thread activity and application or driver initialization at boot, or during a suspend
  • Capturing debug output on a target device with no KITL connection
  • Tracking thread run-times over a long period of time, to catch threads that consume too much CPU or drain too much power
  • Measuring the frequency of thread preemption to meet high performance requirements, such as the requirements of a multimedia player
  • Measuring system idle that might increase power usage
  • Implementing tools that need to track loaded processes and modules, such as notifying profilers of module load events
  • Tracking data per-thread

The CeLog log does not indicate what code a suspect thread is running. For example, if a thread is running at a time when it should not be, it is difficult to use CeLog to determine why. Other tools are more suited to that task, such as the Remote Kernel Profiler and the Remote Call Profiler.
