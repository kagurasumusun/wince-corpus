Maintaining the UIAL

When UI or resource changes are made in the product the UIAL must be updated to reflect these changes.

Rebuild the RCML files

  • In a build window go to the directory where resources are built for your application (example: private\apps\outlook\resfiles\outres\ppc).
  • Check out the sources file in this directory.
  • Add the following line to the sources file in this directory: "RCMLFLAGS=$(RCMLFLAGS) -refresh".
  • Build in this directory.
  • RCMX files are generated if changes are required to RCML files but you don't have them checked out. Do "sd edit" on the RCML files that correspond to any generated RCMX files and then build the directory again.
  • Do "sd revert" on your sources file - checking in the refresh change will slow down builds.

If new RCML files are generated

  • Do "sd add" on any new RCML files that are generated.
  • Check out the IdnHolders.cs file for your UIAL project, since a new class will be added for every new RCML file.
  • Decorate the RCML for processing by RCTOCS.

Re-run RCTOCS to update the UIAL files

  • See RCTOCS for information on running the tool.

If new Dialog classes resulted from re-running RCTOCS

  • Do "sd add" on any new Dialog classes that are generated.
  • Add properties for each new Dialog class to the Application class of your UIAL.
  • Add code to the UIAL self-test that navigates to each new Dialog and calls VerifyAllControls() on each dialog.

If you have changed a top-level window or a Smartphone CPL dialog

  • Top-level windows are not generated from RCML, so you will not see changes in the UIAL using RCTOCS.
  • If you added a top-level window you need to run RcmlSnap on the new window and then rerun RCTOCS to integrate the resulting class into the UIAL.
  • If you added a new Smartphone CPL dialog you need to run SpRcmlGen on the associate xml file and then rerun RCTOCS to integrate the resulting class into the UIAL.
  • If you changed a top-level window or Smartphone CPL dialog you will need to rerun RcmlSnap/SpRcmlGen and RCTOCS.
  • If you removed a top-level window or Smartphone CPL dialog you will need to manually remove the Dialog class from the UIAL project.

·Make sure the UIAL self-test passes

  • Build the UIAL (run "buildManaged -c from your build window)
  • Run the test from PB by typing "s harness -assembly <dll_name>" where <dll_name> is the name of your UIAL project dll.
  • If the test does not pass you will need to debug it in VS - see Getting Ready To Automate for information on setting up your environment and debugging the test.

Have UIAL and RCML files reviewed by your area SDE/T and Toolbx
