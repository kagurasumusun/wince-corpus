Stress Testing

Individual test cases can operate as stress tests, but Tux.Net offers a few low-cost command line options to leverage normal test cases in a stressful fashion.

The –shuffle parameter can be used to explicitly randomize the order in which tests are run. By default, test cases are run in more or less the order they are defined. (NOTE: Test order is not guaranteed by their order in the source code and should not be depended on. If test cases must run in a specific order, they should be programmatically directed to do so. Best practices suggest that test cases be order-independent.) With the shuffle option, the test order will be randomized every time Tux.Net is run.

When run with –shuffle, Tux.Net outputs the random seed used to generate the sequence. A particular order can be reproduced by also providing the –seed parameter to Tux.Net.

Tux.Net can repeat tests any number of times with the –repeat option.
