Test Case Initialization and Cleanup

Test cases should leave the device in the same condition that they found it in. This helps to ensure that a test does not ruin conditions for subsequent tests, and makes debugging test failures more predictable.

If a test needs to do significant cleanup work, then it should use a TestCaseCleanupAttribute to specify a method that should be called after the test completes. Tux.Net will call this method when the test stops running – whether it passed, failed, or failed with an exception. This test cleanup method should be generic enough to handle cases where the test aborts with an exception before the test was done running. Similar to the TestCaseCleanupAttribute, there is also a TestCaseInitAttribute which can be used to specify an initialization method. The attribute is used in exactly the same way as the TestCaseCleanUpAttribute except it specifies a method to be run before the test method is run. Below is an example of how the TestCaseCleanupAttribute and TestCaseInitAttribute are used to specify cleanup and initialization methods:

/// <summary>
/// Sample Test Case demonstrating cleanup method which will
/// be called after test finishes, even if it throws an exception
/// </summary>
/// <returns>Test Result</returns>
[TestCaseAttribute( "description Test1", Type = TestType.BVT )]
[TestCaseInitAttribute( "Init" )]
[TestCaseCleanupAttribute( "CleanUp" )]
public LogResult CleanUpSample()
{
    GlobalLogger.AddComment("inside CleanUpSample");

    // throw an exception to demo the Cleanup attribute
    throw new System.Exception("Throw exception - demo CleanUp");
}
/// <summary>
/// Clean up method called after test completes
/// this method must return void and take no parameters
/// </summary>
public void CleanUp()
{
    GlobalLogger.AddComment("Inside CleanUp method");
    return;
}

/// <summary>
/// Initialization method called before the test is called
/// this method must return void and take no parameters
/// </summary>
public void Init()
{
    GlobalLogger.AddComment("Inside Initialization method");
    return;
}
