Area Libraries

The UIAL is used to hide the complexity of finding controls in DATK, but it does not combine the use of these controls into common usage scenarios. This is what the Area Libraries are for - providing a library of routines that act out common UI scenarios on the device.

The goal of the libraries is to make test script writing as straightforward as typing in descriptions of manual test case steps. The code is very general – comparable to the aggregate steps taken in manual testing. For instance, the first step in a test case for Microsoft Word would be "Open Word", which corresponds to a series of UI based commands: "Click Start", "Click Programs", "Scroll Down", "Click Word". "Open Word" might be implemented in the Area Library, so that the test case doesn't need to deal with the specifics of what it takes to open Microsoft Word. The Area Library also abstracts away the notions of product (PocketPC vs Smartphone) or SKU to provide functions that act appropriately depending on which product is being used.

A test developer should create an "Area Library" to abstract test operations for an application they are testing.

The Area Libraries depend heavily on UIAL, MTK, Utils.Net, and Logging. They rarely directly interface with DATK since the UIAL abstracts that portion out for the Area Library. The Area Library is used exclusively by the Tests layer.
