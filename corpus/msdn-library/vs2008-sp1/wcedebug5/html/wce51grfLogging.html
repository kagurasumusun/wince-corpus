Logging

By default, all Tux.Net output gets logged to the file Results.log, which is created either in the Platform Builder release directory (which is mapped to \release on the device, if available) or else in the same directory Tux.Net is run from on the device.

Logging facilities are provided via the GlobalLogger class. Tux.Net uses and configures GlobalLogger for structure output during test execution, so test cases should also use it in order to take full advantage of the Tux.Net framework. GlobalLogger is actually independent of Tux.Net, and as such can be configured and used separately, which is a great advantage when code must be shared between Tux.Net test cases and stand-alone tools.

The primary GlobalLogger method to be Aware of is GlobalLogger.AddComment. This method simply adds a comment to the log file in the appropriate format. The method also accepts a "detail" level, which can be used to tune the amount of logging data that gets output to the log file. Here is a simplified example without the attributes normally seen on a test case:

/// <summary>
/// Test cases always want logging, so they generally use the
/// Summary level (lowest level) which is always logged.
/// </summary>
public void TestCaseMethod()
{
      // This will always be logged
      GlobalLogger.AddComment(
            GlobalLogger.VerboseLevel.Summary, "Test case");

      // This will also always be logged
      GlobalLogger.AddComment("Test case comment");
}

You can use the verbosity parameter to control how much the harness actually writes to the log file. To do this you call GlobalLogger.AddComment() and pass it in an integer specifying the log level of your comment. The higher the number, the more detailed the comment. Then, when you run TuxNet.exe, you can specify the –logLevel parameter to indicate how detailed you want your log to be. For example, if you pass "-logLevel 4" to the harness then all comments that were added with a LogLevel of 4 or less will be added to the log file. All comments added with a LogLevel of 5 or greater will be excluded from the log file.

The pre-defined log levels are:

  • Summary (level 0)
  • Info (level 1)
  • Detailed (level 2)
  • Debug (level 3)

Using these pre-defined levels is a simple way to express the log-level and intent of the comment in a readable fashion. For more advanced logging techniques, see the sections below on TestStep and GlobalLogResultsManager.
