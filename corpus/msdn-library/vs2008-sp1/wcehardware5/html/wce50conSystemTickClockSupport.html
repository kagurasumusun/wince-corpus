Timer Library

The timer library implements the system tick or clock. For more information, see %_WINCEROOT%\Platform\Common\Src\Inc\Oal_timer.h.

You can replace the production-quality OAL implementation, as long as your custom implementation exports the kernel and OAL interfaces. You can replace the timer related functions with the common implementation for the rest of the library.

The production-quality OAL code implementation assumes the timer has a granularity equal to or higher than 1 millisecond with the ability to reduce and extend the system tick. The code uses system tick manipulation in two situations. It is used in OEMIdle to extend the actual system tick beyond the normal system tick period, which is usually 1 millisecond, before it puts the CPU in idle with OAL. It is also used to return the system to the normal tick period when the system returns from idle. When you use kernel profiling, use the system tick manipulation in OEMProfileTimerEnable to reduce the system tick period. In this case, use the period that is shorter than 1 millisecond. To avoid collision with possible timer manipulation in OEMIdle, set the maximum idle period to the normal system tick period.

The production-quality OAL implements a busy loop in the OALCPUIdle function. Use this implementation for development only. The correct implementation of OALCPUIdle depends on the global variable b_oalInterruptFlag, which must be set to TRUE in the interrupt handler code. In the product you release to customers, use the OEMIdle stub, if your hardware does not support idle mode.

Kernel Interface

UINT32 OALTimerIntrHandler();
This function implements the timer interrupt handler. Depending on the hardware, it is called from the general interrupt handler for ARM-based hardware platforms, or it is used as an interrupt handler for MIPS-based hardware platforms.

This function returns a SYSINTR value from the interrupt handler.

CurMSec
This global variable indicates the number of milliseconds since boot time. It is defined in the kernel.

This global variable is updated with each system tick and contains the system relative time in milliseconds. The update quantum is the system tick period. If the system tick period is a 1 millisecond variable, the variable will contain the actual system-relative time.

OEMIdle
This function places the CPU in an idle state when a thread is not ready to run. It is called by the kernel.
SC_GetTickCount
This function returns the actual system-relative time in 1-millisecond intervals. On systems with a 1-millisecond system tick, this function can return the actual value of CurMSec. However, if the system runs with a system tick period higher than 1 millisecond, this function should get the actual time in 1-millisecond intervals.
pQueryPerformanceFrequency
This function returns the timer frequency with higher granularity than 1 millisecond, if it exists.

If no such timer frequency exists, a timer frequency of 1 kHz, or 1 millisecond, is returned.

pQueryPerformanceCounter
This function returns the number of milliseconds since the device booted. It is used instead of GetTickCount for timers with high granularity.
pOEMUpdateRescheduleTime
This function is a pointer to the function that reprograms the system timer.

OAL Interface

The following functions are used in timer implementations delivered in the common library.

BOOL OALTimerInit(UINT32 msecPerSysTick, UINT32 countsPerMSec, UINT32 margin);

This function initializes the system timer. It is usually called from OEMInit. The msecPerSysTick parameter defines the system-tick period. The countsPerMSec parameter states the timer input clock frequency. The value is equal to the frequency divided by 1000. The margin parameter is used in the timer manipulation routines OALTimerRecharge and OALTimerUpdate to define a safe time range where the timer can be modified without errors.

For variable tick periods, set the msecPerSysTick parameter to the maximum period supported by the hardware. Your implementation should check and fix the value if it is bigger than what is supported. This function allows the use of -1 as a parameter.

VOID OALTimerRecharge();
This function is usually called from the timer interrupt handler to recharge the timer for the next system ticks.

Depending on your timer hardware implementation, this function can be stubbed.

UINT32 OALTimerUpdate(UINT32 period, UINT32 margin);
This function modifies the actual system tick period. The new system tick period is defined in the period parameter. It returns the time that has expired from the actual period in the new system tick period. You can use this value to avoid system tick drift or to count the time the system spent in idle mode. If the actual time is close to the value in the margin parameter, the tick time is not changed. If the new tick time is close to the actual time, shift the value forward by the count specified in the margin parameter.

You should only implement this function when you use the OAL OEMIdle function, IL timing, or profiling implementation.

INT32 OALTimerCountsSinceSysTick();
This function returns the time that has expired since the current system tick.
extern OAL_TIMER_STATE g_oalTimer;
This global variable exports the timer control block.
UINT32 OALGetTickCount();
This function returns the number of 1-millisecond ticks that have elapsed since system boot or reset. The counter can overflow, but the overflow period should not be shorter than approximately 30 seconds.

Because this function is used during system boot, it must be called before the interrupt subsystem is active.

VOID OALStall(UINT32 uSecs);
This function stalls the CPU for uSecs microseconds.

Because this function is used during system boot, it must be called before the interrupt subsystem is active.

Internal Interface

VOID OALTimerRecharge(UINT32 period, UINT32 margin);
This function is usually called from the timer interrupt handler to recharge the timer for the next system ticks.

Depending on your timer hardware implementation, you can stub this function.

VOID OALCPUIdle();
This function puts the CPU or SOC in idle state. The CPU or SOC should exist the idle state when an interrupt occurs. This function is called with interrupts are disabled. When this function returns, interrupts must be disabled also.

Implement this function only when you use the OAL OEMIdle function. The common library contains a busy loop implementation, which you can use for development.

Internal Interface for systems with count/compare counters

VOID OALTimerInitCount(UINT32 period);
This function initializes the system timer with a specified base period.
UINT32 OALTimerGetCount();
This function returns the actual timer value. Use this function only for OALGetTickCount or OALStall implementation in stuations where the global timer variable is not initialized. You can also use this function to implement the OALTimerRecharge, OALTimerCountsSinceSysTick, OALTimerReduceSysTick, and OALTimerExtendSysTick functions for systems with a count and compare timer.

This function call should also clear the timer interrupt.

UINT32 OALTimerGetCompare();
This function returns the timer compare value. Implement this function only for systems with a count and compare timer. You can also use this function to implement the OALTimerRecharge, OALTimerCountsSinceSysTick, OALTimerReduceSysTick, and OALTimerExtendSysTick functions for systems with a count and compare timer.
VOID OALTimerSetCompare(UINT32 compare);
This function sets the timer compare value. Implement this function only for systems with a count and compare timer. You can also use this function to implement the OALTimerRecharge, OALTimerCountsSinceSysTick, OALTimerReduceSysTick, and OALTimerExtendSysTick functions for systems with a count and compare timer.
