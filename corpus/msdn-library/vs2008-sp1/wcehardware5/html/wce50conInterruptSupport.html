Interrupt Library

The interrupt library implements interrupt processing. Support for interrupts is provided by a combination of OAL common routines and processor specific routines.

Depending on the CPU or SOC model, you can implement the interrupt library with hardware platform callbacks. This method is useful on hardware where you have used an external secondary interrupt controller.

For more information, see %_WINCEROOT%\Platform\Common\Src\Inc\Oal_intr.h.

Kernel Interface

OEMInterruptEnable
This function performs hardware operations necessary to enable the specified hardware interrupt.
OEMInterruptDisable
This function disables the specified hardware interrupt.
OEMInterruptDone
This function signals completion of interrupt processing.
IOCTL_HAL_REQUEST_SYSINTR
The kernel calls OEMIoControl with this control code to request an IRQ-to-SYSINTR mapping.
IOCTL_HAL_RELEASE_SYSINTR
The kernel calls OEMIoControl with this control code to release a previously requested SYSINTR.
IOCTL_HAL_REQUEST_IRQ
The kernel calls OEMIoControl with this control code to request a hardware-to-IRQ mapping based on device location.

OAL Interface

#define OAL_INTR_IRQ_MAXIMUM 64
This value defines the maximum number of IRQs. If there is no limitation for this value in the OAL library, the Windows CE resource manager only supports 64 IRQs.
BOOL OALIntrInit();
This function initializes the interrupt hardware. It is usually called during the system initialization process. If your implementation uses hardware platform callbacks, OALIntrInit calls the BSPIntrInit function.
VOID OALIntrStaticTranslate(UINT32 sysIntr, UINT32 irq);
This function sets the static IRQ <-> SYSINTR mapping for a specified value. It is typically used during system initialization for legacy drivers.
UINT32 OALIntrRequestSysIntr(UINT32 count, const UINT32 *pIrqs,
UINT32 flags);
This function allocates a new SYSINTR value for a specified IRQ list. Based on the flags parameter, it can also set backward static mapping (IRQ -> SYSINTR).

Internal Interface

VOID OALIntrMapInit();
This function initializes the IRQ/SYSINTR mapping structure. It must be called from the OALIntrInit function.
BOOL OALIntrReleaseSysIntr(UINT32 sysIntr);
This function releases a SYSINTR. It also clears backward static mapping (IRQ -> SYSINTR), if it exists.
UINT32 OALIntrTranslateIrq(UINT32 irq);
This function returns the SYSINTR for a specified IRQ based on the static mapping.
BOOL OALIntrTranslateSysIntr(UINT32 sysIntr, UINT32 *pCount, const
UINT32 *ppIrqs);
This function returns the list of IRQs for a specified SYSINTR.

Hardware Platform Callback Functions

BOOL BSPIntrInit();
This function is called by OALIntrInit if your implementation uses hardware platform callbacks. OALIntrInit initializes the interrupt hardware and is usually called during the system initialization process.
BOOL BSPIntrRequestIrqs(DEVICE_LOCATION *pDevLoc, UINT32 *pCount,
UINT32 *pIrqs);
BOOL OALIntrRequestIrqs(DEVICE_LOCATION *pDevLoc, UINT32 *pCount,
UINT32 *pIrqs);
This function returns the list of IRQs for the device identified by the pDevLoc parameter. If your implementation uses hardware platform callbacks, OALIntrRequestIrqs must call BSPIntrRequestIrqs if the device is not recognized. On input, pCount contains the maximum number of IRQs allowed in the list. When the function returns, it returns the number of IRQs in the list.
UINT32 BSPIntrEnableIrq(UINT32 irq);
BOOL OALIntrEnableIrqs(UINT32 count, const UINT32 *pIrqs);
This function enables the list of interrupts identified by an IRQ. If your implementation uses hardware platform callbacks, OALIntrEnableIrqs must call BSPIntrEnableIrq for each IRQ in the list before it enables the IRQ. BSPIntrEnableIrq can also perform board-specific actions and modify an IRQ.
UINT32 BSPIntrDisableIrq(UINT32 irq);
VOID OALIntrDisableIrqs(UINT32 count, const UINT32 *pIrqs);
This finction disables the list of interrupts identified by an IRQ. If your implementation uses hardware platform callbacks, OALIntrDisableIrqs must call BSPIntrDisableIrq for each IRQ in the list before it disables the IRQ. BSPIntrDisableIrq can also perform board-specific actions and modify an IRQ.
UINT32 BSPIntrDoneIrq(UINT32 irq);
VOID OALIntrDoneIrqs(UINT32 count, const UINT32 *pIrqs);
This function scans the list of interrupts identified by an IRQ. If your implementation uses hardware platform callbacks, OALIntrDoneIrqs must call the BSPIntrDoneIrq function for each IRQ in the list before it re-enables each IRQ. BSPIntrDoneIrq can also perform board-specific actions and modify an IRQ.
UINT32 BSPIntrActiveIrq(UINT32 irq);
This function translates IRQs for chaining the controller interrupt. It is called from the interrupt handler if your implementation uses hardware platform callbacks.
