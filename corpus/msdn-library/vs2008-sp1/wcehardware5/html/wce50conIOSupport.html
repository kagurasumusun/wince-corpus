I/O Library

The I/O library implements I/O functions. It also contains functions used to map a bus address to a system address, read/write bus configuration space, and power off or power on bus controller. For more information, see %_WINCEROOT%\Platform\Common\Src\Inc\Oal_io.h.

Depending on your hardware platform, the I/O operations can be implemented as macros or as functions. By default, the code uses functions. If your hardware platform does not allow direct inline I/O operation, you must set the OAL_DDK_NOMACRO environment variable before the OAL libraries are compiled.

Kernel Interface

IOCTL_HAL_DDK_CALL
The kernel calls OEMIoControl with this control code to obtain information about the system cache.

OAL Interface

INPORT8(x)
This macro reads a byte from a specified address. On x86-based hardware platforms, the I/O address space is used.
INPORT16(x)
This macro reads a 16-bit word from a specified address. On x86-based hardware platforms, the I/O address space is used.
INPORT32(x)
This macro reads a 32-bit word from a specified address. On x86-based hardware platforms, the I/O address space is used.
OUTPORT8(x, y)
This macro writes a byte to a specified address. On x86-based hardware platforms, the I/O address space is used.
OUTPORT16(x, y)
This macro writes a 16-bit word to a specified address. On x86-based hardware platforms, the I/O address space is used.
OUTPORT32(x, y)
This macro writes a 32-bit word to a specified address. On x86-based hardware platforms, the I/O address space is used.
SETPORT8(x, y)
This macro sets the bits specified in the second parameter. On x86-based hardware platforms, the I/O address space is used.
SETPORT16(x, y)
This macro sets the bits specified in the second parameter. On x86-based hardware platforms, the I/O address space is used.
SETPORT32(x, y)
This macro sets the bits specified in the second parameter. On x86-based hardware platforms, the I/O address space is used.
CLRPORT8(x, y)
This macro clears the bits specified in the second parameter. On x86-based hardware platforms, the I/O address space is used.
CLRPORT16(x, y)
This macro clears the bits specified in the second parameter. On x86-based hardware platforms, the I/O address space is used.
CLRPORT32(x, y)
This macro clears the bits specified in the second parameter. On x86-based hardware platforms, the I/O address space is used.

UINT32 OALIoReadBusData(DEVICE_LOCATION *pDevLoc, UINT32 address,
UINT32 size, VOID *pData);
This function reads data from the device configuration space as specified by the first parameter. On most hardware platforms, this function supports only PCI bus-based devices.
UINT32 OALIoWriteBusData(DEVICE_LOCATION *pDevLoc, UINT32 address,
UINT32 size, VOID *pData);
This function writes data to the device configuration space as specified by the first parameter. On most hardware platforms, this function supports only PCI bus-based devices.
BOOL OALIoTransBusAddress(INTERFACE_TYPE ifcType, UINT32 busNumber,
UINT64 busAddress, UINT32 *pAddressSpace, UINT64 *pSystemAddress);
This function translates the bus-relative address to the system address, which can be used for I/O operations. The interface type and bus number specifies the bus.
BOOL OALIoTransSystemAddress(INTERFACE_TYPE ifcType, UINT32 busNumber,
UINT64 systemAddress, UINT64 *pBusAddress);
This function translates the system address to the bus-relative address, which can be used for DMA operations. This function maps the system RAM address to the bus-relative RAM address.

This function is not the inverse to OALIoTransBusAddress.

BOOL OALIoBusPowerOff(INTERFACE_TYPE ifcType, UINT32 busId);
This function puts the bus driver into power off mode. This function should save the bus driver state, if required, and switch off the power on the bus driver.
BOOL OALIoBusPowerOn(INTERFACE_TYPE ifcType, UINT32 busId);
This function puts the bus driver back into power on mode. This function should power on the bus driver and restore its state, if required.
