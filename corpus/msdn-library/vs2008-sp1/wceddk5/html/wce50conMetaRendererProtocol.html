Meta-Renderer Protocol

The meta-renderer follows a common protocol when its client queries for the interface. The meta-renderer takes the following steps:

  1. Checks that the requested interface is registered with a primary rendering interface and determines if a CLSID of the object is registered as the provider of this interface.
  2. Creates the instance of the renderer with this CLSID and queries for the IBitstreamProcessor interface to start the initialization sequence.
  3. Calls the IBitstreamProcessor::Init method.
  4. Determines which BitstreamType (represented as a DWORD and supplied by the author of the renderer object) should be used with this renderer while rendering the media type represented by the requested primary rendering interface. IBitstreamProcessor::SetBitstreamType method is called with this as an argument.
  5. After SetBitstreamType is called, the renderer should be ready to determine how many separate data streams it will use for rendering. Each data stream is represented by the IDMAChannel interface. The data streams will determine low-level (contiguous physical memory-based and limited in size and alignment) data transfer functionality. The meta-renderer calls the IBitstreamProcessor::GetDMAChannelCount and IBitstreamProcessor::GetDMAChannel methods to enumerate and obtain all DMA channels to be used for this bit stream type.
  6. For every exposed IDMAChannel, the meta-renderer creates an instance of Dataport object, which implements high-level asynchronous data transfer from the client software including virtual memory-based and arbitrary sizes. The default Dataport object is provided but alternative implementations can be specified.
  7. The created collection of Dataports is exposed by the meta-renderer as the IDataPortCollection interface and this is available for access by the client software immediately on return from the described QueryInterface process for primary rendering interface.
