NDIS Synchronization

Synchronization is necessary whenever two execution threads share resources that can be accessed at the same time. For example, if one driver function is accessing a shared resource, the shared resource must be protected to prevent race conditions that leave the resource in an indeterminate state. Such accesses must be synchronized.

  • Spin Locks

    NDIS provides spin locks that can be used to synchronize access to shared resources.

  • NDIS Timers

    When a thread is dependent on the occurrence of an event outside of the thread, driver notification is important. If the event is time-related, timers provide a driver notification mechanism. For instance, a driver might need to be notified when a period of time has passed so that it can check its device, or a NIC driver might have to perform a periodic operation, such as polling.

  • NDIS Events

    Events also provide a mechanism that two execution threads can use to synchronize operations. Events can be used to synchronize an operation between the thread waiting for the interrupt to complete and the thread that handles the interrupt. For example, a miniport NIC driver may need to test the interrupt on its NIC by writing to the device. It must wait for an interrupt to notify the driver that the operation was successful.
