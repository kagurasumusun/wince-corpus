DirectDraw Display Driver Creation Without DDGPE

This topic describes the steps necessary to create DirectDraw display drivers on Windows CE without using GPE.

The native interface to DirectDraw is described. Using the DirectDraw Graphics Primitive Engine (DDGPE) is easier to implement than the native interface, but it will not give you as much functionality. DDGPE is described in Driver Extension Using DDGPE.

For your driver, you will probably need to modify the functions and callbacks to reflect your specific hardware needs. To get your driver running as soon as possible, implement the driver initialization code first, and then add functionality. For example, first add flipping functionality.

In addition to the functions, callbacks, macros, and structures listed in the reference section, you must include both Ddrawi.h and Ddraw.h in your driver. Both of these include files are provided with Platform Builder.

Note   All callback function names listed in this reference section are placeholders that you can change.

Display driver developers should reuse the code base provided by the DDGPE classes. These classes add the small amount of code required to make your display driver function correctly. However, it is possible to write display drivers without DDGPE classes that conform to the Windows CE–based DDI interface definition and that also support the DirectDraw hardware abstraction layer (DDHAL) interface.

Additionally, you can create a native DirectDraw driver on top of GPE, not DDGPE. For an example, see the CT69000 third-party driver. For more information, see Hardware Compatibility and Third Party Device Drivers.

The following topics describe what driver developers must do to create a display driver that supports DirectDraw without using any GPE-based classes.
