Use of COM Aggregation in Meta-Rendering

The DVD-Video renderer (or any renderer to be used in a meta-rendering environment) has to be developed as COM object that can be aggregated. The instance of the renderer that has been created by the meta-renderer is aggregated into the meta-renderer, which means that the meta-renderer essentially becomes a renderer. All QueryInterfaces to the meta-renderer for all interfaces, except for the one used by the meta-renderer itself, are forwarded to the instantiated renderer. The meta-renderer becomes an outer unknown for the renderer.

The meta-renderer is always aggregated into the middleware. As a result, a middleware is forwarding all QueryInterface calls from the application for all interfaces it does not use itself to the meta-renderer. The meta-renderer, in turn, forwards them to the renderer.

Due to the aggregation hierarchy, an author of the renderer can implement any interface that exposes the special functions of the rendering hardware or software that are complimentary to the main playback functionality, for example, zoom or OSD. These interfaces become automatically accessible to the application developer. The renderer is also capable of accessing its outer unknown (meta-renderer) to access its services. For example, it can access data ports to send data to itself through DMA channels, if necessary.
