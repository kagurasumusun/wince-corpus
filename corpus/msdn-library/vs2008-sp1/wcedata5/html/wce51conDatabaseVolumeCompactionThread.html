Database Volume Compaction Thread

CEDB database volumes have an associated compaction thread is used to reclaim dirty space on the volume. By default, this compaction thread is set to normal priority. If another normal priority thread writes data to the volume at a faster rate than the dirty space can be reclaimed by the compaction thread, the volume must be extended. This can be accomplished by increasing the size of the volume file in order to accommodate the new data. If no space is left on the storage device to increase the size of the volume file, the write operations will fail.

This can be avoided by increasing the priority level of the compaction thread in the registry. The following registry example shows the registry settings that can be used to increase the priority level of the compaction thread.

;@CESYSGEN IF CE_MODULES_FILESYS
[HKEY_LOCAL_MACHINE\System\ObjectStore]
     "CompactionPrio256"=dword:252
;@CESYSGEN ENDIF

Alternatively, it is also possible to force the thread that is performing the write operations to sleep periodically. This provides more time for the compactor thread to reclaim the necessary dirty space.
