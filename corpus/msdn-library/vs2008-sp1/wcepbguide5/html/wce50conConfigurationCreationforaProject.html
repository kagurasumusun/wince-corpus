Configuration Creation

When you create a project for a Catalog item, Platform Builder sets the following default options for the Debug and Release configurations for the OS design, which also apply to projects in the workspace:

  • The Debug configuration contains full symbolic debugging information that the integrated debugger in Platform Builder can use. Platform Builder turns off optimizations in the Debug configuration because they generally make debugging more difficult.
  • The Release configuration does not contain any symbolic debugging information and it uses any optimizations that you set after creating the projects.

Depending on your Platform Builder installation and the choices you made when you created your OS design, you might have default configurations with other options, or you might create a custom configuration with other options included.

A configuration consists of build settings that determine the characteristics of the final output file for a project. When you create a configuration, it is based initially on the settings from an existing configuration that you select.

Options that you select for the new configuration, such as the microprocessor, can modify those initial settings. The new configuration always uses the same set of files as the configuration it is based on.

Projects are controlled by the configuration settings for the OS design, which apply to every file in the project. However, you can create different configurations based on conditional settings that you specify in the Project Settings dialog box, such as the target CPU that the project is built for.

In another example, you can specify settings for the Release configuration that do not apply to the Debug configuration. This is done by configuring conditional statements that determine what actions to perform.

For more information, see Project Settings: Edit Conditional.
