File Checkin and Checkout

When you begin work on a project, typically you open the workspace and get the current versions of workspace files to make sure you are working with the most up-to-date sources.

Before you begin to modify the source files, you check them out; after you complete the modifications, you check the files in again.

While a file is checked in, your local copy of the file is read-only, and you cannot save changes to it.

When you check a file out, you can make changes to your local copy of the file and then save those changes to the file.

When you check the file in, you copy those changes to the master copy of the file in the source code control system. This makes those changes available to other members of your group.

Whether multiple developers can check out a file simultaneously depends on the characteristics of your source code control system.
