File Checkin

When you check a file in, the source code control system does the following:

  • Changes the status of the file to read-only and it records that you have checked in the file
  • Records the differences between the contents of the file when you checked it out and when you checked it in

You generally want to view the changes to the file before you check it in to confirm the changes you made.

In some cases, you might want to discard all changes to your file before checking it in. In other cases, you might need to merge changes that other developers made to the file after you checked it out.

If you had the file checked out exclusively, after you check it in, others can check out the file.

If your source code control system does not support exclusive use, it is possible that while you had the file checked out, another developer had the file checked out, made changes, and then checked the file in.

In this case, before you check in your local copy of the file, you must find out changes were made by the other developer.

If so, you must merge those changes into your local copy. Then, you can verify that all changes are compatible and that none of them cause problems when you use the file.

After you verify the changes, you can check in the file.

If you make changes to a local file and then decide that you do not want to keep the changes, you can have the source code control system check in the file, but ignore changes you made to it.
