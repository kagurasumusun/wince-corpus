Provisioning XML Considerations

Send Feedback on this topic to the authors

When creating provisioning XML. you must consider how the XML will be sent and received.

This section discusses considerations when initially configuring a device for each type of deployment scenario. Before using this section, you should have determined how you will deliver the XML provisioning file. The following sections will help make this choice:

  • Options for Delivering Provisioning XML Files to Windows Mobile-Based Devices

For information about bootstrapping a device by using provisioning XML, see Bootstrapping Windows Mobile-Based Devices.

For security considerations, see Considerations when Changing Security Settings.

Do you want to use wireless session protocol (WAP) push services?

You can set up the device to receive services such as Over-the-Air (OTA) provisioning, Multimedia Messaging Service (MMS), Service Loading (SL) and Service Indication (SI) Messages.

If you will use WAP push services, you should consider the following:

  • Consider the combination of services you want to use:
    Service Link to more information
    OTA provisioning OTA provisioning considerations
    Multimedia Messaging Service MMS Provisioning Considerations
    Service Indication (SI) and Service Loading (SL) SI and SL Provisioning considerations
  • Consider which roles should be assigned to messages from the preceding services.
    For information about security roles, see Security Roles and Provisioning XML Considerations when Changing Security Settings.

Do you want to allow remote applications to use RAPI to implement ActiveSync operations?

The RAPI policy restricts access of remote applications that are using Remote API (RAPI) to implement ActiveSync operations.

If using ActiveSync, you must use Desktop ActiveSync version 4.0 or higher.

For more information, see Security Policy Settings.
