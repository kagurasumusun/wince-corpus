Building and Testing Windows Mobile-based Pocket PC Help

This article is aimed at the following audiences:

  • Help authors creating Help for Windows Mobile-based Pocket PC applications
  • Developers of Windows Mobile-based Pocket PC applications responsible for creating links to Help content
  • Testers of Windows Mobile-based Pocket PC applications responsible for testing Help content and links to Help

This article provides information about creating, linking to, and testing Windows Mobile-based Pocket PC Help content. Throughout the paper, emphasis is placed on providing step-by-step instructions and examples of typical content and content setup.

Introduction

The latest release of Windows Mobile software for Windows Mobile-based Pocket PCs introduces a new content model for Windows Mobile-based Pocket PC Help. This new model gives users a consistent entry point to Help, via portal pages, and a revised table of contents that includes a task-based organizational structure. For a representation of a Windows Mobile-based Pocket PC portal page, see Figure 1.

Figure 1. Windows Mobile-based Pocket PC Help portal page

The Help window consists of a content area and a navigation toolbar. The Windows Mobile-based Pocket PC Help application, peghelp.exe, provides the navigation toolbar, and an HTML-rendering program displays the content. The window is always displayed at full size.

From any entry point, the initial Help window displays a portal page containing a list of context-sensitive "best bet" links for that entry point. For example, if the user is in the New Appointment dialog box in Calendar, a portal page headed by a link to the Add an appointment Help topic appears.

Note   In some instances, such as with legacy third-party programs, Help might display a table of contents or a Help topic instead of a portal page.

After Help is opened, navigating within Help files also varies according to the device being used. The following table lists navigational functions.

Button Function
Contents Displays the Windows Mobile-based Pocket PC Help table of contents, which includes both task-based links to Windows Mobile-based Pocket PC Help and a list of links to Help for other installed Windows Mobile-based Pocket PC applications. The latter list can be customized through link files. For more information, see "How to Add Your Help TOC to the Main TOC."
Search Opens the Search dialog box to search for Help content.
Back arrow Displays the previously viewed Help topic.
Forward arrow Displays the next topic in a sequence of previously viewed Help topics.

Portal Pages

In Windows Mobile Version 5.0, a user chooses Start > Help from anywhere on the Windows Mobile-based Pocket PC, a portal page is displayed. This HTML page is similar in its underlying code to any other Windows Mobile-based Pocket PC Help topic. However, instead of a single topic describing the user interface of the entry point, the portal page contains a list of links to "best bet" topics; that is, links to a few of the most likely subjects of interest to a user at that entry point. The topic describing the user's entry point into Help should top that list. For example, if the user launches Help from an edit dialog box, the first Help topic link on the portal page should explain how to use that edit dialog box. From each entry point, the portal page offers the following:

  • Topics related to the current entry point
  • Access to the main Windows Mobile-based Pocket PC Help table of contents
  • Access to the last topic visited
  • Access to search functionality

Table of Contents

Conceptually, the new TOC model for Windows Mobile-based Pocket PCs has two levels. Entries at the top level link to a sub-TOC, and entries in the sub-TOC link to a topic.

The TOC file is a static HTML file named Mainhelp.htm and is similar to other Windows Mobile-based Pocket PC Help files. It is divided into separate topics using <!-- PegHelp --> tags. The first topic in the file is the main TOC, which contains the following:

  • A list of links to sub-TOCs organized by task.
  • A dynamically created list of alphabetically organized links to separately installed Help files. In previous versions, this dynamic list was the entire main TOC for Windows Mobile-based Pocket PC Help.

After the main TOC, the sub-TOCs that link to Windows Mobile-based Pocket PC Help topics are included as separate topics.

Building Windows Mobile-based Pocket PC Help

A Windows Mobile-based Pocket PC Help system consists of regular HTML (.htm) files and graphics, plus some additional HTML coding and special HTML tags that are needed to enable Windows Mobile-based Pocket PC Help to determine where individual topics begin and end.

You can use all of the HTML 4.01 tags supported in Internet Explorer Mobile, in addition to Extensible HTML (XHTML), client-side JavaScript 1.5 (ECMA-262), the Internet Explorer 4.01 Document Object Model, Cascading style sheets (CSS), ActiveX® controls, and eXtensible Markup Language (XML). Microsoft Visual Basic® Scripting Edition (VBScript) is not supported.

The Structure of Windows Mobile-based Pocket PC Help Topics

It is a best practice to use a single HTML file for a Windows Mobile-based Pocket PC application. Within that HTML file, each topic in a Help file must be separated by the <!-- PegHelp --> tag. (Note the space immediately before and immediately after PegHelp.) This tag is placed at the end of the HTML <HEAD> section and again after each topic to mark the beginning and end of each individual Help topic. If you do not use this tag, topics will appear as one long HTML file.

To provide the URL for Windows Mobile-based Pocket PC Help to use with the link (.lnk) files to create a dynamic TOC list, the following <META> tag must be included in the HTML file <HEAD> section: 

<META HTTP-EQUIV="Htm-Help" Content="sample.htm#Main_Contents">

The first topic in each Help file must be identified by an anchor tag named "Main_Contents" (for example, <a name="Main_Contents">). This name is used with the link files to add the Help file to the Windows Mobile-based Pocket PC Help TOC. Each additional topic must have a unique anchor name of your choice. At the end of each topic, insert the <!-- PegHelp --> tag. The following example is the Setting Solitaire Options topic in Solitaire Help:

<!-- PegHelp --><HR>
<!-- ************************Topic Break******************* -->

<A NAME="setting_solitaire_options"></A><B>Setting Solitaire Options</B>

<OL>
<LI>Select <B>Options</B>.</LI>
<LI>Select desired options. </LI>
</OL>

<B>See Also</B><BR>
<A HREF="soltr.htm#playing_the_game" TARGET="_self">Playing the Game</A><BR>
<A HREF="soltr.htm#solitaire_scoring_systems" TARGET="_self">Solitaire Scoring Systems</A>
<BR CLEAR=ALL>
<!-- PegHelp --><HR>
<!-- ************************Topic Break******************* -->
Tip   To help locate topic breaks when viewing in an editor or in Internet Explorer, you can use the <HR><!-- **Topic Break** --> tag combination shown in the preceding example. These tags are not needed by Windows Mobile-based Pocket PC Help and do not change the way Help appears to users, but they can make it easier for Help authors to scan files to find individual topics. Because it is placed after the <!-- PegHelp --> tag, it is not displayed in Windows Mobile-based Pocket PC Help.

How to Add Hypertext Links to a Help Topic

To create a jump to another file that opens that file to its first topic, use the <A HREF=""> anchor tag, as follows:

<A HREF="helpfile.htm">

To jump to a topic within the current file, you must include the file name and the anchor name, as shown in the following code:

<A HREF="helpfile.htm#anchor_name" TARGET="_self">
Tip   Some software used to verify links does not work correctly because the name of the file is in the internal jump. Searching and replacing .htm# with # before running a link test should resolve the problem. Be sure to do this on a copy of the file, not the original.

How to Add Images to a Help Topic

Windows Mobile-based Pocket PC Help supports the following image formats:

  • PNG
  • JPEG
  • GIF
  • Animated GIF files
  • BMP

To add an image bitmap to a topic, use the standard HTML <IMG> tag to specify the file name of the image you want to include, as follows:

<IMG SRC="button.bmp" ALT="button">

How to Customize Content for Windows Mobile-based Pocket PC Phone and Non-Phone Editions

In Windows Mobile Version 5.0, Windows Mobile-based Pocket PC Help automatically provides the ability to dynamically show or hide content that is specific to a particular phone protocol or to a non-phone device. To mark content to take advantage of this functionality, use an HTML <DIV> tag with a CLASS attribute marking the content as shown in the table below.

<DIV CLASS="cdma">
Class value Function
cdma On a Windows Mobile-based Pocket PC with phone that operates on a CDMA-based network, marks content that is exclusively about features unique to that network.
gsm On a Windows Mobile-based Pocket PC with phone that operates on a GSM-based network, marks content that is exclusively about features unique to that network.
phone On a Windows Mobile-based Pocket PC with phone, marks content that is exclusively about features unique to a cellular device.
nophone On a Windows Mobile-based non-phone Pocket PC, marks content that is exclusively about features unique to a non-cellular device.

How to Create Search Keywords for Your Help Topics

Windows Mobile-based Pocket PC Help uses keywords and Windows Mobile-based Pocket PC Search functionality to enable users to quickly search for Help information. Users access the keyword functionality by tapping Search, which is located on the menu bar at the bottom of the Help window. Users then enter a word or words for which to search for and tap Search. For a representation of a Windows Mobile-based Pocket PC Search results page, see Figure 2.

Figure 2. Windows Mobile-based Pocket PC Search results

The Results list in Search displays the titles of all Help topic titles with <KEYWORD> tags that contain the same keyword or keywords that were entered. To open a topic, users tap a topic title in the Results list.

You can tag your topics with keywords by using a special tag in the <HEAD> section of the Help file with the following syntax:

<KEYWORD VALUE="keyword1;keyword2" TITLE="Title of the topic" HREF="helpfile.htm#anchor_name" TARGET="_self">

The <KEYWORD> tag has three attributes, which are described in the following table.

Attribute Function
VALUE Contains the search keywords, separated by semicolons. There is no limit to the number of keywords that can be associated with a topic.
TITLE Contains the title that appears in the Results section of the Search dialog. It should be the actual title of the topic.
HREF Contains the URL for the target topic.

The following is an example using keywords:

<HEAD>
<KEYWORD VALUE="typing;writing;drawing;recording;type;write;record" TITLE="About SIP" HREF="notes.asp?FRAME=true#aboutsip" TARGET="_self">
</HEAD>

Enter a separate <KEYWORD> tag for each topic in the Help file, and list the appropriate keywords for that topic. Use the same strategy that you would use for selecting indexing keywords.

Windows Mobile-based Pocket PC Help does search for partial matches against keywords. For example, the word advantage matches with the keywords advantage and advantages.

Phrases cannot be used as keywords, but users can use phrases, such as high score, when entering queries in the Search dialog box. Windows Mobile-based Pocket PC Help searches for all words listed in the phrase. Users cannot perform OR searches.

How to Add Your Help TOC to the Main TOC

The main TOC in Windows Mobile-based Pocket PC Help provides users with a fast way to scan Help topics for the exact type of information they need. The Windows Mobile-based Pocket PC Help TOC includes static links to Windows Mobile-based Pocket PC Help, organized by task, and a dynamically created list of links to Help for separately installed Windows Mobile-based Pocket PC applications.

Adding Entries to the Static TOC Content

If you are an OEM or Mobile Operator who has access to the ROM image for Windows Mobile-based Pocket PC Help, you can add links to your Help content within the task-based list of static links in the file mainhelp.htm. You can do this with any HTML editor or text editor.

Adding Entries Dynamically

At the end of the main TOC is link titled "Help for Added Programs." The HTML page that is the target of that link is where the an application adds a link to its Help to the Table of Contents. Such links are usually added by programs that are installed by the user.

To add a link to an application's Help file to the Tables of Contents programmatically, you'll need to

  • Use a standard anchor name for the first topic in each Help file you ship
  • Include a corresponding link (.lnk) file for each Help file

New link files can be added at any time.

To add a Help file dynamically to the main TOC

  1. The first topic in the Help file must be identified by an anchor tag named "Main_Contents" (for example, <a name="Main_Contents">)  
    <!-- PegHelp -->
<P><A NAME="Main_Contents"></A><B>Solitaire Help</B></P>
  2. The "Main_Contents" URL must appear in the <META> tag (for example, <META HTTP-EQUIV="Htm-Help" CONTENT="filename.htm#Main_Contents">). 
    <!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 3.2 Final//EN">
<HTML>
<HEAD>
<META HTTP-EQUIV="Htm-Help" CONTENT="soltr.htm#Main_Contents">
<TITLE>Solitaire Help</TITLE>
</HEAD>
  3. Create a .lnk text file with the name you want to appear in the TOC. It must contain only the following:
    1. The number of characters in the file name and location string.
    2. The name and location of the Help file.

      Example: 

      18#\windows\soltr.htm

      Solitaire.lnk contains only the string 18#\windows\soltr.htm (18 characters in \windows\soltr.htm).

  4. The link file must be installed in the \Windows\Help folder on the device. The help file can be installed anywhere, as long as the .lnk file contains its correct location. However, links from your help file to other help files (and vice versa) will not work unless your help file is also in the \Windows\Help folder.

How to Add Context-Sensitive Links to Help Topics from an Application

Windows-based applications for the desktop computer often have both a Help system and context-sensitive What's This? content. The Help system is written and compiled by the Help authors as a WinHelp (.hlp) or HTMLHelp (.chm) file and is opened from the Help menu. What's This? content is stored in the Help file and is opened by a Help button or by pressing F1. Help is then called by means of a header file that maps the Help topic IDs to numeric values that represent specific dialog boxes or dialog box options.

The concept behind all Help linking on Windows Mobile-based Pocket PCs is very similar to What's This? Help, with the following important differences:

  • The Help command always relates to the entire Windows Mobile-based Pocket PC screen that the user is working with at the time Help is opened, and the command cannot be set for a specific option in a dialog box.
  • Instead of using numeric values and then mapping those values to topic names, the actual Help file name and topic name are called from the program code.

Otherwise, tapping Start and then tapping Help on a Windows Mobile-based Pocket PC is the same as pressing F1 on a desktop computer. The WM_HELP message triggers code written for the topmost active dialog box to start Help and instruct Help what to display.

Using the CreateProcess function is one way the call can be made. Using the TEXT macro to first convert the string to Unicode, pass the "peghelp.exe" string, which is the name of the Help engine, as the first parameter. In the second argument, use the TEXT macro again and pass a string containing the file name and specific Help topic you want to display. Set all other parameters to NULL, FALSE, or 0.

Each dialog box in your application should handle the WM_HELP message and display the appropriate topic as shown in the following example.

// **********************************************************************// StartHelp
//
// Purpose:
//  Launches the Help on the device.
// **********************************************************************
void StartHelp(LPCTSTR pszHelpURL)
{
    PROCESS_INFORMATION pi;
    CreateProcess(TEXT("peghelp.exe"),
                  pszHelpURL,
                  NULL,
                  NULL,
                  FALSE,
                  0,
                  NULL,
                  NULL,
                  NULL,
                  &pi);
    CloseHandle(pi.hThread);
    CloseHandle(pi.hProcess);
} 

In the preceding sample code, pszHelpURL is a variable containing a Windows Mobile-based Pocket PC URL in the following format:

file:helpfile.htm#anchor_name
Note   When using Microsoft Foundation Classes, you do not directly process the WM_HELP message but you override the WM_HELPINFO message.

To override the WM_HELPINFO message

  1. Open the Class Wizard by pressing CTRL+W.
  2. Select the dialog box or window class that you want in the Class name drop-down list.
  3. In the Messages list box, double-click WM_HELPINFO (or click it once and then click the Add Function button).
  4. Click the Edit Code button.
  5. Add the CreateProcess call to start PegHelp, as shown previously.

How to Test a Help System

To quickly check for typographical errors, you can browse through all of the Help topics as you would in Internet Explorer on your desktop computer. However, to replicate your user's experience, you should test your Help files on a device to help ensure that they look and work the way you expect.

To browse the Help file on the device, you can use ActiveSync on your PC to copy the Help file to the Windows folder on the device (in ActiveSync, click the Explore button to perform file operations). Do not synchronize or convert the file. Then, to open the Help file in Internet Explorer Mobile on the device, click its name.

To check all of your context-sensitive links, open Help from each window and dialog box in your application. If a link for the Help file has not been added to the list of all installed Help files or connected to an application, you can still open the Help file from the Run dialog box.

To open a Help topic from the Run dialog box

  1. On the Today screen, press and hold the Action key.
  2. Tap and hold the clock in the upper-right corner of the screen, and then tap Run.
  3. In the Run dialog box, type the following: 
    \Windows\peghelp.exe \Windows\filename.htm#Main_Contents.

    Note the space between "peghelp.exe" and "\Windows\."

More Tips and Tricks

Following are some additional useful guidelines to consider as you develop your Help topics:

  • Help information should be fairly comprehensive because mobile device users are unlikely to carry manuals. However, try to convey as much information in as little text as possible. For example, instead of writing, "On the File menu, tap Open," write "File > Open." The writing style you choose affects readability and the amount of memory used.
  • Memory is limited on some devices. Limit graphics to pictures of buttons that are not menu commands or are not familiar to experienced Windows users, or use black-and-white images instead of color images.
  • When developing topics, use HTML tags that are supported by Internet Explorer Mobile. To make your Help topics consistent and easy to read and to reduce overall file size, limit the number of formatting tags.
  • The features and functionality of devices vary, and you might not always know what type of hardware your users have. These conditions call for flexible style guides and the use of more generic terms to avoid confusing your user. For example, if the device could have either a touch screen and stylus or a mouse, you can use select instead of tap or click in your Help text.
