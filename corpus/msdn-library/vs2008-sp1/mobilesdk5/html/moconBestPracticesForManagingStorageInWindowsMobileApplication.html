Best Practices for Managing Storage in a Windows Mobile-based Application

Send Feedback on this topic to the authors

Storage performance varies depending on the storage hardware and the overall system design. Currently, Pocket PC devices can choose a RAM-based file system or a flash-based file system. Smartphone devices use a flash-based persistent storage file system.

For an in-depth discussion of storage hardware technologies, see this Microsoft Web site.

Storage Hardware Performance Considerations

The following table shows a relative comparison of the performance of various operations on flash-based persistent storage file systems and RAM-based file systems.

Operation Flash-based RAM-based
Local read Slower Faster
Local write Slowest Faster
Network read Faster Slower
Network write Faster Slower
Battery-backed hardware No Yes
Registry persistence Preferable over RAM-based Yes

Best Practices for Storage Software Performance

Adhering to the following list of best practices can help you minimize any performance impacts your application may have:

  • Minimize the size of your application.
  • Minimize the amount of persisted data. The file system's resources may be limited, so ensure that your application is tolerant of a storage system that may not perform ideally at all times.
  • Minimize the frequency of altering data. Do not constantly change data.
  • Minimize any periodic writing to the registry. Do not constantly write to the registry.
  • Minimize the number of dynamically-linked libraries (DLLs). If the library is not called into very often, dynamically loading the library is better than statically loading the library, but be sure to unload the DLL after you are done with it.
  • Minimize polling. Instead of polling with a while loop, use an event driven design so your application is notified of any changes that it requests.
  • Execute less code. Code is compressed in ROM, so before code can execute, it must be decompressed. Decompressing code affects performance. For example, on a typical Smartphone development platform, it takes three milliseconds (ms) to decompress one page of code. Executing code consumes power; execute code only if absolutely necessary.
  • Execute code only when appropriate. For example, stop an animation when it is not visible to the user.
  • Minimize reading and writing to flash hardware. On a typical Smartphone development platform, it takes 83 ms to write one page of code to flash hardware. Instead of writing to flash hardware, write to RAM as much as possible. If the write to flash hardware is unavoidable, postpone writing for as long as possible. Writing to flash hardware consumes more power than writing to RAM, so minimize writing to flash hardware to minimize power consumption.
  • Mark drivers as pageable as much as possible. As long as the driver does not execute during suspend or resume, and it is not needed to service a page fault, you can mark it as pageable. RAM contains all nonpageable drivers and DLLs. During boot-time, all nonpageable drivers and DLLs must decompress into RAM.
