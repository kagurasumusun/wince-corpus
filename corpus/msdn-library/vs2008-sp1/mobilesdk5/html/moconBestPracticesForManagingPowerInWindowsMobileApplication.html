Best Practices for Managing Power in a Windows Mobile-based Application

Send Feedback on this topic to the authors

Power management is most effective when you design it into the application. Poorly power managed applications may drastically and negatively affect power management for the entire device by reducing the device's standby time. There are many ways to optimize battery life. You need a way to measure how effectively you are optimizing power and battery life and whether you are getting your desired results.

There are hardware and software tools to track performance, battery life and power consumption. You can characterize the power management of the device by examining the current state of software on device. To characterize the power management, examine what is consuming the most power, what percentage of power each application consumes, what the power management baseline is for the device, what the duty cycle is for each application, what the duty cycle is for GSM polling, and so on. Measuring power management and tracking power consumption helps you to discover areas that you can improve performance.

Microsoft recommends using a regulated power supply that provides power to the device, captures analog data, samples the data, and then logs it to a file. To measure the voltage drop across the device, attach sense resistors in series with the battery, and then measure the current flowing through the sense resistors to measure how much current the device is using with respect to time.

Pocket PC vs. Smartphone

  • Pocket PC implements a standby model for power management. That is, it must maintain a baseline power level because a RAM-based file system's hardware must refresh periodically to maintain its data.
  • Smartphone implements an idle model for power management so the device can idle frequently.

Optimizing Total Power (PTotal)

The following equation determines the total power of the device:

PTotal = PIdle(1 – CPU Utilization) + PActive(CPU Utilization)

PIdle represents the power used while device is idle, and PActive represents the power used while device is active. The operating system and any executing applications determine CPU utilization. To maximize power and battery life, minimize the CPU utilization.

Optimizing Active Power (PActive)

Executing code consumes power; conserve PActive by minimizing CPU utilization. The following list shows how to conserve power and maximize battery life:

  • Close handles to peripherals when your application no longer needs the handle. When calling into device driver to operate on a peripheral, you need a handle to that device driver. When you are done operating on the peripheral, close the handle.
  • Design protocols efficiently. Keep in mind that the device will consume more power when sending bytes as compared to receiving bytes. In any case, sending and receiving bytes consumes power.

Optimizing Idle Power (PIdle)

To optimize PIdle, which conserves power and maximizes battery life, adhere to the best practices in the following list:

  • Design applications to be event driven. Applications should only process when they interact with the user.
  • Execute as little code as possible.
  • Execute code only when absolutely necessary.
  • Avoid polling by using an event driven design.
  • Monitor the WM_ACTIVATE messages so you know when your application is visible. You can use GetClipBox to determine if your application is partially visible.
  • Do useful work in applications that are not visible to the user. Do not do unproductive work in applications that are not visible, for example, do not render animations in an application that is not visible to the user.
  • Avoid using indefinite or continuous timers.
  • Ensure that your application is not continually draining the microprocessor.
  • Use zero microprocessor cycles if the device is not being used.
