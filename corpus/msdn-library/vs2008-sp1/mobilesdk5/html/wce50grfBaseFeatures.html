Windows Mobile Version 5.0 SDK  

Core OS Services Product Reference Guide

Send Feedback on this topic to the authors

The following table shows improvements to the Core OS.

Item Description
General navigation performance on Smartphone (including boot time) (SP Only) Users powering on a Windows Mobile-based Smartphone experience a wait time similar to Windows Mobile 2003 Second Edition before they can make calls, read e-mail, reference their calendar, etc. During and after a synchronization, the device remains usable without noticeable performance lags. Music playing on Windows Media Player in the background is not interrupted by navigating around the device software.
Managed code wrappers (PPC+SP) Original equipment manufacturers, mobile operators, and ISVs can develop applications in managed code (.NET CF) that use many of the deep platform capabilities of the device that earlier would have necessitated the use of native code. Examples of such applications are those for POOM, MAPI, TAPI, and Config.
Secure Digital I/O (SDIO) (PPC+SP) Windows Mobile users can use any of an array of standard SDIO accessories.
DirectX graphics (DirectDraw, Direct3D Mobile library support) (PPC+SP) Users experience rich graphics for an array of applications, from gaming to 3D modeling.
Standalone emulator (without need for Dev Tools) (PPC+SP) Anyone can boot and use a device emulator to experience Windows Mobile without the need for an actual Windows Mobile-based device. This feature will be released for external customer use but not formally supported.
More enterprise class code samples in SDK (PPC+SP) A richer and broader array of enterprise class applications are available for Windows Mobile-based devices.
Improved emulation experience (PPC+SP) Developers are able to build and test applications using the emulator more quickly and easily, resulting in a richer selection of applications available for Windows Mobile-based devices.
Improved documentation in the SDK (PPC+SP) ISVs can more easily create Windows Mobile applications, and more easily get their applications signed.
Documentation enhancements Provides the following highlights.
  • Best Practices information and sections have been added.
  • Design Guidelines provides User Interface design guidelines to help you to provide a good user experience.
  • Device Management Architecture discusses the various options that you can use to manage a device, including using the OMA DM protocol.
  • Added XML examples help you to quickly create XML to customize your devices. Most examples arein Examples are in the following sections:
    • Configuration Service Provider Reference for Windows Mobile-Based Devices
New version of CE OS (PPC+SP) Build Windows Mobile 5.0 on Windows CE 5.01. This version of Windows CE is developed in parallel with Windows Mobile 5.0 and includes features specifically requested by the Mobile Devices team to support Windows Mobile 5.0 features.
Persistent storage (PPC Only) All registry settings, user data, and third-party applications can be stored in nonvolatile memory. Thus, battery power is not required to keep data from being lost.
Persistent data storage (PPC Only) Original device manufacturers will be able to build Pocket PC devices that can save all post-purchase data, applications, and registry changes to nonvolatile memory, as opposed to the current solution which required some data to be saved to volatile memory.
MultiBin system file system (PPC+SP) Replace the MultiXIP mechanism for managing SKUs and feature sets in previous mobile device releases with the completely re-engineered MultiBin mechanism.
Enhanced device update mechanism (PPC+SP) Reliably update mobile devices in the field without losing user data.
File-based digital rights management (PPC+SP) Developers can use the file-based digital rights management (FDRM) API to enable DRM in Windows Mobile Applications. The FDRM API defines the interface to FDRM-managed content for Windows Mobile Version 5.0 for Windows Mobile-based Pocket PCs and Smartphones. OEMs must provide the implementation for the FDRM engine, for example an OMA DRM v1 engine.
Improved install from Getting Started Disc (PPC+SP) Improve the Windows Mobile Getting Started Disc, previously known as the Companion CD, to take the user through a step-by-step install procedure for ActiveSync, Outlook, and other applications. Include detection and intelligence so that only needed applications are installed by the wizard. Allow original equipment manufacturers to add critical or desired applications to the step process in addition to AS and OL.
FIPS 140-2 certification (PPC+SP) Federal Information Processing Standard (FIPS) 140.
Managed Config (PPC+SP) .NET CF developer can access Configuration Manager using C# to make settings or change the home screen.
Unified installer (PPC+SP) Unified installer for Pocket PC and Smartphone.
OMA Device Management (PPC+SP) Supports device management through one-way and two-way communications. OMA Client Provisioning provides a one-way Wireless Application Protocol (WAP) push. The OMA Device Management (DM) protocol provides two-way communications between the server and the device. Microsoft Windows Mobile-based devices accept standard OMA DM task requests. This allows a server that supports the OMA DM protocol to manage the device. For more information, see OMA Device Management.
Remote query for device configuration settings (PPC+SP) Operators can remotely query certain device settings to check whether proper values are set.
Operator initiation of a DM request to device (PPC+SP) To accomplish a device management task, an operator sends a signed SMS notification to the device. The DM client on the device processes the notification and sets up the HTTPS connection with the DM server. The server sends the DM commands to the device over the HTTPS channel.
Secure DM transport (PPC+SP) The DM server initiates the DM session by sending a notification to the device, which sets up an SSL channel with the server. Every message transported between the server and the client is encrypted and data integrity is guaranteed.
Remotely manage OMA DM server access information Operators or enterprises can remotely modify, query, or delete device-stored OMA DM server access information.
OMA DM configuration of Microsoft-specific settings (PPC+SP) Operators will be able to leverage the OMA DM standard to send XML files to configure a number of Microsoft specific settings, such as: certificates, registry, security policies, locale settings (only for Smartphone), sounds settings (only for Smartphone), home screen settings (only for Smartphone), clock (only for Smartphone), e-mail settings, server synchronization settings, VPN, etc. They can also remotely revoke certificates.
Remotely bootstrap the device with OMA DM server access information (PPC+SP) Operators sends WAP Push client provisioning message to the device which contains OMA DM server access information over the air. The device DM client accepts the message and configure the device with that information
DirectX Mobile : DirectDraw/Direct3D Mobile (.NET managed APIs) (PPC+SP) Managed code access for D3D functionality
Managed wrappers for Configuration API (PPC+SP) ISVs who write applications using managed code will easily be able to send provisioning XML from within their applications.
Improved RAM usage on Smartphone (SP Only) Amount of RAM after boot on Windows Mobile 5.0 is higher than on Windows Mobile 2003 Second Edition.
