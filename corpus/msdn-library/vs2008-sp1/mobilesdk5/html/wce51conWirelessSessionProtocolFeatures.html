Wireless Session Protocol Features

Send Feedback on this topic to the authors

Wireless Session Protocol (WSP) defines the methods that client and server applications use to exchange content, such as provisioning files. The methods that WSP defines include procedures for establishing and releasing sessions, the level of protocol functionality, content exchange with compact encoding, and procedures for suspending and resuming sessions. WSP uses Hypertext Transfer Protocol (HTTP) 1.1 functionality. For more detailed information about WSP, see the WAP Wireless Session Protocol Specification Version 4-May-2000, available from this OMA website.

The following table shows the features that are required by the Push Router, such as connectionless unsecure push features. It does not list all of the WSP features that guided Windows Mobile Version 5.0 development.

WSP feature Description
WSP_CL_C001 Push Protocol Data Unit (PDU) for Push Messages The Push Protocol Data Unit (PDU) is used for sending messages without receipt confirmation from the device, as described in "Service Primitives" and "Push and Confirmed Push Facilities" in the WAP Wireless Session Protocol Specification Version 4-May-2000.
WSP_CL_C002 Default Header Encoding Page Default header encoding pages are implemented as described in "Header Encoding" in the WAP Wireless Session Protocol Specification Version 4-May-2000. The SEC and MAC parameter assigned numbers — used by content-type — from the WAP WSP 2.0 specification are also valid.
Note   Windows Mobile-based Smartphones and Windows Mobile-based Pocket PCs (GSM Phone Edition) support only the token text encoded mac attribute. Windows Mobile-based Pocket PC (GSM Phone Edition) does not support the quoted text encoded mac attribute.
