Managing Browser Windows and Window Navigation

Send Feedback on this topic to the authors

To simplify the browsing experience and improve performance and memory footprint, Internet Explorer Mobile uses a single display window. Although sites designed for the desktop-computer browser use multiple windows regularly, Internet Explorer Mobile does not use this feature. This results in the following issues:

  • Using window.open

    In Internet Explorer Mobile 2000, calls to window.open fail silently (if script errors are off). Attempts to use <A HREF="..." TARGET="_new"> (or any other nonexistent frame) do not invoke a new browser window.

    In Internet Explorer Mobile 2002, window.open works if it is caused by a user-initiated navigation but not if the page automatically calls it to open an advertising window or something similar. For example, if the user taps a link that causes some script to execute, which in turn calls window.open, that is treated as a user-initiated navigation and the contents of the specified window are displayed in the browser window. The Back button navigates back to the page that caused the window to open.

  • Using the TARGET attribute of the <a> tag

    Using target=_new with the <a> tag does not open a second window as it would with a browser on a desktop computer. You can use the target attribute to point only to a named frame. Using any other specified target (for example, target=_new) causes Internet Explorer Mobile to behave as if you had not specified any target.

  • Other tags that support the TARGET attribute: <AREA>, <BASE>, <FORM>
  • Valid values for TARGET:
    • Internet Explorer Mobile 2000 supports _top and _parent.
    • Internet Explorer Mobile 2002 supports _top, _parent, and _blank.
    • Internet Explorer Mobile 2003 supports _blank, _top, _parent, and _self.
