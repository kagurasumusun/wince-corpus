User Interface Control Guidelines

Send Feedback on this topic to the authors

The following table provides guidelines for user interface (UI) controls.

UI control Guideline
Check box Use a check box only when it provides choices that are opposite and unambiguous. Otherwise, use option buttons. For more information, see Check Box Guidelines.
Combo box (PPC-only) Use combo boxes in place of option buttons to conserve space or when the user needs to add entries to a list.

Consider the following when you include combo boxes in an application:

  • Pre-scroll the list so that the currently selected item is in view, if the state of the list was saved.
  • Determine the trade-off between saving space and clearly identifying all application options using option buttons.
Note   More than a navigation pad is needed to access all the combo box functionality such as the drop-down list and list selection.

For labels, use the 9pt, Tahoma black font.

Command button On Windows Mobile-based Smartphones, only Microsoft Internet Explorer Mobile has command buttons. All other applications use soft keys.
Note   The command button control refers to software application buttons as opposed to hardware buttons or keys.

To conserve space, do not include an Apply command button in an application, because it requires an OK button. Instead, use only an OK button.

Limit the label to two words. On Windows Mobile-based Pocket PCs, use the 9pt, Tahoma regular font for labels in Asian languages. For all other languages, use the 8pt, Tahoma bold font. On Windows Mobile-based Smartphones, use the 11pt, Segoe bold font.
Date picker The date picker control provides a calendar display that enables a user to select a date and display it in a specified format.

On Windows Mobile-base Pocket PCs, place the date picker control near the top of an application screen to prevent it from being forced off the screen when the input panel is displayed.
Expandable edit control (SP-only) This control is expanded to full screen when the user presses the ENTER hardware button.

Include the expandable edit control in an application to conserve space . Use the control in place of tabs, which are not available for Windows Mobile-based Smartphones.
Header (PPC-only) Include a header control in an application to enable data sorting, folder selection, and other list-specific functionality for a list view control.

In general, a header control should enable folder selection on the left side and data sorting on the right side of the list view control.

In most cases, limit headers to one word. Two words are acceptable when the header is used with a list view control that has only two columns. Use the 11pt, Tahoma font.
Horizontal line separator Include horizontal line separators in an application to visually group items on a screen or to separate content areas of a screen.
Hyperlink When you use an HTML control to create a hyperlink, you can take advantage of other aspects of the HTML control such as background images. For more information, see Hyperlink Guidelines.
List box (PPC-only) Consider the following when you include list box controls in an application:
  • If a list box maintains state, it should display the currently selected item by default.
  • Use icons to help the user quickly differentiate between types of items.
  • When a list box has multiple columns, use a text header to label columns.
Note   The navigation pad alone cannot access all of the list box functionality.

For labels, use the 9pt, Tahoma regular font.

List view Consider enabling full-line selection when you include a list view in an application. For more information, see List View Guidelines.
Menu bar (PPC-only) Use menu bars to consolidate functionality. For more information, see Soft Key and Menu Guidelines.
Mnemonics When you assign mnemonics to menu commands, use the first letter of the command name unless another letter provides a better mnemonic association. For more information, see Mnemonics Guidelines.
Option button (PPC-only) Use option buttons only when they provide mutually exclusive choices and when there are only a few choices. When there are many choices, use list boxes instead.

For labels, use the 8pt, Tahoma black font. If the label text wraps to more than one line, the first line of label text should be vertically centered with the option button.
Shortcut menu (PPC-only) A shortcut menu displays additional commands for a screen item when a user taps and holds the stylus on the item. The menu disappears when the user taps any other area of the screen.

Consider the following when you include shortcut menus in an application:

  • Where possible, display the menu to the right of and below the screen item.
  • In general, commands on the shortcut menu should also be available from menus and buttons on the menu bar.
  • To minimize stylus movement, list commands from top to bottom in order of expected frequency of use.
  • Actions that are difficult to recover from, such as delete, should be placed at the bottom of the menu.
Progress bar A progress bar shows the percent completed for an operation or the percentage of a value.

To communicate the purpose of the progress bar, add static text or other information.

For labels, use the 8pt, Tahoma font.

Scroll bar Due to screen size limitations, a user might need to scroll to view all the information on a screen.

On Windows Mobile-based Pocket PCs, include scroll bars in an application to enable scrolling for a large screen.

On Windows Mobile-based Smartphones, include scroll bars in an application to indicate that a screen is not fully displayed. A user presses a navigation hardware button to scroll the screen.
Shortcut key (PPC-only) The functionality of the shortcut keys in your application should be consistent with shortcut keys in other applications to ensure a consistent user experience. For more information, see Shortcut Key Guidelines.
Slider A slider control is used to set or adjust values within a range.

Consider the following when you include sliders in an application:

  • Generally, static text, graphics, or other information is added to the control to communicate the purpose of the slider and what the beginning and ending values of the range represent.
  • The control supports both horizontal and vertical orientation.

For labels, use the 9pt, Tahoma black font.
Spin box Use spin boxes to conserve space and as an alternative to list boxes and combo boxes.

Consider the following when you include spin boxes in an application:

  • Spin boxes are useful when the range of values is continuous or predictable.
  • The control should include a label to communicate the purpose of the spin box.
Split button (PPC-only) A split button control has a button and a menu. The menu includes commands for secondary functionality. For example, the input panel uses a split button.

Consider the following when you include split buttons in an application:

  • Although this control usually contains an icon, it is acceptable to use text instead.
  • The text or icon should update to reflect the last item selected from the menu.
  • The control is more difficult to use with a stylus.

For labels, use the 8pt, Tahoma bold font.

Tab (PPC-only) Use tabs in an application to group related information and functionality. Consider the following when you include tabs:
  • To avoid scrolling to view the tabs, do not create more tabs than can fit on the screen at one time. In addition, ensure that all of the edit controls are visible on a property sheet when the input panel is displayed.
  • To keep the content area uncluttered at the top of the screen, place tabs at the bottom of the screen.

For labels, use the 8pt, Tahoma black font.
Text box Single-line and multi-line text boxes are supported.

Consider the following when you include text boxes in an application:

  • The buffer should be limited to 255 bytes for a text box containing an e-mail address, street address, phone number, or Inbox subject.
  • On Windows Mobile-based Smartphones, the control can create hyperlinks for telephone numbers, Web page addresses, and e-mail addresses.
  • When a user must enter text in a specific format, provide an example of the format and set the control to accept only data that is formatted correctly.

For labels, use the 9pt, Tahoma font on Windows Mobile-based Pocket PCs. Use the 11pt, Segoe regular font on Windows Mobile-based Smartphones.

Text header (PPC-only) Use text headers to provide context for wizards, context for full-screen dialog boxes that contain settings or options, and instructions for picker dialog boxes.

For complex dialog boxes and wizards, consider adding a Help button.

Limit text headers to one or two words. Use the 8pt, Tahoma bold, blue font.
Text subheader (PPC-only) To conserve space, use text subheaders instead of group boxes to visually group items on a screen. Also, use text subheaders to clarify application data and functionality. Limit text subheaders to one or two words. Use the 8pt, Tahoma bold font.
Time picker Time pickers enable users to set the time, including the hour, minutes, and A.M. or P.M. options. The time displays in 12-hour or 24-hour increments, depending on the regional settings.

For labels, use the 11pt, Tahoma regular font on Windows Mobile-based Pocket PCs. Use the 11pt Segoe regular font on Windows Mobile-based Smartphones.
Tree view A tree view control shows the hierarchical relationship of items. Consider the following when you include tree views in an application:
  • Including icons in a tree view helps users distinguish between different types of items such as files and folders.
  • On Windows Mobile-based Smartphones, tree views do not display dotted lines or collapse or expand icons. In addition, the control should automatically display as expanded, and auto scroll should be enabled.

For labels, use the 11pt, Tahoma regular font on Windows Mobile-based Pocket PCs. Use the 11pt, Segoe regular font on Windows Mobile-based Smartphones.
