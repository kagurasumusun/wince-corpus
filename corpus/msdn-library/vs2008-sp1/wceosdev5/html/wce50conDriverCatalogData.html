Platform Builder for Microsoft Windows CE 5.0  

Driver Catalog Data

The following table shows the Catalog item (.cec) file data for each device driver. This information is used to select the appropriate drivers for your OS design.

Catalog field Use Description
GUID Optional. In Platform Builder 3.0, the component type GUID was not important.

Effective with version 4.0, if you are creating a standard driver, you must use the component type GUID associated with that driver.

For example, to add a display driver to the Catalog, use the type GUID from the Display.cec file.

The BSP Wizard helps with this process by prompting you to select a component type for any drivers added with the wizard.

Each component type maps to a GUID for that specific class of driver.
RequiredCEModules Ignored. Strings from the CE_MODULES environment variable that indicate which Windows CE modules are required for a specific display type.
Note   In Windows CE 5.0, this setting is ignored.
ExcludeWhenSet Ignored. The exclusion variables used to determine whether to exclude a specific driver.
Note   In Windows CE 5.0, this setting is ignored.
MaxResolvedImpsAllowed Optional.

Default = 1.

 The maximum number of implementations this driver supports. This tells Platform Builder whether to enforce exclusivity on this driver type.

Platform Builder supports two values for this field:

  • 1, meaning that only one driver of this type can be in your OS design at a time.

    If the value is set to 1 and you attempt to add another implementation of this driver type to your OS design, Platform Builder displays a dialog box to determine whether to replace the current driver with the new driver.

  • Not 1, meaning that the driver type supports more than one implementation in your OS design.

    If the value is set to some number other than 1, you can add as many drivers of this type as you want.

If you use a standard driver type, this field is automatically set.

For standard drivers that support multiple implementations, the driver resolver uses the value 999.

The MaxResolvedImpsAllowed field is associated with a component type.
MODULE_NAME Strongly recommended. The dynamic-link library (DLL) name for the driver as it appears in %_FLATRELEASEDIR%.

This variable is required to accurately determine whether the driver is included in the run-time image.

Otherwise, Platform Builder might display the driver as being included in the run-time image when it is not actually included.
ImplSize Optional.

Default = 0.

 The size field associated with a specific driver. This tells Platform Builder the approximate size, in bytes, that this driver occupies in the final run-time image.

The size field should be set based on the size of the run-time image in a release build of a CEPC.

The CPUSizeMultiplier field associated with a specific BSP adjusts the size field up or down as required.

If the driver supports only one BSP, you can set the size field to the exact size of the driver, set the SizeIsCPUDependent field to 0.
Variable Strongly recommended. The per-implementation environment variables required for this driver to be included in the run-time image, as follows:
  • The BSP_ inclusion variable. Set to 1.
  • The Sysgen variable needed to run Sysgen.bat and build only this driver.

    Typically, this is the case for drivers in the Public tree. Platform and BSP drivers typically build and link without Sysgen.

    This environment variable tells Platform Builder to run Sysgen.bat on the driver when that driver is being built using the Targeted Build functionality.

    The value of the variable is the command-line value passed to the Sysgen process.

    It is used only when you right-click the driver and select a build option; for the standard run-time image build process, the variable is ignored.

Note   In Windows CE 5.0, if you set the value to "" or leave it blank, the entire declaration is ignored.
If you use any other values as the setting for this variable, Platform Builder sets it to "1".

For example, the ATI Rage XL Expert 98 display adapter requires these pre-implementation environment variables:

Variable("BSP_DISPLAY_RAGEXL", 1)
Variable("MODULE_NAME", "ddi_ragexl.dll")
BSPPlatformDir Optional. The BSP directory where the BSP source is located. The driver resolver uses this to place the drivers correctly in the Catalog and on the OSDesignView tab.

If the driver is a native driver, this field should be used for each native driver implementation that is specific to a BSP.

This field specifies the following:

  • Placement of the drivers under the BSP node in the Catalog.
  • Specifies that the driver is available only for the specific BSP.

If you use the BSPPlatformDir field for native drivers, you do not need to use the Children or OptionalChildren field in the Implementation block.

The value for BSPPlatformDir is the name of the platform directory. By default, the path is %_WINCEROOT%\Platform.
