Platform Builder for Microsoft Windows CE 5.0  

Updating the BSP for a New Build Environment

The following steps show how to update your BSP to support the new build and environment system in Windows CE 5.0. For more information about migrating your BSP to Windows CE 5.0, see Migrating a Board Support Package.

To update the BSP build environment for migration

  1. Adjust for new microprocessor names, as follows:
    • All sources files for your BSP must be updated to use the new microprocessor names. For more information, see Microprocessor Changes.
    • Change Kernel\Hal\SHx to Kernel\Hal\SH.
    • Update the command-line prompt build window parameters to use the new CPU names.
    • Filter %_WINCEROOT%\Platform and %_WINCEROOT%\Public files based on CEModule variables.
  2. Adjust for new kernel names by updating the command-line build window parameters.
  3. Use new BSP and BSP_NO environment variables.

    New BSP and BSP_NO variables make it easier to create and configure your BSP.

    In your OS design batch file, set BSP_NO variables for any options your target device does not support.

    For common drivers such as display, audio, and network, set positive BSP variables to choose defaults for each type of device. For example, set BSP_DISPLAY_PERM3 = 1 or BSP_WAVEDEV_TVIA5000 = 1.

    Set the default drivers for your BSP by modifying the Platform.bat file in your OS design. For example, to set default drivers for a BSP called MyBSP, modify the file %_WINCEROOT%\Platform\MyBSP\MyBSP.bat.

    In the case of hardware such as a PCI bus, a number of drivers can be included in the run-time image. For example, by setting all BSP_DISPLAY variables, the run-time image detects and loads a driver for every supported display device.

  4. Set the BSP_DISPLAY flag.

    The display drivers are in the public drivers tree under %_WINCEROOT%\Public\Common\Oak\Drivers\Display.

    Display drivers are listed in Common.reg and Common.bib files.

  5. Modify Sysgen variables to optimize the build.

    Platform subdirectory (.dirs), registry editor (.reg), and binary image builder (.bib) files can be filtered based on CE_MODULES variables.

    This means that unless a Catalog item is chosen that requires a platform device driver (for example, USB), that driver should not be built and should not be included in a .bib or .reg file. Adding conditionals to the .dirs, .reg, and .bib files does this.
