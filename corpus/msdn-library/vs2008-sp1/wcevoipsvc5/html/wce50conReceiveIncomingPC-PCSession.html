Receive an Incoming PC-PC Session

Version 1.2 of the RTC Client API allows applications to initiate outgoing and incoming PC-PC sessions when either party is situated behind a NAT.

The new IRTCClientPortManagement interface specifies the port and IP address on which the RTC Client API should listen for incoming sessions.

The application is responsible for opening the port on the NAT before setting the listen address and port using the RTC Client API.

To following steps occur when an incoming session is received:

  1. The client application calls IRTCClientPortManagement::StartListenAddressAndPort and specifies the internal port (I1) on the client machine where the RTC Client API should listen.
  2. The client application opens an external port (E1) on the NAT for the incoming session. The RTC Client API is not involved in this step; the application is responsible for opening this port and maintaining the port for the duration of the session, using APIs provided by the NAT.

    The client application should maintain a reference count for each port mapping. Each reference to a mapping should not be released until the RTC Client API calls IRTCClientPortManagement::StopListenAddressAndPort.

  3. For sessions that are using peer-to-peer UDP transport, the client application communicates the port on the NAT to the remote client application using an out-of-band mechanism. For sessions that use TLS or TCP signaling through the SIP server, the port on the NAT is not communicated out-of-band.
  4. Incoming SIP traffic arrives on the E1 port on the NAT and is mapped by the RTC Client API to port I1 on the client machine.
  5. The RTC Client API notifies the application that incoming traffic has been received using the IRTCSessionStateChangeEvent interface.
  6. To accept an incoming session, the application supplies a pointer to the IRTCPortManager implementation it implements by calling IRTCSessionPortManagement::SetPortManager.
  7. The RTC Client API calls IRTCPortManager::GetMapping to determine the IP address and port mapping for the outgoing SIP traffic.

If another session is created on the client machine, the RTC Client API also calls GetMapping. Depending on the application's implementation of this method, this call can return a new IP address and port mapping for the session, or it can return the same mapping as the first session.

Each session receives a reference to the port mapping and is responsible for maintaining the mapping table.

Once the session is disconnected, the application is responsible for releasing the reference to the IP address and port mapping.
