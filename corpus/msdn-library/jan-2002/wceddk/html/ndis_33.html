NDISTest Configuration

Before testing an NDIS miniport, you must set the Hapi.ini configuration file to indicate, which tests will be run, and how each test will be performed. To test a miniport successfully, you must define two sections in Hapi.ini: DLLs and Variables.

The DLLs section specifies the DLLs to load. For NDISTest, this section is always two lines long and looks like the following:

[DLLs]
NDISTST.DLL

The Variables section consists of variable initializations; it can contain multiple lines. The first line must look like the following:

[Variables]

Subsequent lines in the Variables section must have the following format:

<variable_name>=<variable value>

All variables must begin with the dollar sign character ($). Variable names are limited to alphanumeric characters and the underscore character (_). Variables can have either strings or integers assigned as values. Strings must be enclosed in double quotation marks. You can specify integers as either decimal or hexadecimal numerals. To specify an integer as a hexadecimal numeral, use a 0x prefix.

A variable must be created and assigned to a value before it can be used in an expression or as an argument to a function. Therefore, a previously undefined variable can be used only to the left of the equal sign (=). Every time a variable is assigned, its definition is destroyed and recreated. Variables do not have fixed types, and type declarations are generally not necessary. The following examples show valid variable declarations:

# Variable $Temp is created as an integer variable with value 5.
$Temp = 5

# Previous variable $Temp is destroyed and new variable $Temp is created # as a floating point variable with the value 1.75
$Temp = 1.75

# Previous variable $Temp is destroyed, new variable $Temp is created as # a string with the value "string."
$Temp = "string"

For NDISTest, the Hapi.ini configuration file sets values for a number of global variables that control what tests are run and how they are run.

The following are the global variables that are used in the Hapi.ini configuration file:

  • G_DebugLevel

    Creates a global variable that is used to maintain debug settings. The value is unimportant; the scripts will set it as they execute.

  • G_WorkCard

    Specifies the name of the card to be tested.

  • G_TrustedCard

    Specifies the name of a trusted card in the system that will be used to assist in testing the card that is specified in G_WorkCard. This variable can be set to the null string, in which case all of the tests that require two cards in the same system will be skipped.

  • G_MessageCard

    Specifies the name of the card that is used to send commands to the remote Windows NT system that is running the NDISTest server that is used for two-machine testing. This variable can be set to the null string, in which case all of the two-machine tests will be skipped.

  • G_Media

    Specifies the media to be tested. It must be set always to a value of 1 (Ethernet).

  • G_Ndis30Flag

    This variable must be set always to 0.

  • G_ScriptName

    This variable has an effect only if the DO_RUNTEST bit is set in the G_TestOptions variable. If the DO_RUNTEST bit is set, then this variable specifies the name of a specific script to be run, instead of running the functional, stress, or hardware compatibility testing suites.

  • G_TestOptions

    This variable is a combination of the following:

    • DO_FUNCTIONAL_TESTS (0x00001)

      If set, then functional testing will be done.

    • DO_STRESS_TESTS (0x00002)

      If set, then stress testing will be done.

    • DO_HCT_TESTS (0x00008)

      If set, then hardware compatibility testing will be done.

    • DO_RUNTEST (0x00010)

      If set, then a single script only will be run. Functional, stress, and hardware compatibility testing will be skipped.

      The G_ScriptName variable must be set in the Hapi.ini configuration file and must be the name of a script file to be run. The following is an example of this: 

      G_ScriptName=“scripts\lan\1c_srecv.tst”
    • ENABLE_VERBOSE_FLAG (0x10000)

      If set, then the output files that are generated will include more detail.

    • SKIP_1CARD_TESTS (0x20000)

      If set, then the tests that involve only a single card (1c_xxx.tst scripts) will be skipped.
