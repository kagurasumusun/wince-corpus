Data-Link Layer

The data link layer is responsible for delivering data from one computer to another over a physical layer connection. Windows CE provides data-link layer support for both wide area networks (WANs) and local area networks (LANs). Examples of data link protocols supported by CE are PPP, SLIP, and IRLAP.

Windows CE supports the Microsoft Network Driver Interface Specification (NDIS) to allow drivers to manage network interface connections.

Windows CE supports NDIS Ethernet (802.3), Token-Ring (802.5), WAN, Intermediate drivers, Serial Infrared (SIR), and Fast Infrared (FIR) miniport drivers. Support for Token-Ring and WAN miniports, and intermediate drivers is new in Windows CE version 3.0. Also new is NDIS dynamic binding, which allows all NDIS miniports to be bound/unbound dynamically (previously only supported for PCMCIA interfaces). Also, the test tool provided in Windows CE 3.0 to validate network drivers (NDIStest) has some new features — tests are now included for IrDA and Token Ring miniports, as well as performance and stress tests are now included for Token Ring, IrDA and Ethernet miniports.

For more information on NDIS architecture and network connectivity issues, see the Microsoft Windows CE Driver Development Kit (DDK) documentation. For more information on NDIStest please see the Windows CE driver development Test Kit documentation.

The PPP architecture in Windows CE version 3.0 is integrated as part of NDIS (in previous releases it was a standalone component). In addition PPP now supports data compression, encryption (56-bit only) and multiple PPP sessions. AsyncMAC uses TAPI to establish the connection and PPP/SLIP to manage the data once the connection is established.

For more information on PPP and SLIP, see Serial Communications and Remote Access Service.
