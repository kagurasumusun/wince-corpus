Device Suspension Issues

To conserve battery power, Windows CE devices can be configured to suspend automatically after a certain period of inactivity. Because you may not want this behavior to occur when you use network services — for example, when you synchronize a device with the desktop — the Windows CE networking components provide mechanisms to override this behavior. By default, the following conditions prevent device suspension due to inactivity:

  • Connected TCP sockets, including loop back
  • Connected IR sockets
  • Active network adapters
  • An established PPP connection

Several registry settings can be used to modify this behavior — for example, to allow a device to suspend when idle, even if there are connected sockets. These settings include HKEY_LOCAL_MACHINE\Comm\Tcpip\Parms\NoIdleIfConnected and HKEY_LOCAL_MACHINE\Comm\Tcpip\Parms\NoIdleIfAdapter. For more information on these settings, see the entries for these settings in TCP/IP Configuration Parameters.

Note   The registry settings that affect device suspension are global and are read when the device is initialized. If you change these setting, you must reset the device before the new settings take effect.
