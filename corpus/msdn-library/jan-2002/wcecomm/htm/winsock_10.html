IrSock Name Service

Conventional Winsock name service is best suited to fixed networks, in which the group of devices that can accept a socket connection is relatively static. Conversely, IrDA is designed to handle browsing for resources within range. It works in an extemporary manner, and devices disconnect and connect frequently as they move in and out of range.

Because of these differences, IrSock does not use the conventional Winsock name service functions. Instead, name service is incorporated into the communication stream.

IrDA Discovery on Windows 95 and Windows 98

The IrDA discovery process on Win9x operates different than it does with Windows NT and Windows CE. Three winsock api calls are required to do discovery on Win9x:

  1. Put the IrDA device into discovery mode by calling setsockopt(hIrdaSock, SOL_IRLMP, IRLMP_DISCOVERY_MODE, &Mode, sizeof(Mode)); where Mode is an unsigned int whose value is not zero.
  2. Call the winsock function recv(hIrdaSock, (char *)&DevList, sizeof(DevList), 0); where DevList is an array of DEVICELIST (see af_irda.h).
  3. Call setsockopt(hIrdaSock, SOL_IRLMP, IRLMP_DISCOVERY_MODE, &Mode, sizeof(Mode); where Mode is zero. This disables discovery mode.

In contrast, the IrDA discovery process on Windows NT and Windows CE requires one winsock function call: getsockopt(hIrdaSock, SOL_IRLMP, IRLMP_ENUMDEVICES, &DevList, &DevListLen).
