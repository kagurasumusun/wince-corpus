Two-Digit and Four-Digit Dates in Windows CE

All Windows CE functions and external interfaces represent a year with four digits, for example 2020. The OEM is responsible for storing a compressed date in the OAL so that it will pass the correct date to the hardware. This compressed date can have up to a 100-year range, for example 1950 to 2049.

The Windows CE OS does not have any inherit logic for converting two-digit dates to four-digit dates. OLE functions will convert all two-digit dates ending in 29 or less to twenty-first century dates; they will convert all two-digit dates ending in 30 or more to twentieth century dates. For example, OLE will convert 29 to 2029, and it will convert 30 to 1930. OLE internal functions uses four-digit dates; they only convert two-digit dates to four-digit dates when an application supplies a two-digit date string to an OLE function. The date information used by the OS is not affected by OLE conversions.

You can use the real-time clock functions to make sure that your platform will handle dates properly. Use GetSystemTime, SetSystemTime, and CeSetUserNotification to set and then retrieve various twentieth and twenty-first century dates. Because these functions call the OAL real-time clock functions, OEMSetRealTime, OEMGetRealTime, and OEMSetAlarmTime they provide a good test of your platform’s ability to handle various dates.
