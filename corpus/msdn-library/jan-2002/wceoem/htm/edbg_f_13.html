EdbgSendUDP

This function formats and sends a UDP packet using the Ethernet debug interface.

BOOL EdbgSendUDP(
BYTE *pFrameBuffer,
EDBG_ADDR *pDestAddr,
USHORT SrcPort,
BYTE *pData ,
UINT16 cwLength );

Parameters

pFrameBuffer
[in] Byte that contains formatting buffer of a size, in bytes, equal to or larger than 42 + cwLength
pDestAddr
[in] Pointer to a structure that contains the address of destination.
SrcPort
[in] Unsigned short integer that contains the source User Datagram Protocol (UDP) port number.
pData
[in] Byte that contains user data.
cwLength
[in] Unsigned 16-bit integer that specifies the number of bytes of data in *pData.

Return Values

TRUE indicates success. FALSE indicates failure.

Remarks

This function can be used to send a UDP datagram using the debug Ethernet adapter. All protocol formatting is done within this function, so the frame buffer must be large enough to hold all protocol headers (42 bytes) plus the user data.

The debug Ethernet routines do not handle IP fragmentation, so the total number of bytes of user data and protocol headers must be less than the Ethernet maximum transfer unit (MTU) (1,500 bytes). Also, the debug Ethernet subsystem does not send an ARP packet to determine unknown addresses, so the pointer pDestAddr must be filled out completely, including the Ethernet address. Typically, you provide input/output codes and use the KernelIoControl function to obtain the Ethernet addresses that you want; for example, you can obtain the address of the development workstation that is running the Windows CE Ethernet Shell Tool (Eshell.exe).

Note that for Windows CE 3.0, there is no way to receive raw IP or UDP packets on the debug Ethernet interface.

Requirements

Runs on Versions Defined in Include Link to
Windows CE OS 2.10 and later Halether.h
