Application Compatibility Technical Articles  

Resolving Application Compatibility Issues with QFixApp and CompatAdmin

Todd Phillips
Microsoft Corporation

October 2001

Applies to:
     Microsoft® Windows® XP

Summary: Once application testing has revealed possible compatibility issues between an application and Microsoft Windows XP, a resolution must be found to enable the application to run as expected. QFixApp helps you to identify specific compatibility fixes that will help Windows XP to fully support the application. These compatibility fixes can be gathered into compatibility layers and distributed with the CompatAdmin tool. (12 printed pages)

Introduction

One of the most exciting developments in Microsoft® Windows® XP is the addition of a robust series of application compatibility technologies. These technologies are even available to the end-user through the Windows XP shell. Deploying application compatibility fixes to a wide audience can be difficult or impossible if left to each computer user. Fortunately, there is a simpler way to package groups of compatibility fixes and distribute them for automatic installation on Windows XP computers.

QFixApp is a tool that you can use to identify the compatibility fixes required to help Windows XP support a particular application more effectively. Compatibility fixes can be applied individually or in predefined groups called compatibility layers. QFixApp enables you to test the compatibility fixes one at a time until you determine the precise mix necessary to support an application.

Once the group of compatibility fixes has been identified, you can use the Compatibility Administration (CompatAdmin) tool to package the compatibility fixes for distribution to other Windows XP computers. The Windows Application Compatibility team at Microsoft strongly recommends using QFixApp to determine which compatibility fixes to apply for an application and CompatAdmin to package and distribute the fixes.

Identifying Compatibility Fixes Using QFixApp

QFixApp is a small, lightweight tool that provides access to the application compatibility database installed on every Windows XP computer. These databases contain a variety of compatibility fixes that can help Windows XP better support various applications. Most applications won't need this additional help, but some programs contain compatibility issues that might prevent them from running correctly on Windows XP. An example of this would be an application that was written exclusively for Microsoft Windows 95, and will not run on any other version of Windows. If the version issue is the only problem preventing the application from running, then this would be a simple fix. You could use QFixApp to specify the compatibility fix entitled Win95VersionLie, which returns a Windows version compatible with the information that would be returned by Windows 95.

This section describes the usage of QFixApp, and how this tool might fit into your plans for supporting applications on Windows XP.

System Requirements for QFixApp

The system requirements for running QFixApp are the same as those for Windows XP itself:

  • Pentium 233-megahertz (MHz) processor (or equivalent) or greater.
  • 64 megabytes (MB) RAM (128 MB of RAM recommended).
  • 650 MB of free disk space (more for network installs).
  • VGA monitor.
  • Mouse or other supported pointing device.
  • CD-ROM or DVD drive.

For more information regarding supported hardware, please consult the Hardware Compatibility List (HCL).

Installing QFixApp

The QFixApp tool is shipped with Windows XP and can be found in the /Support/Tools folder on the CD-ROM. QFixApp is distributed as part of the Application Compatibility Toolkit version 2.0 and higher. To install the Application Compatibility Toolkit on your Windows XP system, please use the following steps:

  1. Insert the Windows XP CD-ROM in a local CD-ROM drive.
  2. Using My Computer or Windows Explorer, browse to the CD-ROM drive where you placed Windows XP and open the /Support/Tools folder.
  3. Double-click ACT.EXE to begin the setup program. Accept the defaults for the setup program.

Once the Application Compatibility Toolkit has been installed, it can be accessed through the Start menu. QFixApp can be found in the Application Compatibility Toolkit group on the Start menu.

Using QFixApp

QFixApp is the first tool to use when trying to find a solution to an application compatibility issue on Windows XP. The tool enables you to apply single compatibility fixes while you are trying to determine the necessary support for the application to work properly on Windows XP.

QFixApp has two tabs in its main window. The first tab is the Layers tab, and can be used to apply compatibility layers. The second tab, Fixes, enables you to apply individual compatibility fixes to an application. The Layers tab of QFixApp is shown in Figure 1.

Applying Compatibility Layers with QFixApp

Many programs are written specifically for one version of Windows, and most of them will require the same compatibility fixes to run properly on Windows XP. To make it easier to apply the necessary fixes to such an application all at once, instead of having to pick the same compatibility fixes repeatedly, the compatibility fixes have been gathered into groups called compatibility layers.

Compatibility layers are the best way to begin testing an application with QFixApp. For example, when trying to find the correct mixture of compatibility fixes for an application that specifically requires Windows 95, you would begin by applying the Windows 95 compatibility layer in QFixApp. This compatibility layer contains several compatibility fixes for programmatic differences between Windows 95 and Windows XP.

One commonly encountered issue involves heap management. Heap management issues historically have been difficult to trace in Windows 9x. In fact, most heap issues wouldn't readily appear when the application was run initially, but would accumulate over time as the application was left running. Windows XP would detect these same heap issues immediately. The Windows 95 compatibility layer contains compatibility fixes related to heap management to deal with this problem.

To apply a compatibility layer to an application

  1. Open QFixApp by clicking Start | All Programs | Application Compatibility Toolkit | QFixApp.
  2. Click the Browse button and locate the executable file for the application you are testing. This should be the main program file for the application.
  3. If the executable file requires any command line options when starting, enter them in the Command Line text box.
  4. Click to select the compatibility layer to apply to the application.
  5. Click the Run button to start the application with the selected compatibility layer.

In some cases, an application will fail to run once you have applied a compatibility mode. If this happens, check the results of your attempt to start the application in the QFixApp log file. This log will show which individual compatibility fixes were actually required by the application. This enables you to remove the compatibility fixes that are not being used. Removing these extra fixes should resolve the problem and permit the application to run correctly. You may need to repeat this process several times to completely eliminate the compatibility fixes that are not required by the application.

Testing Individual Compatibility Fixes with QFixApp

Some applications will require only one or two compatibility fixes in order to resolve their issue with Windows XP. In this case it might be more effective to apply just the compatibility fixes that are required rather than using a compatibility layer. An application that was written for Windows 95 may be using an obsolete method of checking for free disk space that causes a buffer overrun, but be otherwise fully compatible with Windows XP. To resolve this, you could choose to apply only the EmulateGetDiskFreeSpace compatibility fix to resolve the problem.

To apply individual compatibility fixes to an application

  1. Open QFixApp by clicking Start | All Programs | Application Compatibility Toolkit | QFixApp.
  2. Click the Browse button and locate the executable file for the application you are testing. This should be the main program file for the application.
  3. If the executable file requires any command line options when starting, enter them in the Command Line text box.
  4. Click the Fixes tab to display the list of available compatibility fixes. QFixApp automatically checks the compatibility fixes required for the layer that was selected on the Layers tab. If this is not what you want, click the Clear button to deselect all compatibility fixes.
  5. Check the box beside the compatibility fix you intend to apply. If you are uncertain what a compatibility fix is for, highlight the fix and the description will be displayed in the Fix Description text box.
  6. Once you have selected the compatibility fixes to apply, click the Run button to start the application with the selected fixes.

The compatibility fixes applied in this manner are only effective while QFixApp is running. If you close QFixApp after applying compatibility layers or fixes using the steps listed so far, the changes will be lost. To apply a more lasting solution, the compatibility layers and/or fixes must be saved in a system database file (.sdb) so that Windows XP will understand which fixes to apply when the application is started. QFixApp can create an .sdb file for your application, but it is limited in that it can only create a single .sdb file and cannot change the name of the file. This means that you can only provide compatibility fixes for one application on a single Windows XP computer using QFixApp.

The recommended usage for QFixApp is to perform testing of compatibility fixes so that you know precisely which fixes to apply to support an application. QFixApp is not intended to permanently apply compatibility fixes to more than one application at a time. To successfully apply compatibility fixes to multiple applications, Microsoft recommends using the Compatibility Administration (CompatAdmin).

Creating Custom Compatibility Layers with CompatAdmin

The Compatibility Administration (CompatAdmin) program has many of the same capabilities as QFixApp, with one added feature. In addition to the capabilities to assign compatibility layers and individual compatibility fixes, CompatAdmin can package the compatibility fixes and layers for multiple applications into a single .sdb database file that can then be distributed to other Windows XP computers. This is particularly useful in large network environments where a small number of people must provide software support to a large number of users.

This section discusses how CompatAdmin can be used to create and prepare custom application compatibility database files to support multiple applications on one or more Windows XP computers.

Installing CompatAdmin

The CompatAdmin tool is shipped with Windows XP and can be found in the \Support\Tools folder on the CD-ROM. CompatAdmin is distributed as part of the Application Compatibility Toolkit version 2.0 and higher.

To install the Application Compatibility Toolkit

  1. Insert the Windows XP CD-ROM in a local CD-ROM drive.
  2. Using My Computer or Windows Explorer, browse to the CD-ROM drive where you placed Windows XP and open the \Support\Tools folder.
  3. Double-click ACT.EXE to begin the setup program. Accept the defaults for the setup program.

Once the Application Compatibility Toolkit has been installed, it can be accessed through the Start menu. CompatAdmin can be found in the Application Compatibility Toolkit group on the Start menu.

Using CompatAdmin

Windows XP contains information regarding common compatibility issues that developers may have used in some applications. The application compatibility fixes provided by Microsoft in Windows XP are designed to help Windows XP properly support the normal functionality of these applications without jeopardizing system stability. Four DLLs located in the %WINDIR%\AppPatch folder contain all of the compatibility fixes. The APPHELP.SDB and SYSMAIN.SDB files implement the Application Help messages and application fixes supplied as part of Windows XP. The Application Help messages contain information that is displayed when a program is started on Windows XP that is truly incompatible with the operating system. Examples of applications that might encounter Application Help messages would include anti-virus programs, or other programs that require kernel-level access to the operating system, or that install specific file system drivers.

Applications that worked on earlier versions of Windows may fail to function properly on Windows XP Professional. Some of the reasons why this may happen are:

  • The application refuses to run when Windows reports new, higher operating system version numbers. Often the application will work well on the new version of Windows if the user can get past this block in the application.
  • The application calls older versions of Win32 API functions that return unexpected values on computers with large amounts of resources, such as disk free space.
  • The application expects older formats of Windows data.
  • The application expects user information, such as personal and temporary folders, to be in specific locations or specific formats.

To counteract these problems using CompatAdmin, you would construct a custom database containing the compatibility fix information required by your applications along with file matching information that lets Windows XP uniquely identify the applications requiring assistance.

Creating a Custom Compatibility Database

CompatAdmin enables you to browse through the application compatibility fixes stored in the protected system databases to apply known fixes for hundreds of applications. The main CompatAdmin interface provides a control for viewing and browsing applications with compatibility fixes in the Windows XP Professional system database. This view is always displayed in the upper left pane (System Database pane) of the CompatAdmin window as shown in Figure 2.

Figure 2. CompatAdmin enables you to browse the system application compatibility databases

The system compatibility database is an integral part of the Windows XP Professional operating system, ensuring out-of-box compatibility for hundreds of Windows applications. This database and the corresponding application entries are protected by the operating system.

Once you have identified and tested fixes for your target applications, you can use CompatAdmin to create a custom fix database. You can create a custom fix database that contains applications supported by compatibility layers, as well as applications supported by specific compatibility fixes.

To create a new custom database using CompatAdmin

  1. Open CompatAdmin by clicking Start | All Programs | Application Compatibility Toolkit | Compatibility Administration Tool.
  2. If you have a custom fix database open, select File | New.
  3. Select Database | Change Database Name. Once you have changed the database name, it will be displayed at the top of the Custom Database pane. If the Change Database Name menu item is disabled, click the Custom Database pane of the window.
  4. Select File | Save and name your .sdb file. You are now ready to add fixes to your custom database.

Once you have created an empty custom database to contain your application compatibility fixes, add a compatibility layer.

To add a compatibility layer

  1. Select Create Application Fix for the Database menu. The Create an Application Fix dialog box is displayed.
  2. Select Apply Compatibility Mode, and click the Next button.
  3. Enter the name of the application for which you will specify a compatibility mode and click Next.
  4. Enter the name of the file to which the compatibility mode will be applied. You can type the name of the file, or use the Browse button to locate it.
  5. Select the compatibility mode to apply from the drop down list and click Next.
  6. Click the Add File button to select files that will help to identify the specified file on target computers. Choose files that are associated with your application that will be installed in the same related location. For example, choose a .hlp file that resides in the same directory as the .exe file. Try to uniquely identify your file without choosing an unnecessarily high number of matching files.
  7. Click Next when you have selected all necessary matching files.
  8. If you want to test the application with the fix applied, click Test Run. Otherwise, click Finish.

The same process can be used to add individual compatibility fixes to the custom database, with the exception that on the Create an Application Fix dialog you would select the option to Apply Specific Compatibility Fix as shown in Figure 3. Once all of the compatibility fixes or layers have been added to the database, save the database file and test the applications.

The application compatibility technology in Windows XP provides a way to distinguish files with the same or similar names. Windows XP does this through the use of file matching information. If you were creating a compatibility fix for a SETUP.EXE, but did not want this compatibility fix used every time you ran a file called SETUP.EXE, you would specify a group of other files belonging to the application. By gathering data about the specific properties of these files, Windows XP can uniquely identify the application requiring the compatibility fix wherever it exists on the computer.

Figure 3. Adding a specific compatibility fix to a custom database

Applying a Custom Database to a System

Once you have created your custom database of application compatibility fixes, it must be applied to the computer system where the applications will be run. The general process to deploy compatibility fixes to multiple Windows XP computers includes the following:

  • Identify and test fixes for the target applications. It is recommended that you use QFixApp to determine what fixes are necessary for an application.
  • Create a custom database file with the intended fixes.
  • Deliver the .sdb file to the destination Windows XP computers.
  • Use the SDBINST.EXE command to register the custom database. This will automatically install and add the fix information to the registry of the destination computers.

Delivering the custom database file to the other Windows XP computers can be accomplished in a variety of ways. It is possible to wrap the database file in a custom install program and distribute it with Group Policy in an Active Directory network, but this requires additional development work. The file can be copied manually to each remote Windows XP computer, or this can be accomplished through the use of a logon script. Another possibility would be to place the custom .sdb file in a network share that all Windows XP users can access.

Regardless of how you deliver the file to the remote computers, the information contained in the database file must be registered on each computer. This is done by using the SDBINST.EXE command from a command prompt followed by the full path and name of the custom .sdb file. For example:

Sdbinst c:\Windows\AppPatch\myapp.sdb

Once the database file is registered on a computer, the compatibility information will be used every time the application is launched.

Conclusion

Windows XP provides better application support than any previous Windows operating system. Beyond the built-in support for a wide variety of known application compatibility issues, two tools within the Application Compatibility Toolkit enable system administrators to support all of their applications.

The QFixApp tool gives you a simplified interface to browse the compatibility layers and fixes that are included in the system databases, and to test their effect on your application singly or in groups. QFixApp can apply changes to an application and then provide a detailed log of how the application interacted with the applied compatibility fixes. This lets you narrow down the precise number of compatibility fixes required to support the application on Windows XP.

The Compatibility Administration Tool, CompatAdmin, is a similar tool from the Application Compatibility Toolkit. CompatAdmin enables a system administrator to take the compatibility information that was determined with the help of QFixApp and package that information into a custom compatibility database. This database file can be applied once to support multiple applications and then easily distributed to other Windows XP computers requiring the compatibility fixes. Once on the remote computers, the SDBINST.EXE command is used to register the compatibility database file so the information will be available to Windows XP every time the application is launched.
