Introduction

Microsoft® ActiveX® Data Objects Extensions for Data Definition Language (DDL) and Security (ADOXCE) is an extension to the ADOCE objects and programming model. ADOXCE includes objects for schema creation and modification. Because it is an object-based approach to schema manipulation, you can write code that works against various data sources regardless of differences in their native syntaxes. ADOXCE is a companion library to the core ADOCE objects. It exposes additional objects for creating, modifying, and deleting schema objects such as tables. It is a subset of the desktop ADOXCE object model. The high-level omissions are the security objects (users, groups) and access to stored procedures and views. The focus of ADOXCE is schema objects (DDL).

Certain features of ADOXCE may not be supported, depending on your data provider. For more information about supported features of your OLEDB provider, please see the documentation for that provider.

Microsoft ActiveX Data Objects for the Windows® CE operating system (ADOCE) provides a subset of the desktop ADO specifically engineered to work with Windows CE. ADOCE includes its own internal database provider and enables you to have access to databases stored locally on a Windows CE–based device instead of working with databases stored remotely on desktop computers. The ADOCE version 3.1 control can also work with data sources that use an OLE DB provider.

With the ADOCE control, you can develop applications using most of the same ADO syntax you use for programming on a desktop computer. ADOCE requires minimal work to port existing ADO-based applications. Whenever possible, ADOCE returns the same error values and error strings as ADO, which maintains the separation of errors between OLE DB errors (DB_E_XXX) and native ADO errors (adErrXXX).

The first part of this guide contains information on writing applications that use ADOCE, while the reference sections provide specific information on syntax and the ADOCE object model. This guide is organized so that you can learn to use the ADOCE control by reading the guide from beginning to end. The beginning of the guide contains general information about the control. The middle of the guide discusses how to use the control in an application and a brief introduction to Structured Query Language (SQL). The end of the guide provides information on how to ship an application that uses ADOCE, samples demonstrating the use of the control, and reference guides for ADOCE and SQL.

What's New in ADOCE version 3.1

ADOCE version 3.1 now includes enhanced support for the SQL LIKE statement and the Recordset object. The Connection and Error objects are supported for the first time by the ADOCE control, in the 3.0 version. The ADOCE version 3.1 control continues to allow you to access data sources that use an OLE DB provider. ADOCE version 3.1 supports a new interface, IRowsetBookmark, used to set the next fetch position based on a bookmark. The Microsoft ActiveX Data Objects Extensions for Data Definition Language and Security (ADOXCE) version 3.1 is a companion library to the core ADOCE objects.

The online documentation has been reorganized and updated to facilitate ease of use. The structure of the documentation has changed to resemble that of a traditional book. Introductory topics are at the front, and the topics appear in the order that you encounter them when writing an application that uses the ADOCE control. The guide is concluded by a discussion of the samples that ship with ADOCE and references for ADOCE and SQL.

To support versioning standards for use with the ADOCE control, all references to the new control must explicitly refer to version 3.1. This is an issue when creating a reference to an ADOCE connection or recordset. The following code example shows the string that should be used to reference the new control.

Dim adoConn
Dim adoRecdst
Set adoConn = CreateObject("ADOCE.Connection.3.1")
Set adoRecdst = CreateObject("ADOCE.Recordset.3.1")

Using a string with the CreateObject function without referring to version 3.1 of the control will reference a previous ADOCE control if it exists on your device. If no previous control exists on your device, it will return the following error: "ActiveX component cannot create object."

How ADOCE Differs from ADO

ADOCE supports the following ADO objects:

  • Recordset object
  • Field object
  • Fields collection
  • Connection object
  • Error object and errors collection
  • AppendChunk method
  • GetChunk method
  • OpenSchema method

ADOCE does not support the following standard ADO features:

  • Command object

    All commands are sent using the Open method.

System Requirements

The ADOCE 3.1 release is currently available as a separate download that works with eMbedded Visual Tools 3.0 and Software Development Kits (SDKs).

Platform Support for ADOCE

ADOCE 3.1 is supported on the Windows CE platform for the Handheld PC Pro, Palm-size PC, and Pocket PC devices and also custom Windows CE platforms created with Microsoft® Windows® CE Platform Builder. In order to write an application for a specific platform, you need to install the platform Software Development Kit (SDK) for that platform and be sure the SDK is compatible with the development environment you are using. SDKs are available from the Microsoft web site (see below). ADOCE is supported on the following Windows CE platforms:

  • Handheld PC Professional Edition 3.0 Devices
  • Palm-size PC 1.2 Devices
  • Pocket PC 3.0 Devices
  • Additional Platforms

    Custom Windows CE platforms can be created using Microsoft Windows CE Platform Builder. Support for ADOCE or Visual Basic for Windows CE must be specified when the platform is built. In order for applications to be written on a custom platform, a custom SDK for that platform must be created using Platform Builder. For more information about custom Windows CE platforms and Platform Builder, search the Windows CE Web site for Platform Builder.

Current SDKs for Windows CE–based devices can be downloaded from the Microsoft Windows CE Web site.

Using This Documentation

This documentation is divided into a programming guide and a programming reference. The programming guide introduces you to the ActiveX Data Objects for Windows CE (ADOCE) programming environment. The guide covers the tools, controls, and wizards that are specific to the ADOCE toolkit. Accessing the ADOCE Application Programming Interface (API) is also covered in the guide. The reference covers the language features used to write applications with the ADOCE control and SQL.

To Use the Online Documentation

To find a subject in this document, consult the Contents tab. The structure of the documentation has changed to resemble that of a traditional book. Introductory topics appear on the initial portion of the directory tree, and the topics appear in the order that you encounter them when writing an application that uses the ADOCE control. The guide is concluded by a discussion of the samples that ship with ADOCE and references for ADOCE and SQL. You can read this documentation from beginning to end by opening the first topic in the contents and using ALT+DOWN ARROW to move through the topics.

If you cannot find the topic you need in the contents, or if you have a specific keyword you need information on, choose the Index tab and enter the word in the keyword field. This documentation has been thoroughly indexed to increase ease of use. To find information about a control, object, method, property, or error code, search the index.

To Access the Online Documentation

There are three ways to access the ADOCE Online Documentation:

  • From the eMbedded Visual Basic Help menu when a Windows CE project is open

    When working on a Windows CE project in the eMbedded Visual Basic IDE, select Contents… from the Help menu. This opens the documentation for the IDE. Select the Microsoft ADO for Windows CE 3.1 chapter. You can also refer to the guide and reference for ActiveX Data Objects for Windows CE from the toolkit Help window.

  • In the MSDN Library

    The eMbedded Visual Basic documentation is integrated into the MSDN library. The documentation can be found in the second level under the heading "Windows CE Documentation." The MSDN library is accessed through the Start menu.

  • In the Windows CE Library

    The Microsoft® eMbedded Visual Basic® documentation is integrated into the Windows CE library. The Windows CE library is part of the Windows CE Platform SDK and is installed when the SDK is installed. The library contains information about the Windows CE platform, a CE device chipset reference, and other supporting documentation. You can access the Windows CE library from the Start button. Choose Windows CE Help from the Windows CE Platform SDK group on the Programs menu.

To use context-sensitive Help

Context-sensitive (F1) Help is not yet fully supported by eMbedded Visual Basic or ADOCE. Pressing F1 opens the CE Studio documentation, within which you can navigate to the ADOCE documentation.
