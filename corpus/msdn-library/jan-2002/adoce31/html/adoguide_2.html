Converting Data to a Device

When you import an .mdb file to a Windows CE device, it is converted to a format that ADOCE can read and manipulate. Because the internal Windows CE database system is less robust than Microsoft Access or other ODBC sources, this conversion sometimes results in a loss of information. This topic describes the conversion process, including the types of information that are not converted to the ADOCE database format. Table Conversion

During conversion, table names are truncated to 31 characters. If you choose not to overwrite tables, and if a table exists with the truncated name, the last character is deleted and replaced with the numeric character 0. Values from 1 through 9 are attempted in turn. If all ten tables already exist, the table is not copied.

A table is not converted or copied to the device if either of the following conditions is true:

  • All the table fields are unsupported data types—a condition that causes the converted table to be empty.
  • The table is a system table. A system table is identified by the name MSYS*.

Field Conversion

Field names map directly between Microsoft Access and ADOCE databases. The supported length of 64 characters is the same in both .mdb files and .cdb files.

Index Conversion

All index names are truncated to 64 characters. The only index attribute that is copied is Ascending or Descending. Extra Access index information is omitted. Included are the attributes IgnoreNulls, Primary, and Unique. Index names are not case-sensitive and only the first field of a multicolumn index is indexed on a device. Only three indexes are allowed in a database. When you reach the limit of three indexes, the rest are skipped.

Indexes are created on a device in the three stages described in the following table.

Stage Event
Stage 1 Any unique index called PrimaryKey is processed first. If PrimaryKey is a single-field index and the field is being copied, PrimaryKey is recreated on the device. If the PrimaryKey consists of multiple fields, an index is created for each field that exists on the device. These have 0, 1, and 2 appended to their names, replacing the 64th character of the name, if necessary. If this causes a naming conflict—unlikely because there should be only one PrimaryKey index—then that index is skipped. Boolean fields are not indexed.
Stage 2 Unique indexes are created next. Unique indexes are not created if any of the following are true:
  • The indexed field is not copied to the device.
  • The index name, when truncated to 64 characters, matches an index name that is already present.
  • The field has an index on the device.
  • The indexed field is Boolean.
Stage 3 Nonunique indexes are created next. Nonunique indexes are not created if any of the following are true:
  • The indexed field contains more than one field.
  • The indexed field is not copied to the device.
  • The index name, when truncated to 64 characters, matches an index name that is already present.
  • The field has an index on the device.
  • The indexed field is Boolean.

These rules are designed to create the most useful indexes on a device. However, because device use differs from desktop computer use, you should examine the resulting indexes and adjust them to suit a particular application.

Database types

The Jet 3.51 (Access 97) database format stores international characters using multi-byte encoding. The Jet 4.0 (Access 2000) database format stores all characters using Unicode character sets. Because of these differences, an error may occur if the two formats are treated as interchangeable.

The value of the following registry key determines which type of database is created.

HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows CE Services\Services\Synchronization\Objects\MicrosoftTable\CreateLatestJetDBVer

The following table shows the values and properties that can be set using this registry key.

DWORD Value Property
Zero Jet 3.5 database
Non-Zero Jet 4.0 database

If the registry key is nonexistent, a Jet 3.5 database is created.

Conversion Options

Windows CE filters may have user options. When converting .mdb data into the proprietary Windows CE data source format, the default for the "Overwrite existing tables" option is TRUE. When the default is used, the data in the tables is replaced with the converted data. If this option is set to FALSE, the new tables are renamed.
