CDC::SetAbortProc

This method installs the abort procedure for the print job. 

int SetAbortProc(
BOOL (
CALLBACK EXPORT* lpfn )(
HDC, int ) );

Parameters

lpfn
Pointer to the abort function to install as the abort procedure. For more about the callback function, see Callback Function for CDC::SetAbortProc.

Return Value

Specifies the outcome of the SetAbortProc function. Some of the following values are more probable than others, but all are possible.

SP_ERROR
General error.
SP_OUTOFDISK
Not enough disk space is available for spooling, and no more space will become available.
SP_OUTOFMEMORY
Not enough memory is available for spooling.
SP_USERABORT
User ended the job through the print manager.

Remarks

If an application is to allow the print job to be canceled during spooling, it must set the abort function before the print job is started with the StartDoc method. The print manager calls the abort function during spooling to allow the application to cancel the print job or to process out-of-disk-space conditions. If no abort function is set, the print job fails if there is not enough disk space for spooling.

The features of Microsoft eMbedded Visual C++ 3.0 simplify the creation of the callback function passed to SetAbortProc.

You also do not have to export the function name in an EXPORTS statement in the module-definition file of your application. You can use the EXPORT function modifier, as in the following code example:

BOOL CALLBACK EXPORT AFunction( HDC, int );

This example causes the compiler to emit the proper export record for export by name without aliasing. This works for most needs. For some cases, such as exporting a function by ordinal or aliasing the export, you need to use an EXPORTS statement in a module-definition file.

Callback registration interfaces are now type-safe. You must pass a function pointer that points to the right kind of function for the specific callback.

All callback functions must trap Microsoft Foundation exceptions before returning to Windows CE, because exceptions cannot be thrown across callback boundaries.

Requirements
