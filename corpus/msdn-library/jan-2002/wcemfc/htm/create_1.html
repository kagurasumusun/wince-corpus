Creating ActiveX Controls using MFC

Use the MFC ActiveX ControlWizard to create ActiveX controls.

  • Step 1 of 2 of the wizard lets you establish how many controls will be in your project, and to specify whether you want comments and help files to be automatically generated.
  • Step 2 of 2 lets you rename controls, specify visibility issues, elect to have an "About" box, select ISimpleFrameSite support, and choose to make the control a subclass of an existing window class.
  • Advanced ActiveX Features lets you specify windowless controls, unclipped device context, flicker-free activation, mouse pointer notifications, optimizing of drawing code, and background data loading.

To access the wizard, open the New dialog box by choosing File | New. Select the Projects tab to display available wizards.

The following table outlines the items you can specify in Step 1 of 2 of the wizard.

To... Do this...
Specify the number of controls you plan for the open project Adjust the spin control. You can have up to 99 controls in one project.
Have the Wizard insert comments in your .cpp and .h files to show where you add your own code Select the appropriate radio button.
Generate Help files to run on the target device Select the appropriate radio button.

The following table outlines the items you can specify in Step 2 of 2 of the ActiveX ControlWizard.

To... Do This...
Rename controls and their files Select the control name in the drop-down list, then choose Edit Names to open the Edit Names dialog box.
Cause the currently-selected control to notify its container that it prefers to be activated automatically if it is visible. Choose Activates when Visible.
Cause the currently-selected control to notify its container that it prefers to be visible at design-time but invisible at run time. Choose Invisible at run time.
Create a standard About dialog box. Choose Has an "About" box. The Wizard creates a standard About dialog and AboutBox method for the currently selected control.
Cause the control to support ISimpleFrameSite. Choose Acts as a simple frame control. When the container and control both support this protocol, the container uses simple-frame controls as parents for other controls in the same container.
Make this control a subclass of a specified window class. Select a window class from the drop-down listbox.
Change advanced features. Choose Advanced to open the Advanced ActiveX Features dialog box.

The following table outlines the items you can specify in the Advanced ActiveX Features dialog box of the wizard.

To... Do This...
Provide for a control that does not need a window of its own. Choose Windowless activities.
Disable tests for clipping. Choose Unclipped device context. Select this option to improve speed, but only if you are sure the control does not paint outside its client rectangle. This option is not available for windowless controls.
Eliminate drawing operations and consequent flicker in transiting between inactive and active states. Choose Flicker-free activation. Use this option only if the control draws itself identically in the active and inactive states. This option is not available for windowless controls.
Let a control process WM_SETCURSOR and WM_MOUSEMOVE messages when it is not active. Choose Mouse pointer notifications when inactive. Enabling this option causes the container to delegate messages to IPointerInactive, which dispatches the messages through the control message map.
Cause the control to perform optimized drawing if its container supports it. Choose Optimized drawing code.
Specify that the control can have properties that point to data loaded in the background. Choose Loads properties acynchronously.
