Debugging a Tux DLL Module

There are several methods of debugging a Tux DLL module. The recommend technique is to load the DLL project into Visual C++ and run it. Keep in mind that Tux Client (Tux.exe) is the application that is being debugged, not Tux Server (Tuxsrv.exe).

To debug your Tux DLL project with Visual C++

  1. Open Visual C++ and load your Tux DLL project.
  2. Build a debug version of your test DLL module.
  3. Copy Tux.exe, and Kato.dll if you are using Kato logging, to the same directory where your debug DLL was built. If you have a debug version of Tux or Kato, also copy the debug files.
  4. In Visual C++, choose Settings from the Project menu.
  5. Choose the Debug tab.
  6. In the Executable For Debug Session box, type Tux.exe and its relative path specification from your project root. For example, if the relative path from your project root is Debug, type the following: 
    Debug\Tux.exe
  7. In the Working Directory box, enter the same directory you did in the Executable For Debug Session box, but exclude “\Tux.exe”.
  8. In the Program Arguments box, type “-d test.dll”, where test.dll is the name of your test DLL. You may also add any other parameters that Tux Client supports. The following list shows some common parameters:
    • -t

      Use Tux Server

    • -k

      Use Kato Server

    • -e

      Disable exception handling.

    The -b parameter is unnecessary when using Visual C++. For more information about Tux Client parameters, see Tux Client.

  9. Choose OK to close the Project Settings dialog box.
  10. If necessary, set breakpoints in your code.
  11. Start debugging.

You can also use other debuggers, such as the post-mortem debugger, configured for your system. The post-mortem debugger allows you to launch Tux.exe without a debugger, load your Tux DLL, and then break into Tux Client and hook the debugger to it.

There are two ways of using the post-modem debugger:

  • Run Tux Client (Tux.exe) with the -e parameter.

    This disables exception handling, which allows you to use the post-mortem debugger if your test code raises an exception or crashes.

  • Run Tux Client (Tux.exe) with the -b parameter.

    This forces a debug break in Tux.exe after your DLL is loaded, which gives you an opportunity to let post-mortem debugger hook Tux.exe and your test DLL.
