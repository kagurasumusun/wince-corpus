General Troubleshooting

The following scenarios may occur during testing:

  • Pserial.dll on the development workstation fails test case 10, and then fails all other test cases while the target device is waiting to synchronize

    On some slower target devices, the development workstation may time out while waiting for the target device to load and run Pserial.dll. To resolve this problem, start Pserial.dll on the target device first and wait until it starts to synchronize before running Pserial.dll on the development workstation.

  • Both machines fail when synchronizing for test 10

    Verify that one device is the master and the other is the slave.

  • Error #55 occurs at startup on either the target device or the Windows NT workstation.

    This error indicates that the serial port you are attempting to use is not available. Verify that you are not running the RAS server on the Windows NT workstation.

  • One or more tests fail randomly

    If you are experiencing one or more failures, narrow down the problem by running the failing test case one at a time. Be sure to run test case 10 and 11 along with the failing test case because they are required for proper program operation.

  • Tux unknown command error

    Occurs if one or more of the .dll files that Tux.exe requires is missing.
