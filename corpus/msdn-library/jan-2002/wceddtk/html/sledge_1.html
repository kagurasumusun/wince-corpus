Running the Test

The following command line shows the syntax for running Sledge.exe in client mode, where host_name is the server host machine.

sledge -c "tcp 2 5; packets-per-conn 100; serv-hostname host_name; go"

When run in client mode, Sledge.exe goes through a specified number of cycles. In each cycle, it creates a specified number of connections and, for each successful connection, creates a send thread and a receive thread. The send thread goes through a specified number of iterations. In each iteration, the send thread creates a randomly-sized packet within the bounds of the specified minimum and maximum packet length and sends the packet to the other end of the connection. The receive thread goes through a specified number of iterations. In each iteration, the receive thread optionally sleeps for a specified amount of time, receives a packet, and then checks the validity of the packet received by comparing length and checksum information computed by the send thread.

The following command line shows the syntax for running Sledge.exe in server mode.

sledge -c "serv-tcp on; serv-recv-len 100; go"

When run in server mode, Sledge.exe creates master server threads—one each for TCP/IP, IrDA and IrCOMM. The TCP/IP and IrDA master server threads wait for connections. When a connection is made, the master server threads launch a worker server thread to receive and send data to the other end of the connection. The IrCOMM master server thread also acts as the worker server thread that receives and sends data to the other end of the connection. This implies that several TCP/IP and IrDA connections may be supported by the server side of Sledge.exe at the same time, but only one IrCOMM connection may be supported.

In addition to the send thread, receive thread, master server thread, and worker server thread, Sledge.exe has a display thread and an optional hatchet thread. The display thread periodically displays the current statistics of the test as it is running. The hatchet thread, if turned on, periodically looks for clients that have sent more than half of their total data and closes their socket.

When running Sledge.exe over TCP/IP, verify that the machines on which you are running the client and server instances are on the same TCP/IP network and can communicate with each other. Run the server instance of Sledge.exe on one machine and the client instance of Sledge.exe on the other machine.

When running Sledge.exe over IrDA/IrCOMM, verify that the machines on which you are running the client and server instances are connected to each other by an IR link. Run the server instance of Sledge.exe on one machine and the client instance of Sledge.exe on the other machine.

The following table shows the general test case parameters.

Parameter Description
-f script_filename Loads the script file. To load file over CESH on Windows CE, add the ppsh: prefix.
-c script_commands Specifies a list of script commands separated by semicolons.
-l name Specifies the name of the CNetQaLog object. This affects the log filename when logging to a file.
-o options Specifies the logging method(s) to use. The options are listed below; lower case indicates optional method; upper case indicates required method:
  • b or B

    Log to the debugger

  • k or K

    Log to Kato

  • p or P

    Log to a file over CESH (Windows CE only)

  • f or F

    Log to a local file

  • c or C

    Log to the console

-s server_name Specifies the CNetQaLog server name, which is only required for Kato.

The following table shows the script language commands.

Command Description
tcp cycles connections Client command. Specifies the number of TCP cycles the client instance of Sledge.exe goes through and the number of TCP connections it makes in each cycle. Default: 0 cycles, 0 connections.
irsock cycles connections Client command. Specifies the number of IrDA cycles the client instance of Sledge.exe goes through and the number of IrDA connections it makes in each cycle. Default: 0 cycles, 0 connections.
ircomm cycles connections Client command. Specifies the number of IrCOMM cycles the client instance of Sledge.exe goes through and the number of IrCOMM connections it makes in each cycle. Default: 0 cycles, 0 connections.
packets-per-conn packets Client command. Specifies how many packets the client send thread should send for each connection. Range: 1–1000.
packet-len min max Client command. Specifies the range of the packet size that the client should randomly select from. Default: 1, 2048.
serv-hostname hostname Client command. Specifies the name of the host machine running a server instance of Sledge.exe. Default: “”.
serv-hostaddr n.n.n.n Client command. Specifies the IP address of the host machine running a server instance of Sledge.exe. This is useful only for data transfers involving TCP/IP. Default: 127.0.0.1.
in-flight-closes [on | off] Client command. When turned on, a hatchet thread is created that asynchronously closes client sockets when the client is in the middle of data transfer. Default: off.
above-normal [on | off] Client command. When turned on, the send and receive threads are created at ABOVE_NORMAL priority. Default: off.
serv-tcp [on | off] Server command. When turned on, a TCP/IP master server thread will wait for incoming TCP/IP connections. Default: off.
serv-irsock [on | off] Server command. When turned on, an IrDA master server thread will wait for incoming IrDA connections. Default: off.
serv-ircomm [on | off] Server command. When turned on, an IrCOMM master server thread will wait for an incoming IrCOMM connection. Default: off.
serv-recv-len buffer_size Server command. Specifies the size of the buffer, in bytes, used to receive and send the data at the server. Default: 64. Range: 1–2048.
discover Server command. Causes Sledge.exe to discover/enumerate IR devices.
ircomm-port COMport_number: Client/Server command. Specifies the COM port number on this machine to read/write data. This is useful only for data transfers involving IrCOMM. Default: COM3:. Range: COM1:–COM9:.
msg-mask [add | del] [info | conn | send | recv] Client/Server command. Allows the user to select or unselect the type of debug messages that are outputted during a test. These types relate to general information (info), connection (conn), sending of data (send) and receiving of data (recv).
sleepy-recvs percent Client/Server command. Specifies the percentage of Winsock recv calls (for TCP/IP or IrDA) or serial ReadFile calls (for IrCOMM) preceded by a thread sleep for 5 seconds. Default: 0. Range: 0–100.
go Client/Server command. Starts the execution of the test. The rest of the script is ignored.
quit Client/Server command. Causes Sledge.exe to terminate.
