General Troubleshooting

The most common test failure occurs when the data read from the card does not match the data that was written to the card. In this situation, the device driver may not indicate an error, but a detailed description of where the error occurred is displayed. The sector and byte where the incorrect read/write took place, along with the expected and actual values, are given according to the following screen shot.

ReadPattern FAILED at sector 0, byte 384. Expected: 16000, Returned: 1048631512.
ReadPattern FAILED at sector 0, byte 385. Expected: 15999, Returned: 1048510464.
ReadPattern FAILED at sector 0, byte 386. Expected: 15998, Returned: 1048444928.

In this case, the driver read the memory card successfully, but the data from the card was incorrect, most likely indicating a bad card.

Another common test failure may occur when the device driver tries to access the card and fails. If this happens, the following message is displayed.

WritePattern attempting to write sectors 8576 through 8703.
WritePattern FAILED. DISK_IOCTL_WRITE was unable to write to sectors
8576 through 8703. GetLastError()=0.
Rw_all FAILED. Continuing test.
Successfully wrote 128 sectors in 0 ms.
ReadPattern attempting to read sectors 8576 through 8703.
ReadPattern FAILED. DISK_IOCTL_READ was unable to read sectors
8576 through 8703. GetLastError()=0.
Rw_all FAILED. Continuing test.

The following errors may also occur:

  • Various system errors

    For example, memory was unable to be allocated or freed. These errors require further investigation to determine the cause.

  • Tux unknown command error

    Occurs if one or more of the .dll files that Tux.exe requires is missing.
