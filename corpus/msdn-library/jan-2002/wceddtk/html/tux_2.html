Tux Client

Tux Client is the main component of Tux. It can be run in stand-alone mode or in conjunction with Tux Server. Tux Client is a console application with the following syntax.

tux [-b] [-e] [-s file_name | -d test_dll] [-c parameters] [-r seed]
[-x test_case] [-l] [-t address] [-h] [-k address] [-o] [-f file_name] [-a]

The following table shows the Tux parameters.

Parameter Description
-b Break after each Tux DLL is loaded.
-e Disable exception handling.
-s file_name Specify the Tux suite file to load/execute.
-d test_dll Specify Tux test DLL to load/execute.
-c parameters Command line to pass to Tux DLL.
-r seed Specify starting random seed.
-x test_case Specify test case(s) to run.
-l List of all the test cases in the Tux DLLs.
-t address Specify machine running Tux Server. Use -t with no arguments to specify a local server.
-h Generate Tux parameter list.

The following table shows the Tux parameters that are enabled when Kato.dll is present.

Parameter Description
-k address Specify the machine running Kato Server. Use -k with no arguments to specify a local server.
-o Log all Kato output to the debugger.
-f file_name Log all Kato output to a file.
-a Append to output file (use with -f).

Parameters

-b
Break after each Tux DLL is loaded.

This parameter is often useful for debugging a Tux test DLL. Some debuggers require that a module be physically loaded into memory before a breakpoint can be set in that module. Since Tux Client dynamically loads test modules at runtime, it can be difficult to set a valid breakpoint in your test module. The -b parameter forces Tux Client to break to the debugger after your module has been fully loaded, but before any messages have been sent to your ShellProc function. This gives you an opportunity to set a breakpoint in your test module and then resume execution. For more information, see Debugging a Tux DLL Module.

-e
Disable exception handling.

This parameter turns off the default exception handling built into Tux Client. By default, Tux Client traps all exceptions that occur while running in your module, reports them back to you, and then continues running with the next test. The -e parameter is useful when debugging a Tux test module. For more information, see Debugging a Tux DLL Module.

-s file_name
Specify Tux suite file to load/execute.

This parameter allows Tux Client to load a test suite file. A test suite file is a script of test DLL modules and the test cases to run within each module. If this parameter is used while running with Tux Server (-t parameter), the script will be loaded, but not executed until directed so by the server. If this parameter is used in stand-alone mode (no -t parameter), Tux Client will load the script and immediately start executing it. For Windows CE, suite files can reside on the local Windows CE computer or across the CESH connection remotely. Tux will first try the local CE computer, then it will look on the remote computer. If you wish to force Tux to only look remotely, you can prefix the path with "cesh:". The following command-line example shows the syntax. 

tux -s cesh:test.tux

You may also specify paths relative to the CESH directory on the remote computer as shown in the following command-line example. 

tux -s cesh:..\suites\test.tux
-d test_dll
Specify Tux test DLL to load/execute.

This parameter allows Tux Client to load one or more default test modules. You may use this parameter more than once for a given command line to load multiple Tux test modules. If this parameter is used while running with Tux Server (-t parameter), the test module(s) will be loaded, but not executed until directed by the server. If this parameter is used in stand-alone mode (no -t parameter), Tux Client will load the test module(s) and immediately start executing the specified tests in each module. For more information, see the –x and –l parameter descriptions.

-c parameters
Parameters to pass to Tux DLL.

This parameter allows the user to pass a parameter string to the Tux test DLL itself. The parameter string you pass will be associated with the DLL most recently specified with the -d parameter prior to using -c. This allows you to specify different parameters for different Tux test DLLs. If the parameter string contains spaces or other special characters, then the entire parameter string should be placed in quotes.

-r seed
Specify starting random seed.

This parameter allows the user to specify a starting random seed. The seed you pass will be associated with the DLL most recently specified on the command line with the -d parameter. This allows you to specify different random seeds for different Tux DLLs.

-x test_case
Specify test case(s) to run.

This parameter allows the user to specify individual test cases and ranges of test cases to be run. The values specified are the test case identifier values, which may be obtained by using the –l parameter. The values you pass will be associated with the DLL most recently specified on the command line with the -d parameter. This allows you to specify different test cases for each Tux test DLL on the command line. You may specify this parameter multiple times for a single DLL, which is shown in the following command-line example. 

tux -x10 –x15-20

Or, you may combine all the ranges into one parameter, as shown in the following command-line example. 

tux -x10,15-20

If this parameter is used while running with Tux Server (-t parameter), the test cases specified will be selected, but not executed until directed by the server. If this parameter is used in stand-alone mode (no -t parameter), then Tux Client will load the test module(s) and immediately start executing the specified tests in the test DLL modules. If no –x parameter is specified for a given DLL, the default is to run all tests when Tux Client is running in stand-alone mode.

-l
List all the test cases in the Tux DLLs.

This parameter causes Tux Client to display the contents of all Tux test DLLs specified with the –d parameter. The test directory listing also lists the identifier values associated with each test case. These identifier values can be used with the –x parameter. When using the –l parameter, all arguments besides –d are ignored. This parameter is designed to provide information and does not run any test cases.

-t address
Specify the machine running Tux Server. Use -t with no arguments to specify a local server.

This parameter specifies the location of Tux Server. The address parameter can be a computer name or an IP address. If the -t parameter is not used, Tux assumes stand-alone mode, in which case you must specify either the -s parameter to load and execute a test suite, or the -d parameter to load and execute a test module. If no address is given with the -t parameter, Tux Client defaults to the address of the local machine while running on the development workstation, and to the desktop machine while running on Windows CE.

-h
Generate Tux parameter list.
-k address
Specify the machine running Kato Server. Use -k with no arguments to specify a local server.

This parameter specifies the location of Kato Server. The address parameter can be a computer name or an IP address. If no address is given with the -t parameter, Tux Client defaults to the address of the local machine when running on the development workstation and to the desktop machine when running on the target device. This parameter sends all Kato output to the Kato Server. This is in addition to a file and the debugger, if the -f and -o parameters are specified.

-o
Log all Kato output to the debugger.

This parameter sends all Kato output to the debugger. This is in addition to Kato Server and a file, if the -k and -f parameters are specified.

-f file_name
Log all Kato output to a file.

This parameter saves all Kato output to a file. This is in addition to Kato Server and the debugger, if the -k and -o parameters are specified. The default is to overwrite any existing file with the same name. To override the default and append the file, use the -a parameter along with the -f parameter. For Windows CE, you can prefix the file name with "cesh:" if you wish to create the file on a remote computer via the CESH connection. This is shown in the following command-line example. 

tux -d test.dll -f cesh:test.txt

You may also specify paths relative to the CESH directory on the remote computer as shown in the following command-line example. 

tux -d test.dll -f cesh:..\logs\test.txt

If "cesh:" is not specified, the file is created on the local Windows CE computer.

-a
Append output file.

This parameter can be used with the -f parameter to append the log file instead of overwriting it.

Remarks

The -k, -o, -f, and -a parameters are only available if Kato.dll is present. Kato.dll is the Kato Logging Engine used by most Tux test modules. Neither Kato.dll nor any part of Kato is required to run Tux, but it is the recommended logging engine if you want logging in your test modules. For more information, see Kato Logging Engine.

A space is not required between a command line parameter and its argument. For example, the following two command lines are equivalent.

tux -t tuxdemo.dll
tux -ttuxdemo.dll

Each command-line parameter must be specified separately. For example, the following command line is valid.

tux -b -e

However, the following command line is invalid.

tux -be
