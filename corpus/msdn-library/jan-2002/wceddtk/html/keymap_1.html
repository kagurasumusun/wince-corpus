Running the Test

The following command line shows the syntax for using Tux.exe to run the test.

tux –o –d keymap –x10

After the test case finishes, a status report is displayed indicating whether it passed, failed, skipped, or aborted.

The Keyboard Mapping Engine, KeyEngin.cpp and KeyEngin.h, correlates and verifies a given character to a virtual key combination mapping. The Keyboard Mapping Engine runs in three parts: engine initialization, key testing, and engine termination. Each of the three parts is supported with a single API call:

  • Engine initialization

    CreateKeyMapTestWindow

  • Key testing

    TestKeyMapChar

  • Engine termination

    RemoveTestWindow

The Keyboard Mapping Engine performs the following steps:

  1. The CreateKeyMapTestWindow function is called before any testing is performed.

    This function creates a thread, which in turn creates and manages the test window that will receive the WM_CHAR messages. When the thread has created and initialized the window, CreateKeyMapTestWindow returns the window handle. This window handle is needed for all subsequent calls to TestKeyMapChar.

  2. Using the window handle returned by CreateKeyMapTestWindow, the TestKeyMapChar function is passed a list of virtual keys to press and the UNICODE character that is expected as a result.

    The list can contain several keys to simulate the use of shifting keys, such as SHIFT or CTRL, with a character, which results in a WM_CHAR message. TestKeyMapChar presses and releases each key and then compares the resulting UNICODE WM_CHAR message with the expected character. The TestKeyMapChar function handles all synchronization and communication with the test thread and window and may be called multiple times.

  3. RemoveTestWindow is called to remove the test window and terminate the test thread.

The sample test case, KeyTest.cpp and KeyTest.h, demonstrates how to test a Standard American English keyboard driver’s virtual key to UNICODE character mapping using the Keyboard Mapping Engine. The test initializes a test engine and then iterates through all the keyboard characters and checks their mapping. The test then terminates the test engine. To check a different keyboard layout, the same testing process is used with a different set of test keys.

These tests are designed to test the keyboard and keyboard driver for an American Handheld PC (H/PC) keyboard, but may be used to test any keyboard that includes the keys found on the H/PC. Note that all keys may not be tested, depending on the test coverage.
