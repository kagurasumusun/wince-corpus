Running the Test

The following command line shows the syntax for using Tux.exe to run the test, where test_case is the specific test case or range of test cases to run.

tux –o –d rwtest –x test_case

The following example shows the syntax for using Tux.exe to run the entire test.

tux –o –d rwtest

After each test case finishes, a status report is displayed indicating whether it passed, failed, skipped, or aborted. After all of the specified test cases have finished, a summary of results is displayed.

The following table shows the test cases.

1002 Multiple-thread read/write test. 3 threads, 1000 writes/thread, 1 sector/thread, starting sector: 100.
1003 Multiple-thread read/write test. 4 threads, 1000 writes/thread, 1 sector/thread, starting sector: 100.

2002 Multiple scatter/gather buffers. Buffer sizes: 512, 512.

Test Cases 1001–1003 - Multiple-Thread Read/Write Testing

These test cases verify that a device driver is able to correctly handle multiple, simultaneous requests for service. Each test case creates multiple threads and assigns each thread a block of sectors to write. Each thread attempts to write to its block of sectors multiple times. These test cases provide a set of easy-to-run tests for quick verification of the driver’s behavior—they differ only in the number of threads created. They all assign each thread only one sector, starting at sector 100; each thread makes 1000 writes to its sector.

When running the multiple-thread test cases, you will be given general information about the test, such as the number of threads, number of writes per thread, number of sectors per write, and the starting sector. Progress indicators from each thread will also be displayed.

If an error occurs during the test, the test aborts immediately and returns a failing code to Tux.exe. If an error occurs, the type of error, such as a driver error or corrupt data, and the source of the error, such as a driver or memory location, is displayed.

Test Cases 2001–2004 - Multiple Scatter/Gather Testing

These test cases verify that the block device driver can correctly handle multiple scatter/gather buffers, as well as odd-sized buffers in which the buffer size is not equal to the sector size. These test cases were written assuming a 512-byte sector size; if your driver uses a different sector size, you will need to change the test source code to reflect the correct sector size. This test verifies that the device driver does not return an error and that the data is valid.

The SG_BUF and SG_REQ structures are filled in and their pointers are passed to the driver via DeviceIoControl. The following code example shows the syntax for these structures.

typedef struct _SG_BUF {
PUCHAR sb_buf;            // pointer to buffer
DWORD sb_len;             // length of buffer
} SG_BUF, *PSG_BUF;

typedef struct _SG_REQ {
DWORD sr_start;           // starting sector number
DWORD sr_num_sec;         // number of sectors
DWORD sr_num_sg;          // number of scatter/gather buffers
DWORD sr_status;          // request status
PFN_REQDONE sr_callback;  // request completion callback function
SG_BUF sr_sglist[1];      // first scatter/gather buffer
} SG_REQ, * PSG_REQ;

Additional sr_sglist entries may be filled in as well, according to the value of sr_num_sg.

Each test case outputs a detailed description of the number and location of each scatter/gather buffer that it creates. If an error occurs, the type of error, such as a driver error or corrupt data, and the source of the error, such as a driver or memory location, is displayed.

Test Cases 3001–3002 - Boundary Testing

These test cases are designed to check the behavior of the read/write operations at boundary limits, where errors often occur.

These test cases give a detailed description of the number and location of each DeviceIoControl. If an error occurs, the type of error, such as a driver error or corrupt data, and the source of the error, such as a driver or memory location, is displayed.
