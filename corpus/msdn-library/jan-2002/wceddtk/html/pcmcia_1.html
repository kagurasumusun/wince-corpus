Running the Test

The following command line shows the syntax for running the test.

rats test_case

The following interfaces are tested:

  • Device.exe to Pcmcia.dll
  • Client driver to Pcmcia.dll
  • Pcmcia.dll to OEM Host Bus Adapter (HBA)
  • Device.exe RegisterDevice API call

Device.exe has special support for Pcmcia.dll, which it loads at system startup. Device drivers for Windows CE fall into two categories:

  • Built-in device drivers

    These are drivers for hardware built into the platform, such as a notification LED, the keyboard, and so on. They are adapted to your platform when you port the kernel.

  • Installable device drivers

    These are drivers for hardware devices that are installed in standard slots or ports on the platform, such as PC cards or serial ports.

Device.exe interacts with client drivers, the built-in PCMCIA driver and serial port driver, and the registry. It loads built-in drivers when Windows CE starts, and handles loading and unloading of client drivers when needed.

Because installable device drivers are not loaded at system startup, an event must trigger Device.exe to start the loading process. For PC cards, this event is the insertion of the PC card into the PC card socket. Because connecting a serial device to a serial port does not generate an event that Windows CE can detect, serial devices must be handled differently. Therefore, after connecting a serial device, the user must initiate the loading of the appropriate installable driver.

Device.exe performs the following tasks:

  • Loads built-in drivers at system startup.
  • Loads PC card client drivers when a PC card is inserted.
  • Loads serial client drivers when initiated by the user.
  • Finds the appropriate device driver for a PC card by obtaining the card’s Plug and Play identifier or by invoking a detection routine to find a driver that can handle the PC card.
  • Loads and tracks drivers by reading and writing registry values.
  • Unloads client drivers when they are no longer needed.

The Device Manager requires the following information before loading your driver:

  • Driver type
  • Plug and Play identifier for the device, if it exists
  • Name of the driver’s DLL file
  • DLL entry point function
  • Three-character prefix for DLL functions

You must obtain this information to configure and load a device driver for the H/PC system.

The Card Services API exported by Pcmcia.dll is used by a client driver to perform the following tasks:

  • Establish and maintain communication with Pcmcia.dll
  • Read the PC card Configuration Information Structure (CIS)
  • Configure the PC card for proper operation, memory or I/O interface.

There are two types of test cases:

  • Smoke

    These are simple tests that test functionality by testing an API with a particular attribute.

  • Full

    A range of tests, which test for various combinations of parameter values to test for boundary conditions.
