Contacts Database

The Contacts database is one of the Personal Information Manager (PIM) applications. It is organized as a series of records referred to as address cards. Each address card holds a number of fields referred to as properties. There is a wide range of pre-defined properties, such as names, addresses, telephone numbers, birthdays, and anniversaries. The Contacts application bundled in the system comes with a graphical user interface and can be used as it is if the default application settings are adequate to meet needs of the user.

The Contacts database has an open application programming interface. You can take advantage of this to design new Contacts applications. For example, you could use the Contacts database to track a doctor's patient contact information including dates of previous and future office visits. You can retrieve, store, and query the records and properties in the Contacts database.

The Contacts database application is built upon the Windows CE object store. To completely understand the Contacts database, you need to be familiar with the object store. For more information, see Accessing Persistent Storage.

To design a Contacts database application, it is essential to understand the following basic elements:

  • Address cards

    An address card records information about one individual. The information is parsed into a set of properties, with the number of properties fixed for all address cards in a database. Each address card is represented by an AddressCardstructure. The Contacts database contains an arbitrary number of address cards depending on the amount of available memory on the hardware device. To determine the number of records in the database, call the GetNumberOfAddressCardsfunction.

  • Object identifier and position index

    A typical operation performed against an address card requires the identification of the record and the specification of its location in the database. To accomplish this, each address card is assigned a unique object identifier and a position index value. If you know the object identifier of an address card, you can obtain the position index of the card by calling the GetAddressCardIndex function. Conversely, you can get the object identifier by calling GetAddressCardOid, passing in the position index as a variable.

  • Property and property tags

    A property has an associated identifier called a property tag which is unique within the context of a single address card. To manipulate a property, you must set the property tag with a call to the SetMaskfunction. For example, you must set the HHPR_HOME_TELEPHONE_NUMBER property tag to enable the home telephone number property of an address card. When accessing a property, use the GetPropertyDataStruct function to specify whether the information should be retrieved by the position index, property name or property tag. The information is then passed into a PropertyDataStruct structure.

  • Sort order

    Sort order specifies how the records are indexed. For example, records can be sorted according to the names or telephone numbers of the individuals. You can use up to four properties as the position indices for sorting. However, you can sort only one property at a time. You specify a sort order when you create a new database (CreateAddressBookor open an existing database (OpenAddressBook You can also change and retrieve the sort-order properties using the SetColumnProperties and GetColumnProperties functions. In addition, you can change or retrieve the current sort order in an opened database using the SetSortOrder or GetSortOrder functions.
