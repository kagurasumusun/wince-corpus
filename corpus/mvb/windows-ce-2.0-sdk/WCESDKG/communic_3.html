Using a Modem (Telephony API)

Modems are used to connect Windows CE devices to remote computers for a wide variety of purposes. Data can be exchanged using either serial or network communication techniques. However, before information can be transferred, the modem must first be connected to the remote device, and then managed for the duration of the session. Although similar to the procedures described in the previous section, there is more to managing a modem connection than simply opening or closing a file.

With a modem, an application must be able to handle such tasks as dialing the appropriate phone number and disconnecting the line when the session is over. To simplify the process of using modems Windows CE supports a subset of the Microsoft telephony API (TAPI), focussed on outbound calls. TAPI provides a set of functions that applications can use to handle process of making and managing a modem connection (but not the actual transfer of data).

To make a modem connection using TAPI

  1. Initialize TAPI with lineInitialize.

    This function returns the number of line devices available. The application must provide the name of the callback function that TAPI will use to pass information back (discussed later).

  2. Open the line with lineOpen.

    If in doubt of the line's capabilities, you can obtain this information with lineGetDevCaps.

  3. Place the call with lineMakeCall.

    When the call is set up, the application will receive a LINE_REPLY message through its callback function. This message indicates only that the call has been established at the local end, perhaps indicated by a dial tone.

  4. As the connection process proceeds, an application will receive a series of LINE_CALLSTATE messages through its callback function indicating the progress of the connection (dialtone, ringing, etc.). When the connection is completed, the application will receive a LINECALLSTATE_CONNECTED message.

  5. During information transfer, TAPI continues to manage the connection, but the actual data transmission and reception is handled by the application.

  6. When transmission is finished, the application's callback function will receive a LINE_CALLSTATE message indicating, for example, that a remote disconnect has occurred.

  7. Close the line with lineClose.

  8. Shut down TAPI with lineShutdown.
