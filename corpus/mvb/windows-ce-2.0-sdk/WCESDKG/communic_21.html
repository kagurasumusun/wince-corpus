TCP/IP

Normal TCP/IP stacks are designed to work efficiently on wired networks. However, wireless networks may perform very differently. Settings appropriate to 10 Mbps Ethernet, for instance, may consume more bandwidth than necessary on a wireless network by generating unneeded retransmission requests.

To use wireless networking efficiently, some TCP/IP parameters may need to be tuned to the characteristics of the supporting network. Network parameters are maintained on a per-adapter basis, so applications must determine the appropriate adapter, and change the associated registry settings. The parameters most likely to need modification are:

  • Receive window size (Key: <Adapter Name>\tcpip\parms\TcpWindowSize). In general, larger receive windows work better with high-delay, high-bandwidth networks. For greatest efficiency, the receive window should be an even multiple of the TCP Maximum Segment Size (MSS). It should not exceed the system maximum (Key: tcpip\parms\GlobalMaxTcpWindowSize).

  • Initial round trip time (Key:<Adapter Name>\tcpip\parms\TcpInitialRTT). Round trip times are generally longer for wireless networks. Four seconds is recommended. It will default to a global value of 3 secs.

  • Delayed acknowledgment timer (Key: <Adapter Name>\tcpip\parms\TcpDelAckTicks).
