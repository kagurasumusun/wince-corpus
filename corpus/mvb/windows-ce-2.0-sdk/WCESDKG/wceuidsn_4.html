Designing Controls

Windows CE supplies a set of preconstructed elements or controls that you can use to build an application. Controls are objects that users interact with to enter or manipulate data. They commonly appear in dialog boxes. They also appear on toolbars when an application uses the desktop metaphor. Windows CE supports many standard controls such as buttons, combo boxes, edit boxes, check boxes, list boxes, scroll bars, spin buttons, as well as Windows CE specific controls such as the date month picker and calandar control. You can either add controls to a dialog box with a control editor or add them yourself, with code. To create a control object yourself, you can embed the control object in a dialog or frame-window object.

Besides using the standard controls included in Windows CE, you can also create your own controls. When designing controls for your application, avoid the following pitfalls that many designers incur:

  • Controls that are too close together

    Controls should be spaced far enough apart so that users do not accidentally select one control while intending to select another.

  • Inconsistent control activation

    Controls that have the same function should operate the same way. For example, buttons depress. They do not pop up.

  • Controls that are hard to figure out

    When you design a control, make sure users can figure out how to use it.

  • Controls that are hard to remember

    There are two things to consider when designing a set of controls. First, the user needs to distinguish between the controls, so the controls shouldn't look the same. Second, the user needs to associate each control with the function it controls. So a control should in some way resemble or depict the function it controls. One example of this is placing an image of a scissors on a button control that is used to "cut" or remove text.

  • Hidden controls

    Controls should be obvious so that users do not overlook them. If you want to remove a control from view, place it where users expect to find it such as in a menu.

  • Unexpected mapping between functions and controls

    Users expect a control to have a standard relationship between the control and function. For example, moving a slider control to the right "increases" the function whereas moving the slider to the right "decreases" the function.

  • Controls that don't work the way you expect

    Make sure controls function the same regardless of where they are placed. A control should follow a consistent rule. If a control uses a different operating principle, design the control such that it won't be confused with controls that operate under different operating principles.

  • Different controls that are too similar

    Controls that need to be distinguished from each other should differ by more than just a single feature. When you have several similar controls close together and lined up, people confuse them with each other. Distinguish controls by size, position, shape, and color.

  • Controls that are difficult to use

    Make controls easy to use. For example, make controls larger; use colors that contrast with the screen background; remove nearby controls and images that may be unnecessary, make controls centrally located.

  • Controls that have limited usability

    When you design a control, you need to test it with a variety of people to make sure its usable for everyone. You need to think about the differences in the capabilities of the people that need to use the control.
