Interrupt Handling

To provide efficient processing of interrupts, Windows CE splits interrupt handling into two distinct parts: an interrupt service routine (ISR) and an interrupt service thread (IST). At the hardware level, each interrupt request (IRQ) line is associated with a specific software ISR. When triggered, the ISR does little more than direct the kernel to an IST, which is responsible for handling the event.

The IST is a separate thread. Once it has been launched, the ISR returns and the system is ready to accept and handle the next interrupt. It is up to the application software developer to assign a thread priority to the IST that meets the timing requirements of the application.

Dividing interrupt handling this way allows the ISR to be very small and fast. The end result is that typical interrupt latencies are minimized, as are unacceptable delays in interrupt processing. The Embedded Toolkit and the Windows CE kernel make it possible to customize interrupt timing and priorities for a specific application.
