Windows CE Design Guidelines for Windows

Because Windows CE-based devices have limited screen space, you should generally use the full-screen for an application's primary window, unless your application is designed to be used in context with another application.

The Windows CE Help application and the Calculator are examples of applications whose primary windows don't take up the full screen because the user benefits from seeing another window behind them. If you're creating this type of application, design your primary window to be a fixed size, because Windows CE doesn't support user resizing of windows.

Windows CE doesn't support the Maximize and Minimize buttons. Instead of minimizing a primary window, a user can send the window to the back of the Z order by tapping the window's button on the taskbar. The user can restore the window by tapping its taskbar button again.

The taskbar is always visible on Windows CE. You can't hide the taskbar or use the full screen to display a window.

An important factor to be aware of when designing windows for Windows CE applications is that a window has a button on the taskbar if, and only if, it's a visible, top-level window that has the WS_OVERLAPPED style. This is a very important consideration because, when the system is running low on power, it sends the WM_HIBERNATE message to all windows that have a button on the taskbar. If an application doesn't have a button on the taskbar it can't receive and respond to this message.

You can use controls in either the command bar or the body of both primary and secondary windows. The guidelines for using command buttons in windows are the same as the guidelines for using command buttons in dialog boxes. See Windows CE Design Guidelines for Dialog Boxes for further information.

Windows CE supports 2 bits per pixel (2-bpp), 4 bits per pixel (4-bpp), and 8 bits per pixel (8-bpp) color devices, and can logically support 32 bits per pixel device independent bitmaps (DIBs).

Note An 8-bpp display driver can display a 32-bpp DIB by mapping each color in the DIB's color table to a specific color on the device. The mapping is determined by the palette used by the application displaying the bitmap. Color information can be lost if the application doesn't use an appropriate palette or if the bitmap uses more colors than the palette can hold.

Other design guidelines are the same for Windows CE as they are for other Windows platforms. See The Windows Interface Guidelines for Software Design for more information.
