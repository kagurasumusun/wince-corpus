Memory Architecture

The Windows CE kernel supports a single flat (i.e., not segmented) virtual address space which is shared by all processes. Instead of assigning each process a different address space, Windows CE protects process memory by altering page protections. Virtual addresses are mapped onto physical memory by the kernel. This approach largely eliminates the need for an application developer to be concerned with the physical layout of the target system's memory.

The portion of virtual memory available to processes is divided into 33 "slots", each 32 Mb in size. The kernel protects each process by assigning it a unique slot, with one slot reserved for the currently running process. The number of processes is thus limited to 32, but there is no limit (aside from physical memory) on the total number of threads. Within each slot, memory regions are allocated as follows:

  • 64 KB of reserved space

  • File, code, and data sections for the process

  • The primary thread's stack, and the default heap for the process

  • DLLs loaded from RAM

  • DLLs loaded from ROM

The kernel prevents an application from accessing memory outside of its allocated slot by generating an exception. Applications can check for and handle such exceptions by using the try and except functions.

Windows CE allows memory mapping, which permits multiple processes to share the same physical memory. This feature results in very fast data transfer between cooperating processes or between a driver and an application. One GB of virtual address space, distinct from that used for the slots, is allocated for memory mapping. Other than the total amount available, there is no restriction on how that memory can be allocated.

Memory is always allocated to applications one page at a time. Page size is determined by the system designer and specified when the operating system is built for the target hardware platform. On an H/PC, for example, the page size is normally either 1 KB or 4 KB.
