Control and Command Bar Design

Like Microsoft Windows 95 controls, Windows CE common controls are designed to provide clear, simple, and meaningful information to the user, and a means for the user to furnish input to the system and applications as needed. However, because the H/PC is a portable device, it presents some design challenges.

One of the challenges you'll encounter designing visually appealing applications for the H/PC is the small landscape-oriented screen. To maximize the screen real estate available for applications (the client area), the operating system supports a new type of control, the command bar. A single command bar replaces the separate menu and tool bars found on Windows 95-based application windows. Command bars can contain menus, combo boxes, edit boxes, buttons as well as other types of controls. It also includes the close (X) button, the help (?) button, and the OK button, usually found on the title bar of desktop Windows applications. For more information about working with command bars, see Command Bars.

Command bars are composed of bands, separated by gripper controls. Each band can contain up to one child window, which can be a toolbar or any other control. Additionally, each band can have its own bitmap, which is displayed as a background for the toolbar on that band. A user can resize or reposition a band by dragging its gripper bar. If a band has a text label next to its gripper bar, a user can maximize the band and restore it to its previous size by tapping the label with the stylus. See Command Bands for more information.

Microsoft's style guidelines recommend that you always display either a command bar or a command bands control in all H/PC applications. Command bars vary from 480 pixels to 640 pixels in length depending on the screen resolution. Because you can't place an application's title or icon on the command bar. users identify an application by the label and icon on its taskbar button.

A command bar menu is a list of commands that drops down when a user taps the menu's caption on the command bar with the stylus. Menu titles on a command bar appear in bold text. If you include a menu bar, always position it as the first (leftmost) element on the command bar. If you provide File, Edit, View, Insert, Format, Tools, and/or Window menus, always place them in this order, from left to right. The menu titles appear as bold text surrounded by a rectangular frame.

You can use check boxes or radio buttons on the command bar to enable users to toggle between different views. This can make windows more readable, and avoid the necessity for excessive scrolling.

If you provide individual New, Open, Save, and Print buttons on a command bar, you must position them in this order, from left to right. If you provide individual Bold, Italic, and Underline buttons, you must also place them in this order, from left to right. Always make buttons at least 23 pixels high and 23 pixels wide. Leave at least 2 pixels between adjacent controls and at least 4 pixels between a control and the edge of the screen. If you plan to support touch interaction in which users can use a finger rather than a stylus, make all buttons at least 38 by 38 pixels. However, to conserve space, you may want to consider creating a combo box button instead of three or four separate buttons.

Windows CE supports tool tips for command bar buttons, but not for menus or combo boxes on a command bar. Tool tips usually display only the name of a button's command, but they can also display the command's shortcut key. A command bar button can display a text or images. While tool tips allow you to provide textual descriptions for your command bar buttons, you can also include text as part of the button label, if you have sufficient space in your command bar.

Users of H/PC devices typically select controls by touching the screen with a stylus. On a small screen, they will find large controls to be more readable and easier to select than small controls. If you choose to place a label next to your edit control, you have two choices. You can insert a static text field above or to the left of the control. Alternatively, you can include an edit control label inside the text field as the default text. In this case, you would enclose the label between angle brackets, for example, <name>. Because the user can no longer see the control's label when he or she enters text in the field, using a static text field is preferable.

The default system font for H/PC version applications is Tahoma, 9 point. The H/PC version 1.0 uses MS San Serif, 8 point, which is a smaller raster font. Because many devices have a small screen size and a low contrast LCD, you should generally use a non-bold typeface when displaying control labels unless the labels appear on a light gray background.

You can also create a TAB and ARROW KEY navigation order for command bar buttons. When a command bar button has the input focus, the button activates if the user presses the SPACEBAR or ENTER key. The user must be able to select either option.

In addition to command bars, the H/PC supports two new common controls. They are especially useful when designing for a small screen because they are so compact. They include the Date and Time Picker (DTP) and the Month Calendar controls.

The Date and Time Picker control provides users with an easy a way to modify date and time information. Each field in the control displays a time element, such as month, day, hour, or minutes. Users select a field by tapping it with the stylus and entering a new value from the keyboard. See Using the New Date and Time Picker Control for more information.

The Month Calendar control is a child window that displays a monthly calendar. The calendar can display one or more months at a time. When a user taps the name of a month with the stylus, a pop-up menu appears that lists all the months of the year. A user can select a month by tapping its name on the menu. The user can scroll the displayed months forward or backward either by tapping the left or right arrow at the top of the control or by using the Page Up and Page Down keys on the keyboard. When a user taps the year displayed at the top of the calendar next to the month, an up-down control appears. The user can use this control to change the year. The user can also use CTRL+Page Up and CTRL+Page Down to scroll from one year to another. A user can use the arrow keys on the keyboard to scroll between days, the Home key to move to the beginning of a month, and the End key to move to the end of a month. Unless the calendar has the MCS_NOTODAY style, the user can return to the current day by tapping the Today label at the bottom of the month calendar control. See Using the New Month Calendar Control for more information.

Additionally, Windows CE supports a new custom draw service. The custom draw service is not a common control; it is a service that makes it easy to customize a common control's appearance. You can use the custom draw service to change a common control's color or font, or to partially or completely draw the control. See Using the New Custom Draw Services for more information.

Other design guidelines for controls are the same for the H/PC as they are for other Windows platforms. See the Designing Controls and The Windows Interface Guidelines for Software Design for more information.
