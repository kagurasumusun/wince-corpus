Serial Communication

Serial communication requires a direct one-to-one connection between source and receiver. The most common use is probably transferring information between two devices connected by a cable (usually called a "serial cable"). Infrared transceivers or modems can also used for serial communication.

From the standpoint of software, each serial device is identified by its "COM port" name (COM1:, COM2:, etc). Note that, with Windows CE, the colon (:) is part of the port name and must be included. The COM port assignments are stored in the registry under \HKEY_LOCAL_MACHINE\Drivers. Because they may be installable drivers, check \HKEY_LOCAL_MACHINE\Active to see which drivers are loaded.

Serial communication over a COM port is very similar to reading from or writing to a file, and uses some of the same functions. The basic procedure works in much the same way regardless of the hardware involved. There are three steps:

  1. Open and configure the appropriate COM port

  2. Transmit and receive information.

  3. Close the COM port.

With infrared transceivers, there are some additional considerations. Windows CE supports two ways to use an infrared transceiver for serial communication. An approach supported by some Windows CE devices ("raw IR") is to treat the IR transceiver like a serial cable. The data is not processed in any way, and the application is responsible for dealing with collision detection and other potential problems.

The COM port assigned to raw IR is determined by the OEM of the device and listed in the registry. In some cases, it may share a port assignment with a wired serial connector, but you should check the registry to be certain. Use EscapeCommFunction to set the port to IR mode (see the procedure outlined below for details). Check the return value to make sure that raw IR is supported.

A more robust approach to serial IR communication is to utilize the Infrared Data Association (IrDA) protocols. These protocols are actually part of the network stack (discussed later). To simplify their use for serial communication, Windows CE provides an emulator ("IrComm"), that allows applications to communicate using the IrDA protocols in almost exactly the same way as with raw IR.

From a programming standpoint, the main difference between raw IR and IrComm is that they use different COM ports. The port assignments are determined by the device's manufacturer and stored in the registry. With IrComm, there is also no need to explicitly configure the port for IR by calling EscapeCommFunction.

Windows CE supports the following file system functions to access serial devices.

Function Device Application
CreateFile Open (get a handle to) a device.
CloseHandle Close (the handle to) a device.
ReadFile Read data from the device.
WriteFile Write data to the device.
DeviceIoControl Perform an I/O control operation

Windows CE supports the following functions for setting up and using serial devices.

Function Description
ClearCommBreak Restore character transmission
ClearCommError Get information about a communication error and report the current status
EscapeCommFunction Direct a serial device to perform an extended function.
GetCommMask Get the value of the event mask for a serial device.
GetCommModemStatus Get the modem control register values.
GetCommProperties Get information about the serial driver.
GetCommState Get the current control settings for a serial device
GetCommTimeouts Get time-out parameters
PurgeComm Used to clear I/O buffer and terminating pending read or write operations
SetCommBreak Suspend character transmission.
SetCommMask Specify a set of events to be monitored
SetCommState Configure a serial device
SetCommTimeouts Set the time-out parameters
SetupComm Initialize the communication parameters
TransmitCommChar Transmit a character ahead of any pending data in the output buffer.
WaitCommEvent Waits for a serial communications event specified by SetCommMask
