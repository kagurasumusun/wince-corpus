Analyzing Memory Usage With the Remote Memory Viewer

Once an application is compiled and loaded on a device, use the Remote Memory Viewer, included with the SDK, to understand how it uses memory. This tool, located on the Tools menu of the VC++ IDE, enables developers to examine an application's memory use from a desktop PC. See Remote Tools for more information.

The Remote Memory Viewer contains three elements that help you understand memory usage: the process information window, the kernel summary, and the process memory map.

The process information window is divided into three sections. The first section provides process information, including the slot assignment, and page count. It also details how much memory is devoted to various aspects of the process (such as Read/Write memory or the stack).

The following table describes the process fields included in the process information section.

Field Description
Process Name Process name
Proc # Process handle
PID Process ID
Ptr Address of the slot containing the process
Slot Slot number for the process
Code Number of ROM code pages used. RAM usage is given in parentheses.
R/W The number of Read/Write data pages.
R/O The number of Read-Only data pages.
Stack The number of stack pages.
Reserved The number of reserved pages.

The next section gives information about the threads running in each process. It provides the handle of the thread, the name of the process in which the thread is running, the thread's priority and status.

The last section is devoted to DLL modules, providing each module's name, handle, location in memory, and the "in-use" flag. With Version 2.0 of Windows CE, the in-use flag indicates which processes are currently using the DLL. Each bit corresponds to a process slot number. An in-use flag with a value of 0x00000006 thus indicates that the DLL is being used by the processes in slots two and three.

In addition to the information displayed in the process information window, there are two items on the View menu that are of interest. One is the kernel summary; a dialog box that contains information on the resources currently in use by the Windows CE kernel.

The top line provides the page size, in bytes. This value (which is OEM-dependent) allows you to convert memory usage from pages to bytes. Also listed are the total number of pages, as well as any free pages available.

The next two lines describes the total pages used, and the pages used by the kernel. The following table provides information on each kernel object.

Heading Description
Inx Object number
Size The size, in bytes, of an object of this type.
Used The total number of bytes currently used by the kernel to hold these objects (the number of entries multiplied by the size of each object).
Max The number of bytes allocated to hold the objects.
Extra The amount of extra space currently allocated (the difference between Max and Used).
Entries The first item gives the number of objects currently in use. The second (in parentheses) gives the maximum number of objects of this type the kernel has ever had.
Name The name of the object type.

The second item of interest on the View menu is the Process Memory Map. The following dialog box provides a detailed picture of how memory is used by a selected process.

Each line begins with the address of a 64KB region of memory. The following symbols indicate how the pages in this region are allocated.

Symbol Description
S Stack page
C Code page in ROM
c Code page in RAM
W Read/Write data page in RAM
R Read-Only data page in ROM
r Read-Only data page in RAM
O Object Store page
P Pending Commit
- Reserved page available for commitment

Any white space at the end of a line represents the amount of wasted free space required to get to the next allocation granularity boundary.
