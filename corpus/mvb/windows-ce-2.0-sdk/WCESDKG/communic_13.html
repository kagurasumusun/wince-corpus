Infrared Sockets (IrSock)

Infrared Sockets (IrSock), is an extension to WinSock that allows it to be used for infrared communication utilizing the IrDA protocol. Each endpoint must support an IrDA-compliant device and an IrDA-compliant protocol stack. The SOCKADDR_IRDA structure has been added as an endpoint address type.

Although the same Winsock functions are used with IrSock, some work differently. The principal differences are:

  • Name Service

    Conventional WinSock name service is best suited to fixed networks in which name bindings are relatively static. IrDA is designed to handle to browsing of in-range resources in an ad hoc manner without need for fixed name-servers or the overhead of large hierarchical networks. IrDA networks are completely ad hoc, and devices come and go frequently as they move in and out of range.

    Because of these differences, IrSock does not use the standard WinSock name service functions. Instead, name service is incorporated into the communication stream.

  • Method of addressing

    IrSock introduces a new address structure and a new address family to describe it. The address includes a service name that describes the application in bind and connect calls and a device identifier that describes the device on which the application runs. It is similar to the TCP (port number where the service resides) / IP (machine where the service resides) convention. The address family describing the unique features of IrSockets is called AF_IRDA and is defined in the AF_IRDA.H header file.

    Addressing can be based on IrDA Logical Service Access Point Selectors (LSAP-SELs) or on services registered with the Information Access Service (IAS). Binding sockets directly to LSAP-SELs eliminates the need for the IAS altogether. Binding sockets to IAS services provides for dynamic address allocation.

  • Enhanced socket options

    Socket options are set with setsockopt. Only a subset of the WinSock options are supported for IrSock. In particular, because most SO_xxx socket options are not useful for IrSock, only SO_LINGER is supported. Unsupported options return the error code WSAENOTSUPP.

    A set of socket options to access the unique features of the IrDA protocol have been added:

    • IRLMP_IAS_SET allows an application to set a single class in the local IAS. The application specifies the class to set and the attribute and attribute type. The application must allocate a buffer of the necessary size for the passed parameters.

    • IRLMP_RAW_MODE, allows an application to switch between the reliable TinyTP mode (which is the default setting) and unreliable IrLMP mode. This option is only available after calling socket to obtain a socket handle and before calling bind and connect.

The following subset of WinSock functions are used by IrSock with modifications as noted:

IrSock function Modification
accept None.
bind Must be called before listen is called.
closesocket None.
connect None.
getsockopt IRLMP_IAS_GET and IRLMP_ENUMDEVICES options have been added.
listen None.
recv None.
send None
setsockopt The IR_LMP_IAS_SET option has been added.
socket The AF_IRDA value was added for the address format parameter. Only the SOCK_STREAM socket type is supported.
