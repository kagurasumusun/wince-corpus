Application Hibernation

The system uses the WM_HIBERNATE message as its primary mechanism for asking applications to free memory. It posts the message to one or more applications when required. The system tries to be intelligent. It begins hibernating applications that have been inactive the longest, and hibernates the active application last. It does not send messages to invisible windows.

Note Hibernating is vital. All well-behaved Windows CE applications must have a handler for WM_HIBERNATE.

When an application is brought to the foreground, the system sends an WM_ACTIVATE message. If the hibernating application had released memory, the system does not restore its memory resources to the pre-hibernation state. Applications should have a WM_ACTIVATE handler that can deal with the restoration of memory resources following hibernation.

An application must take the following actions when it receives a WM_HIBERNATE message:

  • Free any large blocks of memory (caches, for instance) that were allocated by VirtualAlloc.

  • Free as many GWES objects as possible, including windows, bitmaps, and device contexts.

  • Save the state of the heap in order to restore it later, then free the entire heap.

As the amount of available memory drops, the system posts WM_HIBERNATE messages at an increasing rate. If the system reaches a situation where a call to VirtualAlloc is about to fail, it tries to free pages by shrinking stacks. The system shrinks stacks in reverse order to minimize the risk of a stack fault, which is fatal to an application. If the system cannot free any stack pages, VirtualAlloc fails, and is returned to the application as a failed function call.
