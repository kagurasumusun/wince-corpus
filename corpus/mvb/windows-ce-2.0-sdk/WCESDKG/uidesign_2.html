Window and Dialog Box Design

The H/PC supports most common Win32 User API window functions; however due to constraints posed by the H/PCs screen size the system is designed for full screen applications. Windows can be moved around the screen but they cannot be resized by users. It is possible to create smaller windows for applications such as a calculator that can be used while another application is displayed, but most applications should utilize the entire screen.

While all H/PCs conform to a hardware specification standard, some manufacturers offer features that extend the functionality of their devices. These additional features including an expanded 640x240 pixel LCD screen. The expanded screen allows applications to be written that display up to 80 characters per line at an easily readable character size or ½ height VGA graphics resolution. This means the font aspect ratio is similar to a desktop PC and it eliminates the feeling that the characters are squeezed on to the screen.

Programmers can take advantage of the expanded screen size by designing applications capable of displaying a full width view of documents and images. This minimizes the amount of left and right scrolling making applications easier to use. Programming applications for the 640 x 240 screen does not necessarily require that a separate set of code be maintained for H/PCs with standard size screens. Create application windows using default values that indicate full screen size regardless of its dimensions. Position objects using relative as opposed to absolute coordinates.

Primary windows for the H/PC are similar to all other standard windows. However, unlike other windows, which contain both frames (borders) and title bars, H/PC primary windows do not contain title bars. Instead, they contain a command bar. See Control and Command Bar Design for more information.

Dialog boxes must be smaller that primary windows in order to differentiate between windows. Windows 95 and Windows NT use a bold system font when displaying dialog box text. Windows CE uses the non-bold system font when displaying text unless displaying text on a light gray background. Then Windows CE uses boldface text. The default system font for Windows CE is Tahoma, 9 point.

Note If you are developing Windows CE applications under emulation, and you want to lay out windows and dialogs that look the same on your PC as they'll look on an H/PC, use Tahoma.fon.

The H/PC v2.0 supports a majority of the common dialogs found in Windows 95 including the Open, Save As, Color, Print, and Font dialogs. These dialogs function the same on the H/PC as they do in Windows 95 with the following exceptions:

  • The H/PC v2.0 Print dialog implements a simple printing interface with one common dialog that enables the user to choose a printer type, printer port, number of copies, print range, orientation, and margin settings. Windows 95 and Windows NT provide a common print dialog, a page setup dialog, and a print setup dialog to cover those operations.

    H/PC applications enable printing by invoking the PrintDlg common dialog box. Initialize the PrintDlg function call by setting up the PRINTDLG structure.

    PrintDlg uses the port that was last selected by the user for a particular printer. If no user selection has been made the default setting is the first installed printer and the first port in the registry, which is COM1 at 9600 baud.

    All H/PC devices have the following ports setup for printing:

    • COM1: (Serial) at 9600 baud

    • COM1: (Serial) at 57600 baud

    • COM3: Infrared
  • The H/PC v2.0 Font dialog used in the Pocket Office applications is a shared dialog that contains a default font option and color list.

For more information on designing windows and dialog boxes, see Designing Windows and Dialog Boxes and The Windows Interface Guidelines for Software Design.
