Handling the H/PC User Interface

The H/PC has a touch-sensitive LCD screen which uses a stylus as the functional equivalent of a mouse. Text is entered with a compact QWERTY style keyboard. Most PC-based applications require some modification to their UI to run effectively on the H/PC.

Tapping the screen with the stylus generates a WM_LBUTTONDOWN message, along with the location of the point. Tapping twice generates a WM_LBUTTONDBLCLK message. Holding the stylus to the screen allows drag-and-drop operations.

Applications that only use the left mouse button need little modification. Because there is no way to keep track of the stylus between taps, there is no cursor support. Windows CE tracks the position of the last tap rather than the current cursor position. Applications that depend on a cursor will have to use a different approach.

There is no direct equivalent to a right mouse button. The customary way to get right-button functionality is to have the user press the ALT key while tapping. The action can be awkward for users, so it is best to use it sparingly. ALT-Tap does not generate right-button messages (WM_RBUTTONDOWN or WM_RBUTTONDBLCLK, for instance). To use ALT-Tap, check to see if the ALT key (VK_MENU) is depressed when handling WM_LBUTTONDOWN messages.

The keyboard is similar in layout to that found on a conventional PC, but it lacks function keys, and some of the special-purpose keys (Print Screen and Scroll Lock, in particular).

Switching between keyboard and stylus is awkward and should be kept to a minimum. Keep text entry as simple as possible. If it is not really necessary, consider adding a screen-based alternative.
