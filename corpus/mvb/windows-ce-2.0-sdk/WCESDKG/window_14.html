Message Functions

You use many of the message functions in Windows CE the same way you use them in Windows 95 and Windows NT, but there are a couple of difference.

When writing Windows CE applications, you should be very careful about using the PeekMessage function. Since the PeekMessage function doesn't block waiting for a message, it's a common practice in Windows 95 and Windows NT programming to use the PeekMessage function in a loop, allowing an application to continue processing whether or not there are any messages in its queue. The problem with doing this in a Windows CE application is, if an application doesn't block waiting for a message or some other event, the kernel can't put the CPU into low power mode. This can quickly drain the device's batteries. In Windows CE, PeekMessage doesn't remove WM_PAINT messages.

Windows CE supports a new message function, called GetMessageSource. Some Windows CE-based devices support both a hardware keyboard and a "soft" keyboard, which is a visual representation of a keyboard on the device's touch screen. A user enters keystrokes on a soft keyboard by tapping the keys on the touch screen with a stylus. You can call the GetMessageSource function, when processing a WM_KEYDOWN, WM_KEYUP, WM_SYSKEYDOWN, or WM_SYSKEYUP message, to determine whether the message was generated by a hardware keyboard or by a software function. Keyboard events that originate from the keyboard driver or keybd_event are identified as coming from hardware. Messages generated from PostMessage are identified as coming from software.

Note The GetMessageSource function is unique to Windows CE. It's not supported in other versions of Windows.

Windows CE doesn't support scan codes or extended key flags, so it doesn't support the values 16 - 24 in the lKeyData parameter (lParam) of the WM_CHAR messages generated by the TranslateMessage function.

Windows CE supports the MsgWaitForMultipleObjectsEx function the same way Windows 95 and Windows NT do, with two exceptions. Windows CE doesn't support the QS_HOTKEY value for the dwWakeMask parameter, or the MWMO_WAITALL or MWMO_ALERTABLE flags for the dwFlags parameter. MsgWaitForMultipleObjects is implemented as a macro that calls MsgWaitForMultipleObjectsEx. The QS_HOTKEY value isn't supported for the dwWakeMask parameter.

Use the following message functions in Windows CE the same way you use them in Windows 95 and Windows NT.

GetMessage

FormatMessage

Windows CE doesn't support the BroadcastSystemMessage, GetInputState, GetMessageExtraInfo, GetMessageTime, GetQueueStatus, InSendMessage, PostAppMessage, ReplyMessage, SendAsyncProc, SendMessageCallback, SendMessageTimeout, SetMessageExtraInfo, or WaitMessage functions.
