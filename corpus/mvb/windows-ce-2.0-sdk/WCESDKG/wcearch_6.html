Physical Memory Usage

Because Windows CE devices usually have no disk drive, physical memory will normally consist of ROM and RAM. These two types of memory thus play a substantially different role on a Windows CE device than they do with desktop computers.

Because it cannot be modified by the user, ROM is used for permanent storage. The contents of ROM are determined by the OEM, and include the operating system and any built-in applications that are provided along with it (such as Pocket Word and Pocket Excel on an H/PC).

RAM is maintained continuously, so it is effectively non-volatile. Portable systems will usually have a backup battery to guard against failure of the primary battery, and to allow batteries to be changed. This allows RAM to be used for persistent storage as well as program execution, compensating for the lack of a disk drive. To serve these two different purposes RAM is divided into program memory and storage memory (the Object Store). Program memory is used for program execution. The Object Store is used for persistent storage of data and any executable code not stored on ROM.

In general, the amount of RAM on a Windows CE device is quite limited, and must be used efficiently. To reduce RAM requirements, executable code stored in ROM normally executes in-place. Because most ROM-based code does not need to be loaded into RAM for execution, only a small amount of RAM is needed for such purposes as stack and heap storage.

Applications may also be stored and execute in RAM. This approach is used primarily with third-party applications, added by the user. RAM-based applications are stored in compressed form, and must be uncompressed and loaded into program memory for execution. To increase the performance of application software and reduce RAM usage, Windows CE uses on-demand paging. With it, the operating system only needs to uncompress and load the memory page containing the portion of the application that is currently executing. When it is finished, the page can be swapped out, and the next page loaded.

ROM-based executable code (including DLLs) can also be compressed. In this case, they do not execute in place, but are handled much like RAM-based code. The code is uncompressed and loaded a page at a time into RAM program memory, and swapped out when no longer needed.
