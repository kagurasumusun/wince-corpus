Non-Standard Debugging

If you are developing software for a standard Windows CE platform, such as the H/PC, you can use the Windows CE emulation environment and remote tools to debug and test your application. However, if you are developing an application for another Windows CE platform, such as an embedded system, you have to build your own debugging environment.

The Windows CE API includes the interfaces necessary to create a full featured debugger application, such as VC++ or Windbg. Although the creation tools exist, the limited size of the Windows CE environment makes such a debugger unrealistic. If you decide to write a debugger application, the best approach is to create a debug client using Windows CE debug functions and to communicate the relevant events to a PC-based debugger. When writing a debugging application, choose one of the following ways to start the debugging session:

  • Launch a process with CreateProcess specifying the DEBUG_PROCESS (or DEBUG_ONLY_THIS_PROCESS) in the dwCreateFlags field. In addition to the DEBUG_PROCESS flag , use CREATE_SUSPENDED to prevent the application from running after it is initialized. Once suspended, a debugger can initialize and add any appropriate break points.

    - Or -

  • Attach to an already running application. To attach to a process, you must obtain permission to the process by calling OpenProcess and passing in the ID of the process you want to debug. If a valid handle is returned, call DebugActiveProcess to start debugging. After attaching to the process, the CREATE_PROCESS_DEBUG_EVENT returns the primary thread handle and the multiple CREATE_THREAD_DEBUG_EVENTs return the secondary thread handles. After attaching to the process and receiving the initial events, the process's thread is resumed. Unlike Windows NT, Windows CE has no EXCEPTION_DEBUG_EVENT. All thread handles must be closed with CloseHandle when you stop debugging.

Windows CE Version 2.0 has built in support for Just-In-Time (JIT) debugging. JIT enables you to run an application outside of the development environment. When an error occurs, the application calls the installed debugger. You register your JIT debugger by placing the name of your debugger in the registry value JITDebugger located at HKEY_LOCAL_MACHINE\Debug. To enable JIT, you must warmboot the device after the above value is added to the registry.

If you choose not to write a debugger application, you must create some debugging tools in the Windows CE system. Windows CE provides both functions and structures to do this.

The following debugging functions and structures are supported by Windows CE:

Supported Debugging Functions
ContinueDebugEvent
DebugActiveProcess
DebugBreak
FlushInstructionCache
GetThreadContext
OutputDebugString
ReadProcessMemory

The following debugging functions and structures are not supported by Windows CE:

Unsupported Debugging Functions
IsDebuggerPresent
GetThreadSelectorEntry
FatalExit
FatalAppExit
SetDebugErrorLevel
Unsupported Debugging Structures
