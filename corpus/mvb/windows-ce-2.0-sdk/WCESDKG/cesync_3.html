Implementing the ActiveSync Components

To implement the desktop synchronization components

  1. Create a project that builds a desktop ActiveSync module.

    This can be a single DLL that implements the required interfaces summarized in the ActiveSync Reference. For a description of a sample ActiveSync template, see the Sample ActiveSync Module.

  2. Analyze the desktop data store.

    Determine the definition of the object, the object type name, the folder, the object identifier, and ways to identify whether an object has changed.

  3. Create one GUID for the store, using the Visual C++ GUID generator tool (Guidgen.exe).

  4. Define HREPLITEM and HREPLFLD. These handles can simply be pointers to some data structures. Also, define HREPLOBJ which is a generic handle that can be either HREPLITEM or HREPLFLD.

  5. Implement all methods in IReplStore.

    These methods implement the following functionality:

    • Initialize the store.

    • Provide a folder handle for the given object type, and return a pointer to the IReplObjHandler interface.

    • Provide for management of the object types.

    • Provide a way for Windows CE Services to display related information in its main window.

    • Enumerate objects for a given object type.
  6. Implement all methods in IReplObjHandler.

To implement the Windows CE platform ActiveSync components

  1. Create a project that builds a Windows CE platform ActiveSync module.

    This can be a single DLL that implements the required platform functions that are summarized in the ActiveSync Reference. For a description of a sample synchronization template, see the Sample ActiveSync Module.

  2. Determine how the objects are stored on the Windows CE platform in the device.

    For example, determine whether the data is stored in a flat file, in a Windows CE database, or in some other custom format.

  3. Implement the required functions referenced in the first step.

  4. Implement the methods in IReplObjHandler.

    These methods do not have to be fully implemented and can simply be stubbed.

To register the ActiveSync components

  1. Create the required registry keys on the desktop PC.

    For a description of the required desktop PC registry settings, see Schedule+ ActiveSync Components: Example.

    For another example, see the file Stsync.reg provided with the SDK sample, located in the Wce\Samples\Win32\Wce200\Sync\v2\Stockpor\desktop\sync directory (See Sample ActiveSync Module).

  2. Create the required registry keys on the Windows CE device. This can be done at application setup time with the device connected.

    For a description of the required Windows CE platform registry settings, see Schedule+ ActiveSync Components: Example.

    For another example, see the file Devsetup.cpp provided with the SDK sample, located in the Wce\Samples\Win32\Wce200\Sync\v2\Stockpor\device directory (See Sample ActiveSync Module).

Sample ActiveSync Module

The Windows CE SDK provides a sample application that will assist you in developing an ActiveSync module. The sample is located on the SDK in the Wce\Samples\Win32\Wce200\Sync\v2\Stockpor directory. The project is named Stockpor; this implements a sample stock portfolio application that synchronizes data between the desktop PC and the Windows CE platform.

Also, the Desksamp and Devsamp directories provide templates that you can use to build your own ActiveSync module.

For a detailed description of this sample, see the file Readme.doc, located on the SDK in the Wce\Samples\Win32\Wce200\Sync directory.

ActiveSync Reference

  • ActiveSync Interfaces

    The following interfaces are implemented on the desktop PC by an ActiveSync service provider and Windows CE Services.

    Interface Description
    IReplStore Implemented in the desktop PC ActiveSync component; implements methods related to the data store.
    IReplObjHandler Implemented in the desktop PC ActiveSync component; implements methods related to the serialization and de-serialization of an object.
    IReplNotify Implemented by the ActiveSync service manager in Windows CE Services (for example, the Explorer Window); the ActiveSync service provider can use this to notify the ActiveSync service manager of certain events taking place in the ActiveSync service provider store.
    IEnumReplItem Enables enumeration of a collection of items; used by IReplStore::ActivateDialog.

  • Windows CE Platform ActiveSync Component Functions

    The following functions are implemented in the Windows CE platform ActiveSync module. They are called by the ActiveSync service manager in the Windows CE platform.

    InitObjType initializes data after module load; frees allocated resources and returns a pointer to IReplObjHandler interface.
    GetObjTypeInfo gets information on an object type
    ObjectNotify notifies ActiveSync service provider of a change/deletion of object and asks for object ID for serialization/de-serialization of the object
    ReportStatus used to notify ActiveSync service provider of certain events (for example, the start and end of synchronization).

  • ActiveSync Structures
    HREPLITEM a handle to a data object stored by the ActiveSync service provider
    HREPLFLD a handle to a folder stored by the ActiveSync service provider
    HREPLOBJ a structure used to set up the object handler before serialization/de-serialization of an object
    CONFINFO used to retrieve information about two conflicting items.
    OBJNOTIFY used to notify ActiveSync service provider that an object has changed or been deleted.
    OBJTYPEINFO used to store information about an object type.
    OBJUIDATA used by IReplStore::GetObjTypeUIData to send UI related data about an object type to the store.
    REPLSETUP used to set up the object handler before serialization/de-serialization of each object.
    STOREINFO used to identify an instance of the store.
    DEVINFO used to store information about a device

  • IReplStore interface methods
    ActivateDialog activate a ActiveSync service provider-specific dialog
    BytesToObject converts an array of bytes to a HREPLOBJ when loading
    CompareItem compares the given handles of two items
    CompareStoreIDs compares the identifiers of two stores
    CopyObject copies a HREPLOBJ to another
    FindFirstItem returns a HREPLITEM of the first object in a given folder, if any
    FindItemClose complete the Find operation in the given folder.
    FindNextItem return a HREPLITEM of the next object in the given folder, if any
    FreeObject free the given HREPLOBJ
    GetConflictInfo get information about two conflicting objects
    GetFolderInfo returns a HREPLFLD for folder, given the object type name; also returns a pointer to IReplObjHandler of the given object type.
    GetObjTypeUIData sends UI related data about an object type to the ActiveSync service manager
    GetStoreInfo get information about the current store instance
    Initialize initializes the ActiveSync service provider
    IsFolderChanged check if any object in the folder has been changed since the method was last called.
    IsItemChanged check if the item is changed.
    IsItemReplicated check if the item should be replicated using ActiveSync service provider defined rules.
    IsValidObject Determines if the given HREPLOBJ is valid.
    ObjectToBytes convert the HREPLOBJ to an array of bytes when saving
    RemoveDuplicates finds and removes any duplicated objects in the store
    ReportStatus servier is reporting to the store about certain operations.
    UpdateItem update the item's time-stamp, change number, etc. that is identified by the handle

  • IReplNotify interface methods:
    GetWindow get the handle of the current active window to be used as parent of the modal dialog or message boxes.
    OnItemNotify tells ActiveSync service manager that an object has been created, deleted, or modified.
    SetStatusText set the status text on the ActiveSync service manager.
    QueryDevice query information about a device

  • IReplObjHandler interface methods:
    DeleteObj deletes an object
    GetPacket de-serializes an object into data packet(s) which is sent between the desktop and the Windows CE device
    SetPacket serializes the data packet(s) into an object
    Setup sets up the ActiveSync service provider so it is ready to serialize/de-serialize an object.
    Reset resets the ActiveSync service provider so all resources used during the serialization/de-serialization process are freed.

  • IEnumReplItem interface methods:
    Clone creates a copy of the current state of enumeration
    GetFolderHandle gets a handle to the folder being enumerated
    Next advances to the next item in the enumeration sequence.
    Reset resets the enumeration sequence to the beginning
    Skip skips over the next item in the enumeration sequence.
