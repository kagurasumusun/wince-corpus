Window Functions

In Windows CE you use the windowing functions the same way you do in Windows desktop platforms, with the following exceptions.

Windows CE doesn't support menu bars outside of the command bar, so you have to set the bMenu parameter to the AdjustWindowRectEx function to FALSE

In CreateWindow and CreateWindowEx, always set the hMenu parameter to NULL, unless you're using it as a child-window identifier. Windows CE 1.0 doesn't support owned windows, except for dialog boxes. Windows CE doesn't support Multiple Document Interface (MDI), so you can't specify the MDICLIENT class in the lpClassName parameter. Windows CE doesn't support all of the window styles Windows desktop platforms support, so there are some restrictions on the window styles you can pass in the dwStyle parameter to the CreateWindow function and in the dwStyle and dwExStyle parameters to the CreateWindowEx function. See these topics for details.

In Windows CE, CreateWindow is implemented as a macro. It works the same way it does in Windows 95 and Windows NT.

The DestroyWindow function sends only the WM_DESTROY message. Windows CE does not support the WM_NCDESTROY message.

Windows CE doesn't support the EnumThreadWindows function, but you can create an equivalent function by using EnumWindows and GetWindowThreadProcessId.

If you pass an atom in the lpClassName parameter to the FindWindow or GetClassInfo functions, the atom must be one returned by the RegisterClass function.

Windows CE doesn't support unaligned access in window classes, so the nIndex parameter to the GetClassLong and SetClassLong functions must be a multiple of 4 bytes. The GetClassLong_wcesdk_GetClassLong function doesn't support the GCW_ATOM, GCL_CBCLSEXTRA, GCL_CBWNDEXTRA, GCL_HBRBACKGROUND, GCL_HCURSOR, GCL_HICONSM, GCL_HMODULE, GCL_MENUNAME, or GCL_WNDPROC values in the nIndex parameter. The SetClassLong_wcesdk_SetClassLong function doesn't support any of the GCL_* values. If you're using the Windows CE Iconcurs component, which supports mouse cursors on appropriate target platforms, you can use the GCL_HCURSOR value in the nIndex parameter of both of these functions.

Because the command bar is part of the client area in Windows CE, it is included in the dimensions returned by the GetClientRect function.

In Windows CE, you use the GetDoubleClickTime function for stylus input the same way you use this function for mouse input in Windows desktop platforms.

Since Windows CE does not support the GetScrollPos or GetScrollRange functions, you use the GetScrollInfo function to retrieve the current position and range of a scroll bar.

Windows CE versions 2.0 and later support two new values you can pass in the nIndex parameter of GetSysColor and the lpaElements parameter of SetSysColors. Use the COLOR_STATIC constant to get or set the background color for static controls and dialog boxes. Use the COLOR_STATICTEXT constant to get or set the text color for static controls. The default color for the background is gray and the default color for text is black.

Windows CE does not support all of the nIndex values for the GetSystemMetrics function that Windows desktop platforms do.

In Windows CE, the GetWindowLong and SetWindowLong functions do not support the values GWL_HINSTANCE, or GWL_HWNDPARENT in the nIndex parameter. Since the bytes have to be aligned, the value of the nIndex parameter must be a multiple of four.

You have to pass a valid window handle to the InvalidateRect and ValidateRect functions. Windows 95 and Windows NT invalidate and redraw all windows if the hWnd parameter is set to NULL. This isn't supported in Windows CE.

Windows CE ignores the bRepaint parameter to the MoveWindowfunction, treating it as TRUE.This function always sends the WM_PAINT message to the window.

In the RegisterClass function, the WNDCLASS structure you pass by way of the lpWndClass parameter doesn't support the lpszMenuName fields. Set this field to NULL. IF your target device doesn't provide mouse cursor support, you must also set the hCursor field to NULL.

Tip When registering a new window class, the class name has to be a Unicode string. You can use the TEXT macro to cast a string as Unicode. For example, TEXT("classname").

You cannot use the SW_SCROLLCHILDREN flag in the flags parameter to the ScrollWindowEx function and, because you can only scroll a window in one direction at a time, you have to set either the dx or dy parameter to zero.

When you set the SWP_FRAMECHANGED flag in the fuFlags parameter to the SetWindowPos function, Windows CE redraws the entire non-client area of the window. Redrawing may change the size of the client area as well. If you set the SWP_NOACTIVATE flag, and the specified window is currently active, but hidden, the activation is passed to another visible top level window
