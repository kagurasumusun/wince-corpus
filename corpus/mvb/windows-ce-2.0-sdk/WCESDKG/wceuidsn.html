Windows CE User Interface Design Guide

An application's user interface serves two main purposes-to receive user input and provide user output. How your application handles this depends on your device's hardware capability, operating system configuration, and input and output requirements. Before designing your application, you need to determine if its interface will be graphical or non-graphical. How will your application receive user input? Will users enter commands using a keyboard or a touch screen, or will they use voice commands or press buttons on a console? How will you provide feedback to the user? Will your device support an LCD screen or audio feedback?

Windows CE supports a range of device platforms, from handheld computers to industrial embedded systems. Its modular design allows you to use only the features you need to create applications for your specific platform. Because user interface requirements vary from one platform to another, the Windows CE User Interface Design Guide describes design techniques to consider when creating a graphical user interface. Platform specific design considerations, such as those pertaining to an H/PC, are discussed in the H/PC User Interface Design Guide.

A well-designed user interface centers on users and their tasks. Good user-interface design considers general design principles as well as how graphics, color, and layout influence the usability of an application. The following list describes general design concepts to apply when creating an interface focused on the needs of the user.

  • Give the user control

    Allow the user, not the computer or software, to initiate actions. Remember, the goal of the user is not to use the application, but to accomplish a task.

  • Use familiar concepts

    To increase familiarity with the interface, allow users to manipulate representations of the tasks they perform. For example, if providing a desktop-like interface, allow users to drag icons depicting documents to an icon depicting a trash bin when deleting a file. For other types of interfaces, make sure buttons and icons relate to the tasks they perform. One example of this would be to display a wrench to initiate an automotive maintenance application.

    Another way to increase interface familiarity is to avoid using modes, since modes force users to think about how the application works instead the tasks at hand. Modes, which occur when identical commands or keystrokes perform different actions in different situations, cannot always be avoided. Warning boxes and message boxes are two types of modes that are necessary and appropriate.

  • Be consistent

    Consistency makes the interface familiar and predictable, reducing user errors and improving performance. Consistency is enhanced with components that have similar appearance and behavior and with actions that have the same result regardless of context. For example, in a desktop environment, scrollbars operate the same way, regardless of whether the scrollbar is in a list box or window. To achieve consistency, reuse standard commands across tasks and present commands in the same way in each task.

  • Allow interactive discovery

    Let the user explore the interface through trial and error, while warning him or her about potential damage to the system or data. To minimize user problems, provide clear error messages and indicate appropriate actions for the user to take to recover from an error or correct the problem that caused it. If possible, make actions reversible or recoverable.

  • Provide feedback

    Present the user with timely visual and audio cues to confirm that the software is responding to input.

  • Focus on aesthetics

    Effective visual design is aesthetically pleasing. An attractive interface helps the user select appropriate competing information and suggests a high-quality application.

  • Design with simplicity

    Simple interfaces, with an uncomplicated, uncluttered display, are easy to learn and easy to use. Display only the most important controls directly on the interface and hide the rest in menus. Reduce the number of different tasks presented in a single window or screen and group related tasks together. Simplicity is especially important in Windows CE-based devices with small displays.

  • Support multiple input methods

    Whenever possible, provide multiple methods for performing an operation. To accomplish this, support different types of input devices if possible, and provide keyboard shortcuts or accelerators for specific tasks, if your device supports a keyboard.
