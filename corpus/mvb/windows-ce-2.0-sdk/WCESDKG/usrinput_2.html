Keyboard Input

The keyboard is an important means of user input on many Windows-CE-based devices. Windows CE maintains a device independent keyboard model which enables it to support a variety of keyboards. When the user selects a keyboard, Windows CE installs a keyboard device driver capable of interfacing with that keyboard.

Windows CE assigns each key on a keyboard a unique device-dependent identifier called a scan code. Each key generates one scan code when it is pressed, and another when it is released. The keyboard device driver translates or maps each incoming scan code to a virtual-key code, a device-independent value defined by Windows CE. After translating a scan code, the keyboard device driver creates a message that includes the scan code, the virtual-key code, and other keystroke-related information, and then places the message in the system message queue. Windows CE removes the message from the system message queue and posts it to the message queue of the appropriate thread. The "appropriate thread" is the thread that created the window that currently has the keyboard focus. In time, the thread's message loop removes the message from the queue and passes it to the appropriate window procedure for processing.

The keyboard is shared among all the windows, but the keyboard messages are only processed by the window that currently has the keyboard focus. Only one window may have the keyboard focus at a time. The window that has the keyboard focus receives all keyboard messages until the focus changes to a different window. The user can easily change which window has the keyboard focus by switching to another window.

You can call the GetFocus function to determine which of your thread's windows currently has the keyboard focus. You can use the SetFocus function to give the keyboard focus to one of your thread's functions. Do not use the SetFocus function to set the keyboard focus to a window associated with another thread's message queue unless the window if your thread's windows is a child or sibling of the other thread.

When the keyboard focus changes from one window to another, the system sends a WM_KILLFOCUS message to the window that has lost the focus, and then sends a WM_SETFOCUS message to the window that has gained the focus.

The active window is the top-level window the user is currently working with. The window with the keyboard focus is either the active window, or a child window of the active window. To make the active window easy to identify, the system places it at the top of the Z order and highlights its title bar, if it has one, and border.

A thread can use the SetActiveWindow function to activate a top-level window. It determines whether a top-level window it created is active by using the GetActiveWindow function. When one window is deactivated and another activated, Windows sends the WM_ACTIVATE message which instructs the default windows procedure to set the keyboard focus to the active window.
