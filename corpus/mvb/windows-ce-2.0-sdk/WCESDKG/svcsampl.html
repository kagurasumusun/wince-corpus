Mail Transport Service

Transport services, packaged as DLLs, provide support functions to allow the mail client to interact with a server. For example, the mail transport service (smtp.dll) that comes with the Windows CE operating system serves as a message broker between Inbox and an Internet mail server compliant with the SMTP and POP3 protocols.

Note The mail store API may be used to deliver messages to the mail client without allowing server interaction, for example, for a built-in one-way pager card. This section covers interactive transports only.

The mail transport service operates behind the scenes to connect to the mail server and to actually transmit or receive messages. As a part of the initialization, the transport service retrieves from the Registry information about the name of SMTP and POP3 servers, their ports, user name, password, return address, etc.

The mail transport service uses a private SERVICE data structure to represent the server it communicate with. It uses the MailMsg structure to transport mail messages between the client and the server.

Transport services work closely with the client application. For example, Inbox calls functions exported by the mail transport DLL (smtp.dll) to perform standard mail operations such as connecting to, sending mail to, receiving and deleting mail from an Internet mail server. A transport service must implement a minimum number of functions the client application needs to call; and additionally may choose to implement a few optional functions. Before the client can communicate with a transport, the transport must register itself in the registry and the client must add the transport to its list of interactive services.

Transport services are not limited to electronic mail. As an application developer, you may wish to write a custom transport for paging, fax, file systems and other services. Similarly, you can write a custom client application. In any case, a transport is responsible for implementing a set of transport API and making it available for a client to call. If you write a transport that will use Inbox as a client, you must declare and implement all the transport service interface functions and structures that Inbox expects.
