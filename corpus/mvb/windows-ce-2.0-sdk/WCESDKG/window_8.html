Foreground Windows

The foreground window is the active window of the foreground thread. Each thread in the system has at most one active window. The active window is always a top-level window. Each thread also has at most one focus window. The focus window is either the thread's active window, or a child of the active window. The focus window is the window that receives keyboard input if its thread has the foreground. There's always exactly one foreground thread in the system at any given time, and the foreground thread's active window is the foreground window. If a user taps the stylus in a non-foreground window, that window's thread becomes the foreground thread.

Every window occupies a position in the Z order. (The expression Z order derives from the fact that windows are conceptually "stacked" along an imaginary z-axis that extends outward from the screen.) The window at the top of the Z order overlaps all other windows. The window at the bottom of the Z order is overlapped by all other windows. Bringing a window to the top of the Z order automatically activates the window, unless you set the SWP_NOACTIVATE flag in the SetWindowPos function. Sending the active or foreground window to the bottom of the Z order doesn't automatically deactivate the window or remove it from the foreground, though. Activating a window or setting it to the foreground doesn't automatically enable it or make it visible. When you hide the foreground window, the system looks for another top-level window to bring to the foreground.

A window is considered visible if it isn't hidden. (Whether or not a user can see the window on the screen has nothing to do with whether or not the window is visible.)

For an overview of foreground window functions and messages, see Foreground Window Functions and Foreground Window Messages.
