Initializing and Terminating RAPI

Before making RAPI calls, the system must be initialized by calling CeRapiInit or CeRapiInitEx. These functions perform routine initialization and set up the communications link between the PC and the device.

CeRapiInit is a synchronous operation. It does not return control to the application until a connection is made or an error occurs. In contrast, CeRapiInitEx returns immediately. It continues the initialization until a connection is made, an error occurs, or there is a call to CeRapiUninit. Although CeRapiInitEx avoids blocking any threads, it is a more complicated process for initialization.

To initialize RAPI using CeRapiInitEx

  1. Call CeRapiInitEx.

  2. If an error is returned, exit.

  3. If successful, call WaitForSingleObject or WaitForMultipleObjects to wait on the event handle passed back in the heRapiInit member of RAPIINIT.

  4. When heRapiInit is signalled, check for a successful connection or an error value.

  5. Check the hrRapiInit member of the RAPIINIT structure for the final return value.

When you are finished with RAPI, call CeRapiUninit to terminate the connection and perform any necessary cleanup. Creating and terminating connections are fairly expensive operations. In general, establish and terminate the link only once per session, not on a per-call basis.

The following example demonstrates the use of the CeRapiInitEx function. Following the CeRapiInitEx call, the MsgWaitForMultipleObjects function is used to wait on one of two events. One is the event handle passed back through the heRapiInit member of the RAPIINIT structure. The other event is when a user terminates a connection ¾ and is generated, for instance, from a dialog box.

/* InitRapi is similar to CeRapiInit except it will exit properly if the hExitevent is set. hExit is a handle to a timeout or a keyboard input that will cancel a wait dialog (note that the dialog procedure is not included here).*/

HRESULT InitRapi(HEVENT hExit)
{
    RAPIINIT ri = { sizeof(RAPIINIT) };
    HRESULT hr = CeRapiInitEx(&ri);
    if ( FAILED( hr ) )
    {
        return(hr);
    }

    HANDLE ahWait[] = { hExit                  , ri.heRapiInit };
    enum              { WAIT_EXIT=WAIT_OBJECT_0, WAIT_INIT     };

    //Wait for an event to happen
    DWORD dwObj = WaitAndDispatch(ARRAYSIZE(ahWait), ahWait);

    if (WAIT_INIT == dwObj)  ///Event signalled by RAPI
    {
        if (FAILED(ri.hrRapiInit)) //Connection failed
        {
            CeRapiUninit();
        }

        return(ri.hrRapiInit);
    }

    //Event signalled by user or timeout occurred
    CeRapiUninit();

    // This should never happen; it indicates a problem with the wait
    if (WAIT_EXIT == dwObj)
    {
        return(HRESULT_FROM_WIN32(ERROR_CANCELLED));
    }

    return(E_FAIL);
}


enum
{
    WAD_ALLINPUT    = 0x0000,
    WAD_SENDMESSAGE = 0x0001,
} ;

/* WaitAndDispatch waits for the hExit handle (from InitRapi()) or
   the event handle associated with the call to CeRapiInitEx().
   This should not be called if there is any UI in this thread unless 
   only the WAD_SENDMESSAGE flag is set. */
DWORD WaitAndDispatch(DWORD nCount, HANDLE *phWait, DWORD dwTimeout, UINT uFlags)
{
    DWORD dwObj;
    DWORD dwStart = GetTickCount();
    DWORD dwTimeLeft = dwTimeout;

    for ( ; ; )
    {
        dwObj = MsgWaitForMultipleObjects(nCount, phWait, FALSE,
            dwTimeLeft, (uFlags&WAD_SENDMESSAGE) ? QS_SENDMESSAGE : QS_ALLINPUT);
        if (dwObj == (DWORD)-1)
        {
            // Wait once more in case MsgWaitForMultipleObjects failed
            dwObj = WaitForMultipleObjects(nCount, phWait, FALSE, 100);
            if (dwObj == (DWORD)-1)
            {
                break;
            }
        }
        else if (dwObj == WAIT_TIMEOUT)
        {
            break;
        }

        if ((UINT)(dwObj-WAIT_OBJECT_0) < nCount)
        {
            // One of the events went off
            break;
        }

        /* There is a pending message or we timed out, so dispatch messages */
        MSG msg;
        if (uFlags & WAD_SENDMESSAGE)
        {
            // This should allow all sent message to go through
            PeekMessage(&msg, NULL, 0, 0, PM_NOREMOVE);
        }
        else
        {
            /* This should allow all sent or posted messages to be dispatched, but without keyboard translation */
            while (PeekMessage(&msg, NULL, 0, 0, PM_REMOVE))
            {
                DispatchMessage(&msg);
            }
        }

        // Update the amount of time left to wait if not infinite
        if (INFINITE != dwTimeout)
        {
            dwTimeLeft = dwTimeout - (GetTickCount() - dwStart);
            if ((int)dwTimeLeft < 0)
            {
                // We've waited long enough
                break;
            }
        }
    }

    return(dwObj);
}
