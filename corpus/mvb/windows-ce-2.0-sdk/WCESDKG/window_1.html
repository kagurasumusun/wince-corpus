Window Management

A window is a rectangular area of the display where an application displays output and receives input from the user. Multiple windows can be open simultaneously, but only one window at a time can receive user input. Every window in a Windows CE application is a member of a window class. A window class is a set of attributes that Windows CE uses as a template to create a window. Each window class has a window procedure that processes messages for all windows of that class.

In Windows CE, you manage windows the same way you do in Windows desktop platforms, with the following exceptions.Windows CE does not support Dynamic Data Exchange (DDE) or Multiple Document Interface (MDI).

Since Windows CE does not support window properties, the only way you can associate instance-specific information with a window is to register extra bytes for the window by using the cbWndExtra field of the WNDCLASSstructure. Because Windows CE does not support unaligned access in window classes, the value of cbWndExtra must be a multiple of four. Since Windows CE does not support the default value GWL_USERDATA in this field, you must allocate the bytes yourself. You can then use the SetWindowLong and GetWindowLong functions to store and access data.

In Windows CE 2.0, changing the visibility of a window does not automatically change the visibility of any windows it owns. Also, if you create a dialog or other owned window whose parent window is not visible, the owned window will be visible under Windows CE 2.0 but will not be visible under later versions of Windows CE. To avoid this inconsistency, do not create a window or dialog that is owned by an invisible window.

Because many Windows CE-based devices have small screens, you should generally use the full-screen for an application's primary window. Different devices have different screen sizes, so either use the dimensions returned by the GetSystemMetrics function to define the size of your primary window, or specify CW_USEDEFAULT in the nWidth and nHeight parameters to CreateWindow or CreateWindowEx.

Note The screen height returned by GetSystemMetrics includes the taskbar. To determine the available screen size, subtract the height of the taskbar from the screen height returned by GetSystemMetrics.

In Windows CE, you specify a window's size when you create it; the user cannot resize it. Although Windows CE does not support the Maximize and Minimize buttons, the user can send a window to the back of the Z order or restore it to the foreground by tapping its icon button on the taskbar.

In Windows CE, a window has a button on the taskbar only if it is a visible top-level window with the style WS_OVERLAPPED.

Note An application can only receive the WM_HIBERNATE message if it has a button on the taskbar. A window that is hidden will not get this message, even if it is a top-level overlapped window.

You use the WindowProc and EnumWindowsProc callback procedures in Windows CE the same way you use them in Windows desktop platforms.
