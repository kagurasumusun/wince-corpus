Messages and Message Queues

A message conveys information to a window or notifies it that an event that has taken place. The operating system communicates with an application window by placing messages in the message queue of the thread that created the window. The thread removes the messages from its queue and directs them to the appropriate window procedure for processing. Applications also use messages to communicate information between their own windows.

Windows CE doesn't send applications any messages dealing with the non-client area of the window. The non-client area is controlled solely by the window manager.

Windows CE doesn't support hooking messages because the extra processing required by hooks could seriously degrade the performance of Windows CE-based devices.

In Windows CE, you can define your own messages to send within a private window class just like you can in Windows 95 and Windows NT. (Use numbers in the range WM_USER through 0x7FFF for these messages.)

The MSG structure is the same in Windows CE as it is in Windows 95 and Windows NT. If the platform you're targeting doesn't support mouse cursors, however, the pt field contains the coordinates of the last position touched on the screen, rather than the coordinates of the current cursor position.

The NMHDR structure for notification messages is also the same as it is in Windows 95 and Windows NT, with the exception that the NM_RCLICK and NM_RDBCLICK values aren't supported in the code field, because there's no right mouse-click event in Windows CE.

For an overview of message-related functions supported in Windows CE, see Message Functions.
