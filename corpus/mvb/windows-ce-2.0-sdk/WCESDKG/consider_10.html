Testing Windows CE Applications

If you are developing an application for a standard Windows CE target such as an H/PC, you can do most of your development and testing in the emulation environment. Once your application is running perfectly in the emulation environment, you can build and test your application, and then download it to your target device for final testing. In addition to testing for defects and reliability, testing for usability is critical, since most Windows CE devices have a small desktop area that can present access problems.

Applications developed for one language and localized for use with another must be tested for correct translation. Since translated material must fit into the menu, control bar, or taskbar, you may need to resize or rearrange some of your user interface items.

Developing applications for non-standard targets, such as a custom embedded system, presents unique testing problems. Perhaps you can use the Remote API tools but you cannot use the emulation environment. You must devise your own debugging and testing tools. The Windows CE API includes debugging interfaces, that can be used to create your own debugger or in-system debugging tools.

No matter what tools you use you must thoroughly test your application on every kind of device that will run your application. See the following for additional information on the emulation environment, remote debugging tools and the Debugging API.
