Tips for Efficient Memory Utilization

This section has some tips and suggestions for creating H/PC applications that use memory effectively.

Any attempt to allocate more than 16K has the potential to fail without the System Out of Memory Dialog displaying and without alerting the user of a low memory problem. The application must handle such failures gracefully.

Once the system is in a low memory regime, any allocation greater than 8K has the potential to fail. It is highly recommended that applications not allocate large amounts of memory in their shutdown code, especially since the user does know that a low memory situation exists.

Small memory allocations almost never fail. Before this type of allocation fails, the user has gone through both low memory and critical memory System Out of Memory Dialog Boxes, and has had an opportunity to respond. An application does not have to handle such failures quite as gracefully as those that may occur without warning.

Even when dealing with large amounts of data, many calculations are sequential and involve only two or three pieces of data at any one time. For example, loading an entire data set into one or more arrays can waste memory resources because this stores a duplicate of the data found in the original data file.

If you are using large data sets, consider loading only the data that is immediately necessary for a particular operation, especially if it will not be modified in the process. When the data is no longer needed, write it back to the file immediately. This practice basically trades speed for memory.

With Version 2.0 of the OS, you can page out of memory read-only pages if resources are tight. If you are not modifying data, declaring it as constant allows the kernel to remove it if necessary. It will be restored the next time data from the page is accessed.

Many programs use temporary files that are deleted when the program terminates. While this may be convenient, such files represent a load on memory resources. There are a number of strategies for using temporary files that you may want to consider.

One consideration is elimination. While eliminating temporary files may decrease speed, simplicity, or perhaps the robustness of the application, the increase in memory efficiency is sufficient to offset the liabilities. If possible, design applications so that they can modify their usage of temporary files depending on the state of memory resources.

Data stored in text format and uncompressed bitmaps are a relatively inefficient use of memory. While compression and decompression of such files takes time, it is worth it to reduce memory usage. Some compression already takes place when files are loaded from a desktop PC to an H/PC.

While one of the most appealing features of Windows is the rich graphical environment you can create, graphics are very demanding in terms of memory. You must limit your use of bitmaps and other graphic displays in order to conserve memory. One approach is to use an algorithm to generate an image, rather than loading a bitmap or other graphics file. This approach provides a speed versus memory tradeoff that may still be attractive. It works best for line drawings but is practical for other types of graphics as well.

While the system has ways of handling limited memory conditions, they are not ideal for all applications. It is often better to include some memory management capabilities in the application itself rather than depend on the system. For example, an application that downloads large amounts of data over a modem connection (e-mail or stock quotations, for example) may require more memory than is available. Determine the amount of free memory in the object store prior to the download (with GetStoreInformation), and warn the user of potential problems.

Automatically creating backup files provides a way to protect users against unintentional data loss. They also take up extra space. Whether or not backup files are automatically generated is usually part of the application's configuration, and must be changed manually by the user (by going to the Tools/Options menu, for instance). If backup files are supported, one option is to prompt users if memory is becoming tight, and offer the option of turning off automatic backups.

If the application has a desktop component, make sure it is sensitive to the memory limitations of the Windows CE platform. When downloading an application or data, inform the user if they have too little memory remaining for the device to operate effectively.
