Handling Low Memory Situations

An H/PC is a low memory device, and RAM is always at a premium. No matter how effectively an application uses RAM, it is always possible for the system to run out of memory. This implies that the VirtualAlloc function cannot find any unallocated pages.

A low memory condition can manifest itself to the application in the following ways:

  • A call to the VirtualAlloc function can fail.

  • The LocalAlloc or HeapAlloc function may attempt to grow a heap, but fail to do so.

  • The stack may try to grow, but not be able to do so.

The first two manifestations cause failures to be returned in an orderly fashion. These failures occur as a result of a direct call by the application, or indirectly following a call to a function such as CreateWindow. The third manifestation is more severe. It causes the process to wait for a free page.

Note Memory limits may change in future releases of the Windows CE operating system.

The system constantly monitors the amount of available memory and tries to prevent limited memory conditions from occurring.

When an application attempts to allocate memory, the system "filters" the request by limiting the amount actually allocated. This prevents a single application from using all available memory with one large allocation. When the system enters a low memory situation, the maximum memory limit is further reduced.

The system continually monitors memory usage. When available memory falls below a Hibernation Threshold, the limited-memory regime is entered, and the system starts asynchronously sending WM_HIBERNATE messages to active applications. This message warns applications that available memory is becoming scarce.

There are two additional thresholds, low and critical, that define successively more restrictive memory regimes. The following table defines values for memory thresholds and maximum allowable memory allocations for the three levels of limited-memory conditions. The numbers are based on a 1K page, with those for a 4K page size provided in parentheses.

Item Value Description
Hibernation Threshold 128K

(160K)

 Point at which the system enters a limited-memory state. A WM_HIBERNATE message is sent when the system memory falls below this value.
Low Memory Threshold 64K

(96K)

 Minimum available memory size the system must maintain when system is in a "low" memory state.
Maximum Low Memory Allocation 16K Maximum amount of memory allowed to be allocated with VirtualAlloc when system is in a "low" memory state.
Critical Memory Threshold 16K

(48K)

 Minimum available memory size system must maintain when system is in a "critical" memory state.
Maximum Critical Memory Allocation 8K Maximum amount of memory allowed to be allocated with VirtualAlloc when the system is in a "critical" memory state.

There are basically four limited memory scenarios that the system must respond to. They include:

  • Request less than the low-memory maximum

  • Request greater than the low-memory minimum

  • Request less than the critical-memory maximum

  • Request greater than the critical-memory minimum

If an application calls VirtualAlloc requesting a memory allocation less than the maximum allowable for a low-memory state, but still enough to cause the system to fall below the low-memory threshold, then a System Out of Memory Dialog Box displays. The user must either select applications for the system to close, or increase the amount of RAM allocated to Program Memory.

If the user opts to close applications the system sends WM_CLOSE messages. If an application marked closed does not shutdown within 8 seconds, an End Task/Wait Dialog Box displays, giving the user the choice of terminating the application or waiting for an additional period of time.

Any VirtualAlloc call that requests more than the low-memory maximum fails if it causes the amount of available memory in the system to fall below the low-memory threshold. The System Out of Memory Dialog Box does not displays. LocalAlloc does not necessarily have the same constraint. Depending on the state of the system's heap, a LocalAlloc can succeed.

If an application calls VirtualAlloc and the request causes the amount of available memory in the system to fall below the critical memory threshold, the System Out of Memory Dialog Box displays. The user must either select applications for the system to close, or increase the amount of RAM allocated to Program Memory (if available). The system calls TerminateProcess to terminate any applications selected by the user.

Applications that call VirtualAlloc requesting a memory allocation greater than critical-memory maximum fail if the amount of available memory in the system falls below the critical-memory threshold. Depending on the state of the system's heap, calls to LocalAlloc can succeed.
