Registering a Transport Service

A transport service library must register itself in the Registry so that a client application can locate and load the DLL. A transport DLL is registered under the HKLM\PMail\ServicLibs key. The Windows CE default mail transport is smtp.dll for the connection services between the Inbox client and an Internet mail server compliant with the SMTP and POP3 protocols. This library is registered as the SMTP subkey.

All interactive transport services must be registered with the client application so that a user can choose one for connecting to the server. An interactive transport is the one which appears in the service list visible to users. In Inbox, interactive services are added to the Service menu once they are registered as a named key under HKLM\PMail\ServiceInfo. If the user remove an interactive service, Inbox deletes the associated registry entry. On the other hand, passive services are those that deliver mail behind the scenes, without requiring the user to drive the interaction. They are registered as a similarly named key under HKLM\PMail\PassiveServiceInfo. The client uses the passive service registration information to allow the user to select the transport for outgoing messages. Unlike interactive services, there are no subkeys for passive services.

Registered interactive services can be added to the Service menu of the Inbox application (by tapping the Compose menu followed by the Options dialog followed by the Add dialog).
