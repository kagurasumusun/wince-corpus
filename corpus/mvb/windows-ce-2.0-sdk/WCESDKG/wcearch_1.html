Summary Description of the Windows CE Operating System

The features supported by the various modules are briefly outlined below. The primary modules are discussed in more detail later in the chapter.

The Kernel Module

The Kernel module is the core of the operating system, and provides system services for managing threads, memory, and resources. Its features include:

  • Preemptive, priority-based thread scheduling based on the Win32 process and thread model. Priority inversion is prevented with a system of priority inheritance that dynamically adjusts thread priorities.

  • Predictable thread synchronization mechanisms, including wait objects such as named mutexes, critical sections, and named and unnamed event objects.

  • Allows Windows CE applications to simultaneously share common routines. This approach minimizes the amount of memory-resident code and reduces the execution overhead associated with repeated calls to Kernel.

  • Efficient memory management based on dynamic-link libraries (DLLs), which link user applications at run-time.

  • A flat virtual address space, with 32 MB reserved for each process. Process memory is protected by altering page protections

  • On-demand paging for both read-only memory (ROM) and random-access memory (RAM).

  • Heap size is limited only by available memory.

  • Control of interrupt handling by software developers. System software developers can map IRQs to hardware interrupts and implement their own interrupt service routines and interrupt service threads.

  • Extensive debugging support, including Just-In-Time debugging.
The Core System Interface Module

This module provides an interface through which applications can access the operating system. It includes:

  • "Thunks" to transfer API calls to the GWES module

  • National language support (localization)

  • Local heap and memory allocation

  • Window class and accelerator support

  • Serial port support
The File System Module

The file system module supports persistent storage of information. It includes:

  • Support for FAT file systems with up to nine FAT volumes.

  • Transactioned file handling to protect against data loss.

  • Demand paging for devices that support paging.

  • FAT file system mirroring, to allow preservation of the file system when power is lost or cold reset is needed.

  • Installable block device drivers.
Graphics, Windowing, and Events Subsystem (GWES) Module

The GWES module provides the essential graphics and windowing functionality for image and text display. It also supports event management, printing, and interprocess communication. It includes:

  • Support for a broad range of window styles including overlapping windows,

  • A large selection of Windows controls (buttons, edit boxes, etc.).

  • A Command Bar, that combines the functionality of a toolbar and a menu bar.

  • A replaceable Out of Memory dialog box that can request user action when the system is low on memory.

  • Full UNICODE support

  • A multi-platform graphics device interface (GDI) that supports:
    • Custom display and printer drivers, implemented by the developer.

    • Both color and grayscale displays, with color depths of up to 32 bits per pixel.

    • Palette management.

    • TrueType and raster fonts.

    • Printer, memory, and display device contexts (DCs)

    • Support for advanced shape drawing and bit block transfers (Bitblits) for bitmapped graphics.
Communications

The communications module supports a wide range of serial and network communications technologies. It includes:

  • Support for serial communication including infrared links

  • Support for internet client applications, including HTTP and FTP protocols

  • A CIFS redirector for access to remote file systems

  • A subset of Winsock version 1.1 plus support for Secure Sockets.

  • A TCP/IP transport layer, configurable for wireless networking

  • An Infrared Data Association (IrDA) transport layer, for robust infrared communication

  • Both PPP and SLIP protocols for serial-link networking.

  • Support for local area networking through the network driver interface specification (NDIS).

  • Support for managing phone connections (the Telephony API)

  • Support for a remote access services client (RAS), which allows connections to remote file systems.
Additional services

There are a number of additional modules that can be added to the system as needed. They include:

  • A shell, to handle such tasks as launching applications. OEMs may use a shell much like that developed for the H/PC, although many will implement one that is customized for the needs of their device.

  • Support for access to databases created by the mail and contacts applications.

  • Support for synchronizing data between a Windows CE device and a desktop computer.

  • Support for COM/OLE object-oriented development

  • Visual Basic run-time support

  • Microsoft Foundation Class Library (MFC) support

  • Microsoft Active Template Library support

  • National language support, that allows you to specify information about the system and the user locale.

  • Support for localization of applications including built-in support for French, German, Italian, Spanish, Brazilian, Portuguese, and Japanese.
