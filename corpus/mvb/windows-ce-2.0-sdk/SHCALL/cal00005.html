Parameter Passing

In general, the argument list is laid out as if it were a memory-based structure with padding inserted to achieve appropriate alignment. The first four 32-bit words (words 0 thru 3) are passed in registers R4 thru R7. If a callee takes the address of any of the arguments passed in these registers (either directly or via varargas), and the resulting pointer has any possibility of being used to reference subsequent arguments, then at least that argument and all that follow it in the registers must be copied to the stack area reserved for that purpose. For now, all argument registers are stored regardless of which argument has its address taken. The reserved area is adjacent to the rest of the argument list so that all varargs dirty tricks work.

Integer and integer-equivalent (e.g., char, pointer) arguments which are 32-bits or smaller are passed as 32-bit words. A 64-bit integer argument is passed as a 4-byte aligned scalar.

A 64-bit floating-point argument (type double) is passed as a 4-byte aligned scalar. 32-bit floating-point arguments (type float) are passed as 32-bit words.

A struct or union parameter is passed as a copy.

The first 4 words of the resulting memory image are then passed in integer registers and the remaining words for the argument list image are passed on the stack. If only part of a structure or union parameter fits into the first 4 words of the argument list, the remainder is stored on the stack.

If stack probes are required, R1 is used to pass the requested size for stack memory allocation to chkstk(). This routine is called in a prolog if a half page or more of stack space is needed for the stack frame. It is also called whenever an alloca() call is made.

The NK/SH-3 calling sequence provides a varargs implementation that supports all the typical abuses of ANSI C's varargs specification.

A va_list can be implemented as a real C pointer.

va_arg() can be implemented as properly casting and dereferencing the va_list, then incrementing the va_list by the size of the given type.

va_start() can be implemented as returning the address of the item immediately following the one given to it.

va_end() can be implemented as a noop.
