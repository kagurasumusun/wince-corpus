2.8.1 Expression Elements

An expression consists of terms, operators, and parentheses. Expressions of arbitrary complexity, using C operators and precedence, may be used almost anywhere that a number is required. The assembler supports many C language operators, using the C precedence.

Terms: Terms include the following:

A constant

The location counter reference ($ or PC)

A symbol (excluding aliases of register names)

The result of a calculation specified by a combination of the above terms and an operator

An independent term is also a type of expression.

Note:

1. Operators in each group have the same precedence. An operator has higher precedence than operators in subsequent groups.

Note:

2. The operators in the first group are the unary operators. The unary operators are right-associative (processed from right to left). All the other operators are left-associative (processed from left to right).

Note:

3. In the assembly language, programs are divided into units called sections. Sections are the units in which linkage processing is performed. When there are multiple sections of the same type and same name within a given program, the linkage editor links them into a single section set. STARTOF is an operator that determines the starting address of the section set. SIZEOF is an operator that determines the size of the section set in byte units. See section 3.1, Sections for reference.

While expressions are permitted almost anywhere, in some contexts they must not contain forward references or relative expressions (those involving symbols whose value is not yet known, or not known until link time).

Expressions are permitted in .AIF, .AELSIF, .AWHILE, and .AREPEAT directives.

The assembler supports preprocessor symbols (of the form \&name) in any context, not just in conditional assembly directives and macro expansions. However, it is important to note that outside of macro expansions, these symbols will always constitute a token of their own (either a numeric constant or a string constant). They may not be included as part of another token. In a macro expansion, a preprocessor symbol may be inserted anywhere, and it will be substituted before token boundaries are determined.

The character string manipulation functions (.LEN, .INSTR, and .SUBSTR) may be used anywhere an expression is valid. See section 8.5, Character String Manipulation Functions, for reference.

Parentheses: Parentheses modify the operation priority. Parentheses may be used to group expression components if the default precedence or associativity is not as desired.

There are two bitwise xor operators (^ and ~): ^ is provided for compatibility with C and C++, and ~ is provided for compatibility with other Hitachi assemblers.

The comparison operators (<, >, <=, >=, ==, and !=) may have either string operands or numeric operands. The addition operator (+) may have either string operands or numeric operands. With string operands, the addition operator concatenates the strings. In other contexts, strings in expressions will either be assumed to be character constants ( “ABC” would be equivalent to H’414243, and character constants longer than 4 characters result in an error message), or are considered erroneous.

The && and || operators work as they do in C and C++: their left-hand operand is evaluated, and if the result of the expression can be determined based on the left-hand operand alone (if the left-hand operand of && is zero, or the left-hand operand of || is non-zero), then the right-hand operand is not evaluated.

The ? : (question-colon) operator works as it does in C and C++: the left-hand operand is evaluated, and then if the left-hand result is zero, the rightmost operand (expr2 in the table above) is evaluated and the result used as the result of the ? : operator; otherwise (if the left-hand result is non-zero), the middle operand (expr1 in the table above) is evaluated and the result used as the result of the ? : operator.

See the next section, Operation Priority, for further reference.
