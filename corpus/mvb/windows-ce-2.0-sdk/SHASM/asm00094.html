5.6.4 .ENDF: End of Function

Syntax:

.ENDF

Statement Elements:

Label: The label field is not used

Operation: Enter the .ENDF mnemonic in the operation field

Operands: The operand field is not used

Description:

The .ENDF directive marks the end of a function, and should appear after the last line of code for each function. If a .ENDF directive is encountered when there is no matching .ENTRY directive (ie, if no .ENTRY directive has been encountered, or no .ENTRY directive has been encountered since the most recent .ENDF directive), the assembler issues an error message. If the end of the program (or section) is reached, and a function is still pending (either because there is a .ENTRY directive with no matching .ENDF directive, or because code was encountered without a .ENTRY directive, and so the assembler implicitly opened a function), the assembler issues a warning message and acts as though there were a .ENDF directive at the end of each section that has a pending function.

When the assembler encounters an .ENDF directive, it writes out any pending literal pool for the current section (as if a .pool directive had been encountered). It also takes any pending .PDATA directive information, applies it to the current function (the one being terminated by the .ENDF directive), and resets the .PDATA directive information.

Refer to examples given in the PDATA directive section.
