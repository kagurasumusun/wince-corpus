1.3 Function-Definition Assembler Directives

To support the requirements of structured exception handling and providing stack traces in the debugger, object files must contain information regarding where functions begin and end, and what part of each function is devoted to setting up the function’s stack frame. For functions written in C and C++, this is handled by the compiler, and need not be a concern of programmers. However, when coding in assembly language, the programmer is responsible for providing this information. You provide this information using the following directives:

.PDATA: defines the language specific exception handler, and optionally data for that handler, for the following or current function.

.ENTRY: defines a function and marks its beginning.

.BIGENTRY: same as ENTRY but only used for exceptional situations.

.PROLOG: marks the end of the function prolog. The function prolog is the code at the beginning of the function that sets up the function’s stack frame, in accordance with the Calling Standard Specification.

.ENDF: marks the end of the function.

For more detailed information on prolog code and related topics, refer to the Calling Standard Main Menu Specification document; here, we are primarily concerned with the syntax and semantics of the relevant assembler directives. Note that it is recommended that you use the calling convention macros described in the Calling Standard Specification, rather than using these directives yourself; these macros are summarized following the description of the directives.
