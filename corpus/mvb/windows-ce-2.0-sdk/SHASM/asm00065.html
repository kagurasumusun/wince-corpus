5.2.1 .SECTION: Section Declaration

Syntax:

.SECTION<section name> [,<section type> [,<section attributes>...]]

Statement Elements:

Label: The label field is not used

Operation: Enter the .SECTION mnemonic in the operation field

Operands: First operand: the section name; the rules for section names are similar the rules for symbols, except that the first character of the section name may be a period (.), and except as noted below for comdat support. (See section 2.5.2, Symbol Coding)

Second operand: the section type; when the specification is omitted, the section will be a code section (Table 5.2)

Table 5.2 Second Operand Section Types

Attribute
Section Type
CODE (default)
Code section
DATA
Data section
BSS
BSS section
DUMMY
Dummy section

When the specification is omitted, the section will be a code section
Third operand: section attributes (Table 5.3)

Table 5.3 Third and Greater Operand Section Attributes

Specification
Meaning
SELECTION=<selection number>
Specifiy comdat selection type
ASSOC=<section symbol>
Specify other section to associate with
ALIGN=<boundary alignment value>
Specify section's alignment
Note:

When the specification is omitted, the section will be a relative address section with a boundary alignment value of four.

Description:

.SECTION is the section declaration assembler directive. A section is a part of a program, and the linkage editor regards it as a unit of processing. Figure 5.1 describes section declaration using simple examples.

Figure 5.1 Section Declaration Assembler Directive

A section name (both in a .SECTION directive and in expression contexts) may be either of the same form as an ordinary symbol (with the extension of allowing a period (.) as the leading character of the name), or of the following form:

<symbol1> { <symbol2> }

In the example above, symbol1 is the section name as it should appear in the object file, and symbol2 is the “COMDAT symbol” as described in the MS-COFF documentation. The curly braces are part of the actual syntax. A section declared using this syntax will be a COMDAT section in the object file. A section is uniquely identified by the combination of symbol1 and symbol2. For instance, .text{foo} and .text{bar} will identify two different sections; both will have the name .text in the object file, and both will be combined into a single .text section (along with all other .text sections) at link time. However, the former will have foo as its COMDAT symbol and the latter will have bar as its COMDAT symbol.

The SELECTION=<expression> option determines the COMDAT selection type for the section. The default is 5 (IMAGE_COMDAT_SELECT_ASSOCIATIVE) if the ASSOC= option is used, and 0 otherwise. This option is valid only for a COMDAT section.

The ASSOC=<section symbol> option causes the section being declared to be linked if the section identified by section_symbol is linked. Use of this option causes the COMDAT selection type to default to 5 (IMAGE_COMDAT_SELECT_ASSOCIATIVE). This option is valid only for a COMDAT section, and the target of the association (section symbol) must be a COMDAT section as well.

Example:

SEL_NODUP .equ 1

.section .text{foo},code,selection=SEL_NODUP

nop

.section .data{bar},data,assoc=.text{foo}

.data 0

.section .text{`??main@A`},code,selection=SEL_NODUP

nop

.section .data{`??main@Q`},data,assoc=.text{`??main@A`}

.data 0

It is possible to redeclare (re-enter) a section that was previously declared in the same file. Figure 5.2 shows a simple example of section restart.

Note:

When using the .SECTION assembler directive to restart a section, the second and third operands can be omitted. The original specifications when first declaring the section remain valid.

Figure 5.2 Section Restart

Use ALIGN = <boundary alignment value> to start a relative address section. The linkage editor will adjust the start address of the section to be a multiple of the boundary alignment value. The boundary alignment value specified must be an absolute value, and forward reference symbols must not appear in the specification. The values allowed for the boundary alignment value are powers of 2 <= 2^6 (64), e.g. 2^0, 2^1, 2^2, , 2^6. For code sections, the values must be 4 or larger powers of 2, e.g. 2^2, 2^3, 2^4, 2^5, 2^6.

The assembler provides a default section for the following cases:

The use of executable instructions when no section has been declared

The use of data reservation assembler directives when no section has been declared

The use of the .ALIGN assembler directive when no section has been declared

The use of the .ORG assembler directive when no section has been declared

Reference to the location counter when no section has been declared

The use of statements consisting of only the label field when no section has been declared

The default section is the following section:

Section name: .text

Section type: Code section

Relative address section with a boundary alignment value of 4

Example:

.ALIGN 4 ; This section of the program belongs to the

.DATA.L H'11111111 ; default section P.

; The default section P is a code section, and

; is a relative address section with a boundary

; alignment value of 4.

.SECTION CD,CODE,ALIGN=4

.MOV R0,R1 ; This section of the program belongs to the

.MOV R0,R2 ; section CD.

; The section CD is a code section, and is a

; relative address section with a boundary

; alignment value of 4.

.SECTION DT,DATA

X1: .DATA.L H'22222222 ; This section of the program belongs to

.DATA.L H'33333333 ; the section DT.

; The section DT is a data section, and

; is an relative address section with a

; boundary alignment value of 4.

.END

Note:

This example assumes the .SECTION assembler directive does not appear in the parts indicated by ~.
