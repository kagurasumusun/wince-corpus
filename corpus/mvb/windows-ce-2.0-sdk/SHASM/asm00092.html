5.6.2 .BIGENTRY: Function Definition (Large Functions)

Syntax:

<symbol>[:].BIGENTRY

Statement Elements:

Label: Enter a reference symbol in the label field; this is required

Operation: Enter the .BIGENTRY mnemonic in the operation field

Operands: The operand field is not used

Description:

The .BIGENTRY directive marks the beginning of a large function, and associates a name with that function. The .BIGENTRY (or .ENTRY) directive should be inserted before the first line of code (.DATA and related directives are fine). If the assembler encounters code before any .ENTRY/.BIGENTRY (or after a .ENDF, with no intervening .ENTRY/.BIGENTRY), a warning is issued and the assembler acts as though a .ENTRY directive had been found immediately before the line of code.

The label operates as a normal label (causing the symbol to be defined with the current value of the location counter as the value of the symbol). The label also associates the symbol with the function. Refer to examples given in the following .PDATA directive section.

Ordinarily, the .ENTRY directive should be used. For functions more than 16,777,214 bytes long, or whose prolog is more than 510 bytes long, the .BIGENTRY directive should be used. If. ENTRY is used for a function that needs .BIGENTRY, the assembler will issue error 554 or 555. If .BIGENTRY is used for a function that could use .ENTRY, no warning or error will result, and the output will be correct. However, 8 bytes is wasted in the code section in which the .BIGENTRY directive appears.

Note:

A function that requires the use of .BIGENTRY would be very unusual.

Refer to examples given in the .PDATA directive section.
