5.6.6 Calling Convention Macros

Calling Convention Macros: It is strongly recommended that programmers use the calling convention macros, rather than directly using the relevant assembler directives. These macros are documented in detail in Appendices A and D of the Calling Standard Specification, and their definitions are provided in the header file kxsh3.h, which may be used via the .INCLUDE directive.

Following is a brief overview of the macros:

START_REGION NameBegin

END_REGION NameEnd
Marks the beginning and end of a contiguous range of text or data. NameBegin labels the beginning of the range and NameEnd labels the end. Both names are in the global name space.

NESTED_ENTRY Name[,[Section=]SectionName]
Declares the beginning of a routine that either has an existing frame or creates a stack frame. Name is the routine name and is in the global name space. SectionName is the name of the section in which the entry will appear. SectionName is optional and defaults to .text. A NESTED_ENTRY must have an associated PROLOG_END and ENTRY_END.

LEAF_ENTRY Name[,[Section=]SectionName]
Declares the beginning of a routine that does not require any prolog code. Name is the routine name and is in the global name space. SectionName is the name of the section in which the entry will appear. SectionName is optional and defaults to .text. A LEAF_ENTRY must have an associated ENTRY_END. An explicit PROLOG_END is not needed in this case because LEAF_ENTRY includes PROLOG_END. Not all leaf routines can use LEAF_ENTRY.

ALTERNATE_ENTRY Name[,[Section=]SectionName]
Declares an alternate entry to a routine of either NESTED_ENTRY or LEAF_ENTRY type. Name is the entry point and is in the global name space. SectionName is the name of the section in which the entry will appear. This parameter is not used by the ALTERNATE_ENTRY macro, but is accepted and ignored for consistency with NESTED_ENTRY and LEAF_ENTRY. If used, an ALTERNATE_ENTRY call must appear in a routine's body.

ENTRY_END [Name]
Ends the current routine that was specified by a prior NESTED_ENTRY or LEAF_ENTRY. Name should be the same name used in the NESTED_ENTRY or LEAF_ENTRY macros. Name is currently ignored by the ENTRY_END macro.

EXCEPTION_HANDLER Handler
Associates the exception handler Handler with the subsequent NESTED_ENTRY or LEAF_ENTRY routine. This association is in effect until the matching ENTRY_END macro is encountered.

EXCEPTION_HANDLER_DATA Handler,HandlerData
Associates the exception handler Handler and the HandlerData with the subsequent NESTED_ENTRY or LEAF_ENTRY routine. This association is in effect until the matching ENTRY_END macro is encountered.

PROLOG_END
Marks the end of the prolog area. This must appear following a NESTED_ENTRY or LEAF_ENTRY macro, following the prolog area and prior to the matching ENTRY_END macro.

NESTED_BIGENTRY Name[,[Section=]SectionName]
The same as NESTED_ENTRY, except uses the .bigentry assembler directive instead of the .entry assembler directive. Use this for functions that are more than 16,777,214 bytes long, or whose prolog is more than 510 bytes long.

Note:

Such a function would be very unusual.

LEAF_BIGENTRY Name[,[Section=]SectionName]
The same as LEAF_ENTRY, except uses the .bigentry assembler directive instead of the .entry assembler directive. Use this for functions that are more than 16,777,214 bytes long.

Note: Such a function would be very unusual.

Example:

Instead of:
Use the following:
.section .text,code
.align 4
.global fun7
fun7: .entry
.prolog
rts
nop
.endf
.section special,code
.align 4
.global fun8
.pdata ex_handler
fun8: .entry
sts.l pr,@-sp
.prolog
bsr fun7
nop
lds.l @sp+,pr
rts
nop
.endf

LEAF_ENTRY fun7
rts
nop
ENTRY_END
EXCEPTION_HANDLER ex_handler
NESTED_ENTRY fun8,Section=special
sts.l pr,@-sp
PROLOG_END
bsr fun7
nop
lds.l @sp+,pr
rts
nop
ENTRY_END
