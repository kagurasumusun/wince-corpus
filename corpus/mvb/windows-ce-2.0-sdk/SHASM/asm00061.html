4.2.3 Address Calculations

When the operand addressing mode is PC relative with displacement, i.e., @(disp,PC), the value of PC must be taken into account in coding. The value of PC can vary depending on certain conditions.

Normal Case: The value of PC is the first address in the currently executing instruction plus 4 bytes. Figure 4.2 shows an address calculation example in a normal case. Consider the state when a MOV instruction is being executed at absolute address H'00001000.

Figure 4.2 Normal Case Address Calculation

During the Delay Slot Instruction: The value of PC is destination address for the delayed branch instruction plus 2 bytes. Figure 4.3 shows an address calculation during the delay slot instruction. Consider the state when a MOV instruction is being executed at absolute address H'00001000.

Figure 4.3 Address Calculation When the Value of PC Differs Due to a Branch

When the operand is the PC-relative specified with the symbol, the assembler derives the displacement, taking account of the value of PC when generating the object code. This occurs during the execution of either a MOV.L @(disp,PC),Rn or a MOVA @(disp,PC),R0.

When the value of PC is not a multiple of 4, SH microprocessors correct the value by discarding the lower 2 bits when calculating addresses. Consider the state when a MOV instruction is being executed at absolute address H'00001002. Figure 4.4 shows an example of this execution.
