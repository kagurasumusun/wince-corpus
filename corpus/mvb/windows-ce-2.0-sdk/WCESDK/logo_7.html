Registry Requirements

Required: Persistence of User Configurations in Registry. User configuration data relating to a currently uninstalled application's setup while on the Microsoft Windows CE-based platform must be installed within the Microsoft Windows CE registry, such that subsequent installations of the application to the Microsoft Windows CE-based platform retain the user's most recent configuration settings.

Required: Register Installation/Uninstallation Script with AppInstall. Applications bearing the Windows CE Logo must also store the necessary installation/uninstallation scripts on the Microsoft Windows CE-based platform.

Required: Store DLLs Only in Windows or Application Directory. Any .dll files used in the installation of the application on the Microsoft Windows CE-based platform must be stored in the Windows directory or in the application's own directory.

Required: Do Not Load Microsoft Windows CE System Components During Installation. Because Microsoft is not authorizing anyone to distribute the Microsoft Windows CE shared system components (included with the original Microsoft Windows CE operating system or with subsequent upgrades), it is not permissible to load these components onto the Microsoft Windows CE-based platform. Attempting to install Microsoft Windows CE core components on top of an existing Microsoft Windows CE-based platform installation could impair the functionality of both the developer's application and all other applications loaded on the Microsoft Windows CE-based platform.

Recommended: Long, Meaningful Filenames for Installed Components. Microsoft Windows CE-based applications installing components to the Windows or application directories should assign long, meaningful filenames to assist users in determining the genesis of installed components. A typical filename might be company_application_function.dll. Note: this is especially important on Microsoft Windows CE where legacy 8.3 filename conventions are not supported.
