MailMsg

The MailMsg structure is used by the Mail and Transport functions to store the contents of messages being sent and received.

Syntax

typedef struct MailMsg {
DWORD dwMsgId;
DWORD dwFlags;
DWORD dwMsgLen;
WORD wBodyLen;
FILETIME ftDate;
LPWSTR szSvcId;
LPWSTR szSvcNam;
WCHAR* pwcHeaders;
LPWSTR szBody;
CEOID oid;
HANDLE hHeap
} MailMsg;

Members

dwMsgId
Specifies an internal identification number maintained by the system. This identification number is used by library routines to access messages in the message store. Applications should not attempt to change the value stored in this member.
dwFlags
Specify the folder containing the message, the status of the message, and how the message is handled. These mail flags are divided into three categories: folder flags, status flags, and message flags. The flags and a brief description of their meanings are listed below.

Folder flags determine which folder to locate or store the message in. Use only one of the following folder flags in combination with status and message flags.

MAIL_FOLDER_ALL
Folder flag mask
MAIL_FOLDER_FIRST
Start of user-defined folders
MAIL_FOLDER_LAST
End of user-defined folders
MAIL_FOLDER_SENT
Copy of sent mail
MAIL_FOLDER_OUTBOX
Local OUTBOX (last local folder)
MAIL_FOLDER_INBOX
Universal INBOX
MAIL_FOLDER_ANY
Search for any folder during "Get"
MAIL_FOLDER_TARGET
Target folder for MAIL_COPY

Status flags verify the status of the message being stored or retrieved, or whether the message has attachment. Status flags can be used to determine what type of messages to search for when calling MailFirst and MailNext functions. These flags can be any combination of the following values.

MAIL_STATUS_ALL
Status flag mask
MAIL_STATUS_FREE
Message deleted - free slot
MAIL_STATUS_DELETE
Message set to be deleted
MAIL_STATUS_COPY
Message set to be copied to local target
MAIL_STATUS_READ
Message marked as having been read
MAIL_STATUS_SERVICE
INBOX Message exists on a service
MAIL_STATUS_COMPOSED
Set for outgoing messages (newly composed, replied, or forwarded). In Windows CE version 2.0, an outgoing message can be saved and later re-edited using the outgoing dialog that includes the SEND button.
MAIL_STATUS_REMOTE
INBOX body exists only on service
MAIL_STATUS_NOT
Look for invert of status bits (GET)
MAIL_STATUS_ANY
(MAIL_STATUS_NOT | MAIL_STATUS_FREE)
MAIL_STATUS_ALIVE
(MAIL_STATUS_ANY | MAIL_STATUS_DELETE)
MAIL_STATUS_LOCAL
(MAIL_STATUS_ALIVE | MAIL_STATUS_SERVICE)
MAIL_STATUS_BODY
(MAIL_STATUS_ALIVE | MAIL_STATUS_REMOTE)
MAIL_STATUS_UNREAD
(MAIL_STATUS_ALIVE | MAIL_STATUS_READ)
MAIL_STATUS_ATTACHMENTS
The message has attachments
MAIL_STATUS_ATT_REQ
The message's attachment is marked for download

Message flags determine how the message will be handled and how much of the message is retrieved on a mail get. If none of the message flags are set, all fields but the body are retrieved. Use any combination of the first two flags with one of the remaining flags.

MAIL_FLAGS_ALL
Message flag mask
MAIL_KEEP
Move from OUTBOX to FILE after sent. In Windows CE Platform SDK version 2.0, this flag is no longer used. Instead, the client application checks the current registry settings to determine whether it does or does not save a message in the Sent Item folder.
MAIL_GET_BODY
Get body (during a MailGet)
MAIL_GET_FLAGS
Get only flags field (during a get)
MAIL_FULL
Get full body when copying

dwMsgLen
Specifies the size, in bytes, of the entire message on the service.
wBodyLen
Specifies the size, in bytes, of the message as maintained in the message store.
ftDate
Specifies the date and time the message was received by the service.
szSvcId
Specifies a unique identification number assigned by the service. The service uses this identification number to access the desired message.
szSvcNam
Specifies the name of the service. Applications can use this name to link messages to a particular service.
pwcHeaders
Pointer to the header fields. The header consists of entries made up of two fields, a name and an associated value. The name fields are separated from the value fields by a NULL character, and the entries are separated from each other by a NULL character. The header string is terminated with two consecutive NULL characters.
szBody
Pointer to the body of the message.
oid
Specifies the object identifier. The object ID is assigned by the system and can be used as a key for storing and receiving messages. The object ID is set when the message is inserted in the message store using the MailPut function and returned in this field when the MailFirst or MailNext functions are called.
hHeap
Handle to the private heap used for all storage related to this message. Any storage allocated to this heap is freed when the MailFree function is called.

Remarks

A mail message can be either local or linked to a service. Local messages exist only the device. User-composed messages fall into this category. Service-lined messages, on the other hand, exist on a service somewhere, but are referenced locally. Messages which are synchronized and retrieved via the SMTP/POP3 transport fall into this category.
