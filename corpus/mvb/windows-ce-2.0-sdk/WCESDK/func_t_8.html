TransportErrorMsg

The TransportErrorMsg function returns a string associated with an integer error number, for the last error that occurred.

Syntax

int TransportErrorMsg(HANDLE hService, LPWSTR szBuf, int iBufLen, int *piSrcLine,);

At a Glance

Header file: Smtp.h
Platforms: H/PC
Windows CE versions: 1.0 and later

Parameters

hService
Handle to a SERVICE structure.
szBuf
Buffer to hold the error string.
iBufLen
Length of szBuff, in wide chars ¾ that is, Unicode chars; not bytes.
piSrcLine
Line where the error occurred ¾ retrieved from hService->iErrLine.

Return Values

A string describing the nature of the error is placed in szBuf, and the line number at which the error occurred is placed in piSrcLine.

Remarks

Note In Windows CE version 2.0, the piSrcLine parameter can be set to -1 to inform the client that the user is aware of the problem and that it needs not to display any more messages.

In general the transport should not display error dialogs. But if the transport uses a communication service which has set up error dialogs, the transport might have to assume the responsibility to display the error information.

The TransportErrorMsg function must be implemented by the transport service provider in a DLL registered as a mail service. The Inbox application can load this DLL and call TransportErrorMsg.

For example, the sample transport service returns one of the following error strings in szBuf.

Error String String Resource Error Code
"No error" TRANS_ERR_NONE
"Service directory unavailable." TRANS_ERR_NO_SVC_DIR
"Could not allocate memory for service handle." TRANS_ERR_HANDLE_NOT_ALLOC
"Could not create message file." TRANS_ERR_CANT_OPEN
"Could not open mail message." TRANS_ERR_CANT_SEND
"Invalid message ID specified." TRANS_ERR_INV_MSG_ID
"Could not allocate message buffer." TRANS_ERR_NO_MSG_BUF
"There was an error reading the message." TRANS_ERR_READ
"Unknown Error" (String table containing error messages failed to load properly.)
