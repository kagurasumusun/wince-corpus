6.8.5 Interrupt Exception

Cause

This exception occurs when one of eight interrupt conditions (software generates two, hardware generates six) occurs.

Each of the eight interrupts can be individually masked by clearing the corresponding bit in the IntMask field of the Status register.

All of the eight interrupts can be masked at once by clearing the IEc bit of the Status register.

Handling

The PR3910 uses the General Exception vector for this exception.

The EPC register points at the coprocessor instruction which caused the exception, unless the instruction is in a branch delay slot: in that case, the EPC points at the preceding branch instruction and the BD bit of the Cause register is set.

The Int(0) code is set in the Cause register’s ExcCode field.

The Cause register IP and SW fields indicate the current interrupt requests. It is possible for more than one of these bits to be set, or none to be set (when an interrupt is asserted and then deasserted before this register is read).

The IP field indicates the status of interrupt signal regardless of Status register IntMask field. Cause of interrupt should be defined by masking the IP field with IntMask.

Servicing

If the interrupt is software generated (SW0 or SW1), the interrupt condition is cleared by setting the corresponding Cause register bit to 0.

If the interrupt is hardware generated, the interrupt condition is cleared by correcting the condition causing the interrupt pin to be asserted. The manner in which this is accomplished is implementation dependent.
