5.2.3 TLB Entries

Each TLB Entry is 64-bit wide, and its format is illustrated in 1. Each field of a TLB entry has a corresponding field in the EntryHi/EntryLo CP0 registers described in the next section.

Figure 5-3 Format of a TLB Entry

Bit(s)
Mnemonic
Description
63-44
VPN
Virtual Page Number: bits 31..12 of the virtual address. These bits identify a 4K page in the virtual address space.
43-38
ASID
Address Space Identifier: a 6-bit number that is used to identify in a multi-tasking system to which process a certain virtual address belongs to. This way, user-level tasks can be loaded at the same virtual address but be mapped to different physical pages. Systems with more than 64 address spaces need the help of the OS for ASID management.
37-32
—
Reserved, must be written as 0, read as zero.
31-12
PFN
Page Frame Number: bits 31..12 of the physical address. These bits identify a 4K page in the physical address space. The MMU translates the VPN into the PFN.
11
N
Cache Control Bit: when this bit is set to 1 the page is made uncachable.
10
D
Dirty Control Bit: when this bit is set to 1 it allows writes to the page to happen. If an entry is accessed for a write operation when this bit is cleared, the exception TLB Mod is raised.
9
V
Valid Control Bit: If this bit is set, it indicates that the TLB entry is valid; otherwise a TLBL (load) or TLBS (store) miss exception occurs.
8
G
Global Control Bit: if this bit is set, the ASID match requirement is ignored for a valid translation. In kseg2, The Global bit lets the kernel access all mapped data without requiring it to save or restore ASIDs values.
7-0
—
Reserved, must be written as 0, read as zero.

Since there is only a limited number of TLB entries on-chip, they serve as a “cache”of a much larger set of entries maintained in main memory. It is the task of the operating system to write a new entry in the TLB when the look-up fails and the TLB Miss exception is raised.
