6.8.4 Coprocessor Unusable Exception

Cause

This exception occurs due to an attempt to execute a coprocessor instruction when the corresponding coprocessor unit has not been marked usable (i.e., the appropriate CU bit in the Status register has not been set.)

For CP0 instructions (including RFE and DERET), this exception occurs when the unit has not been marked usable and the process is executing in User mode: CP0 is always usable from Kernel mode regardless of the setting of the CU0 bit in the Status register.

This exception is not maskable.

Handling

The General Exception vector is used for this exception, and the CpU code is set in the Cause register’s ExcCode field. The contents of the Cause register’s CE (Coprocessor Error) field show which of the four Coprocessor was referenced.

The EPC register points at the coprocessor instruction which caused the exception, unless the instruction is in a branch delay slot: in that case, the EPC points at the preceding branch instruction and the BD bit of the Cause register is set.

Servicing

To identify the coprocessor unit that was referenced, examine the contents of the Cause register’s CE field. If the process is entitled to access, mark the coprocessor usable and restore the corresponding user state to the coprocessor.

If the process is entitled to access to the coprocessor, but the coprocessor does not exist, or has failed, interpretation of the instruction is possible. If the BD bit is set in the Cause register, the branch instruction must be interpreted; then, the coprocessor instruction could be emulated with the EPC register advanced past the coprocessor instruction

If the process is not entitled to access to the coprocessor, the process executing at the time should be notified that it attempted to execute an illegal instruction. Such an error is usually fatal.
