5.2.5 Virtual to Physical Address Translation

During a translation of a virtual address in kuseg or kseg2, the PR3910 compares the ASID and the highest 20 bits of the virtual address (the VPN) to the contents of each TLB entry. The algorithm for this is illustrated in the figure below.

A virtual address matches (or is mapped by the TLB) if:

the VPN of the virtual address matches the VPN field of a TLB entry

either the Global bit of the TLB entry is set, or the ASID field of the virtual address (stored in the EntryHi register) matches the ASID field of the TLB entry.

If a match is found, then the corresponding physical address (PFN) field of the TLB entry is retrieved from the matching entry along with the access control bits N, D and V.

If no match is found, then either a TLB or UTLB miss exception is raised. the access control bits (D and V) indicate that the access is not valid, or the page is write protect or not yet dirty), then a TLB modification or TLB miss exception will be raised. If the N bit is set, then the processor will not look in its caches for the data, but rather will directly retrieve the word from main memory.
