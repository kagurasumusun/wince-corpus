Using the Alternate Output File Options

The following paragraphs describe how to use the alternate output file options. Information is included on specifying paths and extensions, combining options, and using MS-DOS device names.

Path Specifications and Extensions

The filename argument must follow the option with no intervening space. It can be a file specification, a drive name, or a path specification. If filename is a drive name or path specification, the SHCL command creates the specified file or files in the given location; the default name is the base name of the first file plus the default extension. If the filename argument is a path without a filename (that is, a directory), end the path with a backslash (\) or SHCL cannot differentiate the path from a filename.

You can give any name and extension you want for filename. If you give a filename without an extension, SHCL automatically appends the default extension.

Only one kind of object or assembly listing can be produced for each source file. The following list summarizes the effects of each option with each type of argument:

MS-DOS Device Names

You can append the MS-DOS device names AUX, CON, PRN, and NUL to the alternate output-file options, except for the /FAstring option, and direct the resulting listing files to your terminal or printer. There can be no space between the option and the device name. For instance, the following command line generates assembly code for TEST.C and directs the output to the console:

SHCL /FaCON TEST.C

The following list summarizes the result when a device name is appended to an option:

Device name
Result
AUX
Sends the listing file to an auxiliary device
CON
Sends the listing file to the console
PRN
Sends the listing file to a printer
NUL
No file is created

Note:

Do not append a colon (:) to the device names when you use them as arguments to the listing options. For example, use CON instead of CON: and PRN instead of PRN:

Example:

SHCL /FAsc HELLO.CPP

In the first example, SHCL produces a combined source and machine-code listing called HELLO.COD. The object file has the default name HELLO.OBJ.

SHCL /FaPRN HELLO.CPP

In this example, SHCL sends an assembly-code listing to the printer.
