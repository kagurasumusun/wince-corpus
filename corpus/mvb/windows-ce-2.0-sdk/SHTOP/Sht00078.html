/vmx (Specify Type of Pointers to Members of Classes)

Microsoft C/C++ supports pointers to members of any class. If you always declare a pointer to a member of a class after defining the class, you need not use any of the /vmx options. If you need to declare a pointer to a member of a class prior to defining the class, you must use either the /vmx options (where x is one of b, g, m, s, or v) or the related pointers_to_members pragma.

Before designing your code so that it declares a pointer to a member of a class before defining the class, consider the impact that such a declaration has on the size and speed of the resulting executable file. The number of bytes required to represent a pointer to a member of a class and the code required to interpret the representation vary considerably and may depend on whether the class is defined with no, single, multiple, or virtual inheritance. In general, the more complex the inheritance used by a class, the greater the number of bytes required to represent a pointer to a member of the class and the larger the code required to interpret the pointer.

Options and pragma affect the entire translation unit.

All five /vmx options and the pointers_to_members pragma affect the entire compilation module for which they are used.

__single_inheritance, __multiple_inheritance, and __virtual_inheritance keywords control code generated on a per-class basis.
